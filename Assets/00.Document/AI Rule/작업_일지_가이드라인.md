# 작업 일지 가이드라인 v0.1

---

## 1. 문서 작성 철학
"기록은 흐름을 따르고, 요약은 논리를 따른다."

---

## 2. 작업 일지 규율

### 2-1. 일일 작업 일지
* 네이밍: `[일일 작업 일지]YYYY-MM-DD`
* 형태: Markdown
* 포함 항목: 작업 개요 / 문제·변경·성과(Before-After + Why) / 상세 사용 가이드 / 문제 재현 방법
* 규칙: 한 번 작성한 일지 수정 금지. 작성 시점: 사용자 요청 시

### 2-2. 주간 작업 일지
* 네이밍: `[주간 작업 일지]YYYY-MM-DD`
* 형태: Markdown
* 포함 항목: 작업 개요 / 문제·변경·성과(Before-After + 일일 일지 링크)
* 규칙: Mermaid 문법 기반 도표 작성 필수

---

## 3. 기술 문서 규율

### 3-1. 특정 시스템 기술 문서
* 네이밍: `[기술 문서][Feature]`
* 해결책 제시 시 기술 선택 이유 명시. Mermaid 도표 활용

### 3-2. 전체 시스템 통합 기술 문서
* 네이밍: `[프로젝트 통합 기술 문서]`
* 모듈/피처 단위 큰 그림 + 데이터 흐름 중심. Mermaid 도표 활용

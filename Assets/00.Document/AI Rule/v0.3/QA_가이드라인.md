# 코드 QA 검증 가이드라인 v0.1
> 기반: DLV 아키텍처 v0.3, VContainer 가이드라인 v0.2  
> 목적: 작업 결과물의 폴더 구조 및 아키텍처 규칙 준수 여부 자체 검증

---

## 1. 폴더 구조 및 파일 위치 준수 확인

단일 기능 작업 시 다음 넘버링 규칙과 파일 위치를 정확히 지켰는지 검수합니다.

### 표준 기능 폴더 구조
```text
[순번].[기능명]/                    # 기존 최대 번호 + 1 (예: 기존 10번까지 존재 시 11.Inventory)
├── [기능명]LifetimeScope.cs       # 기능 루트 바로 아래 위치 (하위 폴더 진입 금지)
├── 00.Data/                       # PureData, RuntimeData만 위치
├── 01.Logic/                      # MonoBehaviour 없는 순수 C# 로직만 위치
├── 02.Visual/                     # 인터페이스, 비주얼 컴포넌트, UI View만 위치
└── 99.Legacy/                     # 기존 구형 코드 격리 보관
```

### 폴더 및 파일 체크리스트
- [ ] **기능 폴더 순차 넘버링** — 폴더명이 `[순번].[기능명]` 형식이며, 기존 기능 번호에 이어지는 다음 번호인가? (예: `11.[기능명]`)
- [ ] **Scope 파일 위치 준수** — `[순번].[기능명]/` 루트 바로 아래에 `[기능명]LifetimeScope.cs`가 존재하는가? (00.Data, 01.Logic 등 하위 폴더 내부 배치 절대 금지)
- [ ] **00.Data** — `PureData`(ScriptableObject)와 `RuntimeData`(순수 C#)만 위치하는가?
- [ ] **01.Logic** — MonoBehaviour를 상속받지 않는 순수 C# 로직 파일만 위치하는가?
- [ ] **02.Visual** — 인터페이스(`I...`), 비주얼 컴포넌트, UI View 파일만 위치하는가?
- [ ] **99.Legacy** — 기존 코드가 있을 경우 해당 폴더로 안전하게 격리 보관되었는가?

## 2. DLV 아키텍처 체크리스트

### 2-1. [D] 데이터 그룹
- [ ] **PureData 불변성** — 읽기 전용으로 작성되고 로직 코드가 전혀 없는가?
- [ ] **RuntimeData 캡슐화** — 모든 속성에 `private set`이 적용되어 외부 직접 수정을 차단했는가?
- [ ] **상태 변경 전용 메서드** — 값 변경이 내부 전용 메서드(`DecreaseHp`, `AddExp` 등)를 통해서만 일어나는가?
- [ ] **프레임 갱신 금지** — 데이터 스스로 `Tick`을 돌지 않고, 상태 변경 시 이벤트만 발행하는가?

### 2-2. [L] 로직 그룹
- [ ] **MonoBehaviour 배제** — 로직 클래스가 MonoBehaviour를 상속받지 않고 순수 C# 클래스로 작성되었는가?
- [ ] **직접 제어 금지** — `Rigidbody`, `transform.position`, `NavMeshAgent`를 직접 참조하거나 수정하지 않는가?
- [ ] **구체 클래스 참조 금지** — 타 시스템을 직접 참조하지 않고 인터페이스나 이벤트로만 소통하는가?
- [ ] **데이터 수정 방식** — 데이터 값을 직접 연산해 대입하지 않고, 데이터의 전용 메서드를 호출하여 지시했는가?
- [ ] **유니티 생명주기 인터페이스** — 실행 시점에 맞는 VContainer 생명주기(`IInitializable`, `ITickable`, `IFixedTickable`, `ILateTickable`, `IDisposable`)를 사용했는가?

### 2-3. [V] 비주얼 그룹
- [ ] **인터페이스 분리** — 비주얼 동작이 `I[Feature]Visualizer` 추상 메서드로 정의되어 있는가?
- [ ] **수동적 실행** — 비주얼 컴포넌트가 자체 판단 없이 로직의 지시만 받아 시각 연출 및 물리를 수행하는가?
- [ ] **UI 이벤트 구독** — UI View가 데이터를 직접 계산하지 않고 RuntimeData 이벤트만 구독하는가?

## 3. VContainer 의존성 주입 체크리스트

- [ ] **씬 검색 제거** — `GameObject.Find`, `FindObjectOfType`이 완전히 제거되었는가?
- [ ] **정적 싱글톤 제거** — `Manager.Instance` 형태의 전역 정적 호출이 제거되었는가?
- [ ] **직접 생성 제거** — 로직 객체를 `new` 키워드로 직접 생성하지 않고 컨테이너가 생성하도록 등록했는가?
- [ ] **컴포넌트 탐색 제거** — 런타임 `GetComponent` 호출 대신 인터페이스 주입을 사용했는가?
- [ ] **인터페이스 바인딩 준수** — 구체 클래스를 직접 주입받지 않고 반드시 `As<IInterface>`로 바인딩했는가?
- [ ] **주입 경계 준수** — 프리팹 내부 UI나 단순 리소스 컴포넌트를 불필요하게 VContainer로 주입하지 않고 인스펙터 직렬화로 유지했는가?

## 4. 네이밍 및 코드 품질 체크리스트

- [ ] **네이밍 규격 준수**
  - 고정 데이터: `[PureData]명`
  - 상태 데이터: `[RuntimeData]명`
  - 로직 시스템: `[System]명` 또는 `[Calculator]명`
  - 비주얼 인터페이스: `I[Feature]Visualizer`
  - 비주얼 구현체: `[Feature]Visualizer`
  - UI 뷰: `[Feature]UIView`
- [ ] **테스트 가이드 제공** — 작업 완료 후 인게임 테스트 절차가 명확히 작성되었는가?
- [ ] **단일 책임 원칙** — 하나의 클래스가 데이터 보관, 판단, 연출을 동시에 수행하지 않는가?

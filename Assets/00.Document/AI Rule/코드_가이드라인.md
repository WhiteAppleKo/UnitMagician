# 코드 작업 가이드라인 v0.2
> 작업 환경: Unity

## 1. DLV 아키텍처 (Data-Logic-Visual) v0.2

**철학:** "입력은 흐르고, 데이터는 보존되며(Pure), 로직은 판단하고, 비주얼은 표현한다."

* 코드 작성 후 테스트 케이스 가이드 제공 필수.
* 네트워크 관련: 기능 작업 후 추가. 기존 파일 존재 시 `파일명 + 리팩토링 진행` 출력.

### 1-1. [D] 데이터 그룹

| 모듈 | 네이밍 | 형태 | 핵심 규칙 |
|------|--------|------|-----------|
| Pure Data | `[PureData]명` | ScriptableObject | Immutable(readonly/private set), Logic-Free |
| Pure DataBase | `[PureDataBase]명` | SO | `Dictionary<ID, PureData>` 보관, PureData 훼손 금지 |
| Runtime Data | `[RuntimeData]명` | — | PureData 읽기 참조, Observable(C# event), Self-Update(Tick), ISaveableData 상속 |
| Data Save-Load | — | — | ISaveableData 인터페이스, 저장/불러오기로만 RuntimeData 변경 |

### 1-2. [L] 로직 그룹

| 모듈 | 네이밍 | 핵심 규칙 |
|------|--------|-----------|
| Logic | `[System]` (예: ActionLogicSystem) | 판단만 수행. 값 직접 수정 금지. Interface 통해 Visual 호출. `Rigidbody`·`NavMeshAgent`·`transform.position` 직접 참조/수정 금지 |

### 1-3. [V] 비주얼 그룹

| 모듈 | 네이밍 | 핵심 규칙 |
|------|--------|-----------|
| Visual Interface | `I[Feature]Visualizer` | 추상 함수만. 구체 구현 노출 금지. DIP 고리 역할 |
| World Visualizer | `[Feature]Visualizer` | 수동적 수행자. Interface 구현. 물리/이동 실질 수행 |
| UI View Layer | `[Feature]UIView` | Model event 직접 구독. 계산 로직 포함 금지 |

### 1-4. 개발 3대 원칙
* **Rule 1 – Everything is Data:** 모든 입력 Pure Data 객체 변환. 인자 나열 금지.
* **Rule 2 – Blind Logic:** LogicBehaviour는 Interface/event 통해서만 소통. 직접 참조 금지.
* **Rule 3 – Immutable Data:** Pure Data 런타임 수정 금지. Runtime Model 별도 변수 활용.

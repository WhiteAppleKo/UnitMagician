# 9. 시간 정지 마법 시스템 확장 — 게이지 오버라이드 + 이벤트 전용 접근

> 분류: 기존 확장(시간 정지 마법 시스템) · 관련 단계: 3단계
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)

## 9.1 시스템 개요
3단계의 "시간 정지 유지시간을 무제한으로 완화"하는 요구사항, "자동 시간 정지 발동이 반드시 이벤트 시퀀서를 통해서만 이루어져야 한다"는 리뷰 원칙, 그리고 **사용자 확정(세션 5)** 사항 — 유저가 직접 발동하는 시간 정지(1단계)와 이벤트 시퀀서가 자동 발동하는 시간 정지(3단계)는 **서로 다른 종류의 효과**여야 한다는 것 — 세 가지를 함께 다룬다.

## 9.2 핵심 동작

### 9.2.1 두 가지 시간 정지 모드(사용자 확정, 신규)
- **완전 정지 모드(기존, 유저 수동 발동)**: 1단계 돌문 퍼즐에서처럼 유저가 직접 키를 눌러 발동. 시간이 완전히 멈춘다(기존 `PureDataTimeSlow.SlowTimeScale` 그대로 사용, 사실상 0에 가까운 값).
- **감속 모드(신규, 이벤트 시퀀서 전용)**: 3단계에서 06(이벤트 시퀀서)이 `OnBoss50Percent` 시점에 자동으로 트리거. 시간이 완전히 멈추지 않고 **느리게 흐른다**(신규 `PureDataTimeSlow.EventSlowTimeScale`, 완전 정지보다 큰 부분 감속값 — 예: 0.2~0.3배). 유저가 이 구간에서 아무 조작도 하지 않으면, 06의 회복 페이즈 지속시간(`PureDataTutorialSequence.CoreHitTimeoutSeconds`)에 걸쳐 감속이 **점차 원래 속도(1.0배)로 되돌아온다** — 시간이 완전히 정상 속도가 되는 순간이 곧 "이 기회를 놓쳤다"는 시청각 신호이며, 그 시점이 06의 타임아웃 실패 판정 시점과 정확히 일치한다(같은 지속시간 값을 공유하기 때문). 유저가 그 전에 06으로부터 `OnCoreHitSuccess`/`OnCoreHitFail`(성공/게이트실패 판정)을 받으면 램프가 끝나기 전이라도 즉시 정상 속도로 복귀한다.
- 두 모드는 완전히 구분된 트리거 경로를 갖는다 — `TimeSlowLogicSystem.ActivateSlow()`(기존, 유저 입력용) vs `TimeSlowLogicSystem.ActivateEventSlow(float rampDuration)`(신규, 06 전용).

### 9.2.2 게이지 오버라이드
- `RuntimeDataTimeSlow.FocusGauge` 소모를 억제하는 On/Off 모드. On 상태에서는 시간 정지(완전 정지든 감속이든)를 유지해도 게이지가 줄지 않음. 감속 모드가 활성화되는 동안에는 항상 이 오버라이드도 함께 켜진다(9.2.1의 `ActivateEventSlow` 호출 시 자동으로 함께 적용).

### 9.2.3 이벤트 전용 접근 원칙(리뷰 반영)
`ActivateEventSlow()`/게이지 오버라이드 On·Off는 [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)만 호출할 수 있는 경로로 제한한다(강제 메커니즘은 8번 기획서와 동일하게 설계 규약 수준, 미확정). 현재 시간 정지 시스템이 `CharacterLifetimeScope`(플레이어) 하위에 종속돼 있어, 플레이어와 무관하게 전투 필드 전체에 자동 발동시켜야 하는 3단계 요구사항과 구조적으로 맞지 않을 가능성이 있다 — 필요 시 플레이어로부터 독립된 시스템으로 분리하는 것을 구현 단계에서 검토한다(기존 미해결 항목, 유지).

## 9.3 사용자 조작 흐름
1. **1단계**: 유저가 직접 시간 정지를 발동(완전 정지) → 투사체가 완전히 멈춘 상태로 조준·속성 부여·크기 확대 조작 → 유저가 해제할 때까지 유지.
2. **3단계**: 보스 HP 50% 도달 → 시퀀서가 자동으로 감속 모드를 발동(유저 입력 없음, 완전 정지 아님). 유저는 감속된 상태에서 아군 지원 투사체를 조준·속성 부여·크기 확대 — 단, 감속이 시간에 따라 점점 풀리고 있으므로(9.2.1) 조작이 늦어질수록 체감 난이도가 올라간다.
3. 유저가 판정(성공/실패)을 받거나, 감속이 완전히 풀려 타임아웃되면 시퀀서가 게이지 오버라이드와 감속 모드를 함께 해제한다.
4. **재도전(사용자 확정)**: 4단계 실패 후에도 아군이 즉시 재발사하며, 이때도 3단계 진입 시점과 동일하게 감속 모드+게이지 오버라이드가 매번 다시 켜진다(페널티 없음).

## 9.4 시각/청각 효과
- **완전 정지(1단계)**: 기존 그대로 — 흑백 정지 필터 + 투사체 컬러 강조, 시간 완전 정지.
- **감속(3단계, 신규)**: 흑백 필터 + 투사체 컬러 강조는 동일하게 적용되지만, 시간은 멈추지 않고 느리게 흐른다. 감속이 원래 속도로 되돌아오는 동안 체감 속도가 점점 빨라지는 것 자체가 "시간이 얼마 안 남았다"는 시청각 신호 역할을 한다(정확한 필터 강도 연동 여부 등 세부 연출은 미정 — 구현 단계에서 결정).
- 게이지 무제한 구간: HUD 포커스 게이지가 항상 가득 찬 상태로 고정.

## 9.5 예외/실패 케이스
- 오버라이드가 걸리지 않은 일반 전투 중 시간 정지(완전 정지)를 유지하면, 게이지가 정상적으로 소모되어 게이지가 0이 되는 순간 시간 정지가 강제 해제된다(기존 동작 유지).
- 유저가 3단계 도중 수동으로 시간 정지를 해제하려고 시도해도(만약 입력이 막히지 않는다면), 시퀀서가 관리하는 자동 발동 구간에서는 이 조작이 무시되어야 한다 — 정확한 입력 차단 범위는 확인 필요 항목으로 남긴다.
- 감속이 완전히 원래 속도(1.0배)로 돌아왔는데도 유저가 계속 조작을 시도하면, 이미 06이 타임아웃으로 실패 판정을 내린 뒤이므로 이 조작은 무의미하며 곧이어 03(보스 HP 60% 회복)·02(아군 재발사) 연출로 전환된다.

## 9.6 체크리스트
- [ ] 1단계에서 유저가 직접 시간 정지를 발동하면 기존과 동일하게 시간이 완전히 멈춘다(감속이 아님).
- [ ] 보스 체력이 50%에 도달하면, 유저가 아무 입력도 하지 않았는데도 화면이 이미 흑백 정지 필터와 투사체 컬러 강조 상태로 전환돼 있다 — 단, 시간은 완전히 멈추지 않고 느리게 흐른다(1단계와 구분됨).
- [ ] 3단계 감속 구간에서 유저가 아무 조작도 하지 않고 기다리면, 시간이 점차 빨라져 결국 원래 속도(1.0배)로 돌아오고, 그 순간과 거의 동시에 06의 타임아웃 실패 판정(`OnCoreHitFail`)이 발생한다.
- [ ] 3단계 감속 구간 중 유저가 판정(성공/게이트실패)을 받으면, 램프가 끝나기 전이라도 즉시 정상 속도로 복귀한다.
- [ ] 4단계 실패 후 재도전 시에도 감속 모드와 게이지 오버라이드가 3단계 최초 진입 때와 동일하게 다시 켜진다(페널티 없음).
- [ ] 3단계 자동 발동 구간에서 유저가 시간 정지를 오래 유지해도, 포커스 게이지가 줄어들지 않고 계속 가득 찬 상태로 유지된다 — **MP가 아닌 부분값(예: 절반)인 상태에서 오버라이드가 켜져도** 게이지는 항상 100%로 표시된다(8번 시스템의 마나 게이지와 동일한 요구사항).
- [ ] (예외) 오버라이드가 적용되지 않는 일반 전투 구간에서 유저가 시간 정지(완전 정지)를 유지하면, 게이지가 정상적으로 소모되어 게이지가 0이 되는 순간 시간 정지가 강제 해제된다.
- [ ] (데이터 흐름 근거, 9.8) `TimeSlowLogicSystem.ActivateEventSlow(duration)` 호출 시점의 `FocusGauge.CurrentValue`가 부분값이어도 → `CharacterHUDUIView`의 포커스 바가 즉시 100%로 강제 표시되고 → 해제 시 실제 값 기준으로 즉시 복귀한다.
- [ ] (데이터 흐름 근거, 9.8) `ActivateEventSlow(10f)` 호출 후 시간 경과에 따라 `currentTimeScale`이 `EventSlowTimeScale`에서 `1.0f`로 선형 보간되며, 10초 경과 시점에 자동으로 감속이 해제된다.

## 9.7 작업 유형 분류
이 시스템은 **혼합형**이다 — 게이지 소모 억제 로직 자체는 **비시청각 영역**, 그 결과가 HUD 포커스 게이지에 드러나는 부분은 **시청각 표시 영역**(단, 이 표시는 기존 `CharacterHUDUIView`의 `FocusGauge.OnValueChanged` 구독 로직을 그대로 재사용하므로 신규 시청각 코드는 없음 — 이벤트가 안 터지는 것만으로 "가득 찬 상태 유지"가 자연히 충족된다).
- 서술 공식: `RuntimeDataTimeSlow`의 초당 게이지 감소(`DrainFocus`) 호출 경로에 On/Off 오버라이드 분기를 추가하여, 오버라이드 활성 시 게이지 실값 변경을 완전히 스킵하고 비활성 시 기존 감소 로직을 그대로 유지한다.

## 9.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: `Assets/02.System/02.CharacterSystem/00.Data/RuntimeDataTimeSlow.cs`/`PureDataTimeSlow.cs`, `01.Logic/TimeSlowLogicSystem.cs`, `03.UI/CharacterHUDUIView.cs` 기존 코드, 그리고 이미 구현 완료된 [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)의 `TutorialSequencerLogicSystem`/`PureDataTutorialSequence`)
- `PureDataTimeSlow.eventSlowTimeScale` (float, 신규 필드) — 감속 모드(3단계)에서 사용할 부분 감속 배율. 기존 `SlowTimeScale`(완전 정지용)과는 별개 값.
- `RuntimeDataTimeSlow.isGaugeOverride` (bool, private set, 신규 필드) — true면 `FocusGauge` 소모(`DrainFocus`)가 억제된다.
- `RuntimeDataTimeSlow.isEventTriggered` (bool, private set, 신규 필드) — true면 현재 활성 시간 정지가 "감속 모드"(이벤트 시퀀서 트리거)임을 의미. false면 기존 완전 정지 모드.
- `RuntimeDataTimeSlow.eventRampElapsedSeconds`/`eventRampDurationSeconds` (float, private set, 신규 필드) — 감속 모드 진입 후 경과 시간과 총 램프 시간(06에서 전달받은 `CoreHitTimeoutSeconds` 값을 그대로 저장).
- `RuntimeDataTimeSlow.SetGaugeOverride(bool value)` (신규 메서드) — 값이 바뀔 때만 `OnGaugeOverrideChanged(bool)`(신규 이벤트)를 발행(기존 `SetSlowActive`와 동일한 변경 감지 패턴).
- `RuntimeDataTimeSlow.BeginEventRamp(float durationSeconds)` / `EndEventRamp()` (신규 메서드) — 감속 모드 시작/종료 시 위 필드들을 세팅/리셋.
- `TimeSlowLogicSystem.ActivateEventSlow(float rampDurationSeconds)` (신규 메서드, 06 전용 호출 경로) — `runtimeData.SetGaugeOverride(true)` + `runtimeData.BeginEventRamp(rampDurationSeconds)` + 내부적으로 `isSlowActive`를 true로 전환(기존 `ActivateSlow()`의 게이지 체크는 우회 — 이벤트 발동은 게이지 상태와 무관해야 함).
- `TimeSlowLogicSystem.DeactivateEventSlow()` (신규 메서드) — `SetGaugeOverride(false)` + `EndEventRamp()` + `DeactivateSlow()`.
- **06과의 연동(신규, 06번 시스템에 소규모 추가 필요)**: `TimeSlowLogicSystem`이 06의 `TutorialSequencerLogicSystem`이 방송하는 `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail`을 구독해야 하는데, 이 세 이벤트는 현재 구체 클래스(`TutorialSequencerLogicSystem`)에만 있고 VContainer_가이드라인상 구체 클래스 직접 주입은 금지다. 06번 시스템에 **`IEventSequencer` 인터페이스(신규, 이 세 이벤트만 노출)**를 추가하고 `TutorialSequencerLogicSystem`이 이를 구현하도록, 그리고 `EventSequencerSystemLifetimeScope`가 `.As<IEventSequencer>()`로도 등록하도록 하는 작업이 필요하다(기존 로직 변경 없이 인터페이스 노출만 추가 — 8번 작업 때 `IInteractionService`에 `OnDamageProcessed`를 추가했던 것과 동일한 성격의 최소 보완). `PureDataTutorialSequence`(06의 SO)는 순수 데이터 애셋이므로 `TimeSlowLogicSystem`이 직접 참조(주입)해 `CoreHitTimeoutSeconds` 값을 읽어도 DIP 위반이 아니다.

**데이터 가공/흐름 서술**
- **게이지 억제(기존 로직 유지)**: `TimeSlowLogicSystem.ProcessTimeSlow()`가 `Tick()`마다 `runtimeData.IsGaugeOverride`를 확인 → true면 `DrainFocus` 호출 스킵, false면 기존 그대로 실행.
- **감속 트리거**: 06이 `OnBoss50Percent`를 방송하는 시점(또는 재도전 시 같은 신호가 재발행되는 시점, 9.3의 4번) → `TimeSlowLogicSystem.ActivateEventSlow(pureDataTutorialSequence.CoreHitTimeoutSeconds)` 호출.
- **램프 갱신**: `Tick()`에서 `runtimeData.IsEventTriggered`인 동안 `eventRampElapsedSeconds`를 누적 → `t = Mathf.Clamp01(elapsed / durationSeconds)` → `currentTimeScale = Mathf.Lerp(pureData.EventSlowTimeScale, 1.0f, t)` → `visualizer.SetTimeSlowEffect(true, currentTimeScale)`로 매 프레임 반영. `t >= 1`이면 `DeactivateEventSlow()`를 자동 호출(06의 타임아웃 판정과 동일 시점에 도달).
- **조기 종료**: 06의 `OnCoreHitSuccess`/`OnCoreHitFail` 구독 핸들러에서 즉시 `DeactivateEventSlow()` 호출 — 램프가 끝나기 전이라도 판정이 나면 바로 정상 속도로 복귀.
- **완전 정지 모드는 변경 없음**: `ActivateSlow()`/`DeactivateSlow()`(유저 입력용)는 기존 그대로, `isEventTriggered`는 항상 false로 유지되며 감속 로직과 무관.

**시청각 전달(UX) 서술**
- **[정정, 8번 기획서와 동일한 이유로 최초 판단 오류]** `CharacterHUDUIView`(기존 파일)는 **수정이 필요하다.** `OnGaugeOverrideChanged`를 구독해, true 수신 시 `focusBar.style.width`를 실제 값과 무관하게 100%로 강제 표시(오버라이드가 켜지는 시점의 `FocusGauge`가 부분값일 수 있기 때문 — 8번 기획서의 MP와 동일한 이유), false 수신 시 즉시 실제 값 기준으로 복귀.
- 감속 자체의 시각 효과(체감 속도 변화, 흑백 필터)는 기존 `ITimeSlowVisualizer.SetTimeSlowEffect(bool, float)`가 `timeScale` 인자를 받아 이미 처리 가능한 구조이므로, 시각화 계층 자체의 신규 인터페이스 추가는 필요 없다 — 매 프레임 다른 `timeScale` 값을 넘겨주기만 하면 된다.

## 9.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 신규 기능 폴더가 아니라 **기존 `02.CharacterSystem` 확장**이며, 06번 시스템에도 소규모 인터페이스 추가가 필요하다(3-2절의 신규 넘버링 규칙은 이 두 기존 폴더 확장에는 적용 대상이 아님).

- **[D] 00.Data** — `Assets/02.System/02.CharacterSystem/00.Data/PureDataTimeSlow.cs`(기존 파일 확장, `eventSlowTimeScale` 필드 추가), `RuntimeDataTimeSlow.cs`(기존 파일 확장, `isGaugeOverride`/`isEventTriggered`/`eventRampElapsedSeconds`/`eventRampDurationSeconds` 필드 + `SetGaugeOverride`/`BeginEventRamp`/`EndEventRamp` 메서드 + `OnGaugeOverrideChanged` 이벤트 추가).
- **[L] 01.Logic** — `Assets/02.System/02.CharacterSystem/01.Logic/TimeSlowLogicSystem.cs`(기존 파일 확장, `ActivateEventSlow`/`DeactivateEventSlow` 추가 + `Tick()` 내부 램프 계산 추가 + 06의 `IEventSequencer` 구독).
- **[L] 06번 시스템 소규모 추가** — `Assets/02.System/09.EventSequencerSystem/`에 `IEventSequencer.cs`(신규 인터페이스, `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail` 세 이벤트만 선언) 추가, `TutorialSequencerLogicSystem`이 이를 구현(기존 이벤트 선언에 인터페이스만 씌움, 로직 변경 없음), `EventSequencerSystemLifetimeScope`의 등록에 `.As<IEventSequencer>()` 한 줄 추가.
- **[V] 시청각 레이어** — `CharacterHUDUIView.cs`(기존 파일 확장, `OnGaugeOverrideChanged` 구독 추가 — 8번 기획서의 `CharacterHUDUIView` 수정과 동일한 패턴). `ITimeSlowVisualizer`/구현체는 변경 없음(9.8 참고).
- **기존에 이미 열려 있는 미해결 항목(그대로 보존)**:
  - 시간 정지 시스템이 `CharacterLifetimeScope`(플레이어) 하위 종속인 구조가 "전투 필드 전체 자동 발동" 요구사항과 맞지 않을 가능성 — 독립 시스템 분리 여부는 구현 단계 검토 사항으로 유지.
  - 3단계 자동 발동 구간에서 유저의 수동 시간정지 입력(`ToggleSlow()`, 키보드 폴백 포함)을 정확히 어느 범위까지 차단할지는 "확인 필요 항목"으로 유지 — 근거 부족으로 임의로 확정하지 않는다.

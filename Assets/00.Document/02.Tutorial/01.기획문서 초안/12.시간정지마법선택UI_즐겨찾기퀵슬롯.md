# 12. 시간정지 마법 선택 UI — 선택지 팝업 + 즐겨찾기 퀵슬롯(W/E/F)

> 분류: 기존 확장(`01.UnitSystem`, 다크소울3 레퍼런스 마법 락온·시전 흐름의 "마법 선택 방법" 교체) · 튜토리얼 0~10번 번호 체계와 무관한 별도 개편 작업, 11번 기획서(습득/장착 개편)의 후속
> 배경(세션 10 확정): 현재 시간정지(완전정지, 1단계 스타일) 상태에서 마법 락온 후 시전할 마법은 "마우스 휠로 미리 순환 선택해둔 유닛"을 수동으로 시간정지 해제하는 순간 그대로 쓰는 암묵적 방식이었다. 사용자가 레퍼런스로 지목한 **젤다의 눈, 아니 "33원정대"(Clair Obscur: Expedition 33) 스타일의 즉석 선택지 팝업**을 참고해, 락온 직후 명시적으로 어떤 마법을 쓸지 고르는 UI로 교체한다.
> **사용자 확정 사항(세션 10, 대화로 확정됨)**:
> - 이 팝업은 기존 마우스 휠 퀵슬롯(`UnitQuickSlotLogicSystem`)의 "시간정지 중 마법 선택" 역할을 **완전히 대체**한다. 휠 순환 자체(코드)는 그대로 두되, **평상시(시간정지가 아닐 때)** 용도로만 의미를 갖는다 — 이번 작업은 휠 로직을 변경하지 않는다.
> - 다중 락온(여러 타겟을 모았다가 한 번에 일괄 시전)은 **기존 방식 그대로 유지**한다. 팝업은 "몇 명을 락온했든 어떤 마법을 쓸지"를 고르는 것이지, 타겟 선택 방식을 바꾸는 게 아니다.
> - 팝업은 **타겟을 1개 이상 락온하는 즉시 자동으로 나타난다.** 팝업이 떠 있는 동안에도 좌클릭으로 타겟을 계속 추가로 락온할 수 있다(팝업이 조작을 막지 않음).
> - 선택지는 4개(Q/W/E/F, 레퍼런스 이미지와 동일한 키 배치): **Q = "전체 목록" 서브패널**(장착된 유닛 전체를 펼쳐서 그 중 하나를 고름), **W/E/F = 즐겨찾기 슬롯**(미리 등록해둔 유닛이 있으면 즉시 그 유닛으로 확정, 비어있으면 빈 슬롯으로 표시).
> - **선택을 확정하는 그 순간** 시간정지가 자동으로 해제되고, 그때까지 모아둔 모든 락온 타겟에게 선택한 마법이 일괄 시전된다(기존 `UnitCasterSystem.ExecuteBatchCast()` 흐름을 그대로 재사용 — 트리거만 "T키 재입력"에서 "팝업 선택 확정"으로 바뀐다).
> - 타겟을 하나도 락온하지 않은 채 수동으로 시간정지를 끄면(T 키) 팝업 자체가 뜬 적이 없으므로 기존처럼 그냥 조용히 종료된다(취소 경로, 변경 없음).
> - 즐겨찾기(W/E/F) 등록은 **인벤토리에서 장착된 유닛을 우클릭**해서 한다(이번 작업 범위에 포함).

---

## 1. 작업 개요 및 작업 유형 분류
**혼합형**이다.
- 비시청각 요구사항: 다중 락온 타겟 수가 0→1로 바뀌는 시점을 감지해 "선택 대기" 상태로 전환하고, 선택 확정 시 기존 퀵슬롯 선택 데이터를 갱신 + 시간정지를 해제해 기존 일괄 시전 파이프라인을 그대로 트리거하는 로직. 즐겨찾기 슬롯 3개(W/E/F)에 특정 유닛을 등록/해제하는 데이터 관리 로직.
- 시청각 요구사항: 유저가 타겟을 락온하면 Q/W/E/F 4개 선택지가 화면에 나타나고(레퍼런스 이미지 스타일 — 키 아이콘 + 라벨), Q를 누르면 장착된 유닛 전체 목록이 펼쳐지며, W/E/F를 누르면(즐겨찾기가 등록돼 있을 때) 즉시 해당 유닛으로 확정되고 팝업이 사라지며 시간정지가 풀리는 연출. 인벤토리에서 장착된 유닛을 우클릭하면 즐겨찾기 슬롯에 등록되고 아이콘에 배지로 표시됨.

## 2. 유형별 핵심 요구사항
- 서술 공식(비시청각): `RuntimeDataMultiLockOn.OnTargetAdded`/`OnTargetRemoved`/`OnTargetsCleared`를 구독해 타겟 카운트가 0→1이 되는 시점에 팝업을 열고, 선택 확정 시 `RuntimeDataUnitQuickSlot.SelectUnit(unit)`로 캐스팅 대상 유닛을 지정한 뒤 `RuntimeDataTimeSlow.SetSlowActive(false)`를 호출해 기존 시간정지 해제→`MagicLockOnComponent.OnDisable()`→`UnitCasterSystem.ExecuteBatchCast()` 체인을 그대로 발동시킨다.
- 사용자 조작 결과(시청각): 유저가 시간정지 중 타겟을 락온하면 즉시 Q/W/E/F 선택지가 나타나고, 하나를 선택하면 그 즉시 화면이 정상 속도로 돌아오며 선택한 마법이 모든 락온 타겟에게 시전된다. 인벤토리에서 장착 유닛을 우클릭하면 W→E→F→해제 순서로 즐겨찾기 슬롯에 등록되며, 등록된 슬롯은 아이콘에 작은 배지(예: "[W]")로 표시된다.

## 3. 데이터 정의 및 흐름

**데이터 구조 정의** (근거: `Assets/02.System/01.UnitSystem/00.Data/RuntimeDataMultiLockOn.cs`/`RuntimeDataUnitQuickSlot.cs`, `02.CharacterSystem/00.Data/RuntimeDataTimeSlow.cs`, `01.Logic/UnitCasterSystem.cs`, `03.UI/UnitInventoryUIComponent.cs` 기존 코드)
- `RuntimeDataMagicFavoriteSlots`(신규, `00.Data/`) — `PureDataUnit[] slots`(길이 3 고정, 인덱스 0=W/1=E/2=F). 메서드: `AssignSlot(int index, PureDataUnit unit)`, `PureDataUnit GetSlot(int index)`, `ClearSlot(int index)`, `int FindSlotOf(PureDataUnit unit)`(우클릭 순환 등록용 — 이미 등록된 슬롯이 있으면 그 다음 슬롯으로, 없으면 빈 슬롯에, 꽉 차있으면 가장 오래된 걸 교체하거나 제거하는 정책은 구현 시 결정). 이벤트: `event Action<int, PureDataUnit> OnFavoriteSlotChanged`.
- **기존 데이터 재사용(신규 필드 없음)**: `RuntimeDataMultiLockOn.TargetCount`/`OnTargetAdded`/`OnTargetRemoved`/`OnTargetsCleared`(팝업 열고 닫는 트리거 판단), `RuntimeDataUnitQuickSlot.SelectUnit(PureDataUnit, int)`(선택 확정 시 호출), `RuntimeDataTimeSlow.SetSlowActive(bool)`(선택 확정 시 시간정지 해제 — `UnitCasterSystem`이 이미 이 RuntimeData를 직접 주입받는 선례와 동일한 방식으로 접근), `IUnitCatalogService.GetEquippedUnits()`(Q 전체 목록 구성).
- **팝업 열림/닫힘 상태**(신규, `MagicSelectionPopupLogicSystem` 내부 상태) — `bool IsPopupOpen`, `bool IsFullListOpen`(Q로 펼친 서브패널 열림 여부). 이벤트: `event Action OnPopupOpened`, `event Action OnPopupClosed`, `event Action<bool> OnFullListToggled`.

**데이터 가공/흐름 서술**
- 타겟 락온: 유저가 좌클릭으로 타겟 추가 → `RuntimeDataMultiLockOn.AddTarget` → `OnTargetAdded` 발행 → `MagicSelectionPopupLogicSystem`이 `TargetCount == 1`(최초 1개)인 시점만 감지해 `IsPopupOpen = true` + `OnPopupOpened` 발행(이미 열려 있으면 중복 오픈 안 함 — 추가 락온은 팝업에 영향 없음).
- 모든 타겟 해제: 우클릭 등으로 `RemoveTarget`을 반복해 `TargetCount`가 0이 되거나 `OnTargetsCleared`가 발행되면 → 팝업이 열려 있었다면 `IsPopupOpen = false` + `OnPopupClosed` 발행(선택할 대상 자체가 없어졌으므로).
- Q 입력: `IsFullListOpen`을 토글 → true가 되면 `IUnitCatalogService.GetEquippedUnits()` 목록을 UI가 그려서 보여줌.
- 전체 목록에서 유닛 클릭, 또는 W/E/F 입력(해당 슬롯에 `RuntimeDataMagicFavoriteSlots.GetSlot(index)`가 null이 아닐 때만 유효) → **선택 확정 공통 처리**: `RuntimeDataUnitQuickSlot.SelectUnit(chosenUnit)` 호출 → `RuntimeDataTimeSlow.SetSlowActive(false)` 호출(이 한 줄이 기존 `TimeSlowVisualizer.OnSlowStateChanged` → `PlayerLockOnController.SetSlowMode(false)` → `MagicLockOnComponent.OnDisable()` → `UnitCasterSystem.ExecuteBatchCast()`로 이어지는 **기존에 이미 구현된 체인**을 그대로 재사용한다) → `IsPopupOpen = false`/`IsFullListOpen = false` + `OnPopupClosed` 발행.
- 즐겨찾기 등록: 인벤토리에서 **장착된** 유닛 아이콘을 우클릭 → `RuntimeDataMagicFavoriteSlots.AssignSlot(...)`(빈 슬롯 우선, 이미 등록돼 있으면 다음 슬롯으로 순환, 모두 차있으면 정책은 구현 시 결정 — 예: W로 되돌아가 덮어쓰기) → `OnFavoriteSlotChanged` 발행 → 인벤토리 UI가 해당 아이콘에 배지 갱신.

**시청각 전달(UX) 서술**
- `OnPopupOpened` 수신 시 신규 `MagicSelectionPopupContainer`(UI Toolkit)가 화면에 표시된다(레퍼런스 이미지처럼 키 아이콘 박스 + 라벨 4개가 대각선 또는 세로로 배치). W/E/F 슬롯은 등록된 유닛이 있으면 아이콘+이름을, 없으면 빈 슬롯 표시(흐리게/비활성)로 구분한다.
- `OnFullListToggled(true)` 수신 시 Q 자리에 장착된 유닛 전체를 아이콘 그리드로 펼친 서브패널이 추가로 표시된다(기존 11번 작업의 인벤토리 아이콘+라벨 스타일 재사용 가능).
- `OnPopupClosed` 수신 시 팝업 전체가 사라진다(이미 시간정지 해제/일괄 시전은 데이터 흐름에서 처리됨 — UI는 그 결과를 숨기기만 하면 됨).
- 인벤토리 아이콘에 즐겨찾기 배지(`OnFavoriteSlotChanged` 구독) — 해당 유닛이 W/E/F 중 하나에 등록돼 있으면 작은 "[W]"/"[E]"/"[F]" 라벨을 아이콘 모서리에 표시, 해제되면 사라짐.

## 4. DLV 적용 방안 (실제 폴더 경로)

이 작업은 신규 기능 폴더가 아니라 **기존 `01.UnitSystem` 확장**이므로 3-2절의 신규 넘버링 규칙은 적용 대상이 아니다.

- **[D] 00.Data** — `Assets/02.System/01.UnitSystem/00.Data/RuntimeDataMagicFavoriteSlots.cs`(신규, 순수 C#, MonoBehaviour/Transform 비참조).
- **[L] 01.Logic** — `Assets/02.System/01.UnitSystem/01.Logic/MagicSelectionPopupLogicSystem.cs`(신규, 순수 C#, `IInitializable`/`IDisposable` — 이벤트 구독·해제만 담당, Tick 불필요). `RuntimeDataMultiLockOn`, `RuntimeDataUnitQuickSlot`, `CharacterSystem.RuntimeDataTimeSlow`, `IUnitCatalogService`, `RuntimeDataMagicFavoriteSlots`를 생성자 주입받는다(전부 기존에 같은 스코프 트리에서 이미 상호 참조되고 있는 데이터 타입들 — `UnitCasterSystem`이 `RuntimeDataTimeSlow`를 이미 직접 주입받는 선례와 동일).
- **[V] 03.UI** — `Assets/02.System/01.UnitSystem/03.UI/MagicSelectionPopupUIComponent.cs`(신규, MonoBehaviour+UIDocument, `MagicSelectionPopupLogicSystem`의 이벤트를 구독해 패널 표시/숨김 + Q/W/E/F 키 폴링(`Keyboard.current`, `IInputContextManager.CurrentContext == Tactical`이고 `IsPopupOpen`일 때만 반응) + 선택 확정 메서드 호출). `UnitUI.uxml`(기존 파일)에 `MagicSelectionPopupContainer`(신규 섹션) 추가.
- **[V] 03.UI 기존 파일 수정** — `UnitInventoryUIComponent.cs`: `BuildUnitElement(...)`에 우클릭(`ContextClickEvent` 또는 `PointerDownEvent`+버튼 판별) 핸들러 추가해 `RuntimeDataMagicFavoriteSlots.AssignSlot(...)` 호출 + 배지 표시 추가(장착되지 않은 유닛은 우클릭 무시).
- **`UnitSystemLifetimeScope.cs`(기존 파일)** — `RuntimeDataMagicFavoriteSlots`를 Singleton 등록, `MagicSelectionPopupLogicSystem`을 `RegisterEntryPoint`로 등록, 신규 UI 컴포넌트 씬 배선 추가.
- **기존 파일 중 변경 없음(확인 완료)**: `UnitQuickSlotLogicSystem.cs`(휠 로직 무변경), `UnitCasterSystem.cs`/`ExecuteBatchCast()`(무변경 — 이미 `quickSlotUI.CurrentSelectedUnit`을 읽는 기존 코드를 그대로 재사용), `MagicLockOnComponent.cs`/`PlayerLockOnController.cs`/`TimeSlowLogicSystem.cs`(무변경 — 기존 시간정지 해제 체인을 그대로 트리거만 함).

## 5. 예상 검수 방법 (체크리스트는 §3 데이터 흐름 근거)

- [ ] 시간정지 중 타겟을 1개 락온하면 즉시 Q/W/E/F 팝업이 나타난다.
- [ ] 팝업이 떠 있는 동안 추가로 타겟을 더 락온해도 팝업이 유지되고(재오픈/깜빡임 없이) 타겟 카운트만 늘어난다.
- [ ] 락온한 타겟을 전부 해제(우클릭 등)하면 팝업이 자동으로 닫힌다.
- [ ] W/E/F 중 즐겨찾기가 등록된 슬롯을 누르면 그 즉시 시간정지가 해제되고, 모든 락온 타겟에 해당 마법이 일괄 시전된다(기존 `ExecuteBatchCast` 결과와 동일).
- [ ] 즐겨찾기가 비어있는 W/E/F를 눌러도 아무 일도 일어나지 않는다(오동작 없음).
- [ ] Q를 누르면 장착된 유닛 전체 목록이 펼쳐지고, 그 중 하나를 클릭하면 W/E/F와 동일하게 시간정지 해제+일괄 시전이 일어난다.
- [ ] 타겟을 하나도 락온하지 않고 수동으로 시간정지를 끄면(T) 팝업이 뜬 적 없이 조용히 종료된다(회귀 없음).
- [ ] 인벤토리에서 장착된 유닛을 우클릭하면 W→E→F 순서로 즐겨찾기에 등록되고, 아이콘에 배지가 표시된다. 미장착 유닛 우클릭은 무시된다.
- [ ] 마우스 휠로 하는 기존 퀵슬롯 순환(평상시 용도)과 Option 메뉴/Inventory 메뉴/시간정지(T)에 회귀가 없다.
- [ ] 신규 코드가 DLV/VContainer 규칙을 위반하지 않는다(`RuntimeDataMagicFavoriteSlots`/`MagicSelectionPopupLogicSystem`이 MonoBehaviour/Transform을 직접 참조하지 않고, UI 컴포넌트는 인터페이스/RuntimeData로만 로직에 접근).

## 6. 이번 작업 범위 밖 (확정하지 않음, 임의로 채우지 않음)
- 즐겨찾기 슬롯이 이미 3개 다 찬 상태에서 **새로운(미등록) 유닛**을 우클릭으로 등록할 때의 정확한 교체 정책(어떤 슬롯을 덮어쓸지) — 구현 시 합리적 기본값(예: W부터 덮어쓰기)으로 정하고 세부는 나중에 조정 가능. (단, **이미 등록된 유닛을 재우클릭해 슬롯을 순환시키는 경우**는 §6-1에서 별도로 정정·확정함 — 범위 밖이 아니다.)
- Q 전체 목록이 장착 유닛 수가 매우 많을 때의 스크롤/페이지네이션 UX 디테일 — 기본적인 wrap 그리드로 충분, 정교한 스크롤은 범위 밖.
- 팝업의 정확한 연출(애니메이션, 효과음 등) — 레퍼런스 이미지의 시각적 톤(키 박스+라벨, 대각선 배치)만 참고하고 세부 디테일은 나중에 조정.

## 6-1. 정정(세션 10-2) — 즐겨찾기 재순환 시 다른 슬롯 조용한 덮어쓰기 버그 수정 (범위 안으로 편입)

**문제(QA 발견)**: `UnitInventoryUIComponent.OnUnitContextClicked`가 이미 등록된 유닛을 재우클릭해 다음 슬롯(`existingIndex+1`)으로 순환시킬 때, 그 다음 슬롯에 **이미 다른 유닛이 등록돼 있으면** 아무 경고 없이 그 등록을 지워버리고 덮어쓴다(예: W=L, E=kg 상태에서 L을 재우클릭하면 L이 E로 이동하며 kg 등록이 사용자 모르게 사라짐).

**확정 사항**: 재순환 대상 슬롯에 **다른 유닛이 이미 있으면 그 유닛을 지우지 않고, 지금 순환 중인 유닛이 원래 있던 슬롯으로 서로 자리를 맞바꾼다(스왑)**. 즉:
- 순환 대상 슬롯이 비어있던 경우: 기존 동작과 동일(원래 슬롯 비우고 다음 슬롯에 등록).
- 순환 대상 슬롯에 다른 유닛 X가 있던 경우: X를 지금 순환 중인 유닛이 원래 있던 슬롯으로 옮기고, 지금 순환 중인 유닛을 다음 슬롯에 등록한다. 결과적으로 둘 다 유지되고 자리만 바뀐다(데이터 유실 없음).

**수정 대상**: `Assets/02.System/01.UnitSystem/03.UI/UnitInventoryUIComponent.cs`의 `OnUnitContextClicked` 메서드 하나뿐. `RuntimeDataMagicFavoriteSlots`(`AssignSlot`/`GetSlot`) 자체는 변경 불필요(이미 임의의 슬롯에 임의의 값을 넣는 범용 메서드이므로, 판단(스왑 로직)만 호출부에서 바꾸면 된다 — 기존 설계 그대로).

# 20. 판정 구조 개편 — 속성·크기·데미지 게이트 개별 확인 (기획서 초안)

> 작성일: 2026-10-10 · 상태: Goal 작성 완료(§6 가정은 추천안, 변경 가능)
> 형식: `코드_작업_기획서_가이드라인_v1.0.md`
> 사용자 확정(세션 12): ① 3단계(보스) 성공 판정은 **어떤 마법이 적용됐는지(속성·크기)와 최종 데미지를 모두 확인**한다(튜토리얼에는 불필요해 보여도 추후를 위해 모두 확인). ② **돌문도 같은 구조로 통일**한다. ③ 크리티컬은 없다(Goal 30). ④ 플래그 기반 파이프라인에서 게이트는 `HitStepFlags` 비트와 스텝으로 추가한다(예약돼 있던 `SizeGate`).

---

## 1. 작업 개요 및 유형
**비시청각**(Pure Data / Logic / Core System). 시청각은 기존 피드백(스파크 / 금 갔다 복구 / 파괴)을 유지한다.

현재 구조(조사)
- `AttributeGateStep`: 투사체(`context.Source`)의 Temperature가 음수(얼음)가 아니면 `Aborted=true`(이후 스텝·데미지 적용 모두 중단). 통과 시 `FinalDamage = RawDamage × 질량 비율`을 계산.
- 크기 조건은 **데미지 숫자로만 간접 확인**: 돌문(`DestructibleDoorLogicSystem.ApplyDamage(amount>=Hp)`), 3단계(`TutorialSequencerLogicSystem.HandleDamageProcessed`: `!Aborted && FinalDamage >= CoreHitRequiredDamage`).
- `DamageContext`에는 `HitRegistered`, `Aborted`, `FinalDamage`만 있고 게이트별 결과가 없다. `HitStepFlags`에는 `SizeGate` 자리가 주석으로만 예약돼 있다.
- 돌문은 `IDamageable.ApplyDamage(int)`만 받아 컨텍스트를 모른다.

## 2. 핵심 요구사항
`HitStepFlags.SizeGate` 비트와 `SizeGateStep`을 추가하고 `DamageContext`에 속성/크기 게이트 통과 결과를 따로 기록하게 하여, 돌문과 3단계 보스가 같은 구조로 "속성 + 크기 + 최종 데미지"를 모두 개별 확인해 판정하게 한다(조건이 늘어나도 스텝/플래그 추가로 확장).

## 3. 데이터 정의 및 흐름

### 3-1. 데이터
- `HitStepFlags.SizeGate = 1 << 3`(기존 예약 비트 사용).
- `DamageContext`(확장): `bool AttributeGatePassed`, `bool SizeGatePassed`(기본 false, 해당 게이트가 실행된 경우에만 true가 될 수 있음).
- `IGateRequirementProvider`(신규, `Assets/PipeLine/Combat/`): 피격 대상이 요구하는 게이트 조건 값을 제공한다. **모든 요구값은 PureData(ScriptableObject)에서 읽고 코드에 숫자를 박지 않는다.**
  - `float RequiredMaxTemperature { get; }` — 속성 게이트 통과 조건: 투사체 온도가 이 값 **미만**이어야 한다(기존 코드에 박혀 있던 "0 미만"을 PureData 값으로 이동, 기본 0).
  - `float RequiredMassRatio { get; }` — 크기 게이트 통과 조건: 질량 비율이 이 값 **이상**.
  - 구현체가 없는 대상은 해당 게이트가 요구되지 않는 대상으로 보고 `AttributeGatePassed`/`SizeGatePassed`를 `true`로 기록한다(게이트 플래그가 켜진 대상은 돌문/보스뿐이며 둘 다 구현체를 가진다).
- `IGateAwareDamageable : IDamageable`(신규, 선택 구현): `void ApplyDamage(int amount, in DamageContext context)` — 컨텍스트(게이트 결과)를 받는 대상용. `ApplyDamageStep`이 이 인터페이스를 구현한 대상에는 컨텍스트를 함께 전달하고, 아니면 기존 `ApplyDamage(int)`를 호출한다(하위 호환).
- PureData(ScriptableObject, 조정 가능 — 게이트 조건 값은 전부 여기에 둔다):
  - `PureDataDestructibleDoor`: `requiredMaxTemperature`(기본 0), `requiredMassRatio`(기본 1.5, 가정), 기존 `hp`(=데미지 기준 100).
  - `PureDataTutorialSequence`: `requiredMaxTemperature`(기본 0), `requiredMassRatio`(기본 1.5, 가정), 기존 `coreHitRequiredDamage`(100).
  - (조건 비교의 크기 값은 `MassUnitApplicatorSO.CalculateMassRatio` 재사용 — 스케일 계산과 같은 값, 04번 확정.)

### 3-2. 흐름
1. 피격 플래그: 돌문 `AttributeGate | SizeGate`(PureData `hitFlags`), 보스 회복 페이즈 `AddHit(AttributeGate | SizeGate)` + `SuppressHit(Evasion | Defense)`(`BossPhaseLogicSystem`, 해제 시 원복).
2. `AttributeGateStep`(기존): 투사체 온도가 피격 대상의 `RequiredMaxTemperature` **미만**이 아니면(온도 단위가 없는 경우 포함) `AttributeGatePassed=false` + `Aborted=true`(기존 동작 유지: 스파크 피드백), 통과 시 `AttributeGatePassed=true`, `FinalDamage` 계산. 코드의 "0 미만" 하드코딩은 제거하고 요구값을 `IGateRequirementProvider`에서 읽는다.
3. `SizeGateStep`(신규, `AttributeGateStep` 다음): `Source`의 Mass 비율을 계산해 피격 대상의 `RequiredMassRatio`와 비교. 충족 → `SizeGatePassed=true`. 미충족 → `SizeGatePassed=false`이며 **`Aborted`는 세우지 않는다**(속성은 통과했으므로 "금 갔다 복구" 피드백이 나가야 함). 이미 `Aborted`면 실행되지 않는다.
4. 판정(소비자가 자기 기준으로 최종 결정, 세 조건을 모두 확인):
   - 돌문(`IGateAwareDamageable`): `AttributeGatePassed && SizeGatePassed && amount >= hp` → 파괴, 아니면(속성은 통과했으나 크기/데미지 부족) `PlayCrackAndRepair`. 속성 실패(`Aborted`)는 기존대로 `ApplyDamage`가 호출되지 않고 스파크.
   - 3단계 보스(`TutorialSequencerLogicSystem.HandleDamageProcessed`): `AttributeGatePassed && SizeGatePassed && FinalDamage >= CoreHitRequiredDamage` → `OnCoreHitSuccess`, 아니면 `OnCoreHitFail`. 판정 대상은 이벤트 투사체의 명중에 한정(기존 그대로).
5. 판정 사유 로그: 어느 게이트에서 실패했는지(속성 / 크기 / 데미지)를 한 줄 로그로 남긴다(디버깅용, 연출 변경 없음).

### 3-3. 시청각
- 변화 없음: 속성 실패 = 스파크, 속성 통과 후 크기/데미지 부족 = 금이 갔다가 복구(속성만으로는 부족하다는 피드백), 모두 충족 = 파괴 / 보스 결정타 성공.

## 5. 체크리스트
1. [ ] 얼음이 아닌 투사체: 돌문은 스파크만(데미지 미적용), 보스 결정타 실패 — 속성 게이트 실패가 컨텍스트에 기록(`AttributeGatePassed=false`).
2. [ ] 얼음만(질량 ×1): `AttributeGatePassed=true`, `SizeGatePassed=false` → 돌문은 금 갔다 복구(파괴 안 됨), 보스 결정타 실패. 로그에 "크기 게이트 실패".
3. [ ] 크기만(얼음 아님): 속성 게이트에서 중단 — 돌문 스파크, 보스 실패.
4. [ ] 얼음+크기(×2, 기본 요구 1.5·데미지 기준 100): `AttributeGatePassed && SizeGatePassed && FinalDamage(120) ≥ 100` → 돌문 파괴, 보스 `OnCoreHitSuccess`(10회 반복 일관).
5. [ ] 요구 질량 비율을 PureData에서 올리면(예: 3.0) ×2 얼음+크기는 크기 게이트 실패로 돌문/보스 모두 실패한다(코드 수정 없이 인스펙터만으로 조건이 바뀜), 요구 비율을 낮추거나 데미지 기준을 올려도 각각 해당 게이트 사유로 실패한다. 요구 최대 온도를 올리거나 내려도(예: 기존 Frost −15 기준으로 −20) 속성 게이트 결과가 그에 맞게 바뀐다.
5-1. [ ] 게이트 판정 코드(`AttributeGateStep`, `SizeGateStep`, 돌문/보스 판정)에 요구값 숫자(0 온도 기준, 1.5, 100 등)가 박혀 있지 않다(grep) — 모두 PureData에서 읽는다.
6. [ ] `IGateRequirementProvider`가 없는 피격 대상은 크기 게이트가 통과로 기록되어 기존 동작(캐릭터 일반 피격 등)이 변하지 않는다. 일반 캐릭터 피격(`Evasion|Defense`)과 `IDamageable` 기존 구현체(`CharacterStatComponent`)는 변경 없이 동작한다.
7. [ ] 13~19 회귀(3단계 전환점 발동, 재도전, 이벤트 중 차단, 풀링, 보스 회복 페이즈 플래그 전환/원복), 콘솔 에러 0건, 디스크 임시 잔존 없음.

## 6. 확정 및 가정
**확정(사용자, 2026-10-10)**: 현재 기획대로 진행한다 — **결과 값(온도, 질량 비율, 최종 데미지)으로 판정**하며(적용된 마법 목록을 기록·요구하는 방식은 채택하지 않음), **모든 요구값은 ScriptableObject(PureData)로 뺀다**(온도 기준 포함).
**가정(추천안, 변경 가능)**
1. 크기 조건 = 질량 비율 ≥ 요구값이며 데미지 조건과 **별개로** 확인한다.
2. 요구 질량 비율 기본값 1.5는 임의 초안이다(현재 마법 ×2 기준 통과, ×1 실패). 요구 최대 온도 기본값 0은 기존 코드의 "0 미만"과 같다.
3. 돌문과 보스의 요구값은 각자의 PureData에 둔다(공용 한 곳으로 합치지 않음).

# 5. 광역 상태이상(빙결 폭발) 시스템

> 분류: 신규 · 관련 단계: 4단계
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)
> 세션 3 논의로 구체화: "보스 핵 명중"이라는 전용 히트박스/판정을 없애고, [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)가 (이 보스 + 회복 페이즈 상태 + 피격 파이프라인의 속성 게이트 결과)를 조합해 결정타 여부를 판단하는 구조로 변경.

## 5.1 시스템 개요
4단계 피니시 연출 — 거대 얼음 투사체가 불타는 보스를 꿰뚫으며 발생하는 **대규모 빙결 폭발과 주변 지형 동결**을 담당한다. "핵"은 이제 순수 연출(VFX가 시작되는 지점)일 뿐, 별도의 전용 히트박스나 물리 판정이 필요하지 않다 — 보스 몸통 어디에 맞아도 되고, 실제 성공/실패 판정은 이벤트 시퀀서가 상태 조합으로 결정한다.

## 5.2 핵심 동작
- **트리거**: 보스에 대한 피격 파이프라인이 완료되며 `HitContext`(피격 판정 O/X, 온도 속성 게이트 통과 여부)를 발행한다.
- **조건(이벤트 시퀀서가 판단)**: 아래 세 조건이 동시에 만족될 때만 "결정타"로 판정한다.
  1. 대상이 이 튜토리얼의 보스 인스턴스인가
  2. 보스가 현재 [03.보스AI페이즈시퀀스시스템.md](./03.보스AI페이즈시퀀스시스템.md)의 회복(무적) 페이즈 상태인가
  3. 해당 피격의 `HitContext`에서 온도(얼음) 속성 게이트가 통과됐는가 — [08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md](./08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md)에서 설명하듯, 무적 상태라 실제 데미지는 적용되지 않았어도(데미지 판정 X) "피격 판정 O" + "속성 게이트 통과"는 `HitContext`에 그대로 남아있으므로 이 판단에 사용할 수 있다.
- **결과**: 세 조건이 모두 만족되면 이벤트 시퀀서가 이 시스템에 발동 신호를 보내고, 명중 지점을 중심으로 반경 내 대상(보스, 인근 지형 오브젝트)에 빙결 상태 이펙트를 순차 적용한 뒤 보스 AI 시스템에 "처치" 신호를 전달한다.
- **설계 검토 사항**: [04.파괴가능환경오브젝트시스템.md](./04.파괴가능환경오브젝트시스템.md)와 동일하게, 광역으로 여러 대상(보스+지형)에 동시에 효과를 적용해야 하므로 공격/피격 파이프라인 분리 구조에서 "하나의 공격 파이프라인 결과를 다수의 피격 파이프라인에 브로드캐스트"하는 형태로 자연스럽게 확장 가능 — 이 시스템 구현 시점에 함께 검토.

## 5.3 사용자 조작 흐름
1. 유저가 4단계에서 락온 → 얼음 속성 인챈트 → 크기 확대까지 마친 투사체를 보스 방향으로 유도(시간 정지 해제 시 자연 비행).
2. 투사체가 보스 몸통 어디에든 명중하는 순간, 유저의 추가 조작 없이 이벤트 시퀀서가 조건을 판단한다.
3. 조건이 모두 만족되면 광역 빙결 연출이 자동 재생되고, 연출 종료 후 자동으로 승리 화면([06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md) 소관)으로 전환된다.

## 5.4 시각/청각 효과
- 명중 순간: 화면 전체 임팩트 프레임(짧은 화이트아웃/슬로우) + 얼음 폭발 파티클(방사형) + 저음 폭발음.
- 확산: 보스 표면과 주변 사화산 지형에 얼음 텍스처/셰이더가 순차적으로 덮이는 프리징 웨이브 연출.
- 종료: 정적인 얼음 조각상이 된 보스 위로 카메라가 서서히 줌아웃.

## 5.5 예외/실패 케이스
- 보스가 회복(무적) 페이즈가 아닐 때(예: 평상시 BasicAttack 상태) 얼음 속성 투사체가 명중해도, 조건 2(페이즈 상태)가 불만족이라 광역 빙결은 발동하지 않고 일반 피격 이펙트만 재생된다.
- 얼음 속성 게이트를 통과하지 못한 투사체(온도 단위가 중립이거나 부족)가 회복 페이즈 중 보스에 명중하면, `HitContext`에 "피격 판정 O / 속성 게이트 X"가 기록되어 이벤트 시퀀서가 이를 **실패**로 판정 — [03.보스AI페이즈시퀀스시스템.md](./03.보스AI페이즈시퀀스시스템.md)의 체력 60% 회복 분기로 이어진다.
- 투사체가 보스에 아예 명중하지 않고(완전히 빗나감) 회복 페이즈 지속시간이 끝나면, `HitContext` 자체가 발행되지 않으므로 이벤트 시퀀서는 타임아웃으로 동일하게 실패 처리한다.

## 5.6 체크리스트
- [ ] 보스가 회복 페이즈 중일 때 얼음 속성이 부여되고 확대된 투사체가 보스에 명중하면, 명중 지점에서 대규모 빙결 폭발 이펙트가 퍼지며 보스와 주변 사화산 지형이 일제히 얼어붙는다.
- [ ] 빙결 폭발이 발생하면, 보스는 즉시 얼음 조각상 형태의 사망 모션으로 전환되고 화면이 승리 연출로 넘어간다.
- [ ] (예외) 보스가 회복 페이즈가 아닐 때 얼음 속성 투사체가 명중하면, 광역 빙결 폭발이 발생하지 않고 일반 피격 이펙트만 재생된다.
- [ ] (예외) 회복 페이즈 중 얼음 속성이 아닌 투사체가 명중하거나 투사체가 완전히 빗나가면, 광역 빙결 폭발 없이 보스 체력이 60%로 회복되는 재도전 연출이 시작된다.
- [ ] (데이터 흐름 근거, 5.8) 06번 시퀀서의 `OnCoreHitSuccess`가 방송되면 → `AreaFreezeVisualizer`가 보스 위치를 중심으로 `Physics.OverlapSphere(pureData.FreezeRadius)`로 `IFreezable` 대상을 수집해 → `freezeSequenceDelay` 간격으로 각 대상의 `Freeze()`를 순차 호출하며 화이트아웃/파티클/저음 폭발음이 재생된다.

## 5.7 작업 유형 분류
이 시스템은 **혼합형**이다 — "결정타인지 판정"은 이미 06번 시퀀서가 전담하므로(5.2 원문 그대로) 이 시스템 자체의 책임은 판정 결과 수신 이후의 **시청각 표시 영역**(광역 이펙트/텍스처 확산/카메라 줌아웃)이 대부분이고, "반경 내 대상 수집"만 **비시청각 영역**이다.
- 비시청각 요구사항: 06번의 `OnCoreHitSuccess` 신호를 받아, 보스 위치 기준 반경 내 `IFreezable` 대상을 물리 오버랩 조회로 수집하는 로직을 구현한다.
- 시청각 요구사항: 사용자가 4단계에서 투사체를 명중시키는 조작 결과로, 명중 즉시 화이트아웃+얼음 폭발 파티클+저음 폭발음이 재생되고, 이어서 보스와 주변 지형에 순차적으로 얼음 텍스처가 확산되며, 마지막에 카메라가 줌아웃된다.

## 5.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: 이번 보완에서 확정한 [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md) 6.8절의 `OnCoreHitSuccess`, [03.보스AI페이즈시퀀스시스템.md](./03.보스AI페이즈시퀀스시스템.md) 3.8절의 `bossActor`/`INpcCombatActor`. `DamageContext`(`Assets/PipeLine/Contexts/DamageContext.cs`, 기존 코드)에 위치 필드가 없음을 확인 — 아래에서 대체 방식을 명시)
- `PureDataAreaFreeze` (SO, 신규) — `freezeRadius(float)`(반경 내 대상 수집 범위), `freezeSequenceDelay(float)`(대상 간 순차 확산 딜레이, 5.4의 "순차적으로 덮이는" 요구사항 근거).
- `IFreezable` (interface, 신규) — `void Freeze()` 한 개 메서드. 보스(신규 구현 필요 — 03번의 `IBossPhaseVisualizer` 또는 별도 컴포넌트가 구현) 및 지형 오브젝트(신규 `FreezableTerrainComponent`, 씬에 배치된 사화산 지형 메시에 부착)가 각각 구현한다.
- **위치 획득 방식(명시적 확인 필요 없이 확정 가능)**: `DamageContext`에는 명중 좌표 필드가 없으나, 5.1이 "핵은 순수 연출일 뿐 보스 몸통 어디에 맞아도 된다"고 이미 명시했으므로, 정확한 명중 좌표 대신 **`context.Victim.transform.position`(보스의 현재 위치)**을 폭발 중심으로 사용한다 — `DamageContext` 구조체 자체를 확장할 필요가 없다(이미 구현된 04번/파이프라인 코드를 건드리지 않아도 됨).

**데이터 가공/흐름 서술**
- 06번의 `OnCoreHitSuccess`(6.8절 — 세 조건 판정은 이미 06번이 전담 완료한 상태로 신호가 온다) 구독 → `AreaFreezeVisualizer.TriggerAreaFreeze(bossGameObject)` 호출 → `Physics.OverlapSphere(bossGameObject.transform.position, pureData.FreezeRadius)`로 반경 내 콜라이더를 조회 → 각 결과에서 `IFreezable` 컴포넌트를 `TryGetComponent`로 추출해 목록화.
- 수집된 `IFreezable` 목록을 `pureData.FreezeSequenceDelay` 간격으로 하나씩 `Freeze()` 호출(코루틴/시퀀스 처리) — 보스 자신도 이 목록에 포함되어 동일한 방식으로 `Freeze()`가 호출되며, 보스 쪽 `Freeze()` 구현이 사망 모션 전환을 트리거한다.
- 이 시스템은 03번 보스 AI에 별도로 "처치 신호를 전달"하지 않는다(5.2 원문의 표현과 달리) — 03번은 이미 06번의 `OnCoreHitSuccess`를 **독립적으로** 직접 구독해(3.8절) 스스로 `Dead`로 전환하므로, 05번과 03번은 06번의 같은 신호를 각자 구독하는 형제 관계다. 05번이 03번에 순서를 맞춰 신호를 중계할 필요는 없다.

**시청각 전달(UX) 서술**
- 5.4절 그대로: 명중 순간 화이트아웃+방사형 얼음 파티클+저음 폭발음, 확산 중 프리징 웨이브 셰이더, 종료 시 카메라 줌아웃 — `AreaFreezeVisualizer`가 `TriggerAreaFreeze` 호출 시점에 임팩트 연출을, `Freeze()` 순차 호출마다 확산 연출을 재생하는 구조로 구현한다.

## 5.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 신규 기능이다.

```text
Assets/02.System/12.AreaFreezeSystem/
├── AreaFreezeSystemLifetimeScope.cs
├── 00.Data/
│   └── PureDataAreaFreeze.cs
├── 01.Logic/
│   └── AreaFreezeTriggerLogicSystem.cs
└── 02.Visualizer/
    ├── IFreezable.cs
    ├── IAreaFreezeVisualizer.cs
    ├── AreaFreezeVisualizer.cs
    └── FreezableTerrainComponent.cs
```

- **[D] 00.Data** — `PureDataAreaFreeze.cs`(SO) 신규 작성.
- **[L] 01.Logic** — `AreaFreezeTriggerLogicSystem.cs`(신규, 순수 C#) — 06번의 `OnCoreHitSuccess`를 구독해 `IAreaFreezeVisualizer.TriggerAreaFreeze(boss)`를 호출하는 얇은 연결 로직만 담당(코드_가이드라인의 "Logic은 transform 직접 참조 금지" 원칙에 따라, 실제 `Physics.OverlapSphere`+`transform.position` 접근은 Logic이 아닌 아래 Visualizer 쪽에서 수행하도록 계층을 분리했다).
- **[V] 02.Visualizer** — `IFreezable.cs`(인터페이스), `IAreaFreezeVisualizer.cs`(인터페이스), `AreaFreezeVisualizer.cs`(구현체, 물리 오버랩 조회+순차 연출 재생), `FreezableTerrainComponent.cs`(지형 오브젝트용 `IFreezable` 구현체) 신규 작성.
- **번호 관련 주의**: 위 "12"는 이 문서 작성 시점 기준 예상 번호(06="09", 02="10", 03="11"을 이미 배정)이며, 실제 구현 착수 시점에 `Assets/02.System/` 디스크 상태를 다시 확인해 최종 번호를 확정해야 한다(3-2절 규칙). 튜토리얼 기획 문서 번호 체계와는 무관한 별개 번호다.
- **기존에 이미 열려 있는 미해결 항목(이 보완 작업 범위 밖, 그대로 보존)**: 5.2의 "파이프라인 분리 구조에서 1:N 브로드캐스트로 확장 가능 — 구현 시점에 함께 검토" 메모는 원문 그대로 유지 — 위 설계는 파이프라인을 확장하지 않고 `Physics.OverlapSphere` 기반의 별도 시각 계층 로직으로 구현하는 대안을 택했으며, 파이프라인 자체를 확장하는 방향으로 갈지는 이번 보완에서 확정하지 않는다.

# 3. 보스 AI · 페이즈 시퀀스 시스템

> 분류: 신규(두뇌 · FSM) · 관련 단계: 2단계, 3단계, 4단계
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)
> 세션 2 논의로 재설계: 보스는 [01.NPC전투액터공통프레임워크.md](./01.NPC전투액터공통프레임워크.md)의 `INpcCombatActor` 구현체를 "몸통"으로 갖고, 이 문서가 "두뇌"(페이즈 FSM) 역할만 한다. 두뇌는 몸통을 **상속하지 않고 참조(주입)**해서 지시만 내린다.

## 3.1 시스템 개요
사화산의 수호 골렘(보스)의 기본 전투 패턴, HP 50% 감지에 따른 무적/회복 페이즈 전환, 실패 시 체력 소폭 회복까지 담당하는 보스 전용 FSM이다. 실제 이동·공격 실행은 01번 프레임워크가 전담하고, 이 문서는 "언제 무엇을 하라고 지시할지"만 담당한다.

## 3.2 핵심 동작
- **FSM 상태(정정)**: `Idle → BasicAttack(순환) → (HP 50% 도달) → Invulnerable+Healing` 진입 후, 이 상태를 유지하는 동안 06번 시퀀서의 결정타 판정(5.2절)을 기다린다 → `OnCoreHitSuccess` 수신 시 `Dead`로 전환(무적 해제 불필요, 사망 처리) / `OnCoreHitFail` 수신(속성 게이트 실패 또는 타임아웃 포함) 시 `HP 60% 재설정 → BasicAttack 재개(무적 해제)`.
  > 이전 버전은 "회복 완료 → BasicAttack 재개(무적 해제) → 핵 명중 → Dead" 순서로 적혀 있었으나, 이는 "핵 명중"이라는 전용 판정을 없애고 06번이 페이즈 상태를 조합해 판정하는 방식으로 바뀐 세션 3 결정(아래 처치 연동 항목, [05.광역상태이상빙결폭발시스템.md](./05.광역상태이상빙결폭발시스템.md) 헤더 참고)과 어긋나는 이전 표기였다. 판정은 반드시 `Invulnerable+Healing` 상태 "중에" 이뤄져야 하므로 위와 같이 정정한다.
- **BasicAttack 상태**: FSM이 주기적으로 보스 액터(`INpcCombatActor`)의 `Attack(player)`를 호출해 사전 정의된 공격 패턴을 실행시킨다. 패턴 수치(공격 간격, 종류)는 `PureDataBossPattern`(SO)으로 데이터화해, 01번 프레임워크의 `PureDataNpcActor`와 동일한 방식으로 인스펙터에서 조정 가능하게 한다.
- **상태 전환 조건**: `ICharacterStatService.RuntimeData.HP` 변화를 구독해 50% 임계값 도달을 감지. [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)로부터 `OnCoreHitSuccess`/`OnCoreHitFail` 신호를 수신.
- **무적/회복 처리**: FSM이 [08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md](./08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md)의 무적 플래그 API와 `Heal()`을 호출한다 — FSM 자신은 무적 구현을 갖지 않고 호출만 한다.
- **처치 연동(세션 3 확정)**: "핵 명중" 여부를 보스 AI가 직접 판정하지 않는다 — [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)가 피격 파이프라인의 `HitContext`(피격 판정 + 온도 속성 게이트 통과 여부)와 이 FSM의 현재 페이즈 상태를 조합해 성공/실패를 판단하고, 그 결과(`OnCoreHitSuccess`/`OnCoreHitFail`)를 이 FSM에 통보한다. FSM은 통보받은 신호에 따라 `Dead` 상태로 전환하거나 HP 60% 재설정 후 `BasicAttack`으로 복귀할 뿐이다. 상세 판정 조건은 [05.광역상태이상빙결폭발시스템.md](./05.광역상태이상빙결폭발시스템.md) 5.2절 참고.

## 3.3 사용자 조작 흐름
1. 2단계: 유저가 일반 공격/기본 마법으로 보스를 공격 → 보스 FSM이 `BasicAttack` 상태에서 액터에게 반격을 지시, 유저는 회피하며 HP를 50%까지 깎는다.
2. 3단계: HP 50% 도달은 유저 조작과 무관하게 보스 FSM이 자체 감지해 회복 페이즈로 전환한다.
3. 4단계: 유저가 확대된 얼음 투사체로 핵을 명중시키면 즉시 처치, 실패하면 페이즈가 재시작된다.

## 3.4 시각/청각 효과
- 페이즈 전환 시: 전신 화염 이펙트 파티클 + 포효 사운드 + 화면 흔들림(약).
- 회복 중: 체력바가 서서히 차오르는 UI 애니메이션 + 흡수 파티클(사화산 열기 → 보스로 이동).
- 실패 시 소폭 회복: 체력바가 살짝 튀어 오르는 짧은 UI 강조 애니메이션.

## 3.5 예외/실패 케이스
- 유저가 2단계에서 과도하게 피격당해도(현재 시스템 범위 밖) 튜토리얼이므로 사망 처리는 하지 않는 것을 전제로 한다 — 사망 페널티 정책은 별도 확인 필요(이 문서 범위 밖).
- 유저가 4단계에서 아무 조작도 하지 않아 투사체가 자연 낙하/소멸하면, "명중 실패"와 동일하게 처리되어 체력 60% 회복 + 재도전 루프가 시작된다.

## 3.6 체크리스트
- [ ] 유저가 일반 공격과 기본 마법으로 보스를 공격하면, 보스 체력바가 점점 줄어들고 보스는 피할 수 있는 공격 패턴을 주기적으로 반복한다.
- [ ] 보스 체력이 50%에 도달하면, 유저 입력 없이도 보스가 전신 화염에 휩싸이며 무적 상태로 전환되고 체력바가 다시 서서히 차오른다.
- [ ] 4단계에서 거대 얼음 투사체가 보스 핵에 명중하면, 보스가 즉시 사망 모션으로 전환되고 체력바가 0으로 떨어진다.
- [ ] (예외) 4단계에서 유저가 조작하지 않아 투사체가 빗나가면, 보스 체력이 60% 수준으로 튀어 오르듯 회복되고 몇 초 뒤 재도전 연출이 시작된다.
- [ ] (데이터 흐름 근거, 3.8) 보스의 `RuntimeStatData.HP.OnValueChanged`가 50% 도달을 알리면 → `BossPhaseLogicSystem`이 `bossStatService.SetInvincible(true)`(8번 API)와 `runtimeData.ChangePhase(InvulnerableHealing)`을 호출하고 → 보스 비주얼라이저가 화염 이펙트+포효 사운드를 재생하고 HUD 체력바가 서서히 차오르는 애니메이션을 시작한다.
- [ ] (데이터 흐름 근거, 3.8) 06번 시퀀서의 `OnCoreHitFail`을 수신하면 → `BossPhaseLogicSystem`이 `bossStatService.Heal(targetHp60Percent - currentHp)`와 `SetInvincible(false)`, `runtimeData.ChangePhase(BasicAttack)`을 순서대로 호출해 → 체력바가 60% 수준으로 튀어 오르고 보스가 다시 공격 패턴을 재개한다.

## 3.7 작업 유형 분류
이 시스템은 **혼합형**이다 — 페이즈 전환 판정(HP 50% 감지, 06번 신호 수신, 무적/회복 API 호출)은 **비시청각 영역**, 그 결과로 재생되는 화염/포효/체력바 애니메이션은 **시청각 표시 영역**이다.
- 비시청각 요구사항: 보스 HP/06번 시퀀서 신호를 구독해 FSM 상태를 전환하고, 그 시점에 8번 기획서의 무적/힐 API를 정확히 호출하는 판정 로직을 구현한다.
- 시청각 요구사항: 사용자가 보스를 공격하는 조작에 대해, 페이즈 전환 순간마다(50% 도달/치명타 성공/실패) 화염·체력바·화면흔들림 등 3.4에 정의된 연출이 정확한 타이밍에 재생된다.

## 3.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: `Assets/02.System/07.NpcSystem/00.Data/INpcCombatActor.cs`/`PureDataNpcActor.cs`, `Assets/02.System/02.CharacterSystem/01.Logic/ICharacterStatService.cs`, 그리고 이번 보완에서 확정한 [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md) 6.8절의 `OnCoreHitSuccess`/`OnCoreHitFail`, [08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md](./08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md) 8.8절의 `SetInvincible`)
- `BossPhaseType` (enum, 신규) — `Idle / BasicAttack / InvulnerableHealing / Dead`(3.2의 FSM 상태를 그대로 옮김).
- `PureDataBossPattern` (SO, 신규, `PureDataNpcActor`와 동일한 결) — `attackInterval(float)`(BasicAttack 반복 주기), `healPerSecond(float)`(회복 페이즈 중 초당 회복량), `invulnerablePhaseTimeoutSeconds(float)`(회복 페이즈 최대 지속시간 — 06번 시퀀서의 타임아웃 판정이 이 값을 참조), `reviveHpRatioOnFail(float, 기본 0.6f)`(4단계 실패 시 재설정할 HP 비율).
- `RuntimeDataBossPhase` (RuntimeData, 신규, `RuntimeDataPlayerState`/`RuntimeDataTutorialSequence`와 동일한 결) — private set 필드 `currentPhase(BossPhaseType)`, `previousPhase(BossPhaseType)`. 메서드 `ChangePhase(BossPhaseType newPhase)`. 이벤트 `OnPhaseChanged(BossPhaseType previous, BossPhaseType next)`.
- **FSM 전이 표기 정정(사용자 확인 완료)**: 3.2의 이전 화살표 표기는 "핵 명중"이 전용 히트박스 판정이던 구버전 설계가 남아 있던 표현이었다 — 세션 3에서 "핵 명중" 전용 판정을 없애고 06번이 페이즈 상태+속성 게이트를 조합 판단하는 구조로 이미 바뀌었음을 사용자가 확인해줬다. 따라서 판정(성공/실패)은 `InvulnerableHealing` 상태 "중에" 발생하며, 위 3.2와 아래 데이터 흐름이 이 확정된 해석을 반영한다.

**데이터 가공/흐름 서술**
- **BasicAttack 순환**: `BossPhaseLogicSystem.Tick()`이 `currentPhase == BasicAttack`인 동안 `pureData.AttackInterval` 주기로 `bossActor.Attack(playerTarget)`(01번 기존 API) 호출.
- **50% 감지**: `bossStatService.RuntimeData.HP.OnValueChanged(current, max)` 구독 → `current / max <= 0.5f` 최초 도달 시 `bossStatService.SetInvincible(true)`(8번 API 재사용) + `runtimeData.ChangePhase(InvulnerableHealing)` 호출.
- **회복 진행(정정, 튜토리얼 씬 통합 조립 중 발견된 오버슈트 버그)**: `InvulnerableHealing` 상태 동안 `Tick()`에서 `bossStatService.Heal(pureData.HealPerSecond * deltaTime)`을 지속 호출하되, **HP가 `pureData.ReviveHpRatioOnFail * maxHp`(기본 60%)에 도달하면 그 이상 회복하지 않도록 상한선을 둔다**(예: 다음 회복 호출 시 목표치를 넘지 않는 만큼만 `Heal` 호출, 또는 도달 즉시 이후 `Heal` 호출 스킵). 이유: `healPerSecond`(초당 15)가 충분히 빨라서 `invulnerablePhaseTimeoutSeconds`(10초) 안에 HP가 100%까지 회복해버리면, 실패 시 60%로 "재설정"하는 로직(아래)이 `diff = target - current`가 음수가 되어 무동작이 되고 결과적으로 60%가 아니라 100%로 남아버려 3.6/3.8절의 "60% 수준으로 회복" 요구사항을 위반한다. 상한선을 두면 타임아웃 시점엔 이미 60%에 도달해 있으므로 아래 실패 핸들러의 `Heal(diff)`는 자연스럽게 무동작(또는 미세 보정)이 된다.
- **성공(정정, 구현 착수 중 QA가 발견한 공백 보완)**: 06번의 `OnCoreHitSuccess` 구독 핸들러가 `bossStatService.RuntimeData.ReduceHP(bossStatService.RuntimeData.HP.CurrentValue)`(무적 게이트를 우회하는 `RuntimeData`의 직접 mutator — `ICharacterStatService.TakeDamage`가 아니라 `RuntimeStatData.ReduceHP`를 직접 호출하는 이유는, 무적 플래그는 "일반 전투 파이프라인으로부터의 피격"을 막기 위한 것이지 이 FSM 자신이 내리는 "결정타로 확정 처치" 판정까지 막아서는 안 되기 때문이다) + `runtimeData.ChangePhase(Dead)` + `bossActor.PlayMotion("Death")`(01번 기존 API) 호출. 이 순서로 체력바가 0으로 떨어지는 것까지 확인되어야 3.6절 체크리스트 3번("체력바가 0으로 떨어진다")이 충족된다.
- **실패/타임아웃**: 06번의 `OnCoreHitFail` 구독 핸들러가 → 목표 HP(`pureData.ReviveHpRatioOnFail * maxHp`)와 현재 HP의 차이를 계산해 `bossStatService.Heal(diff)` 호출(60% 수준으로 재설정) + `bossStatService.SetInvincible(false)`(무적 해제) + `runtimeData.ChangePhase(BasicAttack)` 복귀.

**시청각 전달(UX) 서술**
- 3.4절 그대로: 페이즈 전환 시 화염 파티클+포효 사운드+화면 흔들림(약), 회복 중 체력바 애니메이션+흡수 파티클, 실패 시 체력바 강조 애니메이션 — 신규 `IBossPhaseVisualizer`(아래 3.9)가 `RuntimeDataBossPhase.OnPhaseChanged`를 구독해 재생하고, 체력바 자체는 기존 `RuntimeStatData.HP.OnValueChanged` 구독 UI 경로를 그대로 재사용한다.

## 3.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 "신규(두뇌·FSM)"으로 분류되어 신규 기능 폴더가 필요하다(3-2절 규칙 적용 대상).

```text
Assets/02.System/11.BossPhaseSystem/
├── BossPhaseSystemLifetimeScope.cs
├── 00.Data/
│   ├── BossPhaseType.cs
│   ├── PureDataBossPattern.cs
│   └── RuntimeDataBossPhase.cs
├── 01.Logic/
│   └── BossPhaseLogicSystem.cs
└── 02.Visualizer/
    ├── IBossPhaseVisualizer.cs
    └── BossPhaseVisualizer.cs
```

- **[D] 00.Data** — `BossPhaseType.cs`(enum), `PureDataBossPattern.cs`(SO), `RuntimeDataBossPhase.cs`(RuntimeData) 신규 작성.

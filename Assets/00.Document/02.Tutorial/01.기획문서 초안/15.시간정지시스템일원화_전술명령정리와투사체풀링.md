# 15. 시간정지 시전 시스템 일원화 — 전술명령(06) 정리 + 마나 비용 계산 통일 + 락온 대상 소실 정리 + 투사체 풀링

> 분류: 기존 정리/확장(`06.TacticalCommand` 정리, `01.UnitSystem`, `07.NpcSystem`/`99.Common/Pooling`) · 13번 기획서(락온별 마법 지정 큐)의 후속 정리 작업
> 배경(세션 12 확정): 13번 작업 중 **같은 기능을 하는 시스템이 둘 다 살아 있다**는 것이 확인됐다.
> - `01.UnitSystem`의 `RuntimeDataMultiLockOn` → `MagicLockOnComponent` → `UnitCasterSystem` 체인(09-01 `[02]` 다중 락온, 13번에서 (대상, 마법) 큐로 확장)과,
> - `06.TacticalCommand`의 `RuntimeDataTacticalQueue` + `TacticalCommandLogicSystem`(09-11 `[04]` 반응형 턴제 시간정지)이다. 후자는 시간정지 중 좌클릭으로 자기 큐에 예약하고(`TryEnqueueCurrentMagic`), 해제 시 `UseMP`로 마나를 차감한 뒤 순차 `ChangeUnit`으로 시전한다.
> 둘이 같은 마우스 입력에 동시에 반응하므로, **실제 마우스 입력에서는 마나 이중 차감/이중 시전이 날 수 있다.** 지금까지의 테스트는 전부 API 호출 기반이라 이 경로를 실제 클릭으로 검증한 적이 없다.
> **사용자 확정 사항(세션 12)**:
> - **시스템 일원화**: 시간정지 중 마법 지정·발동은 13번의 새 시스템(`RuntimeDataMultiLockOn` 큐 + 락온별 팝업 + 해제 시 일괄 발동) **하나로 통일**한다. `06.TacticalCommand`의 예약/시전 경로는 은퇴시킨다.
> - **마나 비용 계산 통일**: 비용 규칙을 한 곳에 두고, 발동·HUD 미리보기 등 모든 소비처가 같은 값을 쓴다(중복 코드 제거).
> - **투사체 오브젝트 풀링**: `Assets/02.System/99.Common/Pooling`(`IPoolService<T,TData>`, `IPoolable<TData>`, `PoolingManager`)을 재사용한다. 반환 경로는 두 가지다 — (1) 투사체가 **충돌 판정을 마친 뒤** 풀로 반환, (2) 아예 **빗나가서 범위 밖으로 날아가는 경우**에도 풀로 반환.
> - 설정 실수(필수 에셋 누락 등)에 대한 방어 로직은 이 작업 범위에 넣지 않는다. 로직상의 버그만 다룬다.

## 1. 작업 개요 및 작업 유형 분류
**비시청각(대부분) + 일부 시청각**이다.
- 비시청각: 중복 시전 경로 제거로 이중 마나 차감/이중 시전을 구조적으로 없앤다. 마나 비용 규칙을 단일 계산기로 통합한다. 락온 대상이 소실(파괴/풀 반환)될 때 큐/pending/미리보기가 정리되도록 한다. 투사체를 풀링해 매 발사마다 생성/소멸하지 않고 재사용한다.
- 시청각: 시간정지 중 상단에 뜨던 옛 `TACTICAL TIME STOP MODE` 패널(마나/큐/안내 문구가 옛 시스템 기준)을 정리해 새 HUD·팝업과 표시가 충돌하지 않게 한다.

## 2. 유형별 핵심 요구사항
- 서술 공식(비시청각): 시간정지 중 마법 예약/발동 경로를 `RuntimeDataMultiLockOn` 기반 하나로 일원화하고 `TacticalCommandLogicSystem`의 입력 처리·큐·시전을 제거해 이중 처리를 막으며, 마나 비용 계산을 단일 계산기로 통합하고, 아군 투사체를 `IPoolService`로 풀링해 충돌 후/범위 이탈 시 반환한다.
- 사용자 조작 결과(시청각): 시간정지 중 좌클릭 락온 → 팝업 → 마법 지정을 하고 해제하면 마법이 **정확히 한 번**, 마나도 **한 번만** 차감되어 적용된다. 옛 패널의 틀린 마나/큐 정보는 더 이상 보이지 않는다.

## 3. 데이터 정의 및 흐름

### 3-A. 06.TacticalCommand 일원화
**조사(구현 전 필수)**: `06.TacticalCommand` 안의 어떤 것을 다른 시스템이 의존하는지 전체 grep으로 확인한다. 현재 확인된 바깥 참조: `CharacterHUDUIView.cs`, `CharacterLifetimeScope.cs`, `UnitMagicSlotSystem.cs`/`IUnitMagicSlotService.cs`, `PlayerStateVisualizer.cs`/`PlayerStateLogicSystem.cs`, `RuntimeDataUnitGroup.cs`, `05.TimeSlowFilter`(`ITargetStencilService`/`TargetStencilService`/`TargetStencilRendererFeature`는 `05`가 소유하며 `06`에서 사용만 함). 참조의 성격(타입 의존인지, 단지 이름만 같은지)을 구분한다.
**정리 방침**:
- `TacticalCommandLogicSystem`의 입력 처리(`ProcessTacticalTargeting`/`TryEnqueueCurrentMagic`/`CancelLastCommand`/`ProcessRightClickCancel`), 큐 실행(`StartQueueExecution`/`ProcessQueueExecution`/`ExecuteSingleCommand`), 마나 차감(`UseMP`)은 **제거**한다.
- 새 시스템이 이미 하는 일은 중복이므로 제거: 시간정지 시 `TacticalContext` Push/Pop과 `SetRequireRightClickToRotate`는 `PlayerLockOnController.SetSlowMode`가 이미 수행한다(`IInputContextManager`가 참조 기준으로 중복 Push를 dedupe한다). 제거 후에도 컨텍스트가 정확히 한 번 Push/Pop되는지 확인한다.
- `06.TacticalCommand/02.Visual`의 옛 패널(`TacticalCommandUIView`의 `TacticalHUDContainer`: 제목, "예상 마나 소모/현재 마나", 큐 목록, "[좌클릭] 타깃 예약 | [우클릭] 예약 취소 | [T키] 연쇄 격발" 안내)은 **제거**한다. 새 HUD(마나 예상 비용)와 팝업이 이를 대체한다.
- 시전/큐와 직접 관련 없지만 아직 의미가 있는 시각 요소(예: 호버 타깃 표시, 스텐실 컬러 보존, 궤적선)가 있다면, 새 시스템(`MagicLockOnComponent`의 호버/하이라이트, 13-C 미리보기)이 이미 같은 역할을 하는지 비교해서 중복이면 제거하고, 새 시스템에 없는 기능이면 **삭제하지 말고 `99.Legacy/`로 격리**한다(코드_작업_기획서_가이드라인 §3-2: 기존 구형 코드는 `99.Legacy`에 안전하게 격리 보관).
- 코드는 삭제 대신 `06.TacticalCommand/99.Legacy/`로 이동하고(컴파일 유지가 필요한 의존이 있으면 최소 스텁/인터페이스만 남김), `TacticalCommandLifetimeScope`와 씬의 `TacticalCommandSystem` 오브젝트(씬에서 `TacticalCommand` 관련 오브젝트 6곳)는 비활성/제거한다. 바깥 의존이 있는 타입은 그 의존이 사라질 때까지 옮기지 않는다.
**데이터 흐름(정리 후)**: 시간정지 → `PlayerLockOnController.SetSlowMode(true)`(Tactical 컨텍스트 + 마법 락온 활성) → 락온마다 팝업 → `RuntimeDataMultiLockOn.Entries`에 쌍 지정 → 해제 시 `MagicLockOnComponent.OnDisable()` → `UnitCasterSystem.ExecuteBatchCast()`(마나 한 번 차감, 쌍별 `ChangeUnit`). 다른 경로로는 시전·마나 차감이 일어나지 않는다.

### 3-B. 마나 비용 계산 통일
- 현재 규칙이 세 곳에 있다: `UnitBatchCastingService.CalculateTotalCost`(실제 발동), `RuntimeDataMultiLockOn.RecalculatePreviewCost`/`PreviewTotalCost`/`OnPreviewCostChanged`(13-A, 아무도 쓰지 않음, 장착 여부 모름), `LockOnPreviewCalculator`(13-C, 장착된 마법의 쌍만 계산).
- **단일 계산기**로 통합한다: "장착된 마법의 쌍만, 대상이 해당 마법 유형의 유닛을 가진 쌍만, 마법 `BaseCost`의 합"이라는 하나의 규칙을 한 클래스(예: `LockOnPreviewCalculator`가 `IUnitBatchCastingService`의 규칙을 호출하는 현재 구조를 정리하거나 그 반대)에 두고, `UnitCasterSystem.ExecuteBatchCast()`(실제 차감), `LockOnManaPreviewLogicSystem`(HUD 예상 비용)이 **모두 그 한 규칙을 호출**한다. 같은 로직을 두 번 쓰지 않는다.
- `RuntimeDataMultiLockOn`의 `PreviewTotalCost`/`RecalculatePreviewCost`/`OnPreviewCostChanged`는 제거하고 호출부를 정리한다(순수 데이터 클래스가 파생 계산을 들고 있지 않게 한다 — 기존 기획서 13번 §3의 해당 항목도 이 문서가 정정한다).
- 일관성: 장착되지 않은 마법의 쌍은 비용 계산·발동·HUD 표시 모두에서 일관되게 제외된다(현재 발동과 HUD는 이미 일치).

### 3-C. 락온 대상 소실 정리 (13-C QA 발견, 풀링 도입으로 중요도 상승)
- 문제 1: pending 대상(`PendingTarget`)이 파괴되면 `CancelPending()`이 `== null` 비교로 일찍 반환해 `OnPendingChanged`가 발행되지 않아 팝업이 화면에 남는다.
- 문제 2: 큐에 쌓인 대상이 파괴되면 HUD 예상 비용이 갱신되지 않는다.
- **풀링과의 관계(핵심)**: 투사체를 풀링하면 "소실"이 `Destroy`가 아니라 `SetActive(false)`(풀 반환)가 된다. 큐/pending이 **풀로 돌아간 투사체**를 계속 들고 있으면 나중에 그 객체가 재사용될 때 엉뚱한 투사체에 마법이 적용될 수 있다. 따라서 "대상이 유효한가"의 기준을 `== null`(파괴)만이 아니라 **파괴됨 또는 비활성/풀 반환됨**으로 통일하고, 소실 시 (1) pending이면 취소 + `OnPendingChanged` 발행, (2) 큐 엔트리는 제거 + `OnEntryRemoved` 발행(→ 미리보기·마나 UI 갱신)한다. 소실 감지 위치(주기 점검 vs 풀 반환 시 통지)는 구현 시 가장 단순한 쪽으로 정하되, 풀 반환 시점에 통지하는 쪽을 우선 검토한다.

### 3-D. 투사체 오브젝트 풀링
**데이터 구조 정의**: `NpcProjectile_Dummy`(아군 투사체, `Assets/03.Resource/NpcProjectile_Dummy.prefab`)가 `IPoolable<TData>`를 구현한다. `TData`는 발사 시 필요한 설정(소유자, 목표, 속도, 데미지, 발사 지점 등 — 현재 `ProjectileAttackBehaviorSO`/`NpcCombatActorVisualizer.SpawnAndInject`가 주입하는 값)을 담는 구조체/클래스로 정의한다. 풀은 `IPoolService<NpcProjectile, TData>`(`Get`/`Release`)로 접근하고 `PoolingManager`를 재사용한다.
**풀 반환 조건 (두 가지)**:
1. **충돌 후 반환**: `CollisionDamageTrigger`가 `ProcessDamageAsync`를 마친 **뒤에** `Release`한다(판정이 먼저 처리되는 현재 순서를 유지해야 13번의 이벤트 투사체 판정/소실 감지와 충돌하지 않는다).
2. **빗나감 반환**: 충돌하지 못하고 플레이어(또는 발사 지점)로부터 최대 거리를 넘거나 최대 수명을 넘기면 `Release`한다. "화면 밖"은 카메라에 따라 달라지므로 거리/수명 기준을 쓰고 값은 PureData(조정 가능)로 둔다. 이벤트 투사체(3단계)는 항상 명중하므로 정상 흐름에서는 이 경로에 걸리지 않으며, 걸리면 기존 "투사체 소실 → 실패" 안전망이 처리한다.
**재사용 시 상태 초기화(`Setting`/`SetActive`에서 반드시)**: 이 투사체는 플레이어 마법으로 값이 바뀐다 — `RuntimeDataUnitGroup`의 온도/질량/부피/방향 값과 스케일, `CollisionDamageTrigger`의 owner(`UpdateCollisionTriggerOwner`가 플레이어로 바꿈)와 피격 이력(`hitHistory`), 하이라이트/락온 마커, 13-C 미리보기 고스트, Rigidbody 속도, `Source` 식별(이벤트 투사체 추적기 참조)이 전부 초기값으로 돌아가야 한다. 초기화가 불완전하면 이전에 걸었던 얼음/크기 확대가 새 투사체에 남아 3단계 판정이 오염된다.
**13번 시스템과의 정합**: 이벤트 투사체 식별(`IsEventProjectile`)과 소실 감지(`HasProjectile = 비어있지 않음 && activeInHierarchy`)가 풀 반환(비활성화)과 올바르게 동작해야 한다 — 판정 후 `End()`가 먼저 실행되어 풀 반환이 "소실 → 실패"를 이중 발행하지 않는다.

## 5. 예상 검수 방법 (체크리스트는 §3 데이터 흐름 근거)
**일원화(3-A)**
- [ ] 시간정지 중 좌클릭 락온 → 팝업 지정 → 해제 시 마법이 **정확히 한 번**만 적용되고 마나가 **한 번만** 차감된다(`TacticalCommand` 로그 `[TacticalCommand] Enqueued/Executing...`가 더 이상 나오지 않는다). 실제 마우스 클릭 경로로도 확인을 시도한다(불가하면 입력 이벤트를 코드로 주입해 `TacticalCommand`가 반응하지 않음을 확인하고 한계를 명시).
- [ ] 시간정지 진입/해제 시 `TacticalContext`가 정확히 한 번 Push/Pop된다(컨텍스트 스택 확인), 카메라 우클릭 회전 설정(`SetRequireRightClickToRotate`)이 시간정지 중 true/해제 후 false로 정상이다.
- [ ] 옛 `TACTICAL TIME STOP MODE` 패널이 시간정지 중에도 나타나지 않는다(UI 트리에서 `TacticalHUDContainer`가 없거나 표시되지 않음).
- [ ] 바깥 의존(`CharacterHUDUIView`, `UnitMagicSlotSystem`, `PlayerState*`, `RuntimeDataUnitGroup`, `05.TimeSlowFilter`)이 컴파일/동작 회귀 없이 유지된다. 시간정지 필터(흑백, 스텐실 컬러 보존)는 그대로 동작한다.
**마나 비용 통일(3-B)**
- [ ] 비용 규칙을 계산하는 코드가 한 곳뿐이다(grep으로 `BaseCost` 합산 로직 중복 없음). `RuntimeDataMultiLockOn`에 비용 관련 멤버가 없다.
- [ ] 장착된 마법 쌍만 비용에 포함되고, HUD 표시 비용 == 실제 차감량이 모든 경우(일반 시간정지, 3단계 마나 무제한, 미장착 마법 제외)에서 일치한다.
**락온 대상 소실(3-C)**

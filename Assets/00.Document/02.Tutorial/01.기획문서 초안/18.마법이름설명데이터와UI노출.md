# 18. 마법 이름·설명 데이터 + UI 노출 (기획서 초안)

> 작성일: 2026-10-10 · 상태: Goal 작성 완료(인벤토리 레이아웃은 §6 가정 A안으로 작성, 변경 가능)
> 형식: `코드_작업_기획서_가이드라인_v1.0.md`
> 사용자 확정(세션 12): 마법(`PureDataUnit`)에 **설명** 데이터를 추가하고 UI별로 다르게 노출한다.
> - 인벤토리 목록과 상세: **이름과 설명 모두**
> - 습득 팝업: **이름과 아이콘만**
> - 시간정지 선택 팝업: **이름만**
> - 습득 팝업 이름 표기 통일: 이름에 따옴표가 들어간 에셋 값 `'"Frost"'`를 `Frost`로 정리.

---

## 1. 작업 개요 및 유형
**혼합형**. 비시청각: `PureDataUnit`에 설명 문자열 필드 추가(인스펙터 입력). 시청각: 세 UI에서 정해진 항목만 노출.

현재 상태(조사)
- `PureDataUnit` 필드: `unitType`, `unitName`, `baseCost`, `icon`, `applicator`, `overlayMaterial`, `massScaleMultiplier`, `temperatureTarget`. **설명 필드 없음.** `PureDataUnitEditor`는 필드를 명시적으로 그리는 커스텀 에디터라 새 필드를 추가하려면 에디터에도 반영해야 한다.
- 인벤토리(`UnitInventoryUIComponent.BuildUnitElement`): 그리드 슬롯 = 64px 폭, 아이콘 48px + 이름(11pt) + 상태("장착됨/미장착/장착 불가") + 즐겨찾기 배지. **상세 영역 없음.**
- 습득 팝업(`UnitUnlockPopupUIComponent`): 제목 `"Unit Acquired: {이름}"` + 아이콘. 이미 이름+아이콘 구성.
- 시간정지 선택 팝업(`MagicSelectionPopupUIComponent`): W/E/F 라벨 = 이름(없으면 "비어있음"), Q 전체 목록 항목 = 아이콘 + 이름.
- 에셋 이름 값: `kg`, `L`, `Torus`(두 개), 온도 유닛은 `'"Frost"'`(따옴표 문자 포함).

## 2. 핵심 요구사항
- 서술(비시청각): `PureDataUnit`에 설명 필드를 추가하고 읽기 프로퍼티와 인스펙터 입력(여러 줄)을 제공해, 코드 수정 없이 마법별 설명을 데이터로 관리한다. 설명이 비어 있으면 UI는 설명 영역을 만들지 않는다.
- 사용자 조작 결과(시청각): 인벤토리에서 마법의 이름과 설명을 읽을 수 있고, 마법을 얻을 때는 이름과 아이콘만 보이며, 시간정지 중 선택할 때는 이름만 보여 흐름을 방해하지 않는다.

## 3. 데이터 정의 및 흐름
**데이터**
- `PureDataUnit.description`(`string`, `[TextArea]`, 기본 빈 문자열) + `Description` 읽기 프로퍼티. 설명 **문구 자체는 사용자가 작성**한다(개발은 문구를 임의로 만들어 디스크에 남기지 않는다).
- `PureDataUnit.unitName` 값 정리: 온도 유닛 에셋 `PureDataUnit_Temperature.asset`의 `'"Frost"'` → `Frost`.

**흐름**
- 인벤토리가 목록을 그릴 때(`RefreshInventory`/`BuildUnitElement`) 각 `PureDataUnit`의 `UnitName`/`Description`을 읽어 표시한다. 설명이 비어 있으면 설명 요소를 만들지 않는다.
- 습득 팝업과 시간정지 선택 팝업은 설명을 읽지 않는다(현행 유지).

**시청각(UX)**
| UI | 이름 | 설명 | 아이콘 |
|---|---|---|---|
| 인벤토리 목록/상세 | O | O | O(현행) |
| 습득 팝업 | O | **X** | O |
| 시간정지 선택 팝업 | O | **X** | 현행 유지(Q 전체 목록 항목에 아이콘 있음 — 확인 항목 §6-2) |

- **[V]** `Assets/02.System/01.UnitSystem/03.UI/UnitInventoryUIComponent.cs`(§6 가정 A안: 행 형태 목록 + 호버 상세 패널), `UnitUnlockPopupUIComponent.cs`·`MagicSelectionPopupUIComponent.cs`는 **변경 없음**(설명이 노출되지 않는지 확인만)

## 5. 체크리스트 (흐름 근거)
1. [ ] `PureDataUnit` 인스펙터에 설명 입력란(여러 줄)이 나타나고, 값을 입력하면 에셋에 저장된다(`description` 직렬화).
2. [ ] 설명을 입력한 마법은 인벤토리에서 이름과 설명이 함께 보이고, 설명이 빈 마법은 설명 영역 없이 기존과 같은 모습이다.
3. [ ] 습득 팝업에는 이름과 아이콘만 보이고 설명은 보이지 않는다. 온도 마법 이름이 따옴표 없이 `Frost`로 표시된다.
4. [ ] 시간정지 선택 팝업(W/E/F, Q 목록)에 설명이 보이지 않는다.
5. [ ] 13~16번 회귀(인벤토리 장착/해제, 우클릭 즐겨찾기 배지, 락온마다 팝업, 큐 발동), 콘솔 에러 0건, 디스크에 테스트용 설명 문구가 남지 않는다.

## 6. 가정 (사용자 미확정 — 추천안으로 작성, 변경 가능)
1. **인벤토리 레이아웃 = A안**: 확정 문구("목록과 상세에서 이름과 설명 모두")를 그대로 따라 목록을 **행(row) 형태**로 바꾼다. 각 행: 아이콘(48px, 클릭=장착/해제, 우클릭=즐겨찾기 — 기존 동작/배지/장착 테두리 유지) + 이름 + 설명(최대 2줄 말줄임) + 장착 상태. 마우스를 올린(호버) 행의 **상세 패널**(모달 우측)에 이름 + 아이콘 + 전체 설명을 표시한다. (대안 B: 그리드 유지 + 호버 상세 패널만.)
2. **시간정지 선택 팝업의 "이름만"**: "설명을 보이지 않는다"로 해석해 Q 전체 목록의 **아이콘은 현행 유지**(아이콘 + 이름), W/E/F 라벨은 이름. 아이콘까지 빼려면 알려 주세요.
3. 설명 문구는 사용자가 작성한다(마법 4종: Frost, kg, L, Torus 등). 비어 있어도 기능은 동작한다(설명 요소 미생성).

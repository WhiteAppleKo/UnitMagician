# 17. `Time.timeScale` 단일 소유 + 일시정지 요청 구조 (기획서 초안)

> 작성일: 2026-10-10 · 상태: 사용자 확정(방향) / 세부 확인 필요 항목은 §6
> 형식: `코드_작업_기획서_가이드라인_v1.0.md`
> 배경: `Time.timeScale`을 쓰는 곳이 세 군데로 갈라져 서로의 값을 덮어쓴다.
> - `TimeSlowVisualizer.SetTimeSlowEffect`(시간정지/이벤트 감속, `Assets/02.System/02.CharacterSystem/02.Visualizer/`) — 이벤트 감속 중에는 `TimeSlowLogicSystem.ProcessTimeSlow`가 **매 프레임** 투사체 위치 곡선 값으로 다시 쓴다.
> - `OptionUIComponent.OpenOption/CloseOption` — 열 때 현재 `timeScale`을 `s_cachedTimeScale`에 저장하고 0으로, 닫을 때 저장값으로 복원(정적 참조 카운트 `s_pauseRefCount`).
> - `UnitInventoryUIComponent.OpenInventory/CloseInventory` — 같은 구조지만 **자기만의** `s_cachedTimeScale`/`s_pauseRefCount`.
> 사용자 확정(세션 12): "`timeScale`을 소유하는 곳을 하나로 두고(`TimeSlowVisualizer`가 쓰는 쪽), UI들은 일시정지 요청만 올리고 내리게 한다."

---

## 1. 작업 개요 및 유형
**비시청각 영역**(Pure Data / Logic / Core System) + 시청각 부수 효과(메뉴를 열고 닫을 때 게임이 정확히 멈췄다 원래 속도로 돌아옴).

해결할 문제
1. **동시 오픈 꼬임**: 인벤토리(캐시 1)→Option(캐시 0)→인벤토리 닫기(1 복원, Option 열린 채 게임 진행)→Option 닫기(0 복원, 게임 영구 정지).
2. **이벤트 감속 중 Option**: Option이 0을 써도 다음 프레임에 감속 곡선 값이 덮어써 일시정지가 되지 않고, 닫을 때는 낡은 캐시 값으로 복원된다.
3. 일시정지 중에도 `Time.unscaledDeltaTime` 기반 포커스 게이지 소모/회복 틱이 계속 돈다.

## 2. 핵심 요구사항 (비시청각: 구현 수단 + 목표)
`Time.timeScale`/`fixedDeltaTime` 쓰기를 `TimeSlowVisualizer` 한 곳으로 모으고, 시간정지·이벤트 감속이 요청하는 배율과 UI들의 일시정지 요청을 `RuntimeDataTimeScale` 한 곳에서 합성해 유효 배율을 계산하게 하여, 메뉴를 어떤 순서로 열고 닫아도 정지가 풀리거나 영구 정지되지 않게 한다.

## 3. 데이터 정의 및 흐름

### 3-1. 데이터 (필드 단위)
`RuntimeDataTimeScale`(신규, `02.CharacterSystem/00.Data/`, 순수 C#)
| 필드 | 타입 | 의미 |
|---|---|---|
| `RequestedScale` | `float` | 시간정지/이벤트 감속이 요청한 배율(기본 1). 시간정지 수동 정지는 `PureDataTimeSlow.SlowTimeScale`(기본 0), 이벤트 감속은 곡선 값 |
| `pauseRequesters` | `HashSet<object>`(비공개) | 일시정지를 요청한 주체 집합. **요청자별 중복 없음(멱등)** — 같은 UI가 두 번 요청해도 한 번으로 취급되어 카운트가 어긋나지 않는다 |
| `PauseCount` | `int`(읽기) | `pauseRequesters.Count` |
| `IsPaused` | `bool`(읽기) | `PauseCount > 0` |
| `EffectiveScale` | `float`(읽기) | `IsPaused ? 0 : RequestedScale` |
| 이벤트 | `OnEffectiveScaleChanged(float)`, `OnPauseStateChanged(bool)` | 값이 바뀔 때만 발행 |

인터페이스 `ITimeScaleService`(신규, `02.CharacterSystem/01.Logic/`)
- `void SetPaused(object requester, bool paused)` — UI가 열릴 때 `true`, 닫을 때 `false`.
- `bool IsPaused`, `float EffectiveScale`, `event Action<bool> OnPauseStateChanged`.

### 3-2. 가공/흐름
1. `TimeSlowLogicSystem`은 더 이상 `Time.timeScale`에 해당하는 값을 비주얼에 직접 전달하지 않고 **`RuntimeDataTimeScale.RequestedScale`을 설정**한다(시간정지 토글 시 `SlowTimeScale`/1.0, 이벤트 감속 중에는 매 프레임 `EvaluateEventTimeScale` 결과).
2. `TimeScaleLogicSystem`(신규, `01.Logic/`, `ITimeScaleService` 구현)이 `EffectiveScale`이 바뀔 때 `ITimeSlowVisualizer`의 **배율 적용 메서드**(`TimeSlowVisualizer`가 `Time.timeScale`/`Time.fixedDeltaTime`을 쓰는 유일한 곳)를 호출한다. 기존 `SetTimeSlowEffect(isActive, ...)`의 부수 효과(`OnSlowStateChanged` 이벤트, 오디오, VFX)는 유지하되 `Time.timeScale` 쓰기만 배율 적용 메서드로 일원화한다.
3. `OptionUIComponent`, `UnitInventoryUIComponent`: `s_cachedTimeScale`/`s_pauseRefCount`/`Time.timeScale` 직접 쓰기를 **삭제**하고 `ITimeScaleService`를 주입받아 열 때 `SetPaused(this, true)`, 닫을 때 `SetPaused(this, false)`만 호출한다. 입력 컨텍스트 Push/Pop(UI 컨텍스트)은 기존 그대로.
4. **일시정지 중 포커스 게이지**: `IsPaused`인 동안 `TimeSlowLogicSystem.ProcessTimeSlow`의 포커스 소모/회복 틱을 건너뛴다(unscaled 시간으로 계속 도는 것 방지).
5. `TimeSlowVisualizer.OnDisable`의 `timeScale = 1` 복원은 유지한다(파괴 시 안전 복원).

스코프: `CharacterLifetimeScope`에 `RuntimeDataTimeScale`, `TimeScaleLogicSystem`(`ITimeScaleService`)을 Singleton 등록한다. `LocomotionLifetimeScope`의 부모가 `CharacterLifetimeScope`이고 `UnitSystemLifetimeScope`/`OptionLifetimeScope`의 부모가 `LocomotionLifetimeScope`이므로, 두 UI는 **부모 체인으로 `ITimeScaleService`를 주입**받을 수 있다(신규 스코프 불필요).

### 3-3. 시청각 전달(UX)
- 메뉴(인벤토리/Option)를 열면 게임이 즉시 멈추고(`timeScale 0`), 닫으면 **그 시점의 올바른 배율**로 돌아간다: 일반 → 1.0, 수동 시간정지 중 → 0, 이벤트 감속 중 → 현재 곡선 값.
- 인벤토리와 Option을 어떤 순서로 열고 닫아도 마지막 메뉴를 닫기 전에는 정지 유지, 모두 닫으면 정확히 복귀한다. 영구 정지/정지 해제 누락이 없다.
- 이벤트 감속 중 Option을 열면 실제로 일시정지되고(곡선이 덮어쓰지 않음) 닫으면 감속이 이어진다.

## 5. 체크리스트 (3번 흐름 근거)
1. [ ] 코드 전체에서 `Time.timeScale =`/`Time.fixedDeltaTime =` 대입이 `TimeSlowVisualizer`에만 있다(grep). `s_cachedTimeScale`/`s_pauseRefCount` 없음.
2. [ ] 인벤토리 열기 → Option 열기 → 인벤토리 닫기: 게임은 계속 정지 → Option 닫기: 정상(1.0) 복귀. 반대 순서도 동일. 같은 메뉴를 연속 `Open` 호출해도 한 번 닫으면 복귀.
3. [ ] 수동 시간정지(`T`, timeScale 0) 중 Option 열고 닫기: 0 유지, 닫은 뒤에도 시간정지 상태(해제는 `T`로만).
4. [ ] 3단계 이벤트 감속 중 Option 열기: `timeScale`이 0으로 유지(매 프레임 덮어쓰이지 않음), 이벤트 투사체·보스 정지. 닫으면 곡선 값으로 이어지고 이벤트가 정상 종료(성공/실패 판정 정상, 정지 잔존 없음). 이벤트 중 인벤토리는 기존대로 열리지 않는다.
5. [ ] 일시정지 중 포커스 게이지 소모/회복이 정지한다(시간정지+Option 오픈 상태에서 게이지 불변).
6. [ ] 13~16번 회귀(락온 팝업, 큐 1회 발동, 전환점, 풀링, 컨텍스트 스택 Player 복귀), `TimeSlowVisualizer` 오디오/VFX/`OnSlowStateChanged` 동작 유지, 콘솔 에러 0건.
7. [ ] DLV/VContainer 규칙(구체 클래스 주입·`Find*` 금지), 폴더 경로 준수.

## 6. 확인 필요 / 가정
1. **"참조 카운트"의 구현**: 숫자 카운터가 아니라 **요청자 집합(멱등)** 으로 구현한다(같은 메뉴의 중복 Open/Close로 카운트가 어긋나는 것을 구조적으로 방지). 사용자가 숫자 카운터를 원하면 알려 주세요.
2. **일시정지 중 포커스 게이지 정지(§3-2 4번)**: 논리적 귀결로 요구사항에 넣었다. 원치 않으면 제외한다.
3. 일시정지 요청 주체는 현재 Option, 인벤토리 둘뿐이다. 이후 다른 메뉴가 생기면 같은 서비스를 쓴다.

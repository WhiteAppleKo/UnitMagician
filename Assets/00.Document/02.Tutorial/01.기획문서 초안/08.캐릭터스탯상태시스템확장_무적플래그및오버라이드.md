# 8. 캐릭터 스탯·상태 시스템 확장 — 무적 플래그 + 소모 무제한 오버라이드

> 분류: 기존 확장(캐릭터 스탯·상태 시스템) · 관련 단계: 3단계
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)
> 세션 3 논의로 구체화: 무적 게이트를 "피격 판정/데미지 판정 분리" 패턴으로 구현하도록 확정.

## 8.1 시스템 개요
3단계 보스 회복 기믹(무적 전환)과 튜토리얼 전용 자원 완화(마나 소모 무제한)를 지원하기 위해, 기존 `ICharacterStatService`에 두 가지 상태 오버라이드를 추가한다.

## 8.2 핵심 동작
- **무적 플래그**: [03.보스AI페이즈시퀀스시스템.md](./03.보스AI페이즈시퀀스시스템.md)의 보스 FSM("두뇌")이 On/Off를 호출하는 상태값.
- **피격 판정과 데미지 판정 분리(세션 3 확정)**: 무적 플래그는 피격 파이프라인의 **마지막 단계(데미지 적용 단계)만** 차단한다. 파이프라인이 시작되는 즉시 `HitContext`에 "피격 판정 O"가 기록되고, 이후 온도(속성) 게이트 등 다른 판정들도 정상적으로 컨텍스트에 누적된다 — 무적 플래그는 오직 최종 `TakeDamage` 호출(HP 감소)만 무효화한다. 즉 파이프라인 흐름은 **"피격 판정 O → (속성 게이트 등 정상 판정) → 무적이라 데미지 판정 X → 파이프라인 종료"**이며, 도중에 조기 반환(early return)해서 컨텍스트 누적 자체를 건너뛰지 않는다.
  - 이 설계가 중요한 이유: [05.광역상태이상빙결폭발시스템.md](./05.광역상태이상빙결폭발시스템.md)가 "보스가 무적인 회복 페이즈 중에도 얼음 속성 피격이 들어왔는지"를 판단해야 하는데, 만약 무적 체크가 파이프라인 맨 앞에서 조기 반환해버리면 이 정보 자체가 유실된다.
- **마나 소모 무제한 오버라이드**: [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)만 호출 가능한 전용 API로 On/Off. On 상태에서는 `UseMP` 호출이 항상 성공 처리되고 실제 MP 값이 차감되지 않는다.

## 8.3 사용자 조작 흐름
유저는 이 오버라이드를 직접 조작하지 않는다 — 3단계 진입/해제 시점에 시퀀서/보스 FSM이 자동으로 On/Off 하며, 유저는 "마법을 아무리 써도 마나가 줄지 않는다", "보스를 때려도 죽지 않는다"는 결과만 체감한다.

## 8.4 시각/청각 효과
- 무적 상태: 보스 HP 게이지 위에 무적 아이콘/이펙트(방어막 형태) 표시.
- 마나 무제한: HUD 마나 게이지가 항상 가득 찬 상태 유지, 소비 시에도 게이지가 줄어드는 애니메이션이 재생되지 않음.

## 8.5 예외/실패 케이스
- 무적 상태에서 유저가 계속 공격을 시도하면, 타격 이펙트(임팩트 파티클)는 재생되지만 데미지 숫자/HP 감소는 발생하지 않는다 — "때리고 있는데 안 죽는다"는 느낌을 의도적으로 준다.
- 무적 상태에서 얼음 속성 투사체가 명중해도 HP는 그대로지만, 05번 문서가 구독하는 `HitContext`에는 "피격 O + 속성 게이트 통과"가 정상적으로 기록되어 있어야 한다 — 광역 빙결 판정이 이 기록에 의존하기 때문에, 무적 로직이 컨텍스트 기록 자체를 막아버리는 구현은 반드시 피해야 한다.
- 오버라이드가 해제된 이후(3단계 종료)에는 마나가 정상적으로 소모되어, 마나가 부족하면 마법 시전이 막히고 슬롯 아이콘이 비활성 표시로 전환된다.

## 8.6 체크리스트
- [ ] 보스 체력이 50%에 도달해 무적 상태로 전환되면, 유저가 보스를 공격해도 데미지 숫자가 뜨지 않고 체력바가 줄지 않는다.
- [ ] 3단계 오버라이드 구간에서 유저가 마법을 계속 시전해도, 마나 게이지가 소모되지 않고 항상 가득 찬 상태로 표시된다.
- [ ] 무적 상태에서 얼음 속성 투사체가 보스에 명중하면, 체력은 줄지 않지만 곧이어 광역 빙결 폭발이 정상적으로 발동한다(피격 정보가 유실되지 않았음을 보여주는 결과).
- [ ] (예외) 오버라이드 구간이 아닌 평소 전투 중에는 마나가 정상적으로 소모되어, 마나가 부족하면 마법 시전이 막히고 슬롯 아이콘이 비활성 표시로 바뀐다.
- [ ] (데이터 흐름 근거, 8.8) `RuntimeStatData.SetInvincible(true)` 호출 후 `ICharacterStatService.TakeDamage`를 호출하면 → `ReduceHP`가 실행되지 않아 → `RuntimeStatData.HP.CurrentValue`가 변하지 않고 체력바 UI도 그대로 유지된다.
- [ ] (데이터 흐름 근거, 8.8) `RuntimeStatData.SetManaUnlimited(true)` 호출 후 `ICharacterStatService.UseMP`를 호출하면 → `TryConsumeMP`가 실행되지 않고 즉시 `true`가 반환되어 → `RuntimeStatData.MP.CurrentValue`가 변하지 않고 `CharacterHUDUIView`의 MP 바가 100%로 유지된다.

## 8.7 작업 유형 분류
이 시스템은 **혼합형**이다 — 무적/마나무제한 게이트 로직 자체는 **비시청각 영역**(Logic/Core), 그 결과가 HUD·보스 게이지에 드러나는 부분은 **시청각 표시 영역**이다.
- 비시청각 요구사항: 피격/마나소모 연산 경로에 상태 오버라이드 분기를 추가하여, 오버라이드 활성 시 `RuntimeStatData`의 HP/MP 실값 변경을 스킵하고 오버라이드 비활성 시 기존 연산 경로를 그대로 유지한다(연산 자체의 분기 오버헤드는 bool 체크 1회 수준으로 무시 가능).
- 시청각 요구사항: 사용자가 보스를 공격/마법을 시전하는 조작에 대해, 무적 중에는 타격 이펙트만 재생되고 체력바가 그대로이며, 마나무제한 중에는 마나 게이지가 항상 가득 찬 상태로 보인다.

## 8.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: `Assets/02.System/02.CharacterSystem/00.Data/RuntimeStatData.cs`, `01.Logic/ICharacterStatService.cs` 기존 코드)
- `RuntimeStatData.isInvincible` (bool, private set, 신규 필드) — true면 이 캐릭터는 무적 상태. HP 실값 변경만 차단하며 피격 판정 자체는 그대로 발생한다.
- `RuntimeStatData.isManaUnlimited` (bool, private set, 신규 필드) — true면 이 캐릭터는 마나 소모가 항상 성공 처리되고 MP 실값은 차감되지 않는다.
- `RuntimeStatData.SetInvincible(bool value)` / `SetManaUnlimited(bool value)` (신규 메서드) — 값이 바뀔 때만 각각 `OnInvincibleChanged(bool)` / `OnManaUnlimitedChanged(bool)` 이벤트를 발행한다(기존 `CurrentFaction` setter와 동일한 변경 감지 패턴).
- `ICharacterStatService.SetInvincible(bool)` / `SetManaUnlimited(bool)` (신규 메서드, `CharacterStatSystem`이 구현) — 내부적으로 `RuntimeStatData`의 대응 메서드를 호출하는 얇은 래퍼. 설계 의도상 전자는 03(보스AI페이즈시퀀스시스템)의 보스 FSM만, 후자는 06(이벤트시퀀서시스템)만 호출한다(단, 이 호출 주체 제한은 컴파일 타임으로 강제되지 않는 설계 규약이다 — 8.9 참고).

**데이터 가공/흐름 서술**
- `ICharacterStatService.TakeDamage(int amount)` 호출 시 → `CharacterStatSystem`이 `runtimeData.isInvincible`을 확인 → true면 `ReduceHP` 호출 없이 즉시 반환(HP 불변), false면 기존 그대로 `runtimeData.ReduceHP(amount)` 실행. 이 분기는 `ICharacterStatService.TakeDamage` **내부에서만** 일어나므로, `InteractionSystem`의 피격 파이프라인(`HitContext` 누적)에는 영향을 주지 않는다 — 8.2에서 요구한 "피격 판정은 정상 기록, 데미지 판정만 무효화"가 이 지점에서 정확히 구현된다.
- `ICharacterStatService.UseMP(int amount)` 호출 시 → `CharacterStatSystem`이 `runtimeData.isManaUnlimited`를 확인 → true면 `TryConsumeMP` 호출 없이 즉시 `true` 반환(MP 불변), false면 기존 그대로 `runtimeData.TryConsumeMP(amount)` 실행.

**시청각 전달(UX) 서술**
- 무적: `RuntimeStatData.OnInvincibleChanged` 이벤트를 보스 측 비주얼라이저가 구독해 방어막 이펙트/아이콘을 HP 게이지 위에 표시·해제한다(실제 구현 위치는 03번 기획서에서 정의 — 8.9 참고).
- 마나 무제한: `CharacterHUDUIView`(`Assets/02.System/02.CharacterSystem/03.UI/CharacterHUDUIView.cs`, 기존 파일)가 `RuntimeStatData.OnManaUnlimitedChanged`를 신규 구독해, true인 동안 `mpBar.style.width`를 100%로 고정 표시한다(현재 `UpdateMPUI`는 값 변경 시 즉시 대입이라 별도 트윈 스킵 처리는 불필요 — `MP.OnValueChanged`가 애초에 발생하지 않으므로 UI 갱신 호출 자체가 없다).

## 8.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 신규 기능 폴더가 아니라 **기존 `02.CharacterSystem` 확장**이므로 3-2절의 신규 넘버링 규칙은 적용 대상이 아니다. 실제 수정 대상은 다음과 같다.

- **[D] 00.Data** — `Assets/02.System/02.CharacterSystem/00.Data/RuntimeStatData.cs` (기존 파일 확장, 신규 필드/메서드/이벤트 추가). `PureStatData`는 변경 없음(런타임 전용 오버라이드로, SO에 굽지 않는 값이므로).
- **[L] 01.Logic** — `Assets/02.System/02.CharacterSystem/01.Logic/ICharacterStatService.cs`, `Assets/02.System/02.CharacterSystem/01.Logic/CharacterStatSystem.cs` (기존 파일 확장, `SetInvincible`/`SetManaUnlimited` 추가 및 `TakeDamage`/`UseMP` 내부 분기 추가).
- **[V] 03.UI** — `Assets/02.System/02.CharacterSystem/03.UI/CharacterHUDUIView.cs` (기존 파일 확장, `OnManaUnlimitedChanged` 구독 추가).
- **[V] 02.Visualizer (보스 무적 이펙트, 미확정)** — 보스 전용 비주얼라이저는 03번(보스AI페이즈시퀀스시스템) 기획서가 아직 작성되지 않아 실제 클래스/경로가 확정되지 않음. 이 항목은 03번 기획서 작성 시점에 함께 확정한다(현재 8번 기획서 범위에서는 데이터/로직 계층까지만 책임진다).
- **접근 제어 관련 공지사항**: `SetInvincible`/`SetManaUnlimited`를 특정 시스템(03/06)만 호출하도록 강제하는 컴파일 타임 메커니즘(예: `internal` + `InternalsVisibleTo`, 별도 권한 인터페이스 분리 등)은 이 기획서에서 다루지 않는다 — 현재는 "호출 주체를 좁게 유지한다"는 설계 규약 수준이며, 필요 시 별도로 논의한다.

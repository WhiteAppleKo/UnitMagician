# 10. 이동·카메라 시스템 확장 — 이벤트 타겟 추적 카메라

> 분류: 기존 확장(이동·카메라 시스템) · 관련 단계: 3단계
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)
> **정정(세션 6, 사용자 확정)**: 이 프로젝트의 3D 카메라는 **항상 다크소울3식 3인칭 숄더뷰가 기본**이다. 최초 작성 시 1단계 퍼즐 구간에 "고정 쿼터뷰"를 강제 적용하는 것으로 설계했었으나, 이는 잘못된 전제였다 — **1단계에서도 카메라를 강제 전환하지 않고, 유저가 평소처럼 직접 3인칭 카메라를 움직이며 아군·돌문·투사체를 확인한다.** 이 문서와 실제 구현에서 `FixedQuarterView` 모드/전략은 전부 제거한다. 3단계 이벤트 추적 카메라(`EventTargetTracking`)는 유지하되, 이것도 완전히 다른 각도가 아니라 **같은 3인칭 숄더뷰 스타일(거리/오프셋 동일)을 유지한 채 카메라가 보는 대상만 플레이어→아군-보스 궤적으로 바뀌는 정도**로 이해한다(사용자 확정).

## 10.1 시스템 개요
3단계 보스 50% 기믹에서 카메라가 자동으로 날아오는 아군 투사체 쪽을 비추는 연출을 지원한다. 기존 `CameraFollowService`는 유저 입력 기반 모드(1인칭/숄더/탑뷰) 전환만 지원하므로, 이벤트로 강제 전환되는 신규 모드(3단계 전용)가 필요하다. **1단계는 이 시스템의 대상이 아니다 — 평소 3인칭 숄더뷰를 유저가 그대로 조작한다.**

## 10.2 핵심 동작
- **트리거**: [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)가 보내는 `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail` 신호.
- **결과**: 3단계 보스 50% → 아군 발사 지점~보스 사이 궤적을 비추는 이벤트 카메라로 전환(기존 3인칭 숄더뷰와 동일한 거리/오프셋 느낌 유지, 바라보는 대상/각도만 전환), 유저 마우스 조준점이 투사체 위에 오도록 뷰포트 배치.
- 이벤트 카메라 활성 중에는 유저의 마우스 회전/줌 입력을 차단(`IInputContextManager`의 UI/Tactical 컨텍스트 차단 패턴과 동일한 방식 적용).

## 10.3 사용자 조작 흐름
1. **1단계**: 유저가 평소처럼 3인칭 카메라를 직접 조작해 아군·돌문·투사체를 확인한다(자동 전환 없음).
2. **3단계**: 유저는 이 카메라 전환을 직접 조작하지 않는다 — 보스 50% 도달 시 자동 전환된다. 전환 이후에는 유저가 조준(락온) 조작만 이어서 수행하면 된다.

## 10.4 시각/청각 효과
- 카메라 전환 시(3단계 진입/해제): 짧은 블렌드 전환(크로스 디졸브 또는 빠른 팬) + 전환 사운드(휙 하는 느낌).

## 10.5 예외/실패 케이스
- 이벤트 카메라가 활성화된 동안 유저가 마우스를 움직여도 시점이 회전하지 않아야 한다(입력 차단 확인 필요).
- 이벤트 카메라 종료(시퀀서가 종료 신호를 보내지 않는 경우) 시 카메라가 원래 유저 제어 모드로 복귀하지 못하고 고정된 채로 남는 회귀 가능성이 있다 — 반드시 시퀀서의 종료 신호와 짝을 맞춰 원복 처리해야 한다.

## 10.6 체크리스트
- [ ] 씬 진입 및 1단계 진행 중에는 카메라가 강제 전환되지 않고, 유저가 평소처럼 3인칭 카메라를 직접 조작할 수 있다.
- [ ] 보스 체력이 50%에 도달하는 순간, 카메라가 자동으로 아군 발사 지점에서 보스 방향으로 이어지는 투사체 궤적을 비추는 구도로 전환되며(기존 3인칭 숄더뷰와 동일한 거리감 유지) 유저의 조준점이 투사체 위에 자연스럽게 위치한다.
- [ ] (예외) 유저가 이벤트 카메라 전환 중 마우스를 움직여도, 이벤트 카메라가 유지되는 동안에는 시점이 회전하지 않고 지정된 구도를 유지한다.
- [ ] (데이터 흐름 근거, 10.8) 이벤트 시퀀서 신호 수신 시 `ICameraFollowService.SetCameraMode(CameraMode.EventTargetTracking)`가 호출되고 `IInputContextManager.PushContext(new EventCameraInputContext())`가 함께 호출되면 → `CameraFollowService`가 `CurrentContext.ContextType == InputContextType.Event`를 감지해 마우스 회전/줌 입력 처리를 스킵하여 → 유저가 마우스를 움직여도 화면 구도가 그대로 유지된다.

## 10.7 작업 유형 분류
이 시스템은 **혼합형**이다 — 카메라 모드 전환/입력 차단 판단은 **비시청각 영역**, 실제 화면 전환·구도는 **시청각 표시 영역**이다.
- 비시청각 요구사항: 이벤트 시퀀서 신호를 구독해 `ICameraFollowService.SetCameraMode`와 `IInputContextManager.PushContext/PopContext`를 정확한 시점에 호출하는 판정 로직을 추가한다.
- 시청각 요구사항: 사용자가 아무 조작도 하지 않는 상태에서(1단계 진입, 3단계 보스 50%) 카메라 구도가 자동으로 전환되어, 퍼즐 전체 구도 또는 투사체 추적 구도로 보인다.

## 10.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: `Assets/02.System/00.Movement/00.Data/01.CameraMovement/CameraMode.cs`, `01.Logic/01.CameraMovement/Interface/ICameraFollowService.cs`, `Assets/02.System/99.Common/Input/IInputContext.cs`/`IInputContextManager.cs` 기존 코드)
- `CameraMode` (기존 enum, 값 확장) — 기존 `HybridFocus/PlayerOnly/MouseFocus/FirstPerson/ThirdPersonShoulder`에 `EventTargetTracking`(3단계 이벤트 추적 카메라) 1개 값만 추가한다. **`FixedQuarterView`는 추가하지 않는다(정정, 사용자 확정 — 쿼터뷰 자체를 취소).**
- `InputContextType` (기존 enum, 값 확장) — 기존 `Player/Tactical/UI`에 `Event`(이벤트 카메라 전용 컨텍스트) 1개 값 추가.
- `EventCameraInputContext` (신규 클래스, `IInputContext` 구현) — 기존 `UIInputContext`와 동일한 구조(`ContextType => InputContextType.Event`, `TargetCursorLockMode`/`TargetCursorVisible`은 시네마틱 특성상 `CursorLockMode.Locked`/`false`로 설정해 유저가 커서로 다른 조작을 하지 못하게 한다).
- `EventTargetTrackingCameraStrategy` (신규 클래스) — 기존 `m_strategies` 딕셔너리(`CameraFollowService.cs` 내부)에 등록되는 카메라 전략 구현체. 기존 `ThirdPersonShoulderCameraStrategy`와 동일한 거리/오프셋 파라미터(`PureDataCameraSetting`)를 공유해서, 바라보는 피벗/각도만 아군-보스 궤적 기준으로 계산하고 카메라 자체의 "느낌"(3인칭 숄더뷰)은 그대로 유지한다.

**데이터 가공/흐름 서술**
- **1단계에서는 아무 신호도 발생하지 않고 아무 것도 전환되지 않는다** — 유저가 평소처럼 `ThirdPersonShoulderCameraStrategy`(기존)를 직접 조작한다.
- 06번 시퀀서의 `OnBoss50Percent` 신호 수신 → 신규 Logic 클래스가 `cameraFollowService.SetCameraMode(CameraMode.EventTargetTracking)` + `inputContextManager.PushContext(new EventCameraInputContext())` 순서로 호출 → 기존 `CameraFollowService`가 마우스 입력을 처리하는 지점(`CameraFollowService.cs` 152~187행 부근, 기존에 `InputContextType.UI`/`InputContextType.Tactical`을 체크해 조기 반환하는 것과 동일한 위치)에 `InputContextType.Event` 조건을 추가로 체크해 조기 반환 → 마우스 회전/줌이 무시된다.
- 이벤트 카메라 종료 시(10.5가 이미 명시한 위험 — 시퀀서가 반드시 종료 신호를 짝지어 보내야 함): 신규 Logic 클래스가 `inputContextManager.PopContext(...)` + `cameraFollowService.SetCameraMode(CameraMode.ThirdPersonShoulder)`(전환 전 원래 모드)를 호출해 유저 제어로 복귀한다.

**시청각 전달(UX) 서술**
- 10.4절 그대로: 3단계 진입/해제 시 짧은 블렌드(크로스 디졸브/빠른 팬) + 전환 사운드 — 블렌드 연출 자체는 기존 `CameraFollowService`가 `OnCameraModeChanged` 이벤트 발행 시 카메라 비주얼라이저(있다면)가 재생하는 책임이며, 이 문서는 "언제 전환을 트리거할지"까지만 다룬다.

## 10.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 신규 기능 폴더가 아니라 **기존 `00.Movement`(카메라)/`99.Common`(입력 컨텍스트) 확장**이므로 3-2절의 신규 넘버링 규칙은 적용 대상이 아니다.

- **[D] 00.Data** — `Assets/02.System/00.Movement/00.Data/01.CameraMovement/CameraMode.cs`(기존 파일, enum 값 2개 추가), `Assets/02.System/99.Common/Input/IInputContext.cs`(기존 파일, `InputContextType.Event` 값 추가).
- **[L] 01.Logic** — `Assets/02.System/00.Movement/01.Logic/01.CameraMovement/CameraFollowService.cs`(기존 파일 확장, 마우스 입력 조기 반환 조건에 `InputContextType.Event` 추가) 및 같은 폴더에 `EventTargetTrackingCameraStrategy.cs`(신규 전략 클래스, `FixedQuarterViewCameraStrategy.cs`는 만들지 않음/제거) 추가. 이벤트 구독 및 트리거 판정을 맡을 `EventCameraTriggerLogicSystem.cs`(신규, 순수 C#, 생성자 주입: `ICameraFollowService`, `IInputContextManager`, 06번 시퀀서가 노출하는 이벤트)를 같은 `01.CameraMovement/` 폴더에 추가 — **씬 진입 시 강제 모드 전환은 하지 않는다(정정).**
- **[V] 신규 시각 컴포넌트 없음** — `Assets/02.System/99.Common/Input/EventCameraInputContext.cs`(신규, `IInputContext` 구현체 — DLV상 Data/Logic 경계에 걸치는 상태 객체이나 기존 `UIInputContext`/`TacticalInputContext`와 동일 계층으로 분류해 `99.Common/Input/`에 위치).
- **미해결 의존성(확정 보류)**: `EventCameraTriggerLogicSystem`이 구독할 06번 시퀀서의 실제 이벤트 인터페이스(예: `OnStageChanged`/`OnBoss50Percent`를 어떤 DIP 인터페이스로 노출할지)는 06번 기획서가 구체 클래스(`TutorialSequencerLogicSystem`)만 정의하고 별도 인터페이스를 아직 정의하지 않아, 두 문서가 함께 구현 단계에서 맞춰야 한다.
- **기존에 이미 열려 있는 미해결 항목(이 보완 작업 범위 밖, 그대로 보존)**: 10.5의 "이벤트 카메라 종료 신호 누락 시 복귀 실패" 회귀 위험은 원문 그대로 유지 — 위 데이터 흐름에서 "반드시 종료 신호와 짝을 맞춰야 한다"는 전제로 서술했을 뿐, 안전장치(타임아웃 강제 복귀 등) 도입 여부는 이번 보완에서 임의로 확정하지 않는다.

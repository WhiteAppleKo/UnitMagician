# 10. 이동·카메라 시스템 확장 — 이벤트 타겟 추적 카메라

> 분류: 기존 확장(이동·카메라 시스템) · 관련 단계: 3단계
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)
> **정정(세션 6, 사용자 확정)**: 이 프로젝트의 3D 카메라는 **항상 다크소울3식 3인칭 숄더뷰가 기본**이다. 최초 작성 시 1단계 퍼즐 구간에 "고정 쿼터뷰"를 강제 적용하는 것으로 설계했었으나, 이는 잘못된 전제였다 — **1단계에서도 카메라를 강제 전환하지 않고, 유저가 평소처럼 직접 3인칭 카메라를 움직이며 아군·돌문·투사체를 확인한다.** 이 문서와 실제 구현에서 `FixedQuarterView` 모드/전략은 전부 제거한다. **시점은 숄더뷰 하나로 고정**이며(22번 리팩토링 기획서), 3단계 이벤트 추적 카메라는 별도 `CameraMode`가 아니라 `ICameraFollowService`의 **이벤트 대상 오버라이드**(`IsEventTargetOverrideActive`/`SetEventTargetOverride(bool)`)로 구현한다 — **평상시는 숄더 가상 카메라이고, 이벤트 구간에는 숄더 카메라가 날아오는 투사체를 캐릭터 몸으로 가리므로 별도의 이벤트 전용 1인칭 가상 카메라(캐릭터 눈 위치, 시선 = 카메라→이벤트 투사체)로 Cinemachine 블렌드 전환한다**(사용자 확정, 22번 §10 / Goal 46 — 직전의 "같은 숄더 vcam에서 시선만 덮어쓰기" 방식을 이벤트 구간에 한해 대체).

## 10.1 시스템 개요
3단계 보스 50% 기믹에서 카메라가 자동으로 날아오는 아군 투사체 쪽을 비추는 연출을 지원한다. 시점은 3인칭 숄더뷰 하나로 고정이므로 카메라 모드를 전환하는 별도 모드는 만들지 않고, `CameraFollowService`에 3단계 전용 이벤트 대상 오버라이드(ON/OFF 상태와 이벤트 1인칭 카메라의 눈 위치·시선 계산)를 두고, 실제 전환은 씬의 이벤트 전용 1인칭 가상 카메라로 Cinemachine 블렌드한다(숄더 vcam은 건드리지 않는다). **1단계는 이 시스템의 대상이 아니다 — 평소 3인칭 숄더뷰를 유저가 그대로 조작한다.**

## 10.2 핵심 동작
- **트리거**: [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)가 보내는 `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail` 신호.
- **결과**: 3단계 보스 50% → 이벤트 대상 오버라이드 ON(**이벤트 전용 1인칭 가상 카메라가 활성화돼 카메라가 캐릭터 눈 위치(플레이어 위치 + `EventCameraEyeHeight`)에 놓이고, 시선이 매 프레임 눈→이벤트 투사체 방향이다**(22번 §8·§10 — 아군~보스 중점 방식 폐기, 접근·지나침·이탈 전 구간 동일). 숄더 카메라와 달리 투사체가 캐릭터 몸에 가려지지 않으며, 이벤트 중 캐릭터 몸/머리 렌더러는 화면에서 숨긴다(그림자 유지)), 투사체가 화면 중앙에 유지되어 유저가 락온해 마법을 지정할 수 있다.
- 이벤트 카메라 활성 중에는 유저의 마우스 회전/줌 입력을 차단(`IInputContextManager`의 UI/Tactical 컨텍스트 차단 패턴과 동일한 방식 적용).

## 10.3 사용자 조작 흐름
1. **1단계**: 유저가 평소처럼 3인칭 카메라를 직접 조작해 아군·돌문·투사체를 확인한다(자동 전환 없음).
2. **3단계**: 유저는 이 카메라 전환을 직접 조작하지 않는다 — 보스 50% 도달 시 자동 전환된다. 전환 이후에는 유저가 조준(락온) 조작만 이어서 수행하면 된다.

## 10.4 시각/청각 효과
- 오버라이드 진입/해제 시(3단계): 숄더 vcam ↔ 이벤트 1인칭 vcam을 **Cinemachine 블렌드**(`PureDataCameraSetting.EventCameraBlendTime`(초), 0 이하면 컷)로 전환한다. 진입 블렌드가 끝나 이벤트 vcam이 화면을 완전히 쥐면 캐릭터 몸 렌더러를 `ShadowsOnly`로 바꿔 숨기고(그림자 유지), 해제 즉시 원복한다. 종료 시 같은 블렌드로 숄더 vcam에 복귀하며 플레이어 시선각(이벤트 중 불변)·피벗(`player+1.4`)은 그대로라 이벤트 직전 시선으로 돌아온다. 전환 사운드(휙 하는 느낌)는 별도 연출 범위.

## 10.5 예외/실패 케이스
- 이벤트 카메라가 활성화된 동안 유저가 마우스를 움직여도 시점이 회전하지 않아야 한다(입력 차단 확인 필요).
- 이벤트 카메라 종료(시퀀서가 종료 신호를 보내지 않는 경우) 시 이벤트 대상 오버라이드가 해제되지 않아 카메라가 이벤트 대상에 고정된 채로 남는 회귀 가능성이 있다 — 반드시 시퀀서의 종료 신호와 짝을 맞춰 오버라이드를 해제해야 한다.

## 10.6 체크리스트
- [ ] 씬 진입 및 1단계 진행 중에는 카메라가 강제 전환되지 않고, 유저가 평소처럼 3인칭 카메라를 직접 조작할 수 있다.
- [ ] 보스 체력이 50%에 도달하는 순간, 활성 가상 카메라가 이벤트 전용 1인칭 vcam으로 블렌드 전환되어 카메라가 캐릭터 눈 위치에 있고 시선이 매 프레임 눈→날아오는 이벤트 투사체 방향이며(접근·지나침·이탈 전 구간), 캐릭터 몸이 화면에 보이지 않고, 투사체가 화면 중앙에 유지되어 유저가 락온해 마법을 지정할 수 있다(22번 §8·§10). 종료 후 숄더 vcam으로 복귀한다.
- [ ] (예외) 유저가 이벤트 카메라 전환 중 마우스를 움직여도, 이벤트 카메라가 유지되는 동안에는 시점이 회전하지 않고 지정된 구도를 유지한다.
- [ ] (데이터 흐름 근거, 10.8) 이벤트 시퀀서 신호 수신 시 `ICameraFollowService.SetEventTargetOverride(true)`가 호출되고 `IInputContextManager.PushContext(new EventCameraInputContext())`가 함께 호출되면 → `CameraFollowService`가 `CurrentContext.ContextType == InputContextType.Event`를 감지해 마우스 회전/줌 입력 처리를 스킵하여 → 유저가 마우스를 움직여도 화면 구도가 그대로 유지된다.

## 10.7 작업 유형 분류
이 시스템은 **혼합형**이다 — 카메라 모드 전환/입력 차단 판단은 **비시청각 영역**, 실제 화면 전환·구도는 **시청각 표시 영역**이다.
- 비시청각 요구사항: 이벤트 시퀀서 신호를 구독해 `ICameraFollowService.SetEventTargetOverride`와 `IInputContextManager.PushContext/PopContext`를 정확한 시점에 호출하는 판정 로직을 추가한다.
- 시청각 요구사항: 사용자가 아무 조작도 하지 않는 상태에서(1단계 진입, 3단계 보스 50%) 카메라 구도가 자동으로 전환되어, 퍼즐 전체 구도 또는 투사체 추적 구도로 보인다.

## 10.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: `Assets/02.System/00.Movement/00.Data/01.CameraMovement/CameraMode.cs`, `01.Logic/01.CameraMovement/Interface/ICameraFollowService.cs`, `Assets/02.System/99.Common/Input/IInputContext.cs`/`IInputContextManager.cs` 기존 코드)
- `CameraMode` (기존 enum) — **22번 기획서로 숄더뷰 하나로 고정**: `ThirdPersonShoulder=4`만 활성이고 나머지 멤버(`EventTargetTracking=6` 포함)는 `[Obsolete]` 호환용(값 보존). 이벤트 카메라는 모드가 아니라 `ICameraFollowService`의 오버라이드(`IsEventTargetOverrideActive`, `OnEventTargetOverrideChanged`, `SetEventTargetOverride(bool)`)다. **`FixedQuarterView`는 추가하지 않는다(정정, 사용자 확정 — 쿼터뷰 자체를 취소).**
- `InputContextType` (기존 enum, 값 확장) — 기존 `Player/Tactical/UI`에 `Event`(이벤트 카메라 전용 컨텍스트) 1개 값 추가.
- `EventCameraInputContext` (신규 클래스, `IInputContext` 구현) — 기존 `UIInputContext`와 동일한 구조(`ContextType => InputContextType.Event`, `TargetCursorLockMode`/`TargetCursorVisible`은 시네마틱 특성상 `CursorLockMode.Locked`/`false`로 설정해 유저가 커서로 다른 조작을 하지 못하게 한다).
- 이벤트 대상 계산 — `CameraFollowService`가 `IEventCameraLookTarget`(투사체 위치 `Vector3`만 노출, 구현 `EventProjectileLookTarget`이 09의 `IEventFlightTracker.ProjectilePosition`을 `LocomotionLifetimeScope.Start()`에서 사후 배선으로 공급)을 주입받아 `ICameraFollowService.TryGetEventCameraPose(playerPosition, out eye, out lookRotation)`가 이벤트 1인칭 카메라의 **눈 위치(= 플레이어 위치 + `PureDataCameraSetting.EventCameraEyeHeight`)와 시선(= 눈→이벤트 투사체(`IEventFlightTracker.ProjectilePosition`) 방향, 22번 §8·§10)**을 값으로 계산한다(`EventTargetTrackingCameraStrategy`와 임시 `IEventCameraTargetProvider`/`EventCameraTargetProvider`는 `99.Legacy/CameraStrategy/`로 격리). `CameraFollowVisualizer`가 오버라이드 ON 동안 매 프레임(Cinemachine Brain보다 먼저 도는 LateUpdate) 그 값을 **이벤트 전용 1인칭 vcam**(Follow/LookAt 없음, FOV = `EventCameraFieldOfView`)의 트랜스폼에 적용하고, 오버라이드 변경 이벤트에 맞춰 vcam 우선순위(숄더 100 < 이벤트 200)와 `CinemachineBrain.DefaultBlend`(= `EventCameraBlendTime`)를 바꿔 블렌드 전환한다. 이전 방식(숄더 피벗 yaw/pitch 역산, vcam 추적 댐핑 일시 해제, `EventTargetBlendWeight`, 시선각 Lerp, `SyncDisplayLookAngles`)은 이 구조에서 불필요해져 제거되었다. 플레이어 시선각(yaw/pitch)은 서비스가 계속 보유하고 이벤트 중에도 변경·스냅샷하지 않는다.

**데이터 가공/흐름 서술**
- **1단계에서는 아무 신호도 발생하지 않고 아무 것도 전환되지 않는다** — 유저가 평소처럼 `ThirdPersonShoulderCameraStrategy`(기존)를 직접 조작한다.
- 06번 시퀀서의 `OnBoss50Percent` 신호 수신 → 신규 Logic 클래스가 `cameraFollowService.SetEventTargetOverride(true)` + `inputContextManager.PushContext(new EventCameraInputContext())` 순서로 호출 → 기존 `CameraFollowService`가 마우스 입력을 처리하는 지점(`CameraFollowService.cs` 152~187행 부근, 기존에 `InputContextType.UI`/`InputContextType.Tactical`을 체크해 조기 반환하는 것과 동일한 위치)에 `InputContextType.Event` 조건을 추가로 체크해 조기 반환 → 마우스 회전/줌이 무시된다.
- 이벤트 카메라 종료 시(10.5가 이미 명시한 위험 — 시퀀서가 반드시 종료 신호를 짝지어 보내야 함): 신규 Logic 클래스가 `inputContextManager.PopContext(...)` + `cameraFollowService.SetEventTargetOverride(false)`를 호출한다 — 이벤트 vcam 우선순위가 내려가 Cinemachine 블렌드로 숄더 vcam에 복귀한다(플레이어 시선각은 이벤트 중 불변이라 이벤트 직전 시선 그대로). 유저 제어로 복귀한다.

**시청각 전달(UX) 서술**
- 10.4절 그대로: 3단계 진입/해제 시 숄더 ↔ 이벤트 1인칭 vcam Cinemachine 블렌드(`EventCameraBlendTime`) + 전환 사운드 — 몸 숨김·vcam 전환은 `CameraFollowVisualizer`가 수행하고, 이 문서는 "언제 오버라이드를 켜고 끌지"까지만 다룬다.

## 10.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 신규 기능 폴더가 아니라 **기존 `00.Movement`(카메라)/`99.Common`(입력 컨텍스트) 확장**이므로 3-2절의 신규 넘버링 규칙은 적용 대상이 아니다.

- **[D] 00.Data** — `Assets/02.System/00.Movement/00.Data/01.CameraMovement/CameraMode.cs`(기존 파일, enum 값 2개 추가), `Assets/02.System/99.Common/Input/IInputContext.cs`(기존 파일, `InputContextType.Event` 값 추가).
- **[L] 01.Logic** — `Assets/02.System/00.Movement/01.Logic/01.CameraMovement/CameraFollowService.cs`(기존 파일 확장, 마우스 입력 조기 반환 조건에 `InputContextType.Event` 추가, 22번 기획서로 이벤트 오버라이드 상태 + 이벤트 1인칭 카메라 눈 위치/시선 계산 포함; 22번 §10으로 `CameraFollowVisualizer`(`02.Visualizer/01.CameraMovement/`)가 이벤트 전용 1인칭 vcam 전환·몸 렌더 숨김을 담당). `EventTargetTrackingCameraStrategy.cs`는 22번 기획서로 `99.Legacy/CameraStrategy/`로 격리되었다(`FixedQuarterViewCameraStrategy.cs`는 만들지 않음/제거). 이벤트 구독 및 트리거 판정을 맡을 `EventCameraTriggerLogicSystem.cs`(신규, 순수 C#, 생성자 주입: `ICameraFollowService`, `IInputContextManager`, 06번 시퀀서가 노출하는 이벤트)를 같은 `01.CameraMovement/` 폴더에 추가 — **씬 진입 시 강제 모드 전환은 하지 않는다(정정).**
- **[V] 신규 시각 컴포넌트 없음** — `Assets/02.System/99.Common/Input/EventCameraInputContext.cs`(신규, `IInputContext` 구현체 — DLV상 Data/Logic 경계에 걸치는 상태 객체이나 기존 `UIInputContext`/`TacticalInputContext`와 동일 계층으로 분류해 `99.Common/Input/`에 위치).
- **미해결 의존성(확정 보류)**: `EventCameraTriggerLogicSystem`이 구독할 06번 시퀀서의 실제 이벤트 인터페이스(예: `OnStageChanged`/`OnBoss50Percent`를 어떤 DIP 인터페이스로 노출할지)는 06번 기획서가 구체 클래스(`TutorialSequencerLogicSystem`)만 정의하고 별도 인터페이스를 아직 정의하지 않아, 두 문서가 함께 구현 단계에서 맞춰야 한다.
- **기존에 이미 열려 있는 미해결 항목(이 보완 작업 범위 밖, 그대로 보존)**: 10.5의 "이벤트 카메라 종료 신호 누락 시 복귀 실패" 회귀 위험은 원문 그대로 유지 — 위 데이터 흐름에서 "반드시 종료 신호와 짝을 맞춰야 한다"는 전제로 서술했을 뿐, 안전장치(타임아웃 강제 복귀 등) 도입 여부는 이번 보완에서 임의로 확정하지 않는다.

# 6. 이벤트 시퀀서 시스템

> 분류: 신규 · 관련 단계: 전체(1~4단계)
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)
> 설계 방식 확정(세션 2): Timeline/비주얼 스크립팅/ScriptableObject 이벤트 채널을 검토했으나, 프로젝트가 이미 쓰는 **명시적 코드 상태 머신 + `event Action<T>` 방송** 패턴(`PlayerStateLogicSystem`과 동일한 결)을 그대로 따르기로 확정했다. 비교 근거는 [00_Overview.md](./00_Overview.md)의 "설계 확정 사항" 절 참고.
> 세션 3 논의로 구체화: 4단계 성공/실패 판정 로직을 구체적으로 정의(6.2절).
> 네이밍 수정(세션 4): 원래 "튜토리얼 이벤트 시퀀서"로 불렀으나, 이 시스템(상태 머신 + `event Action<T>` 방송 프레임워크) 자체는 튜토리얼 전용이 아니라 **다른 컷씬/스테이지/이벤트 연출에도 재사용해야 하는 범용 시스템**이라 이름에서 "튜토리얼"을 뺐다. 튜토리얼 1~4단계 진행은 이 범용 프레임워크 위에 얹는 "설정(구성)"일 뿐이며, [01.NPC전투액터공통프레임워크.md](./01.NPC전투액터공통프레임워크.md)(몸통)와 [02](./02.아군NPC전투지원행동시스템.md)/[03](./03.보스AI페이즈시퀀스시스템.md)(두뇌)의 관계와 동일한 구도다.

## 6.1 시스템 개요
여러 시스템(보스 AI, 아군 NPC, 카메라, 시간 정지 오버라이드 등)을 조건 기반으로 순차/조건부 진행시키고 이벤트로 방송하는 **범용 시퀀싱 프레임워크**다. 이 튜토리얼에서는 1~4단계 전체 진행(단계 전환, HP% 임계값 감지, 자동 시간정지/카메라 트리거, 실패-재도전 분기, 승리 화면 전환)을 총괄하는 용도로 쓰이지만, 프레임워크 자체는 특정 씬에 종속되지 않는다 — 이후 다른 컷씬/스테이지 연출에도 같은 상태 머신 방식을 재사용할 수 있다. 이런 시퀀싱 계층이 프로젝트에 없으면, 개별 시스템들이 서로를 직접 호출하는 강결합 구조가 되어버린다.

## 6.2 핵심 동작
- **구현 형태**: 각 사용처가 정의하는 Stage 열거형(이 튜토리얼에서는 `TutorialStage`: 1단계/2단계/3단계/4단계_성공/4단계_실패/승리)을 갖는 명시적 상태 머신. 상태 전환 조건을 코드로 명시하고, 전환 시 아래 신호를 `event Action<T>`로 방송(broadcast)한다 — 새 이벤트 프레임워크를 도입하지 않고 프로젝트 기존 관례를 그대로 재사용. `TutorialStage`는 이 튜토리얼 전용 구성일 뿐, 시퀀서 프레임워크 자체는 Stage 정의를 바꿔 다른 장면에도 재사용 가능하다.
- **트리거**: 씬 진입(1단계 시작), 보스 HP 임계값(50%) 도달, 4단계 명중 판정 결과, 처치 확정.
- **조건**: 각 단계 진입 조건(이전 단계 완료 여부)을 체크해 순차 진행. 실패 루프는 무한 반복 가능(성공할 때까지).
- **4단계 성공/실패 판정 로직(세션 3 확정)**: 시퀀서는 보스에 대한 피격 파이프라인이 발행하는 `HitContext`를 구독한다.
  - **성공(`OnCoreHitSuccess`)**: 대상이 이 보스 + 보스가 회복(무적) 페이즈 상태 + `HitContext`의 온도 속성 게이트 통과, 세 조건이 모두 만족될 때.
  - **실패(`OnCoreHitFail`)**: 회복 페이즈 중 속성 게이트를 통과하지 못한 피격이 들어오거나(피격 판정 O, 속성 게이트 X), 회복 페이즈 지속시간 동안 조건을 만족하는 피격이 한 번도 발행되지 않고 타임아웃되는 경우(완전히 빗나간 경우 포함).
  - 상세 조건 조합과 근거는 [05.광역상태이상빙결폭발시스템.md](./05.광역상태이상빙결폭발시스템.md) 5.2절 참고.
- **결과**: 아래 신호를 각 시스템에 방송한다.
  - `OnBoss50Percent` → [02.아군NPC전투지원행동시스템.md](./02.아군NPC전투지원행동시스템.md) 지원 사격 발사, [10.이동카메라시스템확장_이벤트타겟추적카메라.md](./10.이동카메라시스템확장_이벤트타겟추적카메라.md) 카메라 전환, [09.시간정지마법시스템확장_게이지오버라이드.md](./09.시간정지마법시스템확장_게이지오버라이드.md) 자동 시간 정지 발동, [08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md](./08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md) 마나/게이지 무제한 오버라이드 On
  - `OnCoreHitSuccess` → [05.광역상태이상빙결폭발시스템.md](./05.광역상태이상빙결폭발시스템.md) 발동, 오버라이드 Off, 승리 화면 전환
  - `OnCoreHitFail` → [03.보스AI페이즈시퀀스시스템.md](./03.보스AI페이즈시퀀스시스템.md) 체력 60% 회복, 오버라이드 Off, 아군 재발사 신호
- **중요 원칙(리뷰 반영)**: 자동 시간 정지 발동과 마나/게이지 무제한 오버라이드는 **이 시퀀서(혹은 시퀀서가 노출하는 전용 이벤트 API)를 통해서만** 트리거 가능해야 한다. 플레이어 입력이나 다른 임의 시스템이 직접 `ActivateSlow()`/오버라이드 API를 호출할 수 없도록 접근을 제한한다.

## 6.3 사용자 조작 흐름
이 시스템은 유저가 직접 조작하는 대상이 아니라, 유저의 결과(전투 진행, 명중/실패)를 관찰해 다른 시스템에 신호를 보내는 배경 로직이다. 유저 입장에서는 "내가 뭔가를 해내면 다음 장면이 자동으로 이어진다"는 흐름으로만 체감된다.

## 6.4 시각/청각 효과
이 시스템 자체는 시각 효과를 직접 그리지 않으며, 신호를 받은 각 시스템(카메라/시간정지/이펙트 시스템)이 실제 연출을 담당한다.

## 6.5 예외/실패 케이스
- 어떤 이유로든 단계 진행 조건이 충족되지 않은 채 다음 신호가 발생하면(예: 보스 HP 이벤트 중복 발행), 시퀀서는 이미 처리된 단계의 신호를 무시해 같은 연출이 중복 재생되지 않도록 한다.
- 4단계 실패 루프는 유저가 성공할 때까지 몇 번이고 반복되어야 하며, 반복 횟수에 따라 페널티가 누적되지 않아야 한다(기획서 상 "지루한 재전투 없이 즉각 재도전"이 명시적 요구사항).

## 6.6 체크리스트
- [ ] 보스 체력이 50%에 도달하는 순간, 유저가 아무 입력도 하지 않아도 카메라가 자동으로 아군 지원 투사체 쪽으로 전환되고 화면이 흑백 정지 필터로 바뀌며 시간 정지가 자동 발동된다.
- [ ] 3단계 자동 시간 정지 구간에서는 유저가 시간 정지나 마법을 아무리 사용해도 게이지·마나 바가 줄지 않고 항상 가득 찬 상태로 표시된다.
- [ ] 4단계에서 투사체 조작에 성공해 보스를 처치하면, 별도 조작 없이 몇 초 뒤 승리 화면으로 자동 전환된다.
- [ ] (예외) 4단계에서 투사체 조작에 실패하면, 시퀀서가 이를 감지해 보스 체력을 60%로 되돌리고 몇 초 내 재도전 연출을 자동으로 다시 시작한다.

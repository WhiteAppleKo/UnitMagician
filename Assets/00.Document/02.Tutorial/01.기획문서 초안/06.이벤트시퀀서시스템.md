## 6.1 시스템 개요
여러 시스템(보스 AI, 아군 NPC, 카메라, 시간 정지 오버라이드 등)을 조건 기반으로 순차/조건부 진행시키고 이벤트로 방송하는 **범용 시퀀싱 프레임워크**다. 이 튜토리얼에서는 1~4단계 전체 진행(단계 전환, HP% 임계값 감지, 자동 시간정지/카메라 트리거, 실패-재도전 분기, 승리 화면 전환)을 총괄하는 용도로 쓰이지만, 프레임워크 자체는 특정 씬에 종속되지 않는다 — 이후 다른 컷씬/스테이지 연출에도 같은 상태 머신 방식을 재사용할 수 있다. 이런 시퀀싱 계층이 프로젝트에 없으면, 개별 시스템들이 서로를 직접 호출하는 강결합 구조가 되어버린다.

## 6.2 핵심 동작
- **구현 형태**: 각 사용처가 정의하는 Stage 열거형(이 튜토리얼에서는 `TutorialStage`: 1단계/2단계/3단계/4단계_성공/4단계_실패/승리)을 갖는 명시적 상태 머신. 상태 전환 조건을 코드로 명시하고, 전환 시 아래 신호를 `event Action<T>`로 방송(broadcast)한다 — 새 이벤트 프레임워크를 도입하지 않고 프로젝트 기존 관례를 그대로 재사용. `TutorialStage`는 이 튜토리얼 전용 구성일 뿐, 시퀀서 프레임워크 자체는 Stage 정의를 바꿔 다른 장면에도 재사용 가능하다.
- **트리거**: 씬 진입(1단계 시작), 보스 HP 임계값(50%) 도달, 4단계 명중 판정 결과, 처치 확정.
- **조건**: 각 단계 진입 조건(이전 단계 완료 여부)을 체크해 순차 진행. 실패 루프는 무한 반복 가능(성공할 때까지).
- **4단계 성공/실패 판정 로직(세션 3 확정)**: 시퀀서는 보스에 대한 피격 파이프라인이 발행하는 `HitContext`를 구독한다.
  - **성공(`OnCoreHitSuccess`)**: 대상이 이 보스 + 보스가 회복(무적) 페이즈 상태 + `HitContext`의 온도 속성 게이트 통과, 세 조건이 모두 만족될 때.
  - **실패(`OnCoreHitFail`)**: 회복 페이즈 중 속성 게이트를 통과하지 못한 피격이 들어오거나(피격 판정 O, 속성 게이트 X), 회복 페이즈 지속시간 동안 조건을 만족하는 피격이 한 번도 발행되지 않고 타임아웃되는 경우(완전히 빗나간 경우 포함).
  - 상세 조건 조합과 근거는 [05.광역상태이상빙결폭발시스템.md](./05.광역상태이상빙결폭발시스템.md) 5.2절 참고.
- **결과**: 아래 신호를 각 시스템에 방송한다.
  - `OnBoss50Percent` → [02.아군NPC전투지원행동시스템.md](./02.아군NPC전투지원행동시스템.md) 지원 사격 발사, [10.이동카메라시스템확장_이벤트타겟추적카메라.md](./10.이동카메라시스템확장_이벤트타겟추적카메라.md) 카메라 전환, [09.시간정지마법시스템확장_게이지오버라이드.md](./09.시간정지마법시스템확장_게이지오버라이드.md) 자동 시간 정지 발동, [08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md](./08.캐릭터스탯상태시스템확장_무적플래그및오버라이드.md) 마나/게이지 무제한 오버라이드 On
  - `OnCoreHitSuccess` → [05.광역상태이상빙결폭발시스템.md](./05.광역상태이상빙결폭발시스템.md) 발동, 오버라이드 Off, 승리 화면 전환
  - `OnCoreHitFail` → [03.보스AI페이즈시퀀스시스템.md](./03.보스AI페이즈시퀀스시스템.md) 체력 60% 회복, 오버라이드 Off, 아군 재발사 신호
- **중요 원칙(리뷰 반영)**: 자동 시간 정지 발동과 마나/게이지 무제한 오버라이드는 **이 시퀀서(혹은 시퀀서가 노출하는 전용 이벤트 API)를 통해서만** 트리거 가능해야 한다. 플레이어 입력이나 다른 임의 시스템이 직접 `ActivateSlow()`/오버라이드 API를 호출할 수 없도록 접근을 제한한다.

## 6.3 사용자 조작 흐름
이 시스템은 유저가 직접 조작하는 대상이 아니라, 유저의 결과(전투 진행, 명중/실패)를 관찰해 다른 시스템에 신호를 보내는 배경 로직이다. 유저 입장에서는 "내가 뭔가를 해내면 다음 장면이 자동으로 이어진다"는 흐름으로만 체감된다.

## 6.4 시각/청각 효과
이 시스템 자체는 시각 효과를 직접 그리지 않으며, 신호를 받은 각 시스템(카메라/시간정지/이펙트 시스템)이 실제 연출을 담당한다.

## 6.5 예외/실패 케이스
- 어떤 이유로든 단계 진행 조건이 충족되지 않은 채 다음 신호가 발생하면(예: 보스 HP 이벤트 중복 발행), 시퀀서는 이미 처리된 단계의 신호를 무시해 같은 연출이 중복 재생되지 않도록 한다.
- 4단계 실패 루프는 유저가 성공할 때까지 몇 번이고 반복되어야 하며, 반복 횟수에 따라 페널티가 누적되지 않아야 한다(기획서 상 "지루한 재전투 없이 즉각 재도전"이 명시적 요구사항).

## 6.6 체크리스트
- [ ] 보스 체력이 50%에 도달하는 순간, 유저가 아무 입력도 하지 않아도 카메라가 자동으로 아군 지원 투사체 쪽으로 전환되고 화면이 흑백 정지 필터로 바뀌며 시간 정지가 자동 발동된다.
- [ ] 3단계 자동 시간 정지 구간에서는 유저가 시간 정지나 마법을 아무리 사용해도 게이지·마나 바가 줄지 않고 항상 가득 찬 상태로 표시된다.
- [ ] 4단계에서 투사체 조작에 성공해 보스를 처치하면, 별도 조작 없이 몇 초 뒤 승리 화면으로 자동 전환된다.
- [ ] (예외) 4단계에서 투사체 조작에 실패하면, 시퀀서가 이를 감지해 보스 체력을 60%로 되돌리고 몇 초 내 재도전 연출을 자동으로 다시 시작한다.
- [ ] (데이터 흐름 근거, 6.8) 보스의 `RuntimeStatData.HP.OnValueChanged`가 발행되어 → `TutorialSequencerLogicSystem`이 비율을 계산해 50% 최초 도달을 감지하면 → `RuntimeDataTutorialSequence.ChangeStage(Stage3)`가 호출되고 `OnBoss50Percent`가 방송되어 카메라/시간정지/오버라이드 3개 시스템이 동시에 연출을 시작한다.
- [ ] (데이터 흐름 근거, 6.8) `IInteractionService.OnDamageProcessed`로 전달된 `DamageContext`의 `Victim`이 보스이고 보스의 `RuntimeStatData.IsInvincible == true`인 상태에서 `DamageContext.Aborted == false`(속성 게이트 통과)이면 → `OnCoreHitSuccess`가 방송되고, `Aborted == true`이거나 회복 페이즈 시간 내 유효 피격이 없으면 → `OnCoreHitFail`이 방송된다.

## 6.7 작업 유형 분류
이 시스템은 **비시청각 영역**(Logic/Core)이다 — 6.4에서 명시했듯 이 시스템 자체는 화면에 아무것도 그리지 않고, 조건을 판정해 신호만 방송한다.
- 서술 공식: 여러 시스템(보스AI/아군NPC/카메라/시간정지/캐릭터스탯)이 서로를 직접 참조하지 않도록, 명시적 상태 머신(`TutorialStage` 전환) + `event Action<T>` 방송 패턴(`PlayerStateLogicSystem`과 동일한 구조)으로 구현하여, 신호 기반의 느슨한 결합 구조와 다른 씬에서도 재사용 가능한 프레임워크를 확보한다.

## 6.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: 6.2가 지정한 `Assets/02.System/02.CharacterSystem/00.Data/RuntimeDataPlayerState.cs` + `01.Logic/PlayerStateLogicSystem.cs` 패턴을 그대로 재사용, 신규 클래스이므로 코드 내 대응 필드는 없고 이 기존 패턴이 유일한 근거)
- `TutorialStage` (enum, 신규, 이 튜토리얼 전용 구성) — `Stage1 / Stage2 / Stage3 / Stage4Success / Stage4Fail / Victory`.
- `RuntimeDataTutorialSequence` (RuntimeData, 신규, `RuntimeDataPlayerState`와 동일한 구조) — private set 필드 `currentStage(TutorialStage)`, `previousStage(TutorialStage)`. 메서드 `ChangeStage(TutorialStage newStage)`(내부에서만 값 변경). 이벤트 `OnStageChanged(TutorialStage previous, TutorialStage next)`.
- `TutorialSequencerLogicSystem` (Logic, 신규, `PlayerStateLogicSystem`과 동일한 결) — 공개 이벤트 `event Action OnBoss50Percent`, `event Action OnCoreHitSuccess`, `event Action OnCoreHitFail`(6.2가 지정한 세 신호, 타입 파라미터 없음 — 구독자는 신호 발생 자체만 필요하고 별도 데이터 페이로드는 요구되지 않음).

**데이터 가공/흐름 서술**
- **50% 감지**: 보스의 `ICharacterStatService.RuntimeData.HP`(기존 `Assets/02.System/02.CharacterSystem/00.Data/RuntimeStatData.cs`의 `IReadOnlyClampValueInt HP`) → `OnValueChanged(current, max)` 구독 → `TutorialSequencerLogicSystem`이 `current / max <= 0.5f`를 최초로 만족하는 순간 감지 → `runtimeData.ChangeStage(TutorialStage.Stage3)` 호출 + `OnBoss50Percent` 방송(중복 방지: 이미 Stage3 이상이면 재판정 무시 — 6.5 예외 요구사항 그대로 구현).
- **4단계 성공/실패 판정**: `IInteractionService.OnDamageProcessed`(기존 `Assets/02.System/03.InteractionSystem/01.Logic/InteractionSystem.cs`가 이미 방송 중인 이벤트) → 전달되는 `DamageContext`(기존 `Assets/PipeLine/Contexts/DamageContext.cs`, 6.2/05번 문서가 말하는 "HitContext"의 실제 타입)를 구독 → `context.Victim`이 보스이고 `bossStatService.RuntimeData` 상의 `IsInvincible == true`(8번 기획서에서 신규 정의한 필드, 회복=무적 페이즈 판정에 재사용)인 동안만 판정 수행:
  - `context.Aborted == false`(속성 게이트 통과 — 기존 `AttributeGateStep`이 얼음 속성 피격에는 `Aborted`를 세우지 않으므로 이 값이 곧 "온도 속성 게이트 통과"를 의미) → `runtimeData.ChangeStage(TutorialStage.Stage4Success)` + `OnCoreHitSuccess` 방송.
  - `context.Aborted == true`(게이트 실패, 비-얼음 속성) 또는 회복 페이즈 지속시간 내 유효 피격이 한 번도 없이 타임아웃 → `runtimeData.ChangeStage(TutorialStage.Stage4Fail)` + `OnCoreHitFail` 방송. 타임아웃 판정은 `TutorialSequencerLogicSystem`이 `ITickable.Tick()`에서 회복 페이즈 진입 시점부터 경과 시간을 직접 카운트한다.
  - **정정(튜토리얼 씬 통합 조립 중 발견된 재도전 회귀 버그, 사용자가 이미 확정한 "재도전 시 매번 동일 번들 재트리거" 요구사항 위반)**: 위 두 실패 분기 모두 `ChangeStage(TutorialStage.Stage4Fail)` 이후 **`ChangeStage(TutorialStage.Stage2)`로 즉시 한 번 더 전환**해야 한다. `TutorialStage` enum 순서(`Stage1<Stage2<Stage3<Stage4Success<Stage4Fail<Victory`)상 `Stage4Fail`도 `>= Stage3`이라, 이렇게 되돌리지 않으면 `HandleBossHpChanged`의 "이미 Stage3 이상이면 재판정 안 함" 가드가 **영구적으로** 재도전 시의 자연스러운 HP 재하락(아군의 즉시 재발사 공격)을 무시해버려 `OnBoss50Percent`가 다시는 방송되지 않는다. `Stage2`로 되돌리면, 아군의 재발사 공격이 보스 HP를 다시 50% 이하로 내렸을 때 `HandleBossHpChanged`가 정상적으로 재감지해 `OnBoss50Percent`를 다시 방송하고, 03(보스AI)도 자신의 독립적인 50% 감지로 동일하게 재진입한다 — 별도의 인위적인 재방송 로직 없이 기존 자연 감지 경로가 그대로 재사용된다.

**시청각 전달(UX) 서술**
- 6.4절 그대로: 이 시스템 자체는 시각 효과를 직접 그리지 않는다. `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail` 신호를 구독하는 각 시스템(02/03/08/09/10번 기획서)이 카메라 전환, 시간정지 필터, 무적 이펙트, 승리 화면 등 실제 시청각 연출을 담당한다 — 이 시스템의 책임은 "언제 신호를 쏠지" 판정하는 것까지다.

## 6.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 신규 기능이다. `Assets/02.System/` 하위 기존 최대 번호가 `08.DestructibleSystem`이므로(코드_작업_기획서_가이드라인_v1.0.md 3-2절 규칙) 다음 번호로 배치한다 — **주의: 아래 "09"는 `Assets/02.System/` 구현 폴더 번호이며, 튜토리얼 기획 문서 번호 "9번(시간정지마법시스템확장)"과는 무관한 별개 체계다.**

```text
Assets/02.System/09.EventSequencerSystem/
├── EventSequencerSystemLifetimeScope.cs
├── 00.Data/
│   ├── TutorialStage.cs
│   ├── PureDataTutorialSequence.cs
```

> **6.9 정정(구현 착수 중 반영)**: 최초 작성 시 50% 임계값을 `current/max <= 0.5f` 리터럴 상수로 서술해 별도 SO 없이도 되는 것처럼 적었으나, 이 프로젝트의 다른 모든 시스템이 튜닝 가능한 수치를 하드코딩하지 않고 PureData(SO)로 노출하는 관례를 따르는 것과 일관되게, `PureDataTutorialSequence`(SO)에 `bossHpThresholdRatio`/`coreHitTimeoutSeconds`를 담기로 확정했다. 03번(보스AI)의 `PureDataBossPattern`이 아직 없어 그 값을 빌려올 수 없다는 실무적 이유도 있다 — 03번 구현 시점에 값 소유권을 재검토한다.
> **6.8 정정(구현 착수 중 발견)**: `IInteractionService`(인터페이스)에는 실제로 `OnDamageProcessed`가 선언돼 있지 않고 구체 클래스 `InteractionSystem`에만 있었다(기획서 6.8절 작성 시 인터페이스까지 직접 확인하지 않은 누락). 이 시스템 구현 착수 시점에 `IInteractionService.cs`에 `event Action<DamageContext> OnDamageProcessed;` 선언을 추가해 인터페이스로 노출했다(기존 구현체의 동작은 변경 없음, DIP 원칙에 맞게 인터페이스만 보완).

- **[D] 00.Data** — `TutorialStage.cs`(enum), `PureDataTutorialSequence.cs`(SO), `RuntimeDataTutorialSequence.cs`(RuntimeData) 신규 작성.
- **[L] 01.Logic** — `TutorialSequencerLogicSystem.cs` 신규 작성(순수 C#, `ITickable`+`IDisposable`, 생성자 주입으로 `RuntimeDataTutorialSequence`, 보스의 `ICharacterStatService`, `IInteractionService`를 받는다).
- **[V] 02.Visualizer 폴더 없음** — 6.4/6.8에서 명시했듯 이 시스템 자체는 시각 연출을 담당하지 않으므로 Visual 계층이 존재하지 않는 것이 정상이다(신호를 받는 각 시스템 쪽에 Visualizer가 위치).
- **보스 참조 방식(사용자 확인 완료)**: 이 튜토리얼 씬에는 보스가 유일하게 하나만 존재하므로, 별도의 태그/식별 인터페이스 없이 씬에 배치된 보스 GameObject의 `ICharacterStatService`를 인스펙터 고정 참조(또는 `RegisterComponentInHierarchy`로 유일한 인스턴스 등록) 방식으로 `TutorialSequencerLogicSystem`에 주입하면 충분하다. 여러 보스가 동시에 존재하는 시나리오에 대한 확장은 이번 튜토리얼 범위 밖이다.

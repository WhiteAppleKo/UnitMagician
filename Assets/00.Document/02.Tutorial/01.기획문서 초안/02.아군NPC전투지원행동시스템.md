# 2. 아군 NPC 전투 지원 행동 시스템

> 분류: 신규(얇은 배선) · 관련 단계: 1단계, 3단계
> 전체 개요/리뷰 반영 사항: [00_Overview.md](./00_Overview.md)
> 세션 2 논의로 재설계: 아군이 자체 타이머/타겟팅 AI를 갖는 게 아니라, [01.NPC전투액터공통프레임워크.md](./01.NPC전투액터공통프레임워크.md)의 `Attack(target)`을 [06.이벤트시퀀서시스템.md](./06.이벤트시퀀서시스템.md)가 호출해주는 방식으로 축소했다.

## 2.1 시스템 개요
1단계 퍼즐 구간(아군이 돌문에 일반 투사체를 주기적으로 발사)과 3단계 보스 50% 기믹(전장 밖 아군 진영의 지원 사격)에 등장하는 아군은, 별도의 "전투 지원 AI"를 갖지 않는다. 대신 01번 프레임워크의 `INpcCombatActor` 구현체로 씬에 배치되고, 언제 무엇을 공격할지는 이벤트 시퀀서가 지시한다. 이 문서는 "아군에게 무엇을 언제 시킬지"를 규정하는 얇은 설정/배선이며, 실제 발사·이동 실행은 01번 프레임워크가 전담한다.

## 2.2 핵심 동작
- 씬에는 아군 NPC 액터(01번 프레임워크의 구현체) 인스턴스가 배치되고, 발사 대상(1단계=돌문, 3단계=보스)은 씬 배치 시점에 인스펙터로 미리 고정 참조해둔다 — 이벤트 시퀀서가 매번 타겟을 계산할 필요가 없다.
- **1단계**: 씬 진입과 동시에 활성화되는 간단한 반복 타이머(3~4초 간격)가 `ally.Attack(stoneDoor)`를 반복 호출한다. 이 타이머는 이벤트 시퀀서의 조건부 로직이 아니라, 1단계 동안 항상 동작하는 단순 반복이므로 아군 액터 설정에 로컬로 둘 수 있다.
- **3단계**: 이벤트 시퀀서가 `OnBoss50Percent` 신호를 낼 때 `ally.Attack(boss)`를 1회 호출.
- **4단계 실패 시**: 이벤트 시퀀서가 `OnCoreHitFail` 신호를 받으면 `ally.Attack(boss)`를 즉시 재호출.

## 2.3 사용자 조작 흐름
1. 유저는 이 시스템을 직접 조작하지 않는다 — 관찰과 "개입 타이밍 포착"이 전부다.
2. (1단계) 아군이 투사체를 발사하는 주기를 관찰하다가, 원하는 타이밍에 시간 정지를 걸어 날아가는 투사체를 가로챈다.
3. (3단계) 보스 체력이 50%에 도달하는 순간 자동으로 카메라·시간정지가 개입되므로, 유저는 화면 전환에 맞춰 조준만 준비하면 된다.

## 2.4 시각/청각 효과
- 발사 시 아군 캐릭터의 시전 모션 + 발사 이펙트(빛 파티클), 발사음 — 01번 프레임워크의 실행 결과.
- 투사체가 돌문에 튕길 때: 스파크 파티클 + 타격음(문에는 흠집 없음).
- 3단계 지원 사격 시: 발사 지점 강조 라이팅 + 궤적 트레일 이펙트.

## 2.5 예외/실패 케이스
- 유저가 1단계에서 계속 개입하지 않으면, 아군은 투사체를 계속 반복 발사하며 돌문은 영원히 파괴되지 않는다(무한 대기 상태, 실패 아님 — 퍼즐이 유저를 기다림).
- 4단계 실패(투사체가 보스를 빗나감) 시, 이벤트 시퀀서 신호를 받아 수 초 내 즉시 재발사한다 — 재발사까지 유저가 아무 것도 못 하는 "죽은 시간"이 생기지 않아야 한다.

## 2.6 체크리스트
- [ ] 1단계 퍼즐 구간에 진입해 아무 조작도 하지 않으면, 아군 동료가 3~4초 간격으로 돌문을 향해 일반 투사체를 자동으로 발사하고, 문에 튕겨나가는 스파크 이펙트만 반복 재생된다.
- [ ] 보스 체력이 50%에 도달하면, 유저의 입력 없이도 전장 밖 아군 진영에서 지원 투사체가 자동으로 발사되며 궤적 트레일이 보스를 향해 이어진다.
- [ ] 4단계에서 조작 없이 투사체를 빗나가게 두면, 몇 초 뒤 아군이 새 투사체를 즉시 재발사해 재도전 기회를 다시 준다.
- [ ] (예외) 발사 목표(돌문)가 이미 파괴된 상태에서는, 아군이 더 이상 투사체를 발사하지 않고 대기 모션으로 전환된다.
- [ ] (데이터 흐름 근거, 2.8) 반복 타이머가 3~4초 경과를 감지하면 → `stoneDoorTarget`의 파괴 상태(`IsDestroyed`)를 확인 → false면 `INpcCombatActor.Attack(stoneDoorTarget)`을 호출해 01번 프레임워크의 시전 모션+발사 이펙트가 재생되고, true면 `Attack` 대신 `PlayMotion("Idle")`만 호출되어 아군이 더 이상 발사하지 않는다.

## 2.7 작업 유형 분류
분류 원문(2행)이 이미 "신규(얇은 배선)"으로 명시하고 있다 — 이 시스템은 **비시청각 영역**(Logic/Core)이다. 실제 시전 모션/발사 이펙트/타격음(2.4)은 이 시스템이 아니라 01번 프레임워크(`INpcCombatActor` 구현체)가 이미 담당하는 결과물이며, 이 문서는 "언제 무엇을 공격시킬지"만 판단한다.
- 서술 공식: 아군 개별 AI/타이머 로직을 새로 만들지 않고, 1단계는 로컬 반복 타이머로 `INpcCombatActor.Attack`을 주기 호출하고 3~4단계는 06번 시퀀서 신호 수신 시 동일 API를 호출하는 얇은 배선 로직으로 구현하여, 실행 로직(01번)과 트리거 판단(이 시스템)을 완전히 분리한다.

## 2.8 데이터 정의 및 흐름

**데이터 구조 정의** (근거: `Assets/02.System/07.NpcSystem/00.Data/INpcCombatActor.cs`의 기존 `Attack(GameObject target, PureDataUnit magic = null)` API, `Assets/02.System/08.DestructibleSystem/`의 기존 코드)
- 이 시스템은 **신규 RuntimeData/PureData를 두지 않는다** — 조작 대상의 실제 상태(HP, 파괴 여부, 이동/공격 실행)는 모두 01번 프레임워크(`INpcCombatActor`)와 04번 파괴가능오브젝트 시스템이 이미 소유하고 있으며, 이 시스템은 그 상태를 읽고 `Attack`을 호출하는 순수 배선 로직만 가진다.
- `AllySupportTriggerLogicSystem`(신규 Logic 클래스) 내부 상태: `elapsedSinceLastFire (float, private)` — 1단계 반복 타이머 경과 시간. `stoneDoorTarget(GameObject)`/`bossTarget(GameObject)` — 씬 배치 시 인스펙터로 고정 참조(2.2가 이미 요구).
- **확인된 의존성 갭 → 확정(사용자 승인 완료)**: 현재 `Assets/02.System/08.DestructibleSystem/`(01.Logic/DestructibleDoorLogicSystem.cs, 02.Visualizer/DestructibleDoorComponent.cs)에는 파괴 여부를 외부에서 조회할 수 있는 공개 프로퍼티가 없다(`PlayDestroy()`는 콜라이더만 비활성화할 뿐 GameObject를 파괴하지 않으므로 `target == null` 체크로는 감지 불가). `DestructibleDoorComponent`에 `bool IsDestroyed { get; }` 프로퍼티(또는 동등한 조회 수단) 추가가 확정되었다. **단, 이 프로퍼티 추가는 이미 구현이 끝난 04번 시스템의 실제 `.cs` 코드를 수정하는 작업이라, 이번(07번 Goal) 문서 전용 보완 범위 밖이다 — 실제 코드 반영은 별도의 명시적 `/goal` 지시로 진행해야 한다.**

**데이터 가공/흐름 서술**
- **1단계**: `AllySupportTriggerLogicSystem.Tick()`이 `elapsedSinceLastFire`를 누적 → 3~4초(임계값) 도달 시 `stoneDoorTarget`의 `IsDestroyed`(위 의존성 갭 해결 후 확보되는 프로퍼티)를 확인 → false면 `ally.Attack(stoneDoorTarget)` 호출 + `elapsedSinceLastFire` 리셋, true면 `Attack` 대신 `ally.PlayMotion("Idle")` 호출하고 타이머 자체를 정지(이후 재개하지 않음 — 2.5의 "돌문 파괴 후 대기 모션 전환"이 곧 최종 상태).
- **3단계**: 06번 시퀀서의 `OnBoss50Percent` 이벤트 구독 → 수신 시 `ally.Attack(bossTarget)` 1회 호출.
- **4단계 실패 시**: 06번 시퀀서의 `OnCoreHitFail` 이벤트 구독 → 수신 시 `ally.Attack(bossTarget)` 즉시 재호출.
- 실제 투사체 발사/이동/모션 재생은 모두 `INpcCombatActor` 구현체(01번, 이미 구현됨) 내부에서 처리되며, 이 시스템은 언제 `Attack`을 호출할지만 결정한다.

**시청각 전달(UX) 서술**
- 2.4절 그대로: 발사 시 시전 모션+발사 이펙트+발사음, 돌문 피격 시 스파크+타격음, 3단계 발사 시 강조 라이팅+궤적 트레일 — 전부 01번 프레임워크의 기존 실행 경로(`INpcCombatActor.Attack` → `OnAttackExecuted` 이벤트 → 비주얼라이저)가 그대로 재생하며, 이 시스템은 신규 시청각 코드를 추가하지 않는다.

## 2.9 DLV 적용 방안 (실제 폴더 경로)

이 시스템은 "신규(얇은 배선)"으로 분류되어 신규 기능 폴더가 필요하다(3-2절 규칙 적용 대상).

```text
Assets/02.System/10.AllySupportSystem/
├── AllySupportSystemLifetimeScope.cs
└── 01.Logic/
    └── AllySupportTriggerLogicSystem.cs
```

- **[D] 00.Data 폴더 없음** — 위에서 명시했듯 신규 데이터 정의가 없어 00.Data 폴더 자체가 불필요하다(정상적인 케이스).
- **[L] 01.Logic** — `AllySupportTriggerLogicSystem.cs`(신규, 순수 C#, `ITickable`+`IDisposable`, 생성자 주입: `INpcCombatActor ally`, `GameObject stoneDoorTarget`, `GameObject bossTarget`, 06번 시퀀서 이벤트).
- **[V] 02.Visualizer 폴더 없음** — 실행/시청각은 전부 01번 프레임워크 담당(위 참고), 이 시스템 자체의 Visualizer는 없다.
- **번호 관련 주의**: 위 "10"은 이 문서 작성 시점 기준 예상 번호(06번 문서가 먼저 "09"를 배정받았다는 전제)이며, 실제 구현 착수 시점에 `Assets/02.System/` 디스크 상태를 다시 확인해 최종 번호를 확정해야 한다(3-2절 "기존 최대 번호+1" 규칙 그대로 적용). 이 번호는 튜토리얼 기획 문서 번호 체계와 무관한 별개의 구현 폴더 번호다.

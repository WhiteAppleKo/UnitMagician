# 14. 필드 아이템 습득 시스템 — 다크소울식 바닥 아이템 줍기

> 분류: 신규 기능(`13.PickupSystem` 신규 폴더) + 기존 확장(`01.UnitSystem`의 `IUnitCatalogService.AcquireUnit` 호출부, `InputReader`, UI 프롬프트)
> 배경(세션 11 확정): 11번 기획서에서 마법을 "아이템처럼 습득 → 장착해서 사용"하는 다크소울3 방식으로 바꿨지만, **실제 습득 트리거(바닥 아이템 줍기)는 범위 밖**으로 두었고 지금은 숫자키 테스트 컴포넌트(`UnitDebugAcquireTestComponent`)가 대신하고 있다. 튜토리얼은 얼음(온도)·크기 확대(질량) 마법을 얻어야 진행되므로, 플레이어가 이 마법들을 얻는 정식 경로가 필요하다.
> **사용자 확정 사항(세션 11)**:
> - 마법은 **바닥에 떨어져 있는 아이템을 주워서** 얻는다(다크소울 시리즈 방식).
> - 바닥 아이템은 **서로 구분될 필요가 없다.** 모든 습득 아이템이 같은 모습이며, 무엇을 얻었는지는 줍고 나서 습득 팝업으로 알게 된다.
> - 튜토리얼의 목표는 **보스 사망 연출까지**다. 승리 화면/씬 전환은 필요 없다(→ 02.예상플레이흐름의 "승리 화면 미구현" 항목은 범위 제외로 정리).
> **기본값으로 정한 것(구현 시 조정 가능, 사용자가 별도 지시하지 않는 한 다크소울3 레퍼런스를 따른다)**: 아이템에 가까이 가면 줍기 프롬프트가 뜨고 **키를 눌러서** 줍는다(키는 임시로 `E`). 줍는다고 자동 장착되지 않는다 — 11번 기획서대로 습득(소유)과 장착은 별개이며 인벤토리(`I`)에서 장착한다.

---

## 1. 작업 개요 및 작업 유형 분류
**혼합형**이다.
- 비시청각: 플레이어 주변의 줍기 가능 아이템 중 가장 가까운 것을 판정하고, 입력 시 해당 `PureDataUnit`을 `IUnitCatalogService.AcquireUnit`으로 습득시키고 아이템을 소비하는 로직. 줍기가 허용되는 입력 컨텍스트 판정.
- 시청각: 줍기 가능 거리에 들어오면 "[E] 줍기" 프롬프트 표시, 줍는 순간 아이템이 사라지고 기존 습득 팝업("Unit Acquired: 이름")이 뜸. 바닥 아이템은 모두 동일한 외형.

## 2. 유형별 핵심 요구사항
- 서술 공식(비시청각): 씬에 배치된 줍기 아이템을 `IPickupTarget` 인터페이스로 추상화하고, 플레이어 근접 판정 결과를 `RuntimeDataPickupFocus`에 담아 로직이 입력 시 습득을 처리하게 해, 아이템 종류가 늘어나도 로직 변경 없이 `PureDataUnit` 참조만 바꿔 배치할 수 있게 한다.
- 사용자 조작 결과(시청각): 유저가 바닥 아이템에 다가가면 줍기 프롬프트가 나타나고 키를 누르면 아이템이 사라지며 습득 팝업이 뜬다. 이후 인벤토리(`I`)를 열면 그 마법이 "미장착"으로 보이고, 클릭해서 장착하면 사용할 수 있다.

## 3. 데이터 정의 및 흐름

**데이터 구조 정의**
- `PickupItemData`(PureData 성격, 아이템 한 개의 인스펙터 데이터 — 별도 SO 없이 `PickupItemComponent`의 직렬화 필드로 충분하면 그렇게 한다): `PureDataUnit GrantedUnit`(이 아이템을 주우면 습득하는 마법).
- `RuntimeDataPickupFocus`(신규, `00.Data/`, 순수 C#): `IPickupTarget CurrentTarget`(현재 줍기 가능 범위 안에서 가장 가까운 아이템, 없으면 null), 변경 시 `OnFocusChanged(IPickupTarget)` 이벤트.
- `IPickupTarget`(신규 인터페이스, `02.Visualizer/` 또는 `00.Data/` 구현 시 위치 결정): `PureDataUnit GrantedUnit { get; }`, `Vector3 Position { get; }`, `void Consume()`(주운 뒤 아이템을 소비(비활성화/제거)).
- `IUnitCatalogService`(기존): `AcquireUnit(PureDataUnit)`, `IsPossessed(PureDataUnit)` 호출 — 변경 없음. 기존 `OnUnitAcquired` → `UnitUnlockPopupUIComponent`("Unit Acquired: …") 연결 그대로 재사용.
- `InputReader`(기존 파일): `public Action onInteractPressed;` 추가, `Update()`에서 임시 키(`E`) `wasPressedThisFrame` 시 발행(`I`/`T`/`Esc` 폴링과 같은 패턴).

**데이터 가공/흐름 서술**
- **근접 판정**: 플레이어 기준 일정 반경(조정 가능) 안의 `IPickupTarget` 중 가장 가까운 것을 매 프레임(또는 일정 주기) 구해 `RuntimeDataPickupFocus.CurrentTarget`에 반영한다. **이미 소유한 마법의 아이템은 줍기 가능 대상에서 제외**한다(아이템은 그대로 남고 프롬프트도 뜨지 않음).
- **줍기**: `onInteractPressed` 수신 → `PickupLogicSystem`이 (1) 입력 컨텍스트가 일반 플레이(`Player`)일 때만 허용(`Tactical`/`UI`/`Event` 컨텍스트에서는 무시 — 시간정지, 메뉴, 이벤트 연출 중에는 줍지 못함), (2) `CurrentTarget != null`이고 `!IsPossessed(GrantedUnit)`이면 `AcquireUnit(GrantedUnit)` 호출 → `target.Consume()`.
- **연결**: `AcquireUnit`이 `OnUnitAcquired`를 발행하면 기존 `UnitUnlockPopupUIComponent`가 습득 팝업을 띄우고 인벤토리 UI가 갱신된다(신규 코드 없음).
- **장착은 하지 않는다**: 습득 후 `IsEquipped == false`. 유저가 인벤토리에서 직접 장착한다(11번 기획서 그대로).

**시청각 전달(UX) 서술**
- 줍기 프롬프트: 화면 하단 중앙에 "[E] 줍기" 한 줄(`CurrentTarget`이 있을 때만 표시, `OnFocusChanged` 구독). 신규 UI 컴포넌트(UI Toolkit).
- 바닥 아이템: **모든 아이템이 같은 모습**(다크소울의 발광 구체처럼 공통 외형, 종류별 구분 없음). 외형(프리팹/이펙트)은 하나만 만든다.
- 줍는 순간 아이템이 사라지고(연출은 단순 비활성화로 충분) 습득 팝업이 뜬다.

## 4. DLV 적용 방안 (실제 폴더 경로) — 신규 기능 폴더
`Assets/02.System/` 기존 최대 번호가 `12.AreaFreezeSystem`이므로 새 폴더는 **`13.PickupSystem`**이다.
```text
13.PickupSystem/
├── PickupSystemLifetimeScope.cs        # 루트 바로 아래
├── 00.Data/        RuntimeDataPickupFocus.cs
├── 01.Logic/       PickupLogicSystem.cs (순수 C#, IInitializable/IDisposable/ITickable), IPickupFocusService 등 필요한 인터페이스
├── 02.Visualizer/  IPickupTarget.cs, PickupItemComponent.cs(씬 아이템), PickupDetectorComponent.cs(플레이어 근접 판정), PickupPromptUIComponent.cs + UXML(줍기 프롬프트)
└── 99.Legacy/      (기존 코드 없음 — 필요 시 생성)
```
- **기존 파일 수정**: `Assets/Synty/AnimationBaseLocomotion/Samples/Scripts/InputSystem/InputReader.cs`(`onInteractPressed` 추가). `UnitSystem` 쪽은 기존 `UnitUnlockPopupUIComponent`/`UnitInventoryUIComponent`를 변경하지 않는다(`UnitDebugAcquireTestComponent`는 유지, 테스트 전용).
- **크로스 스코프**: `PickupLogicSystem`은 `IUnitCatalogService`(`01.UnitSystem`)와 `IInputContextManager`(`99.Common`)가 필요하다. 스코프 트리 관계를 확인해 직접 주입이 되면 그대로, 안 되면 기존 패턴(인스펙터 직접 참조 + `Start()` 사후 `BindXxx`)을 재사용한다. `GameObject.Find`/`FindObjectOfType` 금지, 구체 클래스 주입 금지(인터페이스 경유).
- **씬 배치**: `00.TestScene`(또는 튜토리얼 씬)의 시작 지점 근처에 얼음(Temperature)·크기 확대(Mass) 마법 `PureDataUnit`을 부여하는 `PickupItemComponent` 오브젝트를 배치한다(1단계 퍼즐 전에 두 마법을 얻을 수 있어야 함). 실제 레벨 배치는 대역 위치로 충분.

## 5. 예상 검수 방법 (체크리스트는 §3 데이터 흐름 근거)
- [ ] 플레이어가 줍기 아이템 반경 안으로 들어가면 "[E] 줍기" 프롬프트가 나타나고, 반경 밖으로 나가면 사라진다. 아이템이 여러 개면 가장 가까운 것이 대상이 된다.
- [ ] 일반 플레이 컨텍스트에서 `E`를 누르면 해당 `PureDataUnit`이 `IsPossessed == true`가 되고(`IsEquipped`는 false), 아이템이 사라지며, 기존 습득 팝업("Unit Acquired: …")이 뜨고, 인벤토리(`I`)에 "미장착"으로 나타난다.
- [ ] 이미 소유한 마법의 아이템에는 프롬프트가 뜨지 않고 줍기가 일어나지 않는다(아이템은 그대로 남음).
- [ ] 시간정지(`Tactical`), 인벤토리/옵션 메뉴(`UI`), 이벤트 연출(`Event`) 컨텍스트에서는 `E`를 눌러도 줍지 않는다.
- [ ] 모든 바닥 아이템이 같은 외형이다(종류 구분 없음).
- [ ] 얼음·크기 확대 두 마법을 주워 장착하면 1단계 퍼즐(온도 인챈트 → 크기 확대)을 진행할 수 있다(기존 시전 흐름 회귀 없음).
- [ ] 기존 숫자키 테스트 습득, 인벤토리 장착/해제, 시간정지 선택 팝업에 회귀가 없다.
- [ ] 신규 코드가 DLV/VContainer 규칙을 위반하지 않는다.

## 6. 이번 작업 범위 밖 (확정하지 않음, 임의로 채우지 않음)
- 튜토리얼 조작 안내 UI(예: "습득 후 `I`로 장착하세요" 같은 가이드) — 별도 논의(11번 구조상 습득해도 장착해야 쓸 수 있어 안내가 필요할 가능성이 큼).
- 줍기 키의 최종 확정(`E`는 임시), 아이템 외형/이펙트/효과음 디테일, 습득 연출.
- 아이템 재생성(리스폰), 저장/불러오기에서의 습득 상태 유지.
- 아이템 수량/스택, 마법 외 다른 종류의 아이템(소모품 등).

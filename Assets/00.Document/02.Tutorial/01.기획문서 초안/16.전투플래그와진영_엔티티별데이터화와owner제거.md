# 16. 전투 플래그·진영 엔티티별 데이터화 + `owner` 제거 (기획서 초안)

> 작성일: 2026-10-07 · 상태: **확정 사항 반영 완료, Goal 프롬프트 작성 대기** (코드/에셋 수정 없음. 시작은 `/goal` 지시 후)
> 형식: `코드_작업_기획서_가이드라인_v1.0.md`(3-1 데이터 정의 및 흐름, 3-2 폴더 구조)
> 선행/관련: **Goal 30(`30.Goal프롬프트_크리티컬스텝비사용.md`)** — 크리티컬을 끄는 임시 조치(상수 `DefaultAttackFlags = None`). 이 문서가 구현되면 그 상수는 **사라진다**(엔티티가 자기 플래그를 들고 있게 되므로). 9/18 설계(`리팩토링/18.공격피격파이프라인_분리_리팩토링_Goal프롬프트.md`)의 "공격자/피격자가 각자 플래그를 들고 `ResolveAttackSteps(attacker.CurrentAttackFlags)`/`ResolveHitSteps(victim.CurrentHitFlags)`로 스텝을 정한다"를 실제로 완성하는 작업이다.
> 사용자 확정 사항(세션 12): ① 플래그는 **인스펙터에서 캐릭터별로** 설정한다(하드코딩 상수 폐기). ② 투사체는 **독자적인 공격 컨텍스트**(발사 시 발사자의 공격 플래그를 받아 보관, 마법으로 중간에 변형 가능)를 가진다. ③ 공격 파이프라인은 **충돌 시점에 투사체가 들고 있는 플래그로** 실행한다. ④ `DamageContext.Attacker`의 의미는 **발사자**로 정의한다. ⑤ `owner` 개념은 **제거**한다. ⑥ 충돌 무시는 **진영(FactionType) 기준**으로 만든다. ⑦ **적 투사체를 빼앗는 경우가 있어야 하므로 마법으로 투사체의 진영이 바뀐다.** ⑧ **같은 편 통과는 "충돌 판정 자체를 없애는" 방식(레이어 충돌 매트릭스)으로 구현한다.** 기존 충돌 무시 로직 3종(`CollisionDamageTrigger`의 owner 기반 무시, `UnitChangeService`의 owner 강탈, `EventFlightTrackerComponent`의 `ignorePlayerCollision`)은 목적이 사라지므로 **삭제**한다.

## 1. 작업 개요 및 유형 분류
- **비시청각 영역(Pure Data / Logic / Core System)**. 시청각 변화는 부수 효과로만 나타난다(§3-3).
- 해결하려는 문제
  1. `InteractionSystem.DefaultAttackFlags/DefaultHitFlags`가 하드코딩 상수라 캐릭터별로 다른 공격/피격 스텝을 줄 수 없다(`FlagRefCounter`/`CombatFlagState`는 만들어만 두고 배선되지 않았다).
  2. 투사체의 `owner`가 ① 공격 주체 표시 ② 자기 몸 충돌 제외 ③ 마법 소유권 강탈(`UnitChangeService.UpdateCollisionTriggerOwner`가 owner를 시전자로 교체, 그 부수 효과로 플레이어를 무시)을 한꺼번에 맡고 있다. 마법을 건 순간의 owner로 충돌 시점에 `Attacker`를 읽으므로 공격자 플래그를 읽으면 엉뚱한 주체의 값이 된다.
  3. 같은 편 판정이 없다. 마법을 안 건 아군 샷이 플레이어를 맞힌다(60/90 데미지 관찰). 돌문 같은 비캐릭터 대상은 진영 자체가 없다.
  4. "같은 편 통과"를 흉내 내는 충돌 무시 로직이 **서로 모르는 세 군데**에 따로 있다: ① `CollisionDamageTrigger`의 `IgnoreOwnerCollisions`/`ignoredOwners`/`IsOwnerOrRelative`(발사자 몸체 제외), ② `UnitChangeService.UpdateCollisionTriggerOwner`(owner 강탈의 부수 효과로 플레이어 무시), ③ `EventFlightTrackerComponent.ignorePlayerCollision`(3단계 이벤트 투사체만 플레이어와 `Physics.IgnoreCollision` 쌍을 걸고 종료 때 풀어 줌). 이벤트가 아닌 아군 샷은 이 셋 어디에도 해당하지 않아 플레이어를 맞힌다.

## 2. 핵심 요구사항 (비시청각: 구현 수단 + 목표 한 문장)
1. 공격/피격 파이프라인 플래그를 PureData(인스펙터)와 런타임 `CombatFlagState`로 엔티티별로 보유하게 하여, 캐릭터·NPC·돌문·투사체가 각자 다른 스텝 조합을 쓰게 하고 `InteractionSystem`의 상수를 제거한다.
2. 투사체가 발사 시점에 발사자의 공격 플래그·진영·발사자를 받아 독자적인 공격 상태로 보관하고(마법이 중간에 바꿀 수 있게), 충돌 시 그 값으로 `DamageContext`를 만들어 공격 파이프라인을 실행하게 하여 마법 소유권 변화와 무관하게 공격 계산이 일관되게 한다.
3. `owner` 필드와 소유권 강탈(`UpdateCollisionTriggerOwner`)을 제거하고 `Attacker`(발사자)와 진영으로 역할을 분리하여 "공격 주체 / 자기 몸 충돌 / 같은 편 무시"가 한 규칙(`FactionRelation`)으로 설명되게 한다.
4. 진영을 레이어(충돌 매트릭스)로 변환해 같은 편 사이의 물리 충돌 자체를 제거하고 기존 충돌 무시 로직 3종을 삭제하여, 같은 편 투사체가 맞지도 튕기지도 않고 통과하게 하고(아군 샷이 플레이어를 맞히는 문제와 3단계 투사체가 플레이어를 지나쳐야 하는 요구를 한 규칙으로 해결) 충돌 무시 규칙의 출처를 `FactionRelation` 하나로 일원화한다.
5. 마법으로 투사체의 진영을 시전자 진영으로 바꿀 수 있게 하여 적 투사체를 빼앗는 기능을 정식 규칙으로 만든다.

## 3. 데이터 정의 및 흐름

### 3-1. 데이터 정의 (필드 단위)

**기존(변경 없음)**
- `FactionType`(enum): `Player=0, Enemy=1, Neutral=2, Ally=3` — `02.CharacterSystem/00.Data/FactionType.cs`
- `AttackStepFlags`(Flags): `Critical` — **Critical 비트/스텝은 코드에 남기되 어떤 엔티티도 켜지 않는다**(Goal 30). `HitStepFlags`(Flags): `Evasion`, `Defense`, `AttributeGate`.
- `FlagRefCounter<T>`/`CombatFlagState`(`PipeLine/Combat`): 기본 플래그 + 추가/제외 참조 카운터. **이번에 처음 실제로 배선한다.**

**신규/확장 — PureData (인스펙터 설정)**
| 데이터 | 필드 | 타입 | 의미 |
|---|---|---|---|
| `PureStatData`(캐릭터) | `defaultAttackFlags` | `AttackStepFlags` | 이 캐릭터가 공격할 때 쓰는 공격 스텝 기본값(기본 `None`) |
| | `defaultHitFlags` | `HitStepFlags` | 이 캐릭터가 맞을 때 쓰는 피격 스텝 기본값(기본 `Evasion | Defense`, 기존 동작 유지) |
| | `defaultFaction` | `FactionType` | **기존 필드 그대로** |
| **모든 NPC(아군/중립/보스)** | — | — | **NPC는 예외 없이 `CharacterStatComponent` + `PureStatData`를 가진다(사용자 확정). 진영/공격·피격 플래그의 출처는 이 `PureStatData` 하나뿐이다.** `PureDataNpcActor`에는 진영/플래그를 두지 않는다. 아군 NPC의 `defaultFaction = Ally`, 상인 같은 NPC는 `Neutral`(기본 중립), 보스 `Enemy` |
| `PureDataDestructibleDoor`(돌문) | `faction` | `FactionType` | 돌문 진영(`Neutral` — 누구에게나 피격 대상) |
| | `hitFlags` | `HitStepFlags` | 돌문 피격 스텝(`AttributeGate`) — 현재 컴포넌트가 코드로 반환하는 값을 데이터로 이동 |

**신규/확장 — RuntimeData / 컴포넌트 상태**
| 데이터 | 필드 | 타입 | 의미 |
|---|---|---|---|
| `RuntimeStatData`(캐릭터) | `combatFlags` | `CombatFlagState` | PureData 기본값으로 초기화. 버프/페이즈가 Add/Suppress로 비트를 켜고 끔. `CurrentFaction`(기존)은 런타임 진영 |
| 투사체 공격 상태(`CollisionDamageTrigger` 보관) | `attacker` | `GameObject` | **발사자**(발사 시 1회 확정, 마법이 바꾸지 않음) |
| | `faction` | `FactionType` | 투사체 현재 진영(발사 시 발사자 진영으로 초기화, **마법으로 변경 가능**) |
| | `attackFlags` | `CombatFlagState` | 투사체가 들고 있는 공격 플래그(발사 시 발사자의 값으로 초기화, 마법이 Add/Suppress 가능) |
| | `baseDamage`(기존), `accuracyRate`(기존) | | 기존 그대로 |
| `NpcProjectileLaunchData`(발사 설정) | `Owner` → **`Attacker`**(이름 변경), `+ AttackFlags`, `+ Faction` | | 발사 시 발사자에게서 읽어 담는다 |

**신규 인터페이스 (`Assets/PipeLine/Combat/`, 기존 `IHitStepFlagsProvider`와 같은 패턴)**
- `IAttackStepFlagsProvider { AttackStepFlags CurrentAttackFlags { get; } }` — 공격자 쪽(캐릭터, NPC)
- `IFactionProvider { FactionType Faction { get; } }` — 캐릭터, NPC, 돌문, 투사체 모두
- (피격 쪽 `IHitStepFlagsProvider`는 기존 그대로, 구현체만 데이터에서 읽도록 변경)

**규칙표 (한 곳, `Assets/PipeLine/Combat/FactionRelation.cs` — 정적 순수 C#)**
- 편(side): `{Player, Ally}` = 아군편, `{Enemy}` = 적편, `Neutral` = 편 없음.
- `IsSameSide(a, b)` = 둘 다 `Neutral`이 아니고 같은 편 → **충돌 없음**(아래 레이어 매트릭스로 구현).
- `IsHostile(a, b)` = 둘 다 `Neutral`이 아니고 다른 편. (`RuntimeStatData.IsHostile`은 이 규칙을 **호출만** 한다 — 같은 규칙을 두 번 쓰지 않는다.)
- `Neutral`(돌문 등)은 어떤 투사체에게나 **피격 대상**이다.

**레이어 데이터 (프로젝트 설정 `ProjectSettings/TagManager.asset`에 신규 정의 — 이름 없는 3번 레이어는 씬 오브젝트 5개가 이미 쓰므로 피하고 8번 이후 사용)**
| 레이어 | 대상 | 같은 편 충돌 |
|---|---|---|
| `BodyAlly` | 아군편 몸체(`Player`, `Ally` 캐릭터의 루트+모든 자식 콜라이더) | — |
| `BodyEnemy` | 적편 몸체(`Enemy`) | — |
| `AttackAlly` | 진영이 `Player`/`Ally`인 투사체 | **`BodyAlly`와 충돌 없음**, `BodyEnemy`/`Default`와는 충돌 |
| `AttackEnemy` | 진영이 `Enemy`인 투사체 | **`BodyEnemy`와 충돌 없음**, `BodyAlly`/`Default`와는 충돌 |
- `Neutral` 진영(돌문, 중립 NPC)과 `Neutral` 투사체는 **`Default` 그대로**다(누구와도 충돌 — `Neutral`은 항상 피격 대상 규칙을 레이어 없이 자연히 만족). **(16-D에서 변경, §6-2)**: 중립 캐릭터 몸체는 `BodyNeutral`, `Neutral` 진영 공격 판정체는 `AttackNeutral`이며 `AttackNeutral`↔`BodyNeutral`만 충돌이 꺼진다. 돌문 등 비캐릭터 오브젝트는 진영이 `Neutral`이어도 `Default`를 유지한다.
- 충돌 매트릭스 중 바뀌는 쌍은 위 표의 "충돌 없음" 두 쌍뿐이다. **몸체끼리(플레이어↔아군 NPC↔보스), 투사체끼리, 투사체↔`Default`(벽/지면/돌문)는 현재와 동일하게 충돌한다**(아군 NPC가 몸으로 길을 막는 연출이 가능해야 하고, 투사체가 돌문/벽에서 튕겨야 하므로).
- 편→레이어 변환과 매트릭스 설정은 `FactionRelation`(편 정의)을 출처로 **코드가 시작 시 한 번 설정**한다(`Physics.IgnoreLayerCollision`). 프로젝트 설정의 매트릭스를 손으로 맞추지 않는다 — 규칙이 코드와 설정 두 곳으로 갈라지지 않게 하기 위함.

### 3-2. 데이터 가공/흐름

**발사 → 보관**
1. `ProjectileAttackBehaviorSO.Execute`가 발사자(`visualizer.Owner`에서 `IAttackStepFlagsProvider`/`IFactionProvider`를 읽어) `NpcProjectileLaunchData(Attacker, AttackFlags, Faction, ...)`를 만든다. provider가 없으면 공격 플래그 `None`, 진영 `Neutral`.
2. 풀에서 꺼낼 때(`NpcProjectile.Setting/SetActive`) 투사체의 `attacker/faction/attackFlags`를 발사 설정 값으로 **완전히 초기화**한다(이전 사용 때 마법으로 바꾼 진영/플래그 잔존 금지 — 15-B 풀링 초기화 규칙과 동일).

**마법으로 변형**
3. 마법 시전(`UnitChangeService`)은 단위 값(온도/질량 등)을 바꾸는 기존 동작을 유지하고, `UpdateCollisionTriggerOwner` 대신 **`ApplyCasterFaction`**: 시전자의 `IFactionProvider.Faction`을 대상 투사체의 `faction`에 설정한다(적 투사체를 빼앗는 규칙). `attacker`(발사자)는 **바꾸지 않는다**. 필요 시 투사체의 `attackFlags`에 비트를 Add/Suppress할 수 있는 경로는 열어 두되 이번 작업에서 쓰는 마법은 없다.
4. 진영이 바뀌면 **레이어도 같이 바뀐다**: 투사체 진영 변경(마법) 시 투사체와 모든 자식 콜라이더의 레이어를 새 진영의 투사체 레이어로, 캐릭터 진영 변경(`RuntimeStatData.OnFactionChanged`, 예: 중립 NPC의 적대화) 시 몸체 레이어를 새 진영의 몸체 레이어로 **재귀 적용**한다. 따로 풀어 줄 충돌 쌍이 없으므로 적→플레이어편으로 넘어온 투사체는 원래 발사자(적)와 자연히 충돌한다.

**충돌 → 판정**
5. **충돌 자체가 레이어에서 걸러진다.** 같은 편 투사체는 접촉 이벤트(`OnCollisionEnter`/`OnTriggerEnter`)가 오지 않고 물리적으로도 통과한다. 따라서 `CollisionDamageTrigger.HandleCollision`에는 같은 편 판정이 **없다**: 기존 레이어 마스크 검사(`targetLayer`) → `IDamageable` 검사 → 쓰러진 대상 통과 → 쿨타임 → 판정 진입만 남는다(`IsOwnerOrRelative`, `ignoredOwners`, `IgnoreOwnerCollisions` 삭제).

**삭제되는 기존 충돌 무시 로직 (목적이 사라짐)**
5-1. `CollisionDamageTrigger`의 `IgnoreOwnerCollisions`/`ignoredOwners`/`IsOwnerOrRelative`/`OnReturnedToPool`의 충돌 쌍 해제, `UnitChangeService.UpdateCollisionTriggerOwner`, `EventFlightTrackerComponent`의 `ignorePlayerCollision`(필드, `HandleProjectileSpawned`의 쌍 설정, `RestorePlayerCollision`, 씬 직렬화 값 `ignorePlayerCollision: 1`). 쌍을 걸지 않으므로 풀링 재사용 시 이전 쌍이 남아 오염되는 위험도 함께 사라진다.
6. `DamageContext`: `Attacker = 발사자`, `Source = 투사체`, `Victim = 피격 대상`. `InteractionSystem.ProcessDamageAsync`는 공격 플래그를 **투사체 `attackFlags.CurrentFlags`**에서, 피격 플래그를 피격 대상의 `IHitStepFlagsProvider`에서 읽는다(provider 없으면 `None`). `DefaultAttackFlags`/`DefaultHitFlags` 상수 삭제.
7. `CombatPipelineManager`는 변경 없음 — 새 플래그 조합이 처음 들어올 때만 스텝 배열을 조립해 캐시한다(기존 캐시 규칙 그대로).

**보스 회복(무적) 페이즈**
8. 지금 `BossEventHitFlagsComponent`가 무적일 때만 `AttributeGate` 단독을 코드로 반환한다. 이를 **보스의 `CombatFlagState`**로 바꾼다: 회복 페이즈 진입 시 `AddHit(AttributeGate)` + `SuppressHit(Evasion | Defense)`, 해제 시 되돌림. 페이즈를 관장하는 `BossPhaseLogicSystem`이 갱신한다. 전용 컴포넌트는 `09.EventSequencerSystem/99.Legacy/`로 격리.

**이 기획서가 다루지 않는 것(판정 구조)**: `SizeGate` 비트와 게이트별 통과 결과 플래그(`DamageContext`에 속성 게이트/크기 게이트/데미지 게이트 통과 여부를 따로 기록)는 3단계 판정을 "속성 + 크기 + 데미지 모두 확인"으로 바꾸는 **별도 기획서**의 일이다.

### 3-3. 시청각 전달(UX)
- 같은 편 투사체는 **맞지도 튕기지도 않고** 통과한다: 플레이어 HP 바 변화/피격 이펙트·사운드가 없고, 스파크가 튀지 않는다(아군 샷이 플레이어를 때리던 현상 제거).
- 3단계에서 아군 투사체가 플레이어를 지나쳐 보스로 간다(마법 소유권을 빼앗지 않아도 통과 — 같은 편이라서).
- 빼앗긴 적 투사체는 시전자 편이 되어 **원래 발사자(적)를 맞힐 수 있다**(데미지 숫자/HP 바 변화로 전달).
- 보스 회복 페이즈의 연출(무적 + 속성 게이트 피드백)은 **기존과 동일**해야 한다(회귀 없음).

## 5. 예상 검수 방법 및 체크리스트 (3번 흐름 근거)
1. **[ ] 데이터화**: 인스펙터에서 `PureStatData_Boss`의 `defaultHitFlags`를 바꾸면 → 보스 피격 스텝 조합이 바뀌고(`CombatPipelineManager` 캐시 MISS 로그로 새 조합 확인) 코드 수정이 필요 없다. `InteractionSystem`에 `DefaultAttackFlags`/`DefaultHitFlags`가 남아 있지 않다(grep).
2. **[ ] 투사체 독자 상태**: 아군 투사체를 쏘면 → 투사체가 `attacker = 발사 NPC`, `faction = Ally`, `attackFlags = NPC 값`을 들고 있고, 마법을 걸어도 `attacker`는 그대로이며 `DamageContext.Attacker`가 발사 NPC로 찍힌다(`[InteractionSystem.Damage]` 로그). 풀 재사용 후에는 이전 사이클에서 바꾼 진영/플래그가 초기화돼 있다.
3. **[ ] owner 및 충돌 무시 로직 삭제**: `CollisionDamageTrigger`에 `owner`/`SetOwner`/`IgnoreOwnerCollisions`/`ignoredOwners`/`IsOwnerOrRelative`가 없고, `UnitChangeService.UpdateCollisionTriggerOwner`, `EventFlightTrackerComponent.ignorePlayerCollision`/`RestorePlayerCollision`이 없다(grep). 코드 전체에 `Physics.IgnoreCollision` 호출이 0건이다. 투사체가 발사 NPC 자신을 맞히지 않는다.
4. **[ ] 같은 편 통과(충돌 제거)**: 마법을 걸지 않은 아군 샷이 플레이어와 겹쳐도 → 레이어 매트릭스(`AttackAlly`↔`BodyAlly` 충돌 없음)로 접촉 이벤트 자체가 없어 데미지 0, **궤적이 바뀌지 않고**(튕김/감속 없음) 통과한다(플레이어 HP 불변, 반복 20회). 3단계에서 마법을 건 아군 투사체가 플레이어를 지나 보스에 명중해 판정이 정상 처리된다(성공/실패 기존 기준 그대로, 10회 반복, `ignorePlayerCollision` 없이도). `Physics.GetIgnoreLayerCollision`으로 매트릭스가 규칙표와 일치함을 확인한다(바뀐 쌍은 2개뿐).
4-1. **[ ] 레이어 적용/회귀**: 플레이어/아군/보스/투사체의 루트와 **모든 자식 콜라이더**가 진영에 맞는 레이어에 있다(자식 누락 없음, Play Mode에서 계층 전수 확인). 몸체끼리(플레이어↔아군 NPC↔보스), 투사체끼리, 투사체↔벽/지면/돌문(`Default`)은 이전과 똑같이 충돌한다(아군 NPC가 플레이어를 몸으로 밀어낼 수 있고, 투사체가 돌문에서 튕김 스파크를 낸다). 풀 반환 후 재사용된 투사체의 레이어가 발사 진영 값으로 복원돼 있다. 이전에 사용 중 걸린 충돌 쌍이 남지 않는다(애초에 쌍을 걸지 않음).
4-2. **[ ] 지면 판정 회귀**(`LocomotionLogicSystem.GroundedCheck`는 현재 3인칭 이동의 접지/중력/점프/낙하 애니메이션/경사/앉기 해제에 쓰인다): 플레이어를 `BodyAlly`로 옮긴 뒤 `groundLayerMask`(Default 전용)에 대한 접지 판정이 바뀌지 않거나 개선돼야 한다 — 평지 서기, 점프, 낙하, 경사, 앉기 해제가 이전과 같다(옮기기 전 자기 캡슐이 접지 구에 걸리는 부작용이 있었다면 그 차이를 보고).
4-3. **[ ] 레이어 마스크 사용처 영향 없음**: 락온/조준 탐지(`MagicLockOnComponent`, `NormalCombatLockOnComponent`, `MultiLockOnVisualizer`는 `DefaultRaycastLayers` 또는 마스크 없음), 줍기 감지(`~0`), 광역 빙결 탐지가 새 레이어의 대상(적, 투사체, 아군)을 이전처럼 잡는다.
5. **[ ] Neutral 피격**: 아군(Ally) 샷이 돌문(Neutral)을 맞히면 기존처럼 1차(속성)/2차(데미지) 게이트가 돈다(얼음만 → `cracked but survived`, 얼음+크기 → `DESTROYED`). 보스(Enemy) 샷이 플레이어(Player)를 맞히면 기존처럼 HP가 감소한다.
6. **[ ] 진영 변경(빼앗기)**: 적(Enemy) 투사체에 플레이어가 마법을 걸면 → 투사체 진영이 `Player`로 바뀌어 `AttackAlly`로 이동(루트+자식 콜라이더 모두) → 플레이어를 통과하며 원래 발사자(적, `BodyEnemy`)를 맞힌다. 풀 반환 후 재사용된 투사체는 다시 발사자 진영/레이어로 시작한다. 중립 NPC의 `CurrentFaction`을 `Neutral → Enemy`로 바꾸면 몸체가 `Default → BodyEnemy`로 이동해 이후 적 진영 투사체와는 충돌 없음, 아군 진영 투사체와는 충돌한다.
7. **[ ] 보스 회복 페이즈 회귀**: 회복(무적) 페이즈에서 보스의 피격 플래그가 `AttributeGate` 단독으로 바뀌고 해제 시 원복된다. `BossEventHitFlagsComponent`가 `99.Legacy`로 이동했고 씬에서 참조가 없다. 3단계 판정, 재도전, 13~15번 흐름에 회귀가 없다.
8. **[ ] 크리티컬**: 어떤 엔티티의 공격 플래그에도 `Critical`이 켜져 있지 않고 `[CriticalStep]` 로그가 나오지 않는다(Goal 30과 동일 결과).
9-1. **[ ] NPC 스탯/PlayerStat**: 아군 `NpcCombatActor_Dummy`에 스탯이 붙어도(`Ally`) `CharacterStatComponent.PlayerStat`이 플레이어를 가리킨다(씬 로드 순서와 무관, Play Mode에서 `PlayerStat`의 진영이 `Player`). 아군이 보스 샷(`Enemy`)에 맞으면 HP가 감소하고 아군 샷에는 맞지 않는다. 런타임에 NPC의 `CurrentFaction`을 `Neutral → Enemy`로 바꾸면(검증용 직접 호출) 이후 투사체 판정이 바뀐 진영을 따른다.
9. **[ ] 규칙 단일화**: `FactionRelation` 외에 같은 편/적대 판정 로직이 없다(`RuntimeStatData.IsHostile`은 위임만).
10. **[ ] DLV/폴더**: §4의 파일 배치를 따른다. 콘솔 에러 0건, 디스크에 임시 코드/수치 잔존 없음.

## 6. 확정/열린 질문
**확정(사용자 확인 완료)**
1. **무시 규칙**: 같은 편(`Player`+`Ally` / `Enemy`끼리) 무시, `Neutral`은 항상 피격 대상. **적끼리 오사도 무시한다**(보스 샷이 다른 적을 맞히지 않음).
4. **진영 변경 마법의 범위**: **현재 동작 그대로, 단위를 바꾸는 마법 전부가 투사체 진영을 시전자 진영으로 바꾼다**(현재 owner 강탈과 같은 범위).

2. **진영/플래그의 단일 출처 = `CharacterStatComponent` + `PureStatData`(A안 확정)**. NPC는 예외 없이 스탯을 가진다. 아군 `Ally`, 기본 중립(상인 등) `Neutral`, 보스 `Enemy`. 아군도 `IDamageable`이 되어 적 진영 투사체에 맞을 수 있다(진영 규칙상 일관). 락온 대상은 `IsEnemy()`가 `Enemy`일 때만이므로 영향 없음. **진영은 런타임에 바뀔 수 있다**(예: 중립 NPC를 공격하면 `Enemy`가 됨) — 규칙/판정은 `PureStatData.defaultFaction`이 아니라 **`RuntimeStatData.CurrentFaction`(기존, 변경 이벤트 있음)을 읽는다.** "공격받으면 적대화" 트리거 규칙 자체는 이 기획서의 범위가 아니다(§7).

3. **같은 편 통과의 구현 = 충돌 자체를 레이어로 제거**(확정). 사전 조사 결과: 전투 오브젝트는 전부 `Default`, 충돌 매트릭스는 전부 켜짐, 코드의 `Physics.IgnoreLayerCollision` 사용 없음, 락온/줍기/광역 탐지는 전체 레이어 또는 `DefaultRaycastLayers`라 새 레이어 영향 없음, 카메라 컬링 전체 켜짐, 렌더러 기능/Cinemachine 충돌의 레이어 사용 없음. 위험 항목은 지면 판정(4-2)이며 구현 후 Play Mode 회귀로 확인한다.
5. **투사체끼리의 충돌은 현재 동작 유지**(투사체 레이어끼리 충돌 켜짐, 기본값). 필요하면 별도 논의.
6. **(16-B QA 후속, 2026-10-10 확정)** 마법으로 투사체 진영을 바꾸는 것은 **시전이 성공한 경우에만** 한다(마나 부족/검증 실패 시 진영 불변). 기존 `UnitChangeService` 파이프라인 분기의 즉시 호출(결과 무시)은 이 규칙과 어긋나므로 후속 Goal에서 수정한다.
7. **(16-B QA 후속, 2026-10-10 확정)** 중립 진영 발사자의 투사체가 발사자 자신의 몸체를 맞히는 문제를 위해 **중립 전용 투사체 레이어가 필요하다**(구체 레이어 구성은 후속 Goal 작성 전 사용자 확인 중).
8. **(2026-10-10 확정, 별도 기획서 대상)** 판정 구조 개편에서 돌문도 3단계(보스)와 같은 구조로 통일한다. 중립 NPC는 **3번 연속 공격받으면 `Enemy`가 된다**(연속의 정의 등 세부는 해당 기획서에서 확인).

**열린 질문 (사용자 확인 전까지 구현 금지)**
- 없음(현재 시점). 구현 중 새로 발견되는 모호한 지점은 개발자 확인 후 진행한다.

## 6-1. 후속 16-C: 진영 변경 경로 정리 (16-B QA에서 발견, 2026-10-10 확정)

**문제**
1. `UnitChangeService.ChangeUnit`의 파이프라인 분기가 `pipeLine.Run(context).Forget()` 직후 **결과를 보지 않고** `ApplyCasterFaction`을 호출한다. 마나 0으로 시전이 실패(`ManaCheckFailed`)해도 투사체 진영이 바뀌어 플레이어를 통과한다(QA 재현).
2. `ApplyUnitChangeStep`(`Assets/PipeLine`, 범용 하부 계층)이 `UnitSystem.UnitChangeService`의 **정적 메서드**를 직접 호출한다. 하부→상부 로직 서비스 의존이라 `UnitSystem → PipeLine → UnitSystem` 순환이며, 정적 호출이라 VContainer를 우회하고 교체가 안 되며, 그 메서드가 `CollisionDamageTrigger`(InteractionSystem 구체 클래스)를 직접 찾는다.
3. 같은 일을 두 곳(`UnitChangeService` 파이프라인 분기 + Step)이 호출해 중복이다.

**데이터/인터페이스 (신규)**
- `IFactionSettable { void SetFaction(FactionType faction); }` — `Assets/PipeLine/Combat/IFactionSettable.cs`. `CollisionDamageTrigger`가 구현(기존 `SetFaction` 그대로).
- `FactionChange`(정적 순수 C# 헬퍼) — `Assets/PipeLine/Combat/FactionChange.cs`: `ApplyCasterFaction(GameObject target, GameObject caster)`. 시전자의 `IFactionProvider.Faction`을 읽어, 대상의 부모/자식에 있는 모든 `IFactionSettable`(`GetComponentsInParent/InChildren<IFactionSettable>(true)`)에 설정한다. 구체 클래스를 모른다. `attacker`(발사자)는 바꾸지 않는다.

**흐름**
- `ApplyUnitChangeStep`: 단위 변경이 **실제로 적용된 경우**(적용 블록 안)에만 `FactionChange.ApplyCasterFaction(context.TargetObject, context.Caster)`를 호출한다. `ManaCheckFailed`/`TargetInvalid`로 조기 반환하는 경로에서는 호출되지 않는다.
- `UnitChangeService.ChangeUnit`의 **파이프라인 분기 호출은 삭제**한다(Step이 성공 시 처리). 파이프라인이 없는 폴백 분기는 마나 소모가 성공한 뒤 같은 헬퍼를 호출한다. `UnitChangeService.ApplyCasterFaction`(정적)은 삭제한다.

**경로**: `Assets/PipeLine/Combat/IFactionSettable.cs`·`FactionChange.cs`(신규), `Assets/PipeLine/UnitMagic/Steps/ApplyUnitChangeStep.cs`, `Assets/02.System/01.UnitSystem/01.Logic/UnitChangeService.cs`, `Assets/02.System/03.InteractionSystem/01.Logic/CollisionDamageTrigger.cs`.

**체크리스트**
- [ ] 마나가 부족해 시전이 실패(`ManaCheckFailed`)하면 대상 투사체의 `faction`과 레이어가 시전 전과 같다(보스 투사체가 `Enemy`/`AttackEnemy` 유지, 플레이어를 통과하지 않고 명중).
- [ ] 시전이 성공하면 (단일 투사체, 부모/자식 트리거 모두) 진영이 시전자 진영으로 바뀌고 레이어가 `AttackAlly`로 이동하며 `attacker`는 불변이다(16-B 5-6과 동일 결과).
- [ ] `ApplyUnitChangeStep.cs`가 `UnitSystem`의 클래스를 참조하지 않는다(타입 의존은 기존 데이터 타입 `UnitType` 등 컨텍스트용만 허용, `UnitChangeService` 참조 0건). `UnitChangeService`에 진영 변경 정적 메서드가 없고, 파이프라인 분기에서 진영 변경 호출이 없다(grep).
- [ ] 파이프라인 분기/폴백 분기 두 경로 모두에서 진영 변경이 정확히 한 번만 일어난다(중복 호출 없음). 13~16번 회귀(3단계 판정, 락온 팝업, 큐 1회 발동, 풀링 초기화).

## 6-2. 레이어 명칭 변경 예정 (2026-10-10 확정)
`Projectile*` 레이어명은 투사체에 한정되므로 **`Attack*`로 변경한다** — 근접 무기 판정체, 범위 공격 영역 등 "충돌로 피해를 주는 공격 판정체" 전체가 같은 레이어 체계를 쓰기 위함이다. 변경 대상: `ProjectileAlly`→`AttackAlly`, `ProjectileEnemy`→`AttackEnemy`(+ 중립 레이어가 생기면 `AttackNeutral`), `TagManager` 레이어 정의, `FactionLayers`의 이름 상수와 `GetProjectileLayer` 계열 메서드명, 이 기획서·Goal 문서의 레이어 표기. 몸체 레이어 `Body*`는 유지. 레이어 번호(8~11)와 충돌 규칙은 변하지 않는다.

**16-D 레이어 구성 (가정 — 사용자 미확정 항목은 추천안으로 작성, 변경 가능)**: 이름 변경과 함께 중립 레이어 2개를 추가한다.
| 번호 | 레이어 | 대상 |
|---|---|---|
| 8 | `BodyAlly` | Player/Ally 캐릭터 몸체 |
| 9 | `BodyEnemy` | Enemy 캐릭터 몸체 |
| 10 | `AttackAlly` (구 `ProjectileAlly`) | Player/Ally 진영 공격 판정체 |
| 11 | `AttackEnemy` (구 `ProjectileEnemy`) | Enemy 진영 공격 판정체 |
| 12 | `BodyNeutral` (신규) | `Neutral` 진영 **캐릭터** 몸체(상인 등 중립 NPC) |
| 13 | `AttackNeutral` (신규) | `Neutral` 진영 공격 판정체 |
- 꺼지는 충돌 쌍: `AttackAlly↔BodyAlly`, `AttackEnemy↔BodyEnemy`, **`AttackNeutral↔BodyNeutral`**(중립 공격은 중립 몸체(자기 자신 포함)를 맞히지 않는다). 그 밖은 모두 충돌(아군/적 공격은 중립 몸체를 맞힌다 — "중립은 항상 피격 대상").
- 돌문 등 **비캐릭터 오브젝트는 `Default` 유지**(진영 `Neutral`이어도 몸체 레이어를 적용하지 않는다) — 중립 공격도 돌문을 맞힌다.
- `FactionRelation`: 레이어 목적의 편 정의에 중립 편(`NeutralSide`)을 추가하고 `IsSameSide(Neutral, Neutral) = true`. `IsHostile`은 **변경 없음**(Neutral은 누구에게도 적대적이지 않다).
- 이 구성은 16-B QA가 발견한 "중립 진영 발사자 자기 몸 피격"도 해결한다.

## 6-3. 구르기 무적 = `IgnoreAttack` 레이어 (2026-10-10 확정, 구현은 구르기 기획서에서)
구르기(회피) 중에는 플레이어를 **`IgnoreAttack` 레이어**로 옮겨 모든 공격 판정체와의 충돌을 끈다. 진영과 무관한 단일 레이어이며 충돌 매트릭스는 `IgnoreAttack`↔`AttackAlly`/`AttackEnemy`/`AttackNeutral`만 끈다(벽·지면·몸체끼리 충돌은 유지). 구르기 종료 시 **저장해 둔 레이어가 아니라 그 시점의 `CurrentFaction`에 맞는 몸체 레이어**로 복원한다(구르기 중 진영이 바뀌어도 올바르게 복원). 구르기 중에는 `CharacterStatComponent`의 `OnFactionChanged` 반응이 몸체 레이어를 덮어쓰지 않아야 하고, 구르기가 중단되는 모든 경로(피격 경직, 사망, 비활성)에서 복원이 보장되어야 한다. 구현 시 검증할 위험: 공격 판정체가 겹친 채로 구르기가 끝날 때 충돌 재개로 접촉 이벤트가 새로 발생하는지.

## 7. 범위 밖 (별도 논의/작업)
- **3단계/돌문 판정 구조 변경**(`SizeGate`, 게이트별 결과 플래그, "어떤 마법이 적용됐는지 + 최종 데미지" 전수 확인) — 별도 기획서.
- **아군 NPC가 길을 막고 돌문이 부서지면 길이 열리는 연출**: 시스템이 플레이어 이동을 막는 것이 아니라 NPC 몸체(콜라이더)가 물리적으로 막고, 돌문 파괴 시 NPC가 비켜 길이 열리는 **씬 구성/이벤트 연출**. 이 기획서(진영/플래그)와 무관. 현재 NPC 몸체 충돌/이동 연출이 어디까지 구현돼 있는지는 미확인이므로 별도 확인 후 다룬다.
- **중립 NPC가 공격받으면 `Enemy`로 전환되는 규칙**(누가 어떤 조건에서 `CurrentFaction`을 바꾸는지, 상인 등 중립 NPC 연출): 별도 논의/작업. 이 기획서는 진영이 런타임에 바뀌어도 충돌 규칙이 `CurrentFaction`을 읽어 올바르게 동작하는 데이터 경로까지만 보장한다.
- **광역(범위) 마법의 같은 편 예외**: 규칙을 `FactionRelation` 한 곳에 모아 두었으므로 예외 인자 추가로 확장 가능. 지금은 구현하지 않는다.
- 구르기 무적 프레임(다크소울식), 보스가 투사체를 쏘는 이유 — 각각 별도 논의.
- 범용 예시 코드(`EvadeStep`, `BlockStep`, `BaseDamagePipeLineSO`, `BaseDamageContext`) 정리.

## Goal

인벤토리에서 이미 즐겨찾기(W/E/F)에 등록된 유닛을 재우클릭해 다음 슬롯으로 순환시킬 때, 그 슬롯에 이미 있던 **다른 유닛의 등록이 조용히 사라지는** 버그를 고친다. 다른 유닛이 있으면 지우지 말고 **서로 자리를 맞바꾼다(스왑)**.

## 배경 (QA가 실측으로 확인한 현재 버그)

`Assets/02.System/01.UnitSystem/03.UI/UnitInventoryUIComponent.cs`의 `OnUnitContextClicked(PureDataUnit)`(약 300~324행):

```csharp
int existingIndex = favoriteSlots.FindSlotOf(unitData);
if (existingIndex >= 0)
{
    int nextIndex = (existingIndex + 1) % RuntimeDataMagicFavoriteSlots.SlotCount;
    favoriteSlots.ClearSlot(existingIndex);
    favoriteSlots.AssignSlot(nextIndex, unitData);
    return;
}
```

W=L, E=kg, F=Torus로 다 채운 상태에서 L을 재우클릭하면: `existingIndex=0`(W), `nextIndex=1`(E) → `ClearSlot(0)` 후 `AssignSlot(1, L)` → E에 있던 kg가 아무 경고 없이 사라지고 L로 덮어써진다. 데이터 유실이며 사용자에게 피드백도 없다.

## 범위

### 포함
`OnUnitContextClicked`의 재순환 분기(`existingIndex >= 0`)만 수정:
1. `nextIndex`에 현재 등록된 유닛을 `AssignSlot` 전에 미리 읽어둔다(`PureDataUnit displaced = favoriteSlots.GetSlot(nextIndex);`).
2. `favoriteSlots.AssignSlot(nextIndex, unitData)`로 순환 중인 유닛을 다음 슬롯에 등록.
3. `favoriteSlots.AssignSlot(existingIndex, displaced)`로, 원래 슬롯에는 방금 밀려난 유닛(`displaced`, 없었으면 `null`)을 넣는다 — `nextIndex`가 비어있던 경우(`displaced == null`)는 기존과 동일하게 원래 슬롯이 그냥 비워지고, 다른 유닛이 있던 경우는 그 유닛이 원래 슬롯으로 옮겨가 유실 없이 스왑된다.
4. `RuntimeDataMagicFavoriteSlots.cs`(`AssignSlot`/`GetSlot`) 자체는 변경하지 않는다 — 범용 setter/getter이므로 호출부 로직만 바꾸면 충분하다.

### 제외 (이번 작업 범위 아님)
- 즐겨찾기 슬롯이 꽉 찬 상태에서 **새로운(미등록) 유닛**을 등록할 때의 "W부터 덮어쓰기" 정책 — 기존 그대로 유지, 이번 버그와 무관.
- `MagicSelectionPopupLogicSystem`/`MagicSelectionPopupUIComponent`/팝업 UI 등 이번 버그와 무관한 다른 코드 — 변경 금지.

## 완료 기준 (Definition of Done)

- [ ] W=A, E=B, F=C로 3슬롯이 모두 등록된 상태에서 A를 재우클릭하면: A는 E로 이동하고, B는 A가 있던 W로 이동한다(둘 다 유지, F=C 그대로).
- [ ] 재순환 대상 슬롯이 비어있던 경우(기존 정상 케이스)는 회귀 없이 그대로 동작한다(원래 슬롯 비우고 다음 슬롯에 등록).
- [ ] 미장착 유닛 우클릭 무시, 꽉 찬 상태에서 새 유닛 등록 시 W부터 덮어쓰기 등 기존 동작에 회귀가 없다.
- [ ] `OnFavoriteSlotChanged` 이벤트가 두 슬롯 변경 모두에 대해 정상 발행되어 인벤토리 UI 배지가 두 아이콘 모두 올바르게 갱신된다.
- [ ] 신규/수정 코드가 DLV/VContainer 규칙을 위반하지 않는다.

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(Play Mode / `unity eval`)**:
   - 시나리오 A(스왑): 유닛 3개를 장착 후 각각 W/E/F에 순서대로 등록(우클릭 3회) → W의 유닛을 재우클릭 → E로 이동 + 기존 E에 있던 유닛이 W로 이동(둘 다 `GetSlot`으로 조회해 유실 없음 확인) → 배지 UI도 두 아이콘 모두 갱신 확인.
   - 시나리오 B(빈 슬롯 순환, 회귀): 2개만 등록(W, E만 채움, F는 비움) 후 **E의 유닛** 재우클릭 → 다음 슬롯(F)이 비어있었으므로 기존처럼 E가 비워지고 F에 등록되는지 확인. (재순환 대상은 항상 `(existingIndex+1)%3`이므로 W의 유닛을 누르면 다음 슬롯은 E이다.)
   - 시나리오 C(회귀): 미장착 유닛 우클릭 무시, 신규 유닛 등록 시 빈 슬롯 우선/꽉 찬 경우 W부터 덮어쓰기가 정상 동작하는지 확인.
   - 시나리오 D(팝업 연동 회귀): 수정 후에도 즐겨찾기 확정(`ConfirmFavoriteSlot`) → 시간정지 해제+일괄시전 흐름이 정상 동작하는지 확인(12번 기획서 본 기능 회귀 없음).
4. **범위 확인**: `git diff --stat`로 `UnitInventoryUIComponent.cs` 한 파일에만 변경이 한정되는지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

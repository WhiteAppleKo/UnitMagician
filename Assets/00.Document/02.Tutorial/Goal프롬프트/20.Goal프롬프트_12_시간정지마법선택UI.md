## Goal

시간정지(완전정지) 중 마법 락온 후, 다크소울3이 아니라 **33원정대(Clair Obscur: Expedition 33) 스타일의 Q/W/E/F 선택지 팝업**으로 시전할 마법을 고르게 한다. Q는 장착 유닛 전체 목록, W/E/F는 인벤토리에서 미리 등록해둔 즐겨찾기. 선택을 확정하는 순간 시간정지가 풀리며 모든 락온 타겟에 일괄 시전된다.

## 배경 (조사로 확인된 현재 상태 — 반드시 그대로 재사용할 기존 체인)

- `Assets/02.System/01.UnitSystem/00.Data/RuntimeDataMultiLockOn.cs`: `AddTarget`/`RemoveTarget`/`ClearTargets` + `OnTargetAdded`/`OnTargetRemoved`/`OnTargetsCleared` 이벤트, `TargetCount` 프로퍼티. 다중 락온 누적 방식은 **변경 없음**.
- `Assets/02.System/01.UnitSystem/00.Data/RuntimeDataUnitQuickSlot.cs`: `SelectUnit(PureDataUnit, int)` — 이 메서드를 호출하면 `UnitCasterSystem.ExecuteBatchCast()`가 읽는 "현재 선택된 유닛"이 바뀐다.
- `Assets/02.System/02.CharacterSystem/00.Data/RuntimeDataTimeSlow.cs`: `SetSlowActive(bool)` — `false`를 호출하면 `OnSlowStateChanged` 발행 → `TimeSlowVisualizer`/`PlayerLockOnController.HandleSlowStateChanged`가 반응해 `SetSlowMode(false)` 호출 → `magicLockOnObject.SetActive(false)` → `MagicLockOnComponent.OnDisable()`이 자동으로 `UnitCasterSystem.ExecuteBatchCast()`를 호출하는 **기존 체인이 이미 완성돼 있음**(`Assets/02.System/00.Movement/02.Visualizer/00.Locomotion/PlayerLockOnController.cs`, `Assets/02.System/01.UnitSystem/02.Visualizer/MagicLockOnComponent.cs`). `UnitCasterSystem`은 이미 `RuntimeDataTimeSlow`를 선택적 생성자 주입으로 받는 선례가 있다(`Assets/02.System/01.UnitSystem/01.Logic/UnitCasterSystem.cs` 생성자) — 즉 01.UnitSystem 스코프에서 `RuntimeDataTimeSlow`에 직접 접근 가능함이 이미 증명됨.
- `Assets/02.System/01.UnitSystem/01.Logic/UnitCasterSystem.cs`의 `ExecuteBatchCast()`(약 231~273행): `quickSlotUI.CurrentSelectedUnit`을 읽어 그 유닛으로 `multiLockOnData.LockedTargets` 전체에 일괄 시전한다. **이 메서드는 수정하지 않는다** — `RuntimeDataUnitQuickSlot.SelectUnit(...)`으로 선택을 바꿔두기만 하면 자동으로 이 로직이 올바른 유닛을 읽는다.
- `Assets/02.System/01.UnitSystem/03.UI/UnitInventoryUIComponent.cs`: `BuildUnitElement(...)`가 이미 아이콘+이름+장착상태 라벨 구조로 되어 있고 `ClickEvent`로 장착/해제 토글(11번 작업). 이번엔 우클릭 핸들러만 추가한다.
- `Assets/02.System/01.UnitSystem/03.UI/UnitUI.uxml`: 기존 `InventoryContainer`(§8 정정으로 중앙 모달), `QuickSlotContainer`(바텀레프트 단일 슬롯) 등 참고할 기존 패널 스타일 보유.

## 범위

### 포함
1. **`RuntimeDataMagicFavoriteSlots.cs`(신규, `00.Data/`)** — 12번 기획서 §3대로 `PureDataUnit[3]` 슬롯(W/E/F) + `AssignSlot`/`GetSlot`/`ClearSlot`/`FindSlotOf` + `OnFavoriteSlotChanged` 이벤트.
2. **`MagicSelectionPopupLogicSystem.cs`(신규, `01.Logic/`)** — `RuntimeDataMultiLockOn`, `RuntimeDataUnitQuickSlot`, `RuntimeDataTimeSlow`, `IUnitCatalogService`, `RuntimeDataMagicFavoriteSlots` 생성자 주입. `OnTargetAdded` 구독해 `TargetCount==1`일 때 팝업 오픈, `OnTargetsCleared`/타겟 0복귀 시 팝업 클로즈. `ConfirmFavoriteSlot(int index)`/`ConfirmUnit(PureDataUnit)` 공개 메서드 — 호출 시 `SelectUnit` + `SetSlowActive(false)` + 팝업 닫기를 순서대로 수행. `OpenFullList()`/`CloseFullList()`. `IsPopupOpen`/`IsFullListOpen` 프로퍼티, `OnPopupOpened`/`OnPopupClosed`/`OnFullListToggled` 이벤트.
3. **`MagicSelectionPopupUIComponent.cs`(신규, `03.UI/`)** — `MagicSelectionPopupLogicSystem`의 이벤트를 구독해 `UnitUI.uxml`의 신규 `MagicSelectionPopupContainer` 표시/숨김. `Update()`에서 `IInputContextManager.CurrentContext==Tactical`이고 `IsPopupOpen`일 때만 `Keyboard.current.qKey/wKey/eKey/fKey.wasPressedThisFrame`를 체크해 Q→`OpenFullList()`/`CloseFullList()` 토글, W/E/F→`ConfirmFavoriteSlot(0/1/2)` 호출. 전체 목록 패널은 장착 유닛 아이콘 그리드(클릭 시 `ConfirmUnit(unit)`).
4. **`UnitUI.uxml` 수정** — `MagicSelectionPopupContainer`(신규 섹션) 추가: Q/W/E/F 4개 슬롯(키 아이콘 박스 + 라벨, 레퍼런스 이미지 스타일 참고 — 대각선 또는 세로 스택) + Q로 펼쳐지는 전체 목록 서브패널(기본 숨김).
5. **`UnitInventoryUIComponent.cs` 수정** — `BuildUnitElement(...)`에 우클릭(`ContextClickEvent`) 핸들러 추가: 장착된 유닛이면 `RuntimeDataMagicFavoriteSlots.AssignSlot(...)` 호출(순환 등록), 아이콘에 즐겨찾기 배지(`OnFavoriteSlotChanged` 반영) 추가. 미장착 유닛은 우클릭 무시.
6. **`UnitSystemLifetimeScope.cs` 수정** — `RuntimeDataMagicFavoriteSlots` Singleton 등록, `MagicSelectionPopupLogicSystem` `RegisterEntryPoint` 등록, 신규 UI 컴포넌트 씬 배선.

### 제외 (이번 작업 범위 아님)
- `UnitQuickSlotLogicSystem`(마우스 휠 순환) 로직 변경 — 평상시 용도로 그대로 둔다, 손대지 않는다.
- `UnitCasterSystem.ExecuteBatchCast()`/`MagicLockOnComponent`/`PlayerLockOnController`/`TimeSlowLogicSystem` 로직 변경 — 기존 체인을 트리거만 하고 내부는 그대로.
- 즐겨찾기 슬롯이 꽉 찼을 때의 정확한 교체 정책, Q 전체 목록의 스크롤/페이지네이션, 팝업 연출(애니메이션/효과음) — 기획서 §6 범위 밖, 합리적 기본값으로만 구현.
- 09번 기획서의 이벤트 시퀀서 전용 감속 모드(3단계) 중 이 팝업 적용 여부 — 이번엔 유저 수동 완전정지(1단계 스타일) 흐름만 다룬다.

## 완료 기준 (Definition of Done)

- [ ] 시간정지 중 타겟을 1개 락온하면 즉시 Q/W/E/F 팝업이 나타난다.
- [ ] 팝업이 열린 상태에서 추가 타겟을 락온해도 팝업이 유지되고 깜빡이거나 재오픈하지 않는다.
- [ ] 락온한 타겟을 전부 해제하면 팝업이 자동으로 닫힌다.
- [ ] 즐겨찾기가 등록된 W/E/F를 누르면 그 즉시 시간정지가 해제되고 모든 락온 타겟에 해당 마법이 일괄 시전된다.
- [ ] 즐겨찾기가 비어있는 W/E/F는 눌러도 아무 효과가 없다.
- [ ] Q를 누르면 장착 유닛 전체 목록이 펼쳐지고, 클릭 시 W/E/F와 동일하게 동작한다.
- [ ] 타겟 없이 수동으로 시간정지를 끄면 팝업 없이 조용히 종료된다(회귀 없음).
- [ ] 인벤토리에서 장착 유닛 우클릭 시 W→E→F 순서로 즐겨찾기 등록, 아이콘에 배지 표시. 미장착 유닛 우클릭은 무시.
- [ ] 마우스 휠 퀵슬롯 순환(평상시), Option/Inventory 메뉴, 시간정지(T), 기존 장착/해제 클릭에 회귀 없음.
- [ ] 신규 코드가 DLV/VContainer 규칙을 위반하지 않음(인터페이스/RuntimeData로만 로직 접근, `GameObject.Find`/`FindObjectOfType` 없음).

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(Play Mode / `unity eval`)**:
   - 시나리오 A(팝업 오픈): 시간정지 진입 → 타겟 1개 락온 → `MagicSelectionPopupLogicSystem.IsPopupOpen==true` 확인.
   - 시나리오 B(추가 락온 중 유지): 팝업 열린 채로 타겟 1개 더 락온 → `IsPopupOpen` 유지, `TargetCount==2` 확인.
   - 시나리오 C(즐겨찾기 확정): 미리 `AssignSlot(0, unitA)` 설정 → `ConfirmFavoriteSlot(0)` 호출 → `RuntimeDataUnitQuickSlot.SelectedUnit==unitA`, `RuntimeDataTimeSlow.IsSlowActive==false`, 락온 타겟들에 실제 효과 적용(기존 `ExecuteBatchCast` 검증 방식 재사용) 확인.
   - 시나리오 D(빈 슬롯 무효): 빈 슬롯 번호로 `ConfirmFavoriteSlot` 호출 → 아무 변화 없음 확인.
   - 시나리오 E(전체 목록): `OpenFullList()` → `IsFullListOpen==true`, `IUnitCatalogService.GetEquippedUnits()`와 UI에 그려진 목록 일치 확인 → `ConfirmUnit(unit)` → C와 동일하게 확정.
   - 시나리오 F(타겟 없이 종료): 타겟 0개 상태에서 시간정지 해제 → 팝업 관련 이벤트 발행 안 됨 확인(회귀 없음).
   - 시나리오 G(즐겨찾기 등록): 인벤토리에서 장착 유닛 우클릭 반복 → W→E→F 순서로 `RuntimeDataMagicFavoriteSlots` 상태 변화 확인, 미장착 유닛 우클릭 시 무변화 확인.
   - 시나리오 H(회귀): 마우스 휠 퀵슬롯 순환, Option(Escape)/Inventory(I) 메뉴, 시간정지(T), 기존 인벤토리 클릭 장착/해제가 정상 동작하는지 확인.
4. **범위 확인**: `git diff --stat`로 변경 범위가 §4에 명시된 파일들에 한정되는지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

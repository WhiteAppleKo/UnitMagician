## Goal
이벤트 시퀀서가 시간을 통제하는 3단계 감속 중에는 관련 기능을 차단해 감속이 반쯤 풀리는 상태 불일치 버그를 구조적으로 막고, 3단계 판정에서 타임아웃 실패를 제거해 명중 결과로만 판정한다.

## 배경 (확인된 현재 상태)
- `TimeSlowLogicSystem.ToggleSlow()`가 이벤트 감속 중에도 `DeactivateSlow()`만 호출 → `IsSlowActive`만 꺼지고 램프(`IsEventTriggered`)/게이지 오버라이드/마나 무제한은 남는다.
- `TimeSlowLogicSystem.DeactivateEventSlow()`가 이벤트 종료 정상 경로(`SetGaugeOverride(false)` → `EndEventRamp()` → `DeactivateSlow()` → `SetManaUnlimited(false)`).
- `TutorialSequencerLogicSystem.Tick()`(약 124~142행)가 Stage3 진입 후 `CoreHitTimeoutSeconds`가 지나면 `OnCoreHitFail`을 방송. 명중 판정은 `HandleDamageProcessed`가 게이트 통과 여부로 처리.
- 쏘는 주체는 아군 NPC라 투사체는 반드시 명중한다. 플레이어가 아무것도 안 하면 인챈트 없이 맞아 게이트 실패가 될 뿐이다.

## 범위
### 포함
1. `RuntimeDataTimeSlow.SetSlowActive(false)`: `IsEventTriggered`(이벤트 감속 진행 중)이면 거부(무시). 이벤트 종료는 `DeactivateEventSlow()`만 가능(이 메서드는 `EndEventRamp()`로 `IsEventTriggered`를 먼저 끄므로 정상 해제는 영향 없음). `ForceSlowActive`/활성화 경로는 변경하지 않는다.
2. `TimeSlowLogicSystem.ToggleSlow()` 상단에 `IsEventTriggered` 조기 반환 가드(입력 단계 차단).
3. `UnitInventoryUIComponent.OpenInventory()`/`ToggleInventory()`: `RuntimeDataTimeSlow.IsEventTriggered`이면 열지 않음(이미 열려 있는 경우는 닫을 수 있어야 함). 옵션 메뉴(Esc)는 건드리지 않는다.
4. `TutorialSequencerLogicSystem`: `Tick()`의 타임아웃 실패 분기 및 `stage3ElapsedSeconds` 관련 코드 제거(필요하면 `ITickable` 등록도 정리). 명중 판정 경로(`HandleDamageProcessed`)와 재도전 로직(`Stage2` 복귀)은 그대로 유지. `PureDataTutorialSequence.CoreHitTimeoutSeconds`는 13-D 이후 더 이상 쓰이지 않으므로 사용처를 grep으로 확인하고 제거하거나 deprecated 처리(직렬화된 `PureDataTutorialSequence` 에셋 값에 영향이 없는지 확인).
5. **3단계 성공 조건 확장**: `TutorialSequencerLogicSystem.HandleDamageProcessed`의 성공 판정을 `!context.Aborted && context.FinalDamage >= pureData.CoreHitRequiredDamage`로 바꾼다(그 외는 `OnCoreHitFail`). `PureDataTutorialSequence`에 `CoreHitRequiredDamage`(int) 필드를 추가하고 에셋(`PureDataTutorialSequence` SO)의 값을 "얼음만 쓴 경우 미달, 얼음+크기 확대를 쓴 경우 충족"하도록 실제 `AttributeGateStep`의 `RawDamage × 질량 비율`(`CollisionDamageTrigger.baseDamage`, `MassUnitApplicatorSO.CalculateMassRatio`, 크기 확대 마법의 `MassScaleMultiplier`)을 확인해서 정한다. 판정에 쓰는 `FinalDamage`가 파이프라인 후속 스텝에서 바뀌는지(방어 등)도 확인해 06이 읽는 시점의 값을 기준으로 한다.
6. 06 6.2절/09 9.2.1절의 타임아웃-램프 결합 설명을 이 변경에 맞춰 짧게 정정(코드 주석 + 해당 기획서 문단에 "13번 기획서로 대체됨" 한 줄).

### 제외
- 큐 구조/팝업 지정 변경(13-A), 미리보기/마나 UI(13-C).
- 접근/이탈 곡선과 전환점 발동(13-D). 투사체 명중이 전환점 이후에만 일어나는 것은 13-D가 구조적으로 보장하므로 이 작업에서 따로 튜닝하지 않는다.

## 완료 기준 (기획서 §5 해당 항목)
- [ ] 이벤트 감속 중 `T` 키(`ToggleSlow()`)를 눌러도 `IsSlowActive`/`IsEventTriggered`/`IsGaugeOverride`/`IsManaUnlimited`가 모두 변하지 않는다. 어떤 경로로든 `SetSlowActive(false)`를 호출해도 이벤트 중에는 상태가 어긋나지 않는다.
- [ ] 이벤트 감속 중 인벤토리(`I`)가 열리지 않는다. 이벤트가 아닐 때는 기존대로 열고 닫힌다.
- [ ] 이벤트 정상 종료(`OnCoreHitSuccess`/`OnCoreHitFail`)에서는 `DeactivateEventSlow()`가 이벤트 상태(`IsEventTriggered`/구간·진행도, 게이지 오버라이드)를 모두 정상 해제하고 마나 무제한도 꺼진다(회귀 없음).
- [ ] 플레이어가 아무것도 하지 않아도 타임아웃으로 `OnCoreHitFail`이 나가지 않는다. 투사체 명중 시 **얼음 게이트 통과 AND `FinalDamage >= CoreHitRequiredDamage`**면 `OnCoreHitSuccess`, 그 외(얼음 아님 / 얼음이지만 크기 확대 없이 데미지 미달 / 마법 없음)는 `OnCoreHitFail`이 나가고, 실패 후 재도전(`OnBoss50Percent` 재방송)이 회귀 없이 동작한다.
- [ ] 일반 시간정지(1단계 스타일, `IsEventTriggered == false`)의 `T` 토글은 기존과 똑같이 동작한다.
- [ ] DLV/VContainer 규칙 준수.

1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인. `clear_console` 후 `console --level error` 0건.
2. Play Mode(`Time.frameCount` 정지 시 리플렉션 직접 호출): 이벤트 시작(`OnBoss50Percent` 발행 경로로 `ActivateEventSlow`) → `ToggleSlow()`/`SetSlowActive(false)` 호출 전후 상태 4종 비교 → `OpenInventory()` 호출 결과 → 명중 판정 신호(`OnCoreHitSuccess`/`OnCoreHitFail`) 발행으로 `DeactivateEventSlow()` 정상 종료 확인 → 일반 시간정지 `T` 토글 회귀 확인 → 명중 판정(성공/실패)과 재도전 확인(`ChangeStage` 선행 전이 후 이벤트 발행 순서 주의) → 타임아웃 시간이 지나도 `OnCoreHitFail`이 안 나가는지 확인.
3. `git diff --stat`로 범위 확인(이전 세션 미커밋분은 구분).

# Goal 50: 이벤트 시스템 — 범용 실행기 골격 + 돌문 이벤트(약 이벤트) + BlockerNPC

## Goal
이벤트를 SO로 정의하고 어떤 이벤트 SO가 들어와도 같은 방식으로 실행하는 **범용 이벤트 시스템(실행기)** 의 골격을 만들고, 가장 단순한 약 이벤트인 **돌문 이벤트**(일반 NPC들이 길을 막고 돌문에 투사체를 쏜다 → 마법으로 문을 부순다 → NPC들이 길을 비켜선다)를 `BlockerNPC` 컴포넌트와 함께 이 구조 위에서 동작시킨다. 기존 보스 50% 시퀀서는 이 Goal에서 동작을 바꾸지 않고 병존한다.

## 사용자 확정 (25번 기획서 §1-1, §7, §10)
- 이벤트 = SO로 정의(시작 조건·강제 동작·완료 조건·결과별 동작), 시퀀서는 어떤 이벤트 SO가 들어오든 동적으로 작동. 이벤트 SO는 **씬 시작 시 등록**, **조건 분기가 있는 이벤트가 마무리되면 활성 이벤트 목록을 갱신**. 모든 값은 이벤트 SO에서 조정.
- 약/강 = 플레이어에 영향을 주냐 안 주냐(돌문 이벤트는 약).
- 돌문 이벤트 NPC = `BlockerNPC.cs`(신규): 막는 위치·비켜설 위치를 가지고 이벤트 시스템의 명령에 따라 `MoveTo`로 비켜선다. 돌문을 향해 투사체를 쏘는 것은 로직 반복이 아니라 이벤트가 확정적으로 일으킨다.
- 이름은 25번 §10의 고정 이름: 기능 `09.EventSystem` / `EventSystemLifetimeScope` / `EventLogicSystem` / `IEventSystem` / `RuntimeDataEvent` / `PureDataEvent` / `EventTriggerSO`·`EventCompletionSO`·`EventActionSO` / `IEventActionHandler` / 네임스페이스 `GameEvent`. (Unity `EventSystem` 클래스 충돌 회피.)

## 범위
### 포함
1. **조사 먼저**: 현재 `09.EventSequencerSystem` 전체 구독자(`TimeSlowLogicSystem`, `EventCameraTriggerLogicSystem`, `AllySupportTriggerLogicSystem`, `BossPhaseLogicSystem`, `EventCastTriggerLogicSystem`)와 `using EventSequencerSystem`/`namespace` 사용처, `DestructibleDoorComponent`/`IDestructibleTargetStatus`의 파괴 알림(이벤트 유무), 씬의 돌문·아군 NPC·통로 지오메트리를 확인해 보고. 기획서와 다르면 임의 판단 말고 "결정 필요".
2. **이름 변경**: 폴더 `09.EventSequencerSystem` → `09.EventSystem`, 네임스페이스 `EventSequencerSystem` → `GameEvent`, `EventSequencerSystemLifetimeScope` → `EventSystemLifetimeScope`. 파일 이동은 반드시 에디터 `AssetDatabase.MoveAsset`(GUID 유지, 씬 참조 보존). **LifetimeScope 이름 변경은 VContainer 에디터 훅이 신규 `*LifetimeScope.cs`를 빈 스텁으로 리셋하는 함정이 있으므로**(메모리 `project_vcontainer_lifetimescope_reset_gotcha.md`) 먼저 소규모로 검증하고, 리셋되거나 씬 컴포넌트가 깨지면 이름 변경을 중단·원복하고 보고(새 `*LifetimeScope.cs` 파일을 만들지 않는다). 기존 `Tutorial*` 클래스(보스 50% 시퀀서 구현)는 이 Goal에서 동작 변경 없이 이름·네임스페이스 갱신만 하고 Goal 51에서 대체한다.
3. **데이터(`00.Data`)**: `PureDataEvent`(이벤트 한 개: `eventId`, `intensity`(Weak/Strong), `trigger`, `requiresCompleted`, `onStart`, `completion`, `onSuccess`, `onFail`, `rearmOnFail`), `EventTriggerSO`+`SceneStartTrigger`, `EventCompletionSO`+`TargetDestroyedCompletion`, `EventActionSO`+돌문 이벤트용 동작 SO(`NpcRepeatAttackAction`, `NpcStopAttackAction`, `NpcStepAsideAction` — 필드는 25번 §3-1), `RuntimeDataEvent`(이벤트별 상태 `Locked/Armed/Running/Completed`와 마지막 결과, 변경 시 이벤트만 발행). 모든 조정 수치(사격 주기·투사체 속도/데미지 지정·비켜서기 이동 속도 등)는 동작 SO 필드.
4. **실행기(`01.Logic`)**: `EventLogicSystem` — 씬 시작 시 등록된 이벤트 SO 목록 로드, 트리거 평가 → `Running` + `onStart` 동작을 `IEventActionHandler`로 실행, 완료 판정 → `onSuccess`/`onFail` 실행, `rearmOnFail`·선행 조건(`requiresCompleted`)에 따른 활성 이벤트 목록 갱신, 범용 신호 `OnEventStarted(eventId)`/`OnEventCompleted(eventId, result)`를 `IEventSystem`으로 노출. 스코프 트리가 달라 생성자 주입이 안 되면 기존 `BindEventSequencer`류 사후 배선으로 핸들러를 등록하고 방식·이유 보고. 인터페이스 주입, Find* 금지.
5. **NPC 쪽(`07.NpcSystem`)**: `BlockerNPC`(`02.Visualizer`, [V] MonoBehaviour: `groupId`, 막는 위치, 비켜설 위치 직렬화 필드) + 인터페이스(`IBlockerNpc`: 위치 값 읽기·`groupId`), `NpcSystemLifetimeScope`의 `BlockerNPC` 인스펙터 목록(기존 `NpcCombatActorVisualizer` 목록 패턴), `01.Logic`에 동작 핸들러(반복 사격 / 사격 중단 / 비켜서기). 비켜서기 전에 반드시 사격 반복을 멈춘다(공격이 이동을 끊는 기존 규칙, 25번 §9). 이동은 `INpcCombatActor.MoveTo`.
6. **돌문 이벤트 에셋 + 씬**: `PureDataEvent` 돌문 이벤트 에셋(trigger=`SceneStartTrigger`, onStart=반복 사격, completion=`TargetDestroyedCompletion`(돌문), onSuccess=사격 중단 → 비켜서기, `rearmOnFail=false`)을 만들고 씬에 일반 NPC들(`BlockerNPC`)을 배치·등록한다. **NPC 개수는 사용자가 정하지 않았으므로 최소 2개로 두고 보고**한다(위치는 인스펙터에서 조정). 돌문 사격은 이 이벤트가 일으키고, `AllySupportTriggerLogicSystem`의 돌문 타이머/`IsDestroyed` 폴링은 제거한다(보스 50%용 `HandleBoss50Percent`는 Goal 51까지 유지).
7. **문서**: 06·02·24·25번 및 해당 구현 결과를 새 이름/구조에 맞게 정정.

## 완료 기준 (25번 §5의 1·2·4·5번)
- [ ] 폴더/네임스페이스/스코프 이름이 25번 §10과 같고, 파일 GUID와 씬 참조가 유지된다(이동한 `.meta` GUID 비교, 씬 Missing Script 0 · Missing Reference 기존 1건 불증가). LifetimeScope 이름 변경이 불가하면 사유와 함께 보고.
- [ ] 이벤트 SO 에셋만 추가해 새 약 이벤트(테스트용)를 동작시킬 수 있다 — 시퀀서 코드 수정 없이 `OnEventStarted/Completed`와 동작 실행 확인.
- [ ] 돌문 이벤트: 씬 시작 시 NPC들이 길을 막고 돌문에 투사체를 쏜다(발사 간격이 이벤트 SO 값) → 돌문 파괴 → 이벤트 완료(1회) → 사격 중단 → NPC들이 비켜설 위치로 이동 → 플레이어가 통과 가능(NPC 위치 변화와 플레이어 통과를 라이브로 확인). 시퀀서 밖 타이머/폴링이 없다.
- [ ] 이벤트 SO의 수치(사격 주기, 비켜설 위치/속도)를 바꾸면 실제 동작이 바뀐다(원복). 코드에 이벤트 수치 하드코딩이 없다.
- [ ] 보스 50% 이벤트 기존 동작 회귀 없음(성공/실패 각 1회). 돌문 샷 값(속도·데미지)은 변경 없음.
- [ ] 컴파일 에러 0(DLL mtime 교차), 콘솔 에러 0(Animator `Hash 468800000` 기존 경고 제외), md5 불변.

## 검증 절차 (이벤트·반복은 필요한 만큼만)
수정 전 상태 기록 → 구현 → recompile + recompile_status + 어셈블리 mtime 교차 → 콘솔 에러 0. 돌문 파괴는 실제 경로(시간 정지 + 마법 투사체 명중, 불가하면 API로 데미지 부여). QA는 개발과 분리해 독립 재측정하고, 한계(하드웨어 마우스/실제 입력)를 명시한다.

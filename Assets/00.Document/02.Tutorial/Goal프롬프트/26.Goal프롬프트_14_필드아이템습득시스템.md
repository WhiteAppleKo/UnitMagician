## Goal
바닥에 떨어진 아이템을 줍는 것으로 마법(`PureDataUnit`)을 습득하는 정식 경로를 만든다. 아이템은 모두 같은 외형이고, 가까이 가면 "[E] 줍기" 프롬프트가 뜨며, 키를 누르면 습득(소유, 자동 장착 아님)되고 아이템이 사라진다. 튜토리얼 시작 지점 근처에 얼음(Temperature)·크기 확대(Mass) 아이템을 배치한다.

## 범위
### 포함
1. 신규 폴더 `Assets/02.System/13.PickupSystem/`(기획서 §4 구조): `PickupSystemLifetimeScope.cs`(루트), `00.Data/RuntimeDataPickupFocus.cs`, `01.Logic/PickupLogicSystem.cs`(+필요한 인터페이스), `02.Visualizer/`(`IPickupTarget`, `PickupItemComponent`, `PickupDetectorComponent`, `PickupPromptUIComponent` + UXML).
2. `InputReader.cs`에 `onInteractPressed` 추가(임시 키 `E`, `I`/`T`/`Esc` 폴링과 같은 패턴).
3. `PickupLogicSystem`: 근접 판정 결과(`RuntimeDataPickupFocus.CurrentTarget`)와 입력으로 줍기 처리. 입력 컨텍스트가 `Player`일 때만 허용(`Tactical`/`UI`/`Event`에서는 무시). 이미 소유한 마법의 아이템은 줍기 대상에서 제외. `AcquireUnit` 호출 → `target.Consume()`. 자동 장착 금지.
4. `PickupDetectorComponent`(플레이어 근접 판정, 반경 조정 가능), `PickupItemComponent`(씬 아이템, `PureDataUnit GrantedUnit` 직렬화, `Consume()`은 비활성화), `PickupPromptUIComponent`("[E] 줍기", `OnFocusChanged` 구독).
5. 공통 외형의 바닥 아이템 프리팹 하나(종류 구분 없음, 간단한 발광 구체 정도로 충분).
6. 씬 배치/배선: 튜토리얼 시작 지점 근처에 Temperature·Mass 마법 `PureDataUnit` 에셋을 부여하는 `PickupItemComponent` 오브젝트 2개 배치, 신규 스코프/UI 컴포넌트 씬 배선(`unity` CLI 라이브 편집 후 `save_scene`). `IUnitCatalogService`/`IInputContextManager`는 인터페이스로만 접근하고 스코프 간 접근이 직접 주입으로 안 되면 기존 크로스 스코프 패턴(인스펙터 직접 참조 + `Start()` 사후 `BindXxx`)을 재사용한다.

### 제외
- 튜토리얼 조작 안내 UI, 줍기 키 최종 확정, 아이템 외형/이펙트/효과음 디테일, 리스폰, 저장/불러오기, 마법 외 아이템.
- `UnitSystem`의 기존 파일 변경(`UnitDebugAcquireTestComponent` 포함) — 변경하지 않는다.

## 완료 기준 (기획서 §5)
- [ ] 아이템 반경 진입 시 프롬프트가 뜨고 벗어나면 사라지며, 여러 아이템이면 가장 가까운 것이 대상이 된다.
- [ ] 일반 플레이에서 `E`로 줍으면 `IsPossessed == true`/`IsEquipped == false`가 되고, 아이템이 사라지며, 기존 습득 팝업이 뜨고, 인벤토리에 "미장착"으로 보인다.
- [ ] 이미 소유한 마법의 아이템에는 프롬프트도 줍기도 일어나지 않는다.
- [ ] `Tactical`(시간정지)/`UI`(메뉴)/`Event`(이벤트 연출) 컨텍스트에서는 `E`를 눌러도 줍지 않는다.
- [ ] 모든 바닥 아이템이 같은 외형이다.
- [ ] 얼음·크기 확대 두 마법을 주워 인벤토리에서 장착하면 기존 시전 흐름(1단계 퍼즐)을 진행할 수 있다.
- [ ] 숫자키 테스트 습득, 인벤토리 장착/해제, 시간정지 선택 팝업, Option/Inventory 메뉴에 회귀가 없다.
- [ ] 폴더 구조가 기획서 §4와 일치하고 DLV/VContainer 규칙을 준수한다.

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 DLL 함정). `clear_console` 후 `console --level error` 0건.
2. Play Mode(`Time.frameCount`가 멈추면 `editor_focus`, 안 되면 리플렉션 직접 호출): VContainer 컨테이너에서 `PickupLogicSystem`/`RuntimeDataPickupFocus`/`IUnitCatalogService`를 Resolve해 근접 판정(플레이어 위치 이동), 줍기, 소유 중 아이템 제외, 컨텍스트별 차단(`PushContext`로 `Tactical`/`UI`/`Event` 상태 만들기)을 실측한다. 프롬프트 UI(`display`/텍스트)와 습득 팝업 표시도 UI 트리로 확인한다. 가능하면 실제 `E` 키 입력 경로(`InputReader.onInteractPressed` 호출)로 한 번 재현한다.
3. `git diff --stat`/`git status`로 범위 확인(이전 세션 미커밋분은 구분).

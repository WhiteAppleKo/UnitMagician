## Goal

기존 `ICharacterStatService`/`RuntimeStatData`(`Assets/02.System/02.CharacterSystem/`)에 **무적 플래그**(`IsInvincible`)와 **마나 무제한 오버라이드**(`IsManaUnlimited`) 두 가지 상태를 추가한다. 둘 다 "피격/마나소모 판정 자체는 정상적으로 발생하되, 실제 HP/MP 실값 변경만 무효화"하는 방식으로 구현한다(08번 기획서 8.2/8.8절 — 특히 무적은 `InteractionSystem`의 피격 파이프라인 `HitContext` 누적에는 전혀 개입하지 않고, `ICharacterStatService.TakeDamage` 내부에서만 HP 변경을 막아야 한다).

## 배경 (조사로 확인된 현재 상태)

- `Assets/02.System/02.CharacterSystem/00.Data/RuntimeStatData.cs` — `hp`/`mp`(`ClampValueInt`), `IncreaseHP`/`ReduceHP`/`IncreaseMP`/`TryConsumeMP` 메서드, `CurrentFaction` setter처럼 "값이 바뀔 때만 이벤트 발행"하는 기존 패턴이 이미 있음(`OnFactionChanged` 참고 — 이번에 추가할 `OnInvincibleChanged`/`OnManaUnlimitedChanged`도 이 패턴을 그대로 따를 것).
- `Assets/02.System/02.CharacterSystem/01.Logic/ICharacterStatService.cs` / `CharacterStatSystem.cs` — `TakeDamage(int)`가 `runtimeData.ReduceHP(amount)`를, `UseMP(int)`가 `runtimeData.TryConsumeMP(amount)`를 그대로 호출하는 얇은 wrapper 구조.
- **[정정, 최초 작성 시 판단 오류]** `Assets/02.System/02.CharacterSystem/03.UI/CharacterHUDUIView.cs` — 기존에 `statSystem.RuntimeData.MP.OnValueChanged`를 구독해 `mpBar.style.width`를 갱신 중. 이 문서는 최초 작성 시 "`MP.OnValueChanged`가 발생하지 않으니 UI 코드 수정 없이 게이지가 고정된다"고 서술했으나, 이는 **오버라이드가 항상 MP 100% 상태에서 켜진다는 잘못된 전제**였다. 실제로는 06번 시퀀서가 "보스 HP 50% 도달" 시점에 오버라이드를 켜는데, 그 시점의 플레이어 MP는 전투 중 이미 일부 소모된 **부분값일 가능성이 높다** — 이 경우 `TryConsumeMP` 호출이 스킵되어 `OnValueChanged`가 안 터지는 건 맞지만, 그 결과 게이지는 "그 순간의 부분값에 고정"될 뿐 "가득 찬 상태"가 되지 않는다. 08번 기획서 8.4절이 요구하는 "HUD 마나 게이지가 **항상 가득 찬 상태 유지**"를 만족하려면, `CharacterHUDUIView`가 `OnManaUnlimitedChanged`를 구독해 true인 동안 `mpBar.style.width`를 실제 값과 무관하게 100%로 강제 표시해야 한다(기획서 8.8/8.9절이 원래 요구한 그대로) — **실제 MP 실값은 건드리지 않고 표시만 강제**하는 것이므로 8.2의 "실값은 변경 안 됨" 요구사항과 충돌하지 않는다.
- **보스 전용 무적 이펙트(방패 아이콘 등, 08번 기획서 8.4/8.9절)는 이번 작업 범위에서 제외한다** — 보스 AI 시스템(03번)이 아직 미구현 상태라 무적 이펙트를 표시할 보스 비주얼라이저 자체가 존재하지 않는다. 이번 작업은 `RuntimeStatData.OnInvincibleChanged` 이벤트를 노출하는 데까지만 책임지며, 실제 시각 연출 구독은 03번 구현 시점에 이어붙인다.

## 범위

### 포함
1. **`RuntimeStatData`에 신규 필드/메서드/이벤트 추가**:
   - `private bool isInvincible;` / `public bool IsInvincible => isInvincible;`
   - `private bool isManaUnlimited;` / `public bool IsManaUnlimited => isManaUnlimited;`
   - `public event Action<bool> OnInvincibleChanged;` / `public event Action<bool> OnManaUnlimitedChanged;`
   - `public void SetInvincible(bool value)` — 값이 바뀔 때만 `isInvincible` 갱신 후 `OnInvincibleChanged?.Invoke(value)` 발행(변화 없으면 조기 반환, `CurrentFaction` setter와 동일 패턴).
   - `public void SetManaUnlimited(bool value)` — 위와 동일한 패턴으로 `OnManaUnlimitedChanged` 발행.
2. **`ICharacterStatService`에 메서드 추가**: `void SetInvincible(bool value);` / `void SetManaUnlimited(bool value);`
3. **`CharacterStatSystem` 수정**:
   - `SetInvincible`/`SetManaUnlimited` 구현 — `runtimeData.SetInvincible(value)`/`runtimeData.SetManaUnlimited(value)`로 위임.
   - `TakeDamage(int amount)` 수정 — `if (runtimeData.IsInvincible) return;`을 `ReduceHP` 호출 **이전**에 추가(피격 파이프라인 쪽 `HitContext` 기록에는 영향 없음 — 이 메서드가 호출되는 시점 자체는 그대로 유지되고, 내부 HP 변경만 스킵되므로 08번 기획서 8.2절의 "피격 판정은 정상, 데미지 판정만 무효화" 요구사항을 그대로 만족).
   - `UseMP(int amount)` 수정 — `if (runtimeData.IsManaUnlimited) return true;`를 `TryConsumeMP` 호출 **이전**에 추가.
4. **`PureStatData`는 변경하지 않는다** — 두 오버라이드는 런타임 전용 상태이며 SO에 굽지 않는다(08번 기획서 8.9절).
5. **`CharacterHUDUIView` 수정** — `OnManaUnlimitedChanged` 구독 추가. `true` 수신 시 `mpBar.style.width = Length.Percent(100f)`로 강제 고정(실제 `mp.CurrentValue`는 건드리지 않음), `false` 수신 시 즉시 `UpdateMPUI(statSystem.RuntimeData.MP.CurrentValue, statSystem.RuntimeData.MP.MaxValue)`를 호출해 실제 값 기준으로 정상 갱신(오버라이드 해제 직후 게이지가 실제 값으로 즉시 복귀해야 함 — 08번 기획서 8.9절 [V] 03.UI 항목).

### 제외 (이번 작업 범위 아님)
- 보스 전용 무적 이펙트/아이콘 시각 연출(03번 보스AI 구현 시점에 `OnInvincibleChanged` 구독으로 이어붙임) — 이번 작업은 이벤트 노출까지만.
- `SetInvincible`/`SetManaUnlimited` 호출 주체를 03번/06번으로 제한하는 컴파일 타임 접근 제어 메커니즘(08번 기획서 8.9절이 이미 "다루지 않는다"고 명시) — 이번 작업에서 임의로 설계하지 않는다.
- 03번(보스AI)/06번(이벤트시퀀서) 시스템 자체의 구현 — 이번 작업은 08번 시스템 단독으로, 두 API를 호출할 향후 소비자가 없어도 컴파일·동작 가능해야 한다.

## 완료 기준 (Definition of Done)

- [ ] `RuntimeStatData`에 `IsInvincible`/`IsManaUnlimited` 프로퍼티, `SetInvincible`/`SetManaUnlimited` 메서드, `OnInvincibleChanged`/`OnManaUnlimitedChanged` 이벤트가 추가되고 컴파일 에러 없음
- [ ] 값이 실제로 바뀔 때만 이벤트가 발행됨(같은 값으로 재호출 시 이벤트 미발행) — `CurrentFaction` setter와 동일한 변경 감지 패턴 준수
- [ ] `ICharacterStatService`/`CharacterStatSystem`에 `SetInvincible`/`SetManaUnlimited`가 추가되고, 내부적으로 `RuntimeStatData`의 대응 메서드에 위임됨
- [ ] `SetInvincible(true)` 상태에서 `TakeDamage(int)`를 호출해도 `RuntimeStatData.HP.CurrentValue`가 변하지 않음(08번 기획서 8.6 체크리스트 1번째·데이터흐름근거 항목)
- [ ] `SetManaUnlimited(true)` 상태에서 `UseMP(int)`를 호출하면 `true`를 반환하고 `RuntimeStatData.MP.CurrentValue`가 변하지 않음(08번 기획서 8.6 체크리스트 2번째·데이터흐름근거 항목)
- [ ] 오버라이드가 `false`인 평소 상태에서는 `TakeDamage`/`UseMP`가 기존과 동일하게 동작함(회귀 없음 — 08번 기획서 8.6 예외 체크리스트)
- [ ] `CharacterHUDUIView`가 `OnManaUnlimitedChanged`를 구독해, MP가 부분값인 상태에서 오버라이드를 켜도 `mpBar`가 즉시 100%로 표시되고, 해제 시 실제 MP 값 기준으로 즉시 복귀함
- [ ] `PureStatData`는 수정되지 않음(범위 제외 항목 그대로 유지됨을 diff로 확인)
- [ ] `RuntimeStatData`/`CharacterStatSystem`이 `MonoBehaviour`/`Transform`/`Collider` 등 구체 타입을 직접 참조하지 않음(DLV 준수, 기존 코드 스타일 그대로 유지)

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` "completed, no errors"까지 폴링, `Assembly.GetAssembly(type).Location` mtime과 소스 mtime 비교로 재확인(단정 금지 — 기록된 함정, `project_unity_pipeline_recompile_gotcha` 참고).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `unity command console --level error`로 에러 0건.
3. **기능 검증 (`unity eval`/Play Mode)** — 씬에 이미 존재하는 캐릭터(예: 플레이어 또는 `EnemyTest`)의 `ICharacterStatService` 인스턴스를 대상으로 검증(보스 인스턴스가 아직 없으므로 대체 검증 대상으로 충분 — 로직 자체가 인스턴스 무관 일반 동작임):
   - 시나리오 A(무적 HP 차단): `SetInvincible(true)` 호출 → `TakeDamage(30)` 호출 → `RuntimeData.HP.CurrentValue` 불변 확인.
   - 시나리오 B(무적 해제 회귀): 같은 인스턴스에 `SetInvincible(false)` 호출 → `TakeDamage(30)` 호출 → HP가 정상적으로 30 감소함을 확인.
   - 시나리오 C(마나 무제한): `SetManaUnlimited(true)` 호출 → `UseMP(9999)`(현재 MP보다 큰 값) 호출 → 반환값 `true` 확인 + `RuntimeData.MP.CurrentValue` 불변 확인.
   - 시나리오 D(마나 무제한 해제 회귀): `SetManaUnlimited(false)` 호출 → `UseMP(9999)` 호출 → 반환값 `false`(부족) 확인 + `OnInsufficientMana` 이벤트 발행 확인(기존 동작 유지).
   - 시나리오 E(이벤트 발행 확인): `OnInvincibleChanged`/`OnManaUnlimitedChanged`에 임시 델리게이트를 걸어, 같은 값으로 두 번 연속 `Set...` 호출 시 이벤트가 1회만 발행되는지 확인.
   - 시나리오 F(HUD 부분값 고정 확인, Play Mode 필요): MP를 일부러 소모시켜 부분값(예: 최대치의 절반 이하)으로 만든 뒤 `SetManaUnlimited(true)` 호출 → HUD의 `mpBar.style.width`가 실제 `mp.CurrentValue`와 무관하게 100%로 표시되는지 확인 → `SetManaUnlimited(false)` 호출 → `mpBar`가 실제 부분값 기준으로 즉시 복귀하는지 확인(정정 전 설계의 허점을 검증하는 핵심 시나리오).
4. **DLV 준수 자체 점검**: `RuntimeStatData.cs`/`CharacterStatSystem.cs` 소스에 `UnityEngine.Transform`/`Collider`/`ParticleSystem` 등 구체 타입 참조가 신규로 추가되지 않았는지 확인(기존 `UnityEngine` using은 `Mathf`/`Debug`/`JsonUtility`용이라 그대로 둠). `CharacterHUDUIView.cs`는 MonoBehaviour/UI Toolkit 코드이므로 이 규칙 대상이 아님.
5. **범위 확인**: `git status`/`git diff --stat`로 이번 작업이 `PureStatData.cs`, `02.Visualizer/` 하위 파일 등 범위 밖 파일을 건드리지 않았는지 확인(`CharacterHUDUIView.cs`는 이번 정정으로 수정 대상에 포함됨).

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

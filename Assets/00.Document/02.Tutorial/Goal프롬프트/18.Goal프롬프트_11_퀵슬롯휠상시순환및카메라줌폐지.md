## Goal

사용자 지적: "카메라 확대 축소는 필요없어 퀵슬롯 순환이 휠로돌아가야하고 시간정지 상태에서는 별도의 UI를 제공할거임."

1. 마우스 휠은 **컨텍스트와 무관하게 항상** 장착된 유닛(퀵슬롯) 순환에 사용된다 — 기존의 `Tactical` 컨텍스트 한정 게이트를 제거한다. 단, `UIContext`(인벤토리/옵션 메뉴가 열린 상태)에서는 계속 막는다.
2. 카메라 줌(휠로 확대/축소하는 기능) 자체를 폐지한다 — 휠 입력이 카메라 줌에 반영되지 않도록 한다.
3. 시간정지 상태 전용 UI는 이번 범위 밖(설계·구현하지 않음).

## 배경 (조사로 확인된 현재 상태)

- `Assets/02.System/01.UnitSystem/01.Logic/UnitQuickSlotLogicSystem.cs`의 `HandleMouseWheelScrolled(float)`(119~131행): `contextManager.CurrentContext.ContextType != Tactical`이면 조기 반환 → Tactical 컨텍스트(시간정지 또는 락온 중, `TacticalCommandLogicSystem`/`PlayerLockOnController` 둘 다 같은 `TacticalContext`를 Push)일 때만 `CycleSlot(direction)` 호출.
- `Assets/02.System/00.Movement/01.Logic/01.CameraMovement/CameraFollowService.cs`: `HandleMouseWheelScrolled(float scrollY)`(144~147행)가 `m_accumulatedWheelDelta`에 누적하고, `LateTick()`(149~197행)이 이를 읽어 `wheelDelta`로 `UpdateCameraOffset`에 전달 → `UpdateCameraOffset`(199행~) 253~258행에서 `m_targetZoomRatio`를 조정. 191~194행에 이미 "Tactical 컨텍스트에서는 줌에 반영 안 함" 처리가 있음 — 이번엔 Tactical 여부와 무관하게 **항상** 줌에 반영하지 않도록 바꾼다.
- 두 클래스 모두 같은 `InputReader.onMouseWheelScrolled` 이벤트를 구독하는 구조이므로, 한쪽 게이트를 없애면 다른 쪽도 반드시 같이 손봐야 휠 입력이 두 시스템에서 동시에 충돌하지 않는다.

## 범위

### 포함
1. **`UnitQuickSlotLogicSystem.cs` 수정** — `HandleMouseWheelScrolled`의 조기 반환 조건을 `ContextType != Tactical` → `ContextType == UI`로 변경(즉 UI 메뉴가 열려 있을 때만 막고, 그 외에는 Player/Tactical/Event 등 어떤 컨텍스트든 항상 순환). `Tick()`의 `InputReader` 미주입 폴백 스크롤 처리(162~174행)도 동일한 조건으로 맞출 것.
2. **`CameraFollowService.cs` 수정** — 휠 입력이 줌에 반영되는 경로를 제거. 방법은 구현 시 선택하되(예: `LateTick()`에서 wheelDelta를 항상 0으로 고정, 또는 `HandleMouseWheelScrolled` 구독 자체를 제거), `m_currentZoomRatio`가 `defaultZoomRatio`로 고정되어 더 이상 변하지 않아야 한다. `CurrentZoomSize`/`OnZoomSizeChanged` 등 다른 코드가 참조하는 퍼블릭 API는 그대로 두되(구현 전 grep으로 참조 여부 확인), 값 자체가 더 이상 휠로 바뀌지 않게만 만든다.
3. Play Mode 라이브 검증으로 두 변경이 서로 충돌 없이 동작하는지(휠을 돌리면 항상 퀵슬롯만 바뀌고 카메라 거리/FOV는 고정) 확인.

### 제외 (이번 작업 범위 아님)
- 시간정지 상태 전용 UI 설계/구현 — 사용자가 "나중에 제공할 것"이라고만 밝힘, 이번엔 손대지 않는다.
- 카메라 줌 관련 필드/프로퍼티의 완전 삭제 — 참조가 남아 있으면 값만 고정하고 API 자체는 유지.
- 퀵슬롯/카메라 시스템의 다른 부분(락온, 조준 연출 등) — 변경 없음.

## 완료 기준 (Definition of Done)

- [ ] 평상시(Player 컨텍스트, 락온도 시간정지도 아닌 상태)에 마우스 휠을 돌리면 장착된 유닛이 순환 선택된다(`RuntimeDataUnitQuickSlot.SelectedUnit`/`SelectedSlotIndex` 변경 확인).
- [ ] 락온 중이나 시간정지 중(Tactical 컨텍스트)에도 기존처럼 휠로 퀵슬롯이 순환된다(회귀 없음).
- [ ] 인벤토리 또는 옵션 메뉴가 열린 상태(`UIContext`)에서는 휠을 돌려도 퀵슬롯이 바뀌지 않는다.
- [ ] 어떤 상태에서도 마우스 휠이 카메라 확대/축소(FOV 또는 거리 변화)를 더 이상 유발하지 않는다.
- [ ] 카메라 회전(마우스 이동), 락온, 시간정지, Option/Inventory 메뉴 토글 등 기존 기능에 회귀가 없다.
- [ ] 신규/수정 코드가 DLV/VContainer 규칙을 위반하지 않는다(인터페이스 주입만 사용, `GameObject.Find`/`FindObjectOfType` 없음).

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(Play Mode / `unity eval`)**:
   - 시나리오 A(평상시 휠 순환): Player 컨텍스트에서 휠 스크롤 시뮬레이션(또는 `HandleMouseWheelScrolled`/`CycleSlot` 직접 호출) → `SelectedUnit` 변경 확인.
   - 시나리오 B(Tactical 회귀 없음): 락온 또는 시간정지 진입 후 휠로 순환 → 기존과 동일하게 동작 확인.
   - 시나리오 C(UI 차단): 인벤토리/옵션 메뉴 연 상태에서 휠 스크롤 → `SelectedUnit` 불변 확인.
   - 시나리오 D(줌 폐지): 아무 상태에서나 휠 스크롤 후 `ICameraFollowService.CurrentZoomSize`(또는 실제 카메라 FOV/거리)가 변하지 않는지 확인.
   - 시나리오 E(회귀): 카메라 회전, 락온 토글, 시간정지(T), Option(Escape)/Inventory(I) 메뉴가 정상 동작하는지 확인.
4. **범위 확인**: `git diff --stat`로 `UnitQuickSlotLogicSystem.cs`, `CameraFollowService.cs`에 한정되고 다른 시스템은 무변경인지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

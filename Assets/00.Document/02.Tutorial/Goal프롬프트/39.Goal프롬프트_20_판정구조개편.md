## Goal
돌문과 3단계 보스의 성공 판정을 "속성 게이트 + 크기 게이트 + 최종 데미지"를 각각 개별 확인하는 같은 구조로 통일한다. 예약돼 있던 `HitStepFlags.SizeGate` 비트와 `SizeGateStep`을 추가하고 `DamageContext`에 게이트 통과 결과를 기록한다.

## 범위
### 포함
1. **조사 먼저**: `AttributeGateStep`, `CombatPipelineManager`(정준 순서), `DamageContext`, `ApplyDamageStep`, `IDamageable`, `DestructibleDoorLogicSystem`/`DestructibleDoorComponent`/`PureDataDestructibleDoor`, `TutorialSequencerLogicSystem.HandleDamageProcessed`/`PureDataTutorialSequence`, `BossPhaseLogicSystem`(회복 페이즈 플래그 전환), 보스 오브젝트의 컴포넌트 구성을 읽고 기획서 §3~§4와 다른 점이 있으면 구현 전에 보고한다.
2. **파이프라인(§3-1, §3-2)**: `HitStepFlags.SizeGate = 1<<3`, `CombatPipelineManager` 정준 순서에 `AttributeGate → SizeGate → Evasion → Defense`로 등록, `SizeGateStep`(`Source`의 질량 비율 vs 피격 대상 `RequiredMassRatio`, **실패해도 `Aborted`는 세우지 않음**, 이미 `Aborted`면 실행 안 함), `DamageContext`에 `AttributeGatePassed`/`SizeGatePassed` 기록(`AttributeGateStep`도 결과 기록, 기존 중단 동작 유지). `AttributeGateStep`의 온도 기준은 코드의 "0 미만" 하드코딩을 제거하고 피격 대상의 `RequiredMaxTemperature`(미만이어야 통과)를 읽는다. `IGateRequirementProvider`(`RequiredMaxTemperature`, `RequiredMassRatio` 제공; 없으면 해당 게이트 요구 없음 → 통과)·`IGateAwareDamageable`(컨텍스트를 받는 선택 인터페이스, `ApplyDamageStep`이 구현체에는 컨텍스트 전달·아니면 기존 호출) 추가. **모든 게이트 요구값은 PureData(ScriptableObject)에서 읽고 코드에 숫자를 박지 않는다.**
3. **돌문**: `PureDataDestructibleDoor`에 `requiredMaxTemperature`(기본 0)/`requiredMassRatio`(기본 1.5), 플래그 `AttributeGate | SizeGate`, `DestructibleDoorComponent`가 `IGateRequirementProvider`/`IGateAwareDamageable` 구현. 판정: `AttributeGatePassed && SizeGatePassed && amount >= hp` → 파괴, 속성은 통과했으나 크기/데미지 부족 → 금 갔다 복구, 속성 실패(`Aborted`) → 기존 스파크(데미지 미적용).
4. **3단계 보스**: `PureDataTutorialSequence`에 `requiredMaxTemperature`(기본 0)/`requiredMassRatio`(기본 1.5), 보스의 요구값 제공(`IGateRequirementProvider` 구현 위치는 개발이 선택해 보고), `BossPhaseLogicSystem`이 회복 페이즈 진입/해제 시 `AttributeGate | SizeGate` 비트를 추가/제거(+`Evasion|Defense` 제외/복원 — 기존 동작 유지). `TutorialSequencerLogicSystem.HandleDamageProcessed`: `AttributeGatePassed && SizeGatePassed && FinalDamage >= CoreHitRequiredDamage`이면 성공, 아니면 실패(이벤트 투사체 명중 한정은 그대로).
5. **로그**: 판정 시 실패한 게이트(속성/크기/데미지)를 한 줄 로그로 남긴다(연출 변경 없음).

### 제외 (건드리지 않는다)
- 새 마법/속성 종류, `DefenseStep`과 게이트의 상호작용, 연출 변경, 범위 마법 예외, 중립 NPC 적대화(Goal 40), 크리티컬, 마법 UI.

## 완료 기준 (기획서 §5)
- [ ] 얼음 아님: 돌문 스파크만(`ApplyDamage` 미호출)·보스 결정타 실패, 컨텍스트 `AttributeGatePassed=false`.
- [ ] 얼음만(질량 ×1): `AttributeGatePassed=true, SizeGatePassed=false` → 돌문은 금 갔다 복구(파괴 안 됨, 20회 반복), 보스 결정타 실패, 로그에 크기 게이트 실패.
- [ ] 크기만: 속성 게이트에서 중단 — 돌문 스파크, 보스 실패.
- [ ] 얼음+크기(×2, 요구 1.5, 데미지 기준 100): 돌문 `DESTROYED`, 보스 `OnCoreHitSuccess`(새 Play 세션 반복 10회 이상 일관, `FinalDamage` 120).
- [ ] 요구 질량 비율을 PureData에서 올리면(예: 3.0) ×2 얼음+크기가 크기 게이트 실패로 돌문/보스 모두 실패하고, 낮추거나 데미지 기준을 올려도 각각 해당 게이트 사유로 실패한다(코드 수정 없이 인스펙터 값만으로 변경; 검증 후 원복, 디스크에 임시 값 없음).
- [ ] 요구 최대 온도 값을 PureData에서 바꾸면(예: 기존 Frost −15 대비 −20) 속성 게이트 결과가 코드 수정 없이 바뀐다. 게이트 판정 코드(`AttributeGateStep`, `SizeGateStep`, 돌문/보스 판정)에 요구값 숫자(0 온도 기준, 1.5, 100 등)가 없다(grep).
- [ ] `IGateRequirementProvider`가 없는 대상은 크기 게이트가 통과로 기록되어 일반 캐릭터 피격 동작이 변하지 않는다. 13~19 회귀(3단계 전환점 발동, 재도전, 이벤트 중 차단, 풀링, 보스 회복 페이즈 플래그 전환/원복, 컨텍스트 스택 Player 복귀), 콘솔 에러 0건.
- [ ] DLV/VContainer 규칙, 기획서 §4 경로 준수.

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 DLL 주의). `clear_console` 후 `console --level error` 0건.
2. Play Mode 실측(각 마법 조합을 실제 `ExecuteBatchCast`/`ChangeUnit` 경로로 적용; 3단계는 새 Play 세션 반복 — 성공 시 보스가 사망하므로). 입력 주입이 필요한 항목은 Game 뷰 포커스 후 `InputSystem.QueueStateEvent`, 안 되면 UNVERIFIED로 명시.
3. `git diff --stat`/`git status`로 범위 확인(이전 세션 미커밋분과 구분).

## Goal

여러 시스템(보스AI/아군NPC/카메라/시간정지/캐릭터스탯)을 직접 참조 없이 신호로 느슨하게 결합시키는 **범용 상태 머신 + 이벤트 방송 프레임워크**를 구현한다. 이 시스템 자체는 화면에 아무것도 그리지 않으며(6.4/6.7절), "보스 HP 50% 도달"과 "결정타 성공/실패"를 판정해 `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail` 세 신호를 방송하는 것까지만 책임진다.

## 배경 (조사로 확인된 현재 상태 + 이번 작업의 전제)

- `Assets/02.System/02.CharacterSystem/00.Data/RuntimeDataPlayerState.cs` + `01.Logic/PlayerStateLogicSystem.cs` — 06번 기획서 6.2/6.8절이 지정한 참고 패턴(상태 머신 + `event Action<T>` 방송, private set + 변경 메서드). 이번 신규 클래스들은 이 구조를 그대로 따른다.
- `Assets/02.System/02.CharacterSystem/01.Logic/ICharacterStatService.cs`의 `RuntimeData.HP`(`IReadOnlyClampValueInt`, `OnValueChanged` 이벤트 보유), `IsInvincible`(직전 08번 작업에서 이미 구현 완료) — 이번 작업이 그대로 재사용.
- **[정정, 최초 작성 시 확인 누락]** `Assets/02.System/03.InteractionSystem/01.Logic/InteractionSystem.cs`(구체 클래스)에는 `OnDamageProcessed` 이벤트가 실제로 존재하지만, `IInteractionService.cs`(인터페이스)에는 선언돼 있지 않았다(개발 착수 중 발견). VContainer_가이드라인상 구체 클래스 직접 주입은 금지이므로, `IInteractionService.cs`에 `event Action<DamageContext> OnDamageProcessed;` 선언을 추가해 인터페이스로 노출하는 작업이 **이번 작업 범위에 포함**된다(기존 구현체 로직은 변경 없음, 인터페이스 멤버 추가뿐). `Assets/PipeLine/Contexts/DamageContext.cs`의 `Victim`(`GameObject`)/`Aborted` 필드는 기획서 설명과 실제 코드가 일치함(확인 완료).
- **보스는 아직 없다(중요, 테스트 방식에 영향)**: 03번(보스AI페이즈시퀀스시스템)이 구현 순서상 이 작업(6번)보다 나중이라, 실제 "보스" GameObject/FSM이 씬에 없다. 06번 기획서 6.9절이 이미 "보스는 씬에서 유일하므로 인스펙터 고정 참조로 충분하다"고 확정해뒀으므로, 이번 작업에서는 **씬에 이미 있는 임의의 캐릭터(예: `EnemyTest`, `CharacterStatComponent`가 붙어있는 아무 오브젝트)를 "보스 참조" 자리에 임시로 꽂아서** 배선과 판정 로직을 구현·검증한다. 실제 보스로 교체하는 작업은 03번 구현 시점에 인스펙터 참조만 바꾸면 되므로 이번 작업의 책임이 아니다.
- **타임아웃 판정 기준값의 출처(이번 작업에서 확정)**: 06번 기획서 6.8절은 "회복 페이즈 지속시간"을 타임아웃 기준으로 언급하지만, 이 값을 정의하는 03번(보스AI)의 `PureDataBossPattern`도 아직 존재하지 않는다. 03번이 구현되기 전까지 이 시스템이 독립적으로 컴파일·동작해야 하므로, 이번 작업에서는 **이 시스템 자신의 작은 `PureDataTutorialSequence`(SO)**를 만들어 `bossHpThresholdRatio(float, 기본 0.5f)`와 `coreHitTimeoutSeconds(float, 기본 10f)` 두 값을 여기에 둔다. 03번이 나중에 구현되면 두 값의 최종 소유권(이 SO에 남길지 03번 것으로 옮길지)은 그때 다시 검토한다 — 지금은 이 시스템이 컴파일·동작 가능한 최소 형태로 자체 보유한다.

## 범위

### 포함
1. **`Assets/02.System/09.EventSequencerSystem/`** 폴더 신규 생성(디스크 확인 결과 현재 최대 번호가 `08.DestructibleSystem`이라 다음은 09 — 착수 직전 `Assets/02.System/` 재확인해서 여전히 09가 맞는지 한 번 더 확인할 것).
2. **`00.Data/TutorialStage.cs`**(enum, 신규) — `Stage1, Stage2, Stage3, Stage4Success, Stage4Fail, Victory`.
3. **`00.Data/PureDataTutorialSequence.cs`**(SO, 신규, 위 "배경" 항목 참고) — `bossHpThresholdRatio(float, 기본 0.5f)`, `coreHitTimeoutSeconds(float, 기본 10f)`.
4. **`00.Data/RuntimeDataTutorialSequence.cs`**(RuntimeData, 신규, `RuntimeDataPlayerState`와 동일한 결) — private set `currentStage`/`previousStage`(`TutorialStage`), 메서드 `ChangeStage(TutorialStage newStage)`(같은 값이면 조기 반환), 이벤트 `OnStageChanged(TutorialStage previous, TutorialStage next)`.
5. **`01.Logic/TutorialSequencerLogicSystem.cs`**(Logic, 신규, 순수 C#, `ITickable`+`IDisposable`) — 생성자 주입: `RuntimeDataTutorialSequence runtimeData`, `PureDataTutorialSequence pureData`, `ICharacterStatService bossStatService`, `IInteractionService interactionService`.
   - 공개 이벤트: `event Action OnBoss50Percent`, `event Action OnCoreHitSuccess`, `event Action OnCoreHitFail`.
   - 생성자에서 `bossStatService.RuntimeData.HP.OnValueChanged += HandleBossHpChanged;`, `interactionService.OnDamageProcessed += HandleDamageProcessed;` 구독.
   - `HandleBossHpChanged(current, max)`: `runtimeData.CurrentStage < Stage3`이고 `current / (float)max <= pureData.BossHpThresholdRatio`이면 `runtimeData.ChangeStage(Stage3)` + `OnBoss50Percent` 방송(6.5절 "이미 처리된 단계 신호 무시" 요구사항 — Stage3 이상이면 재판정하지 않는 방식으로 구현).
   - `HandleDamageProcessed(DamageContext context)`: `context.Victim == bossStatService`가 속한 GameObject이고 `bossStatService.RuntimeData.IsInvincible == true`(08번에서 이미 구현된 필드)인 동안만 판정 — `context.Aborted == false`면 `ChangeStage(Stage4Success)` + `OnCoreHitSuccess`, `context.Aborted == true`면 `ChangeStage(Stage4Fail)` + `OnCoreHitFail`.
   - `Tick()`: `currentStage == Stage3`인 동안 `pureData.CoreHitTimeoutSeconds` 경과를 카운트, 그 안에 `HandleDamageProcessed`로 아무 판정도 나지 않으면 타임아웃으로 `ChangeStage(Stage4Fail)` + `OnCoreHitFail` 방송(빗나간 경우 포함, 6.2절 그대로).
   - `Dispose()`: 위 두 구독 해제.
6. **`EventSequencerSystemLifetimeScope.cs`**(신규, 폴더 루트) — `[SerializeField] private CharacterStatComponent bossStatComponent;`(인스펙터 고정 참조, 6.9절 "보스 참조 방식" 그대로) 필드를 두고, `Configure`에서 `builder.RegisterInstance<ICharacterStatService>(bossStatComponent.StatService)`(또는 동등한 방식)로 이 스코프 내에서만 유효한 바인딩을 만든 뒤 `TutorialSequencerLogicSystem`을 `Register<T>(Lifetime.Scoped).As<ITickable>().As<IDisposable>()`로 등록. `IInteractionService`는 기존 `InteractionSystemLifetimeScope`를 부모로 연결(`ParentReference.Create<InteractionSystemLifetimeScope>()`)해서 주입받는다.
7. 테스트: `00.TestScene`에 이미 배치된 캐릭터(예: `EnemyTest`) 하나를 `bossStatComponent` 자리에 임시로 연결해 배선 검증.

### 제외 (이번 작업 범위 아님)
- 02/03/08/09/10번 시스템이 이 신호들을 실제로 구독해 카메라 전환/시간정지 발동/무적 이펙트 등을 재생하는 것 — 이번 작업은 신호를 "쏘는" 쪽까지만, 받는 쪽은 각 시스템 구현 시점에 이어붙인다.
- 실제 보스 GameObject/FSM 배치 — 03번 구현 시점 작업.
- `bossHpThresholdRatio`/`coreHitTimeoutSeconds`를 03번의 `PureDataBossPattern`으로 이전하는 리팩토링 — 이번 작업 범위 아님(위 "배경" 참고, 나중에 재검토).

## 완료 기준 (Definition of Done)

- [ ] `Assets/02.System/09.EventSequencerSystem/` 폴더 구조가 06번 기획서 6.9절과 정확히 일치하고 컴파일 에러 없음
- [ ] `TutorialStage`/`PureDataTutorialSequence`/`RuntimeDataTutorialSequence`/`TutorialSequencerLogicSystem`이 모두 명시된 폴더에 위치
- [ ] 보스(대체 참조) HP가 임계값(기본 50%) 이하로 처음 떨어지는 순간 `OnBoss50Percent`가 정확히 1회 방송되고, 이후 같은 대상의 HP가 계속 변해도 중복 방송되지 않음
- [ ] 보스(대체 참조)가 `IsInvincible == true`인 상태에서 `Aborted == false`인 피격을 받으면 `OnCoreHitSuccess`가 방송됨
- [ ] 같은 상태에서 `Aborted == true`인 피격을 받으면 `OnCoreHitFail`이 방송됨
- [ ] `IsInvincible == false`(평소 상태)일 때는 어떤 피격이 와도 `OnCoreHitSuccess`/`OnCoreHitFail`이 방송되지 않음
- [ ] Stage3 진입 후 `coreHitTimeoutSeconds` 동안 유효 피격이 없으면 자동으로 `OnCoreHitFail`이 방송됨
- [ ] `TutorialSequencerLogicSystem`이 `MonoBehaviour`/`Transform`/`Collider` 등 구체 타입을 직접 참조하지 않음(DLV 준수)
- [ ] `IInteractionService.cs`에 `OnDamageProcessed` 이벤트 선언이 추가되고, `InteractionSystem.cs`(구현체) 자체는 로직 변경 없이 그대로 인터페이스를 만족함(컴파일 확인)
- [ ] `02.CharacterSystem`, `PipeLine/` 등 그 외 기존 파일은 수정되지 않고, `03.InteractionSystem/01.Logic/IInteractionService.cs` 한 파일만 이번 정정으로 수정됨(신규 폴더 추가 + 이 파일 하나 외 기존 파일 무변경)

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` 폴링 + `Assembly.GetAssembly(type).Location` mtime과 소스 mtime 교차 확인(스테일 함정 주의).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `unity command console --level error`로 에러 0건.
3. **기능 검증 (`unity eval`/Play Mode)** — `EventSequencerSystemLifetimeScope`의 `bossStatComponent`에 씬의 기존 캐릭터(예: `EnemyTest`)를 임시로 연결해두고:
   - 시나리오 A(50% 감지): 대상 HP를 최대치의 51%→49%로 낮추는 시퀀스로 `TakeDamage` 호출 → `OnBoss50Percent` 1회 방송 확인, 이후 추가로 HP를 낮춰도 재방송되지 않음 확인.
   - 시나리오 B(성공 판정): 대상에 `SetInvincible(true)` 호출 후, `Aborted == false`인 `DamageContext`를 만들어 `IInteractionService`를 통해 처리(또는 `OnDamageProcessed`를 직접 invoke) → `OnCoreHitSuccess` 방송 확인.
   - 시나리오 C(실패 판정 - 게이트): 같은 무적 상태에서 `Aborted == true`인 `DamageContext`로 처리 → `OnCoreHitFail` 방송 확인.
   - 시나리오 D(무적 아닐 때 무시): `SetInvincible(false)` 상태에서 임의의 `DamageContext`(Aborted 무관)를 처리 → `OnCoreHitSuccess`/`OnCoreHitFail` 둘 다 미방송 확인.
   - 시나리오 E(타임아웃): Stage3 진입 후 `coreHitTimeoutSeconds`(테스트 편의상 짧은 값으로 임시 조정 가능) 동안 아무 피격도 주지 않고 대기 → 시간 경과 후 `OnCoreHitFail` 자동 방송 확인.
4. **DLV 준수 자체 점검**: `TutorialSequencerLogicSystem.cs`에 구체 타입 직접 참조가 없는지 grep으로 확인.
5. **범위 확인**: `git status`/`git diff --stat`로 `02.CharacterSystem/`, `PipeLine/` 하위 기존 파일이 건드려지지 않고, `03.InteractionSystem/`은 `IInteractionService.cs` 한 파일만(이벤트 선언 추가, `InteractionSystem.cs`는 무변경) 바뀌었으며, 나머지는 `09.EventSequencerSystem/` 신규 파일만 추가됐는지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

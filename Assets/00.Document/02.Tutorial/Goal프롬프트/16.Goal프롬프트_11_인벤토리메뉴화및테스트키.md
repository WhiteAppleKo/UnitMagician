## Goal

인벤토리(`UnitInventoryUIComponent`)를 상시 표시 HUD에서 **`Assets/02.System/04.OptionSystem/02.Visualizer/UI/OptionUIComponent.cs`와 동일한 패턴의 여닫는 메뉴**로 전환한다(키 입력으로 토글, 열리면 시간 정지+UI 입력 컨텍스트, 닫히면 원복). 더불어 지금 소유한 유닛이 1개뿐이라 눈으로 테스트할 게 없으므로, 숫자키로 유닛을 즉시 습득시키는 테스트 전용 컴포넌트를 추가한다.

## 배경 (조사로 확인된 현재 상태 — 재사용할 정확한 패턴)

`OptionUIComponent.cs`가 이 프로젝트의 표준 "여닫는 메뉴" 구현이다. 다음을 그대로 따를 것:
- `InputReader`(`Assets/Synty/AnimationBaseLocomotion/Samples/Scripts/InputSystem/InputReader.cs`)의 `Update()`가 `Keyboard.current.XXX.wasPressedThisFrame`을 폴링해 `Action onXXXToggled`를 발행하는 방식(예: 71~74행 `escapeKey`→`onOptionToggled`, 66~69행 `tKey`→`onTimeSlowToggled`). 이번엔 `iKey`→`onInventoryToggled` 추가.
- `[Inject] Construct(...)`로 `InputReader`(옵션)를 받아 토글 이벤트 구독, `Update()`에 `InputReader == null`일 때의 키보드 직접 폴링 폴백(395~405행, 165~172행 패턴).
- `OpenOption()`/`CloseOption()`(407~457행): 패널 `style.display = DisplayStyle.Flex/None`, `Time.timeScale`을 **정적 참조 카운트**(`s_pauseRefCount`/`s_cachedTimeScale`)로 관리해 다중 인스턴스에도 안전하게 0/원복, `IInputContextManager.PushContext(manager.UIContext)`/`PopContext(...)`.
- `Start()`에서 `CloseOption()` 호출로 기본 닫힌 상태 시작.
- `UnitInventoryUIComponent.cs`(직전 작업에서 클릭 장착/해제 기능이 이미 추가됨)는 그대로 두고 이 여닫기 구조만 씌운다.

## 범위

### 포함
1. **`InputReader.cs`(기존 파일)**: `public Action onInventoryToggled;` 필드 추가, `Update()`에 `Keyboard.current.iKey.wasPressedThisFrame` 체크 후 발행 추가(기존 `tKey`/`escapeKey` 블록과 같은 자리에 나란히).
2. **`UnitInventoryUIComponent.cs`(기존 파일) 확장** — `OptionUIComponent`와 동일한 구조로:
   - `[Inject] Construct(IUnitCatalogService catalogService, IUnitEquipRequirementChecker requirementChecker, InputReader inputReader = null, Common.InputSystem.IInputContextManager contextManager = null)`(기존 시그니처에 `inputReader`/`contextManager` 추가).
   - `ToggleInventory()`/`OpenInventory()`/`CloseInventory()` 메서드(패널 표시 토글 + `Time.timeScale` 정지/복원(이 클래스 전용 정적 참조 카운트, `OptionUIComponent`의 것과는 별개) + `UIContext` Push/Pop).
   - `Start()`에서 `CloseInventory()` 호출(기본 닫힌 상태로 시작 — 지금처럼 상시 표시하지 않음).
   - `InputReader` 미주입 시 `Update()`에서 `Keyboard.current.iKey.wasPressedThisFrame` 폴백.
   - `RefreshInventory()`는 열릴 때(또는 매번 열 때마다) 호출해 최신 상태 반영.
3. **`UnitDebugAcquireTestComponent.cs`(신규, `03.UI/` 또는 적절한 폴더)** — 순수 테스트 편의용. `[SerializeField] private PureDataUnit[] testUnits;`(인스펙터에 4개 정도 배정) + `[Inject] Construct(IUnitCatalogService catalogService)`. `Update()`에서 숫자키 1~4(`Keyboard.current.digit1Key` 등) 입력 시 `testUnits[index]`가 있으면 `catalogService.AcquireUnit(testUnits[index])` 호출 + 콘솔 로그. 클래스/파일명에 "Test"를 명시해 실제 게임 기능이 아님을 드러낸다. 씬에 이 컴포넌트를 붙인 GameObject를 하나 배치하고 `testUnits`에 실제 존재하는 4개 유닛(Mass 2개/Vector/Temperature 등)을 인스펙터로 연결.
4. 씬 배선: 인벤토리 GameObject(`UI Test`)와 신규 디버그 컴포넌트가 올바르게 DI 주입받도록 `UnitSystemLifetimeScope`의 `autoInjectGameObjects` 또는 기존 등록 방식 확인 후 필요시 추가.

### 제외 (이번 작업 범위 아님)
- 장착 조건 스탯 실제 구현 — 여전히 스텁.
- 필드 아이템 픽업 등 정식 습득 트리거 — 3번의 테스트 키가 당분간 대신함.
- Option 메뉴와 Inventory 메뉴 동시 오픈 시 `Time.timeScale` 상호작용 처리 — 알려진 한계로 남김.
- 정확한 열기 키(`I`) 확정 — 나중에 바뀔 수 있는 임시값.

## 완료 기준 (Definition of Done)

- [ ] `I` 키를 누르면 인벤토리 패널이 열리고(`Time.timeScale==0`, `UIContext` 활성), 다시 누르면 닫힌다(`Time.timeScale` 원복, 컨텍스트 pop)
- [ ] 씬 시작 시 인벤토리 패널은 기본적으로 닫혀 있다(상시 표시 아님)
- [ ] 인벤토리가 열려 있는 동안 소유 중인 유닛 클릭으로 장착/해제가 여전히 정상 동작한다(직전 작업 기능 회귀 없음)
- [ ] 숫자키 1~4로 테스트 유닛을 즉시 습득할 수 있고, 습득 직후 인벤토리를 열면 새 아이템이 보인다
- [ ] `InputReader` 미주입 시에도(폴백) 키보드로 토글이 동작한다
- [ ] 기존 `OptionUIComponent`(Escape 키)와 `TimeSlowLogicSystem`(T 키) 동작에 회귀가 없다
- [ ] 신규/수정 코드가 `MonoBehaviour`/`Transform` 등을 DLV 위반 방식으로 다루지 않고(UI 컴포넌트 자체는 MonoBehaviour이므로 해당 없음), `IUnitCatalogService`/`IUnitEquipRequirementChecker`/`IInputContextManager`는 인터페이스로만 주입받는다

2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(`unity eval`/Play Mode)**:
   - 시나리오 A(기본 닫힘): 씬 시작 직후 인벤토리 패널의 `style.display`가 `None`인지 확인.
   - 시나리오 B(토글): `I` 키 입력 시뮬레이션(또는 `onInventoryToggled` 직접 invoke) → 패널 `Flex`, `Time.timeScale==0`, `IInputContextManager.CurrentContext==UIContext` 확인 → 다시 토글 → 전부 원복 확인.
   - 시나리오 C(테스트 습득 키): 숫자키 1 입력(또는 직접 메서드 호출) → 해당 유닛이 `IsPossessed==true`가 되는지 확인.
   - 시나리오 D(장착 회귀): 인벤토리 연 상태에서 클릭으로 장착/해제가 여전히 되는지(직전 QA가 썼던 `ClickEvent` 디스패치 방식 재사용).
   - 시나리오 E(회귀): Option 메뉴(Escape)와 시간정지(T)가 여전히 정상 동작하는지 빠르게 확인.
4. **범위 확인**: `git diff --stat`로 `InputReader.cs`, `UnitInventoryUIComponent.cs`, 신규 `UnitDebugAcquireTestComponent.cs`(+씬 배선)에 한정되고 다른 시스템은 무변경인지 확인.

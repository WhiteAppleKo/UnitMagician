## Goal
같은 편 사이의 물리 충돌 **자체를 레이어 충돌 매트릭스로 없애** 같은 편 투사체가 맞지도 튕기지도 않고 통과하게 하고(아군 샷이 플레이어를 맞히는 문제와 3단계에서 투사체가 플레이어를 지나쳐야 하는 요구를 한 규칙으로 해결), 그 과정에서 목적이 사라지는 `owner` 개념과 기존 충돌 무시 로직 3종을 삭제한다. 마법은 투사체의 **진영**을 시전자 진영으로 바꾼다(적 투사체 빼앗기).

## 범위
### 포함
1. **조사 먼저**: `Physics.IgnoreCollision`/`IgnoreLayerCollision` 호출 전수(코드 전체 grep — 기획서 조사 기준 `CollisionDamageTrigger`, `EventFlightTrackerComponent` 두 곳), `CollisionDamageTrigger`의 owner 관련 코드(`owner`, `initialOwner`, `ignoredOwners`, `SetOwner`, `IgnoreOwnerCollisions`, `IsOwnerOrRelative`, `OnReturnedToPool`/`ResetForReuse`), `UnitChangeService.UpdateCollisionTriggerOwner` 호출부(두 곳), `EventFlightTrackerComponent`의 `ignorePlayerCollision` 관련 코드, `LocomotionLogicSystem.GroundedCheck`(접지/경사/천장 판정, `groundLayerMask`=Default)를 읽고 기획서 §4와 다른 점이 있으면 구현 전에 보고한다.
2. **레이어 정의와 변환(§3-1 레이어 데이터)**: `ProjectSettings/TagManager.asset`에 `BodyAlly`/`BodyEnemy`/`AttackAlly`/`AttackEnemy`를 **8번 이후**에 정의한다(이름 없는 3번은 씬 오브젝트 5개가 이미 쓰므로 사용 금지). `Assets/PipeLine/Combat/FactionLayers.cs`(신규)가 진영→몸체/투사체 레이어 변환(`Player`/`Ally` → `BodyAlly`/`AttackAlly`, `Enemy` → `BodyEnemy`/`AttackEnemy`, `Neutral` → `Default`), 루트+모든 자식 콜라이더 재귀 적용 헬퍼, **시작 시 충돌 매트릭스 1회 설정**(`Physics.IgnoreLayerCollision` — `AttackAlly↔BodyAlly`, `AttackEnemy↔BodyEnemy` 두 쌍만 끔, 편 정의는 `FactionRelation`이 출처)을 담당한다. 매트릭스 설정 호출 위치는 기존 시작 경로에서 가장 단순한 곳(예: `InteractionSystemLifetimeScope` 시작 경로)을 골라 근거와 함께 보고한다. 프로젝트 설정의 충돌 매트릭스를 손으로 바꾸지 않는다.
3. **레이어 적용**: `CharacterStatComponent`가 시작 시와 `RuntimeStatData.OnFactionChanged` 때 자신의 루트+모든 자식 콜라이더를 `FactionLayers`로 갱신한다(플레이어/아군/보스/적). 돌문과 `Neutral`은 `Default` 유지. 투사체는 발사 시 진영 레이어, 진영이 바뀌면(마법) 새 진영 레이어로 루트+모든 자식 콜라이더를 갱신하고, 풀 재사용 시 발사 진영 값/레이어로 복원한다.
4. **진영 변경 마법(§3-2의 3·4, §6 확정 4)**: *(16-A 개발 중 발견: `owner`를 시전자로 바꾸는 호출이 `UnitChangeService.UpdateCollisionTriggerOwner` 외에 `Assets/PipeLine/UnitMagic/Steps/ApplyUnitChangeStep.cs`의 `trigger.SetOwner(context.Caster)`(46·53행 부근)에도 있다. 두 경로 모두 같은 방식으로 `ApplyCasterFaction`으로 대체/삭제하고, 코드 전체에 `SetOwner` 호출이 0건이어야 한다.)* `UnitChangeService.UpdateCollisionTriggerOwner`를 삭제하고 `ApplyCasterFaction`으로 대체한다 — 시전자의 `IFactionProvider.Faction`을 대상 투사체(부모/자식 `CollisionDamageTrigger` 모두, 기존과 같은 탐색 범위)의 진영으로 설정한다. 현재와 같은 범위로 **단위를 바꾸는 모든 마법**이 진영을 바꾼다. `attacker`(발사자)는 바꾸지 않는다.
5. **삭제(§3-2의 5, 5-1)**: `CollisionDamageTrigger`의 `owner` 필드/`SetOwner`/`initialOwner`/`IgnoreOwnerCollisions`/`ignoredOwners`/`IsOwnerOrRelative`/`OnReturnedToPool`의 충돌 쌍 해제(`NpcProjectile.SetActive`의 `SetOwner` 호출 포함, 발사자는 `attacker`로만 존재), `EventFlightTrackerComponent`의 `ignorePlayerCollision` 필드/`HandleProjectileSpawned`의 충돌 쌍 설정/`RestorePlayerCollision`/`projectileIgnoredColliders`·`playerIgnoredColliders`와 씬 `00.TestScene.unity`의 직렬화 값. `HandleCollision`에는 같은 편 판정을 **추가하지 않는다**(충돌 이벤트 자체가 오지 않음). 이벤트 비행 추적/진행도/소실 감지 기능은 그대로 유지한다. 완료 후 코드 전체에 `Physics.IgnoreCollision` 호출이 0건이어야 한다.
6. **회귀 확인(§5의 4-1~4-3)**: 몸체끼리·투사체끼리·투사체↔`Default`(벽/지면/돌문)가 이전과 똑같이 충돌한다(아군 NPC가 플레이어를 몸으로 밀어낼 수 있고, 투사체가 돌문에서 튕김 스파크를 낸다). **지면 판정**(점프/낙하/경사/앉기 해제/평지 서기)이 플레이어를 `BodyAlly`로 옮긴 뒤에도 이전과 같다 — 옮기기 전 자기 캡슐이 접지 구에 걸리는 부작용이 있었다면 그 차이를 보고한다. 락온/조준 탐지(`MagicLockOnComponent`/`NormalCombatLockOnComponent`/`MultiLockOnVisualizer`), 줍기 감지, 광역 빙결 탐지가 새 레이어 대상을 이전처럼 잡는다. 플레이어 좌클릭 락온 등 실제 입력 경로로 확인을 시도한다.

### 제외 (건드리지 않는다)
- 투사체끼리의 충돌 규칙 변경(현재 동작 유지, 투사체 레이어끼리 충돌 켜짐), 충돌 매트릭스의 다른 쌍 변경, 지면 판정 로직/마스크 변경(문제가 확인되면 **보고만** 하고 고치지 않는다 — 사용자 확인 후 별도 처리).
- 중립 NPC 적대화 트리거 규칙, NPC가 길을 막는 씬/이벤트 연출, 범위 마법의 같은 편 예외, `SizeGate`/게이트별 결과 플래그, 구르기 무적, 보스 투사체 존재 이유, 범용 예시 코드 정리.
- `CriticalStep` 등 16-A의 제외 항목.

## 완료 기준 (기획서 §5 해당 항목)
- [ ] (5-3) `CollisionDamageTrigger`에 `owner`/`SetOwner`/`IgnoreOwnerCollisions`/`ignoredOwners`/`IsOwnerOrRelative`가 없고, `UnitChangeService.UpdateCollisionTriggerOwner`, `EventFlightTrackerComponent.ignorePlayerCollision`/`RestorePlayerCollision`이 없다. 코드 전체에서 `Physics.IgnoreCollision` 호출 0건(grep). 투사체가 발사 NPC 자신을 맞히지 않는다.
- [ ] (5-4) 마법을 걸지 않은 아군 샷이 플레이어와 겹쳐도 접촉 이벤트 없이 **궤적이 바뀌지 않고**(튕김/감속 없음) 통과하고 플레이어 HP가 불변이다(반복 20회). 3단계에서 마법을 건 아군 투사체가 플레이어를 지나 보스에 명중해 판정이 정상 처리된다(얼음만/크기만/없음 실패, 얼음+크기 성공, 10회 반복, `ignorePlayerCollision` 없이도). `Physics.GetIgnoreLayerCollision`으로 매트릭스가 규칙표와 일치함을 확인한다(바뀐 쌍은 2개뿐).
- [ ] (5-4-1) 플레이어/아군/보스/투사체의 루트와 **모든 자식 콜라이더**가 진영에 맞는 레이어에 있다(Play Mode에서 계층 전수 확인). 몸체끼리·투사체끼리·투사체↔`Default`는 이전과 똑같이 충돌한다. 풀 재사용된 투사체의 레이어/진영이 발사 값으로 복원돼 있다(이전 사이클에서 빼앗은 진영 잔존 없음).
- [ ] (5-4-2) 지면 판정 회귀 없음(평지 서기, 점프, 낙하, 경사, 앉기 해제 — 이전과 같음, 달라진 점은 보고).
- [ ] (5-4-3) 락온/조준 탐지, 줍기, 광역 빙결 탐지가 이전처럼 동작한다.
- [ ] (5-5) 아군(Ally) 샷이 돌문(Neutral, `Default`)을 맞히면 1·2차 게이트가 기존대로 돈다(얼음만 `cracked but survived`, 얼음+크기 `DESTROYED`). 보스(Enemy) 샷이 플레이어를 맞히면 HP가 감소한다.
- [ ] (5-6) 적(Enemy) 투사체에 플레이어가 마법을 걸면 진영이 `Player`로 바뀌어 `AttackAlly`로 이동(루트+자식 모두) → 플레이어를 통과하며 원래 발사자(적, `BodyEnemy`)를 맞힌다. 풀 반환 후 재사용된 투사체는 발사자 진영/레이어로 시작한다. 검증용으로 NPC `CurrentFaction`을 `Neutral → Enemy`로 바꾸면 몸체가 `Default → BodyEnemy`로 이동한다(검증 후 복원, 디스크에 남기지 않음).
- [ ] (5-9) 같은 편/적대/충돌 레이어 규칙의 출처가 `FactionRelation` 하나다(`FactionLayers`는 변환·적용만, 매트릭스 설정이 `FactionRelation`을 참조).
- [ ] 13~15번 회귀(락온마다 팝업, 전환점 1회 발동, 이벤트 중 차단, 풀링 상한, 컨텍스트 스택 `Player` 복귀), 1단계 돌문 퍼즐, 3단계 판정/재도전에 변화가 없다. 보스 회복(무적) 페이즈 연출 회귀 없음.
- [ ] (5-10) §4 파일 배치와 DLV/VContainer 규칙을 지킨다. 콘솔 에러 0건, 디스크에 임시 코드/수치/테스트 레이어 변경 잔존 없음(`TagManager`에는 기획서 정의 레이어 4개만 추가).

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 DLL 주의). `clear_console` 후 `console --level error` 0건.
2. Play Mode에서 위 완료 기준을 실측한다. `Time.frameCount`가 멈추면 `editor_focus`, 안 되면 Game 뷰 포커스 후 `InputSystem.QueueStateEvent`로 실제 입력을 주입하거나 리플렉션으로 직접 호출한다(안 되는 항목은 UNVERIFIED로 명시). 레이어 계층 전수 확인은 `eval`로 루트/자식 콜라이더의 `gameObject.layer`를 열거한다.
3. `git diff --stat`/`git status`로 범위를 확인한다(이전 세션 미커밋분과 구분, `ProjectSettings/TagManager.asset` 변경이 정의된 레이어 4개뿐인지 확인).

## Goal
마법을 지정하는 동안 (1) 적용되면 대상이 어떻게 바뀔지 **적용 전에** 대상 위에 시각적으로 보여주고, (2) 마나 UI에 이번 발동의 **예상 총비용**을 표시한다.

## 범위
### 포함
1. **적용 전 변화 미리보기**: `LockOnCastEntry`가 추가/제거될 때마다 해당 대상 위에 변화 결과(예: 질량 → 크기 변화, 온도 변화 등 마법이 일으킬 결과)를 표시한다. 한 대상에 마법이 여러 개면 **큐 순서대로 적용한 누적 결과**를 보여준다(같은 종류 마법이 겹치면 나중 것이 덮어쓴 결과). 발동 또는 취소(큐 비움) 시 사라진다. 표현 방식은 구현 단계에서 정한다 — 기존 `UnitGhostPreviewComponent`/`04.VFX/01.Ghost Object`(Ghost Shader)를 재사용해도 되고 다른 표현도 된다. 단, 고스트는 대상마다 하나씩 필요하고 현재 `UnitGhostPreviewComponent`는 한 번에 하나만 만든다는 점(Vector 기즈모에서만 사용 중)을 고려해 대상별 인스턴스 관리 방식을 정한다. 미리보기 계산은 `UnitBatchCastingService.CalculateNewValue`와 동일 규칙을 써서 실제 적용 결과와 일치해야 한다.
2. **마나 UI 예상 총비용**: `RuntimeDataMultiLockOn.PreviewTotalCost`가 0보다 크면 HUD 마나 바에 예상 비용을 표시하고, 현재 마나보다 크면 부족함을 구분해 보여준다(`OnPreviewCostChanged` 구독). 3단계(마나 무제한)에서는 소모가 0이므로 표시하지 않거나 무제한 상태로 표시(구현 시 결정). `CharacterHUDUIView`(`02.CharacterSystem/03.UI`)와 `01.UnitSystem`은 서로 다른 스코프이므로 통신은 인터페이스/RuntimeData 이벤트 경유(`GameObject.Find`/`FindObjectOfType` 금지, 기존 크로스 스코프 패턴 재사용).
3. 미리보기와 마나 표시가 지정 취소(`CancelPending`/`RemoveLastEntry`/`ClearEntries`), 발동 후 큐 비움, 시간정지 종료 시 정리되는지 확인.

### 제외
- 큐 구조 변경(13-A), 이벤트 중 차단/판정 정리(13-B).
- 미리보기의 정교한 연출(애니메이션, 효과음) — "적용 전 변화가 보인다"까지만.

## 완료 기준 (기획서 §5 해당 항목)
- [ ] 마법을 지정할 때마다 해당 대상 위에 적용 전 변화가 표시되고, 한 대상에 마법이 여러 개면 누적 결과가 표시된다. 표시된 결과가 발동 후 실제 적용 결과와 일치한다.
- [ ] 취소/발동/시간정지 종료 후에는 미리보기가 남지 않는다(잔상 없음).
- [ ] 큐가 바뀔 때마다 마나 UI의 예상 총비용이 갱신되고, 현재 마나보다 크면 부족함이 구분된다. 큐가 비면 표시가 사라진다.
- [ ] 마나 UI 표시가 실제 차감량(`Σ BaseCost`)과 일치한다.
- [ ] 12번/13-A 기능(락온별 팝업, 큐 발동, 즐겨찾기), 기존 HUD(HP/MP/포커스 게이지, 마나 무제한 표시)에 회귀가 없다.
- [ ] DLV/VContainer 규칙 준수.

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인. `clear_console` 후 `console --level error` 0건.
2. Play Mode(`Time.frameCount` 정지 시 리플렉션 직접 호출 + UI 트리/씬 오브젝트 직접 조회): A/B/C 시나리오(A에 1번, B에 2번, C에 1+2)로 지정 → 대상별 미리보기 오브젝트/표시 존재 여부와 값, 마나 UI 표시값을 확인 → 발동 후 실제 결과와 미리보기 일치 확인 → 취소/발동 후 잔상 없음 확인 → 마나 부족 상황의 표시 확인.
3. `git diff --stat`로 범위 확인(이전 세션 미커밋분은 구분).

## Goal

`ICharacterStatService.SetManaUnlimited(bool)`/`UseMP` 내부 게이트는 8번 작업에서 이미 구현·검증됐지만, 이를 실제로 켜고 끄는 호출이 어디에도 연결돼 있지 않아 3단계(보스 50% 이후 자동 감속 구간)에서 마법을 시전하면 마나가 정상적으로 소모된다(무제한이어야 함). 이번 작업은 `TimeSlowLogicSystem`이 이미 06(이벤트 시퀀서)의 `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail`을 구독해 게이지 오버라이드·감속 램프를 켜고 끄는 지점에, 마나 무제한 토글을 정확히 같은 타이밍으로 얹는다.

## 배경 (조사로 확인된 현재 상태)

- `Assets/02.System/02.CharacterSystem/01.Logic/TimeSlowLogicSystem.cs`:
  - `HandleBoss50Percent()`(173~178행) — 06의 `OnBoss50Percent` 수신 시 `ActivateEventSlow(rampDuration)` 호출(게이지 오버라이드 On + 감속 램프 시작).
  - `DeactivateEventSlow()`(197~203행) — `OnCoreHitSuccess`/`OnCoreHitFail` 구독 핸들러로 직접 연결돼 있고, `ProcessTimeSlow()`의 램프 완료(t>=1) 시에도 호출됨(198행 주석: "감속 모드 조기 종료(06의 성공/실패 판정 수신) 또는 램프 완료 시 호출"). 즉 이 메서드 하나가 "3단계 종료"의 모든 경로를 대표한다.
  - 생성자(24~41행)는 `RuntimeDataTimeSlow`, `ITimeSlowVisualizer`(옵션), `InputReader`(옵션)만 주입받음 — `ICharacterStatService`는 아직 주입 안 됨.
- `Assets/02.System/02.CharacterSystem/CharacterLifetimeScope.cs`: `CharacterStatSystem`을 `.As<ICharacterStatService>()`로 등록(47행)하고 `TimeSlowLogicSystem`도 같은 스코프에 `RegisterEntryPoint`(91행) — **같은 LifetimeScope**이므로 크로스 스코프 사후 배선(`BindXxx` 패턴) 불필요, 그냥 생성자 주입으로 충분.
- `ICharacterStatService.SetManaUnlimited(bool)`/`IsManaUnlimited`, `UseMP` 내부 게이트는 이미 `Assets/02.System/02.CharacterSystem/01.Logic/CharacterStatSystem.cs`/`ICharacterStatService.cs`에 구현·검증 완료(8번 작업) — 이번엔 호출부만 추가.

## 범위

### 포함
1. **`TimeSlowLogicSystem.cs` 생성자에 `ICharacterStatService characterStatService` 파라미터 추가**(같은 스코프에 항상 등록돼 있으므로 필수 의존성으로 추가 — `runtimeData`와 동일하게 null 체크 후 저장).
2. **`HandleBoss50Percent()`에 `characterStatService.SetManaUnlimited(true)` 호출 추가** — 기존 `ActivateEventSlow(rampDuration)` 호출과 같은 지점.
3. **`DeactivateEventSlow()`에 `characterStatService.SetManaUnlimited(false)` 호출 추가** — 기존 `SetGaugeOverride(false)`/`EndEventRamp()`/`DeactivateSlow()`와 같은 지점. 이 메서드가 성공/실패/타임아웃 세 경로 전부를 대표하므로 별도 분기 불필요.
4. Play Mode 라이브 검증으로 (a) `OnBoss50Percent` 발행 시 `IsManaUnlimited==true`, (b) 그 상태에서 `UseMP` 호출해도 MP 불변, (c) `OnCoreHitSuccess`/`OnCoreHitFail`/타임아웃 중 아무 경로로 종료돼도 `IsManaUnlimited==false`로 복귀, (d) 재도전 시 사이클 반복을 확인.

### 제외 (이번 작업 범위 아님)
- `ICharacterStatService.SetManaUnlimited`/`UseMP`의 내부 로직 자체 — 이미 구현·검증 완료, 변경 없음.
- `CharacterHUDUIView`의 마나 게이지 100% 강제 표시 로직 — 이미 구현·검증 완료(8번 작업), 변경 없음.
- 09번 기획서에 이미 열려 있는 다른 미해결 항목(시간정지 시스템의 `CharacterLifetimeScope` 종속 구조 분리 여부, 수동 시간정지 입력 차단 범위) — 이번 작업과 무관, 손대지 않는다.

## 완료 기준 (Definition of Done)

- [ ] `TimeSlowLogicSystem`이 `ICharacterStatService`를 생성자로 주입받고 컴파일 에러 없음.
- [ ] 06이 `OnBoss50Percent`를 발행하면 `ICharacterStatService.IsManaUnlimited`가 `true`로 바뀐다.
- [ ] `IsManaUnlimited==true`인 동안 `UseMP(int)`를 호출하면 `true`를 반환하고 `RuntimeStatData.MP.CurrentValue`가 변하지 않는다(8번 작업의 기존 게이트가 그대로 반영됨).
- [ ] `OnCoreHitSuccess`/`OnCoreHitFail` 중 어느 쪽이 발행되든, 또는 감속 램프가 타임아웃으로 완료되든, `IsManaUnlimited`가 `false`로 복귀한다.
- [ ] 위 종료 이후 `UseMP` 호출 시 마나가 정상적으로 소모된다(무제한 해제 확인).
- [ ] 재도전(4단계 실패 후 06이 `OnBoss50Percent`를 다시 방송하는 경우)에도 위 온/오프 사이클이 동일하게 반복된다.
- [ ] 게이지 오버라이드(9번 기획서 기존 기능), 감속 램프, HUD 포커스/마나 게이지 표시 등 기존 기능에 회귀가 없다.
- [ ] 신규 코드가 DLV/VContainer 규칙을 위반하지 않는다(인터페이스 주입만 사용).

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(Play Mode / `unity eval`)**:
   - 시나리오 A(발동): VContainer 컨테이너에서 `IEventSequencer`/`ICharacterStatService` Resolve → `OnBoss50Percent` 발행(또는 시퀀서 상태를 실제로 그 지점까지 진행) → `IsManaUnlimited==true` 확인.
   - 시나리오 B(무제한 소비): 그 상태에서 `UseMP(큰 값)` 호출 → `true` 반환 + MP 불변 확인.
   - 시나리오 C(성공 종료): `OnCoreHitSuccess` 발행 → `IsManaUnlimited==false` 확인 → `UseMP` 호출 시 정상 소모 확인.
   - 시나리오 D(실패 종료): 재도전 후 이번엔 `OnCoreHitFail` 발행 → 동일하게 `false` 복귀 확인.
   - 시나리오 E(타임아웃 종료): 램프가 자연 완료(`t>=1`)될 때도 `false` 복귀 확인.
   - 시나리오 F(회귀): 게이지 오버라이드(HUD 포커스 게이지 100% 고정), 감속 시각효과, 1단계 완전 정지 모드에 회귀 없는지 확인.
4. **범위 확인**: `git diff --stat`로 `TimeSlowLogicSystem.cs`(및 필요시 `CharacterLifetimeScope.cs`의 생성자 파라미터 관련 등록 확인용 diff, 실제로는 등록 방식이 자동 해결되면 변경 불필요)에 한정되고 다른 시스템은 무변경인지 확인.

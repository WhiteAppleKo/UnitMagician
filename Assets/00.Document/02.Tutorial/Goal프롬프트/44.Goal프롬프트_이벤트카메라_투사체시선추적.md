## Goal
3단계 이벤트 카메라를 수정한다. **카메라(피벗 `player+1.4`)는 플레이어 위치에 그대로 두고, 시선각만 매 프레임 "카메라→이벤트 투사체" 방향으로 돌린다.** 투사체가 플레이어에게 접근하고(`L`→`P`), 플레이어를 지나치고, 보스로 멀어지는(`P`→`B`) 전 과정에서 같은 규칙이다. 현재의 "아군 발사 지점~보스 중점" 피벗/"아군→보스" 시선(임시 `EventCameraTargetProvider` 기반)은 폐기한다.

## 연출 흐름 (사용자 확정, 22번 §8 — 구현 시 이 흐름을 어기지 않는다)
이벤트 연출은 플레이어의 시점과 다르지 않다(별도 연출 카메라 아님). 이벤트 호출 시점의 보스·플레이어 위치를 고려해 정한 발사 지점으로 NPC를 옮겨 투사체를 쏘면(기존 13번 흐름), 카메라가 그 투사체를 따라가며 플레이어가 마법을 적용할 수 있다. 투사체가 플레이어를 스쳐 지나가는 순간 시간 속도가 가장 느려진다(기존 13번 전환점). 이 중 발사·감속은 이미 구현돼 있다. **NPC를 발사 지점으로 옮기는 부분은 현재 미구현**(투사체만 `L`에서 스폰, Goal 45 조사)이며 이 Goal의 범위가 아니다(결정 대기). 이 Goal의 범위는 카메라뿐이다.

## 범위
### 포함
1. **조사 먼저**: `CameraFollowService`의 이벤트 오버라이드 계산(Goal 43 결과), `EventCameraTargetProvider`/`IEventCameraTargetProvider` 사용처(씬 직렬화, `LocomotionLifetimeScope` 등록 포함), 09번 `IEventFlightTracker`(`ProjectilePosition`: 매 프레임 값, 획득 전 발사 지점, 소실 후 마지막 관측 위치)와 그 구현체 `EventFlightTrackerComponent`의 위치·스코프(`EventSequencerSystemLifetimeScope`, 별도 VContainer 트리)를 확인하고 보고한다.
2. **카메라 계산 변경**: 오버라이드 중 피벗은 `player+1.4` 그대로(투사체/중점으로 옮기지 않는다), 표시 시선각 = 카메라 위치에서 투사체 위치를 향하는 yaw/pitch를 매 프레임 계산. 진입/해제 보간, 플레이어 시선각 불변·스냅샷 없음, 입력 차단, 숄더 구도(거리/오프셋/FOV 동일)는 Goal 43 결과 그대로 유지한다.
3. **투사체 위치 공급**: 카메라(L 계층)는 Transform/구체 타입이 아니라 인터페이스(위치 `Vector3`)에만 의존한다. 09는 다른 VContainer 스코프 트리이므로 `EventCameraTriggerLogicSystem.BindEventSequencer`와 같은 사후 배선 패턴(인스펙터 직접 참조 + 두 컨테이너 Build 후 배선) 등 기존 가이드라인 안의 방식으로 연결하고, 선택한 방식과 이유를 보고한다. 임시 `EventCameraTargetProvider`(씬 임의 Transform 2개)는 제거하거나 `99.Legacy`로 격리하고, 관련 씬 직렬화 필드/등록을 정리한다. 새 `*LifetimeScope.cs` 파일 금지.
4. **옵션 Camera 탭**: 모드 버튼 5개가 사라진 뒤 남은 의미 없는 "Camera View Mode" 라벨을 제거한다(탭 자체는 유지, 비어 있어도 된다 — 나중에 세부 옵션으로 채울 예정, 사용자 확정). `OptionUI`와 `UIDocument (1)` 두 컴포넌트에 에러가 없어야 한다.
5. **문서 정합**: 이 정정과 충돌하는 서술이 남아 있으면 수정한다(22번 §8, 10번, `98.System/02.Locomotion_CameraSystem.md`, `02.예상플레이흐름.md`, 43번 Goal은 이미 정정됨 — 남은 곳만).

### 제외 (건드리지 않는다)
- 시간 감속 곡선·전환점·마법 발동 로직(13번), `IEventFlightTracker`/`EventFlightTrackerComponent`의 기존 동작, 숄더 오프셋/FOV, 일반 락온 카메라, 혼합 파일(`CameraSettingSO.cs`, `ThirdPersonShoulderCameraStrategy.cs`, `CameraOptionUIController.cs`), `ProjectSettings/DynamicsManager.asset`.
- 기획서에 없는 판단(예: 투사체 근접 통과 시 각속도 완화 수치)은 임의로 정하지 말고 **실측값을 보고하고 제안만** 한다.

## 완료 기준 (기획서 §8, §5-2)
- [ ] 이벤트 중 피벗이 `player+1.4`에서 움직이지 않고(플레이어가 이동하지 않는 한 일정), 카메라 forward가 매 프레임 "카메라→`ProjectilePosition`" 방향과 일치한다(접근·지나침·이탈 전 구간, 슬로모션 구간 포함). 같은 프레임의 투사체 위치·계산 방향·실제 카메라 forward를 수치 로그로 대조하고, 시퀀서 이벤트를 억지로 호출하지 말고 실제 3단계 경로(보스 HP 50%)로 확인한다.
- [ ] **이벤트의 목적(22번 §8)**: 이벤트 시작 시 카메라가 플레이어 뒤쪽 발사 지점 `L` 방향을 향하고, 접근 구간 동안 투사체가 화면 안에 유지되어 실제 락온→팝업→마법 지정이 가능하다(락온이 성공하는지 라이브로 확인). 플레이어가 마우스를 움직여도 시선은 투사체를 따른다.
- [ ] 투사체가 플레이어 바로 옆을 지나는 순간의 최대 시선 각속도를 실측해 보고한다.
- [ ] 이벤트 종료 후 시선이 플레이어 시선각으로 보간 복귀하고, 3회 반복해도 누적 오차가 없다. 마우스 회전/줌 차단, 락온과 이벤트 겹침 시 이벤트 우선은 유지된다.
- [ ] 임시 `EventCameraTargetProvider` 의존이 제거되고 컴파일 에러 0, 씬 Missing Script 0, Missing Reference는 기존 1건에서 늘지 않는다. 콘솔 에러 0(Animator `Hash 468800000` 기존 경고 제외).
- [ ] Camera 탭에 "Camera View Mode" 라벨이 없고 탭은 유지된다.
- [ ] 시간정지→락온→지정→전환점 발동→보스 명중(성공/실패 모두) 이벤트 흐름 회귀 없음, `DynamicsManager.asset` md5 `803bedbcc15227e788d4fcc3332d80b4` 불변.

## 검증 절차
1. 수정 전 상태를 기록 → 구현 → `unity command recompile` + `recompile_status` + 어셈블리 mtime 교차 → `clear_console` 후 `console --level error` 0건.
2. Play Mode에서 실제 3단계 경로로 이벤트를 발생시켜, 투사체 위치·카메라 위치·카메라 forward를 프레임 단위로 로깅한다(접근/전환점/이탈 구분, `timeScale` 포함). 스크린샷은 scratchpad 절대경로에 저장한다.
3. QA 에이전트는 개발 에이전트와 분리하고, 개발자 보고를 믿지 않고 위 수치를 독립 재측정한다. 지난 QA(아군~보스 중점 판정)는 이 정정으로 무효다.

## Goal
이벤트 구간에 **전용 1인칭 가상 카메라**를 사용한다. 평상시는 숄더 vcam, 이벤트 오버라이드 ON이면 이벤트 vcam(캐릭터 눈 위치, 시선 = 카메라→이벤트 투사체)으로 블렌드 전환하고 종료 시 숄더로 복귀한다. 숄더 카메라에서 투사체가 캐릭터 몸에 가려지던 문제를 없앤다.

## 사용자 확정 / 미확정
- 확정: 이벤트 카메라는 숄더와 별도, 1인칭. 시선은 투사체를 따라가며 플레이어가 마법을 지정할 수 있어야 함. 플레이어 시선 조작 차단. (22번 §8, §10)
- 미확정 추천안(22번 §10-1~3: 눈 위치·몸 렌더 숨김, 블렌드 전환, 종료 시 숄더 복귀): 추천안대로 구현하고 최종 보고에 "사용자 확인 필요"로 명시. 몸을 숨기는 방식(레이어 컬링/ShadowsOnly 등)은 개발이 정하고 이유 보고.

## 범위
### 포함
1. **조사 먼저**: 현재 `CameraFollowService`(이벤트 오버라이드, `EventTargetBlendWeight`, 댐핑 해제 관련 44번 구현과 중단된 A/B/C 수정 흔적 — 중간에 끊긴 상태일 수 있으니 컴파일/동작 상태부터 확인), `CameraFollowVisualizer`, `EventCameraTriggerLogicSystem`, 씬의 vcam 구성(Shoulder, Orbit 등), `CinemachineBrain` 블렌드 설정, 플레이어 모델의 머리/눈 위치 기준(본·`CharacterController` 등), `IEventCameraLookTarget`/`EventProjectileLookTarget`을 확인하고 보고.
2. **이벤트 전용 1인칭 vcam**: 씬에 신규 생성(평상시 비활성/낮은 우선순위). 눈 위치 추종(플레이어 이동 시 따라감), 매 프레임 회전 = 눈→투사체(`IEventCameraLookTarget` 위치). FOV/눈 높이 오프셋/블렌드 시간 등 수치는 `PureDataCameraSetting` 조정값(하드코딩 금지).
3. **전환**: 오버라이드 ON→이벤트 vcam 활성(Cinemachine 블렌드), OFF→숄더 복귀. 이 구조에서는 숄더 기준 시선 역산·각도 Lerp·댐핑 일시 해제·표시 시선 가중치가 불필요해지면 정리한다(범위와 이유 보고, 입력 차단·플레이어 시선각 불변·`SetRequireRightClickToRotate`·락온 정렬은 유지).
4. **몸 숨김**: 이벤트 중 캐릭터 몸/머리가 1인칭 카메라 화면에 보이지 않게 한다(렌더링만 숨김, 이벤트 종료 시 원복, 반복 안정).
5. **문서**: 22번 §9 구현 결과 갱신, 10번 기획서/`98.System/02.Locomotion_CameraSystem.md`/`02.예상플레이흐름.md`에서 충돌하는 서술 정정.

## 완료 기준 (22번 §10)
- [ ] 이벤트 중 활성 vcam이 이벤트 1인칭 vcam이고 위치는 눈 위치(플레이어가 이동하면 따라감), forward가 매 프레임 카메라→투사체 방향과 0.1° 이내(접근·스침·이탈 전 구간, 독립 프레임 로깅). 평상시는 숄더 vcam.
- [ ] 이벤트 중 캐릭터 몸이 화면에 보이지 않고 종료 후 원복된다(스크린샷 + 렌더러 상태 확인).
- [ ] 전환·복귀·재도전·락온 상태 시작·플레이어 시선 yaw 여러 값(0/12/31/39/-60/180)에서 프레임 간 시선 변화에 한 프레임 큰 각도 스냅이 없다(최대 °/프레임 실측, 이전 QA 결함 A=약 178°, B=약 109°, C=약 12° 재현 조건 포함).
- [ ] 접근 구간 투사체가 화면 안에 들어오고 실제 입력 주입으로 락온→팝업→마법 지정→전환점 발동→SUCCESS까지 가능(화면 밖 구간 길이 보고).
- [ ] 이벤트 중 마우스 입력으로 플레이어 시선각 불변, 종료 후 숄더 복귀하고 플레이어 시선각 그대로, 3회 이상 반복·성공/실패 양쪽 경로 회귀 없음.
- [ ] 컴파일 에러 0(DLL mtime 교차), 콘솔 에러 0(Animator `Hash 468800000` 기존 경고 제외), 씬 Missing Script 0 · Missing Reference 기존 1건 불증가, md5 불변.

## 검증 절차
1. 수정 전 상태 기록 → 구현 → recompile + recompile_status + 어셈블리 mtime 교차 → 콘솔 에러 0.
2. **실제 3단계 경로(보스 HP 50%)** 로 이벤트 발생(시퀀서 이벤트 억지 발화 금지). 프레임 단위 로그: 활성 vcam, 카메라 위치/눈 위치, forward, 투사체 방향, 오차, 프레임 간 시선 변화, timeScale. 이전 QA 스크립트(scratchpad의 `qa44_*.js/.csv`) 재사용 가능. 스크린샷은 scratchpad 절대경로.
3. QA 에이전트는 개발 에이전트와 분리하고 독립 재측정. 실제 입력 주입으로 락온~지정 확인, 몸 가림 여부는 스크린샷으로 확인.

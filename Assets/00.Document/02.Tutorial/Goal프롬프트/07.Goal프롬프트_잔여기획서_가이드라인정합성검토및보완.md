## 1. 작업 배경

`Assets/00.Document/AI Rule/가이드라인/코드_작업_기획서_가이드라인_v1.0.md`가 이번 세션에 v1.0으로 개정되면서, 기획서에 **3. 데이터 정의 및 흐름**, **4. DLV 적용 방안(+실제 폴더 경로)** 두 항목이 신규 필수 항목으로 추가되었다. 튜토리얼 시스템 8번(캐릭터스탯상태시스템확장) 기획서를 이 기준으로 대조한 결과 두 항목이 완전히 누락되어 있음을 확인했다. 같은 시기(v1.0 이전)에 작성된 나머지 미착수 시스템 기획서들도 동일한 문제를 가질 가능성이 높다.

## 5. 절차 (문서 1개당 반복)

1. **읽기**: 대상 기획서 전체를 읽는다.
2. **대조**: 가이드라인 필수 5항목 각각에 대해 충족/부분충족/누락 여부를 판단한다.
3. **근거 수집** (3·4번 항목이 누락/미비한 경우만 해당):
   - 데이터 필드명·타입은 **반드시 기존 코드**(예: 캐릭터 스탯이면 `ICharacterStatService`/`CharacterStatComponent` 등 관련 실제 클래스, 이벤트 시퀀서면 관련 기존 시스템)를 직접 열어 확인한 실제 필드/메서드 시그니처를 근거로 서술한다. 코드에 없는 필드를 상상으로 만들어내지 않는다.
   - 폴더 경로는 기존 `Assets/02.System/` 하위 번호 체계를 실제로 확인해서, 해당 기능이 기존 시스템의 확장인지 신규 시스템인지에 맞춰 정확한 경로를 적는다(확장이면 기존 경로, 신규면 `코드_작업_기획서_가이드라인_v1.0.md` 3-2절의 `[다음순번].[기능명]/` 규칙 적용).
4. **보완 작성**: 기존 8.1~8.6 같은 서술형 섹션(개요/핵심동작/조작흐름/시청각효과/예외)은 **삭제하지 말고 그대로 유지**한 채, 누락된 "데이터 정의 및 흐름" 섹션과 "DLV 적용 방안(+실제 폴더 경로)" 섹션을 추가한다. 체크리스트는 기존 항목을 보존하되, 새로 정의한 데이터 흐름을 근거로 하는 항목이 빠져 있다면 추가한다(기존 체크리스트 항목을 삭제하지 않는다).
5. **자체 재검증**: 수정한 문서를 다시 읽고 5항목이 모두 충족됐는지 재확인한다.
6. **로그 남기기**: 이 시스템에서 무엇을 채워 넣었는지 2~3줄로 기록해두고(최종 보고에 사용) 다음 문서로 이동한다.

## 6. 중단 조건 (탈출 불가능한 반복 방지 — 반드시 준수)

- **문서당 보완 시도는 최대 2회.** 1차 보완 후 자체 재검증(5단계)에서 여전히 3·4번 항목을 충족 못 시키면 1회에 한해 재시도하고, 그래도 실패하면 **그 문서는 "미해결"로 표시하고 즉시 다음 문서로 넘어간다.** 같은 문서를 3회 이상 고치지 않는다.
- **근거(3단계)를 찾을 수 없어 데이터 필드/폴더 경로를 확정할 수 없는 경우, 추측하지 말고 즉시 작업을 멈추고 사용자에게 질문한다.** (CLAUDE.md 기본 룰 3 — 모호한 지점 임의 판단 금지) 이 경우 해당 문서는 "사용자 확인 대기"로 표시하고 다음 문서로 넘어가되, 질문 내용은 반드시 최종 보고에 포함한다.
- **전체 처리 대상은 위 7개 문서로 고정.** 이 목록에 없는 문서를 추가로 열거나 수정하지 않는다.
- **코드/씬/에셋 수정 없음.** 이 작업 중 코드 결함이나 개선점을 발견해도 수정하지 않고 보고만 한다(별도 Goal로 분리).
- 7개 문서를 모두 처리(완료/미해결/확인대기 중 하나로 분류)하면 작업을 종료하고, 문서별 처리 결과 요약을 보고한다.

## 7. 완료 조건

7개 대상 문서 각각이 "완료"(5항목 모두 충족) / "미해결"(2회 보완에도 실패) / "확인대기"(사용자 질문 필요) 중 하나로 분류되고, 그 결과가 요약 보고되면 이 Goal은 완료된 것으로 간주한다.

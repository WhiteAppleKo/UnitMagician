## Goal
하드코딩된 공격/피격 파이프라인 플래그(`InteractionSystem.DefaultAttackFlags/DefaultHitFlags`)를 없애고, 플래그와 진영을 **엔티티(캐릭터·NPC·돌문·투사체)가 각자 데이터로 들고** 파이프라인이 그 값을 읽게 한다. 투사체는 발사 시 **발사자·진영·공격 플래그**를 받아 독자적인 공격 상태로 보관하고, 충돌 시 그 값으로 `DamageContext`를 만들어 공격 파이프라인을 실행한다. 이번 단계에서 `owner` 필드와 기존 충돌 무시 로직은 **건드리지 않는다**(16-B).

## 범위
### 포함
1. **조사 먼저**: `AttackStepFlags`/`HitStepFlags`/`FlagRefCounter`/`CombatFlagState`/`IHitStepFlagsProvider`의 현재 사용처, `InteractionSystem.ProcessDamageAsync`의 플래그 결정 경로, `NpcProjectileLaunchData`/`ProjectileAttackBehaviorSO`/`NpcProjectile.Setting/SetActive`/`CollisionDamageTrigger`의 발사 설정 경로, `BossEventHitFlagsComponent`/`BossPhaseLogicSystem`(회복 페이즈 진입/해제 위치), `CharacterStatComponent.PlayerStat` 사용처(`UnitCasterSystem`, `UnitVectorGizmoUIComponent`)를 읽고 기획서 §4의 위치/구현과 다른 점이 있으면 구현 전에 보고한다.
2. **플래그 데이터화(§3-1, §3-2)**
   - `PureStatData`에 `defaultAttackFlags`(`AttackStepFlags`, 기본 `None`)/`defaultHitFlags`(`HitStepFlags`, 기본 `Evasion|Defense`)를 추가하고, `RuntimeStatData`가 이를 초기값으로 `CombatFlagState combatFlags`를 보유한다(`FlagRefCounter`/`CombatFlagState`를 처음 실제로 배선). 기존 `PureStatData_*.asset`에는 기존 동작을 유지하는 값이 들어가야 한다(필드 초기값으로 처리되는지, 에셋에 명시해야 하는지 확인).
   - `PureDataDestructibleDoor`에 `faction`(`Neutral`)/`hitFlags`(`AttributeGate`)를 추가하고 돌문 컴포넌트가 PureData에서 읽는다(현재 코드가 반환하는 값을 데이터로 이동).
   - 신규 인터페이스 `IAttackStepFlagsProvider`, `IFactionProvider`(`Assets/PipeLine/Combat/`, 기존 `IHitStepFlagsProvider`와 같은 패턴). `CharacterStatComponent`가 세 인터페이스를 모두, `DestructibleDoorComponent`가 `IFactionProvider`+`IHitStepFlagsProvider`를 구현한다. 규칙표 `FactionRelation`(`Assets/PipeLine/Combat/FactionRelation.cs`, 순수 C#: 편 정의/`IsSameSide`/`IsHostile`)을 만들고 `RuntimeStatData.IsHostile`은 이 규칙을 **호출만** 하게 한다(같은 규칙 중복 금지). 충돌에 쓰는 레이어/매트릭스는 16-B 몫이므로 여기서는 만들지 않는다.
3. **투사체 독자 공격 상태(§3-1, §3-2의 1~3·6)**
   - `NpcProjectileLaunchData`에 `Attacker`(기존 `Owner`의 의미를 "발사자"로 정의, 이름을 바꾸되 `owner` 필드 자체와 충돌 무시 로직은 이번에 유지), `AttackFlags`, `Faction`을 추가한다. `ProjectileAttackBehaviorSO.Execute`가 발사자 오브젝트의 `IAttackStepFlagsProvider`/`IFactionProvider`에서 읽어 채운다(provider가 없으면 공격 플래그 `None`/진영 `Neutral`).
   - `CollisionDamageTrigger`는 발사자(`attacker`), 진영(`faction`), 공격 플래그(`CombatFlagState attackFlags`)를 보관하고, 풀 재사용(`ResetForReuse`/`Setting`/`SetActive`)에서 **발사 설정 값으로 완전히 초기화**한다. 충돌 시 `DamageContext.Attacker = attacker(발사자)`, `Source = 투사체`로 만든다 — 마법으로 `owner`가 시전자로 바뀌어도 `Attacker`는 바뀌지 않아야 한다.
   - `InteractionSystem.ProcessDamageAsync`는 공격 플래그를 투사체의 `attackFlags.CurrentFlags`에서, 피격 플래그를 피격 대상의 `IHitStepFlagsProvider`에서 읽는다(provider 없으면 `None`). `DefaultAttackFlags`/`DefaultHitFlags` 상수를 삭제한다.
4. **아군 NPC 스탯 부착 + `PlayerStat` 전제 수정(§3-1, §4)**
   - 아군 `NpcCombatActor_Dummy`에 `CharacterStatComponent`와 신규 `PureStatData`(`defaultFaction = Ally`)를 붙인다(씬 수정). 보스(`Enemy`)/플레이어(`Player`) 에셋의 진영 값을 확인한다. `PureDataNpcActor`에는 진영/플래그를 추가하지 않는다.
   - `CharacterStatComponent.Awake`의 `if (!IsEnemy()) PlayerStat = this;`는 "적이 아니면 플레이어"라는 가정이라 아군/중립 NPC에 스탯을 붙이면 `PlayerStat`이 덮어써진다. 플레이어 판별을 `진영 == Player`로 바꾼다(`PlayerStat` 정적 구조 자체의 변경은 이번 범위가 아님).
5. **보스 회복(무적) 페이즈 플래그 전환(§3-2의 8)**: 회복 페이즈 진입 시 보스의 `CombatFlagState`에 `AddHit(AttributeGate)` + `SuppressHit(Evasion|Defense)`, 해제 시 되돌림(`BossPhaseLogicSystem`이 갱신; 위치가 조사 결과와 다르면 보고하고 기획서의 의도 — 페이즈를 관장하는 로직이 갱신 — 를 지킨다). `BossEventHitFlagsComponent`는 `09.EventSequencerSystem/99.Legacy/`로 격리 이동(삭제 아님)하고 보스 오브젝트에서 컴포넌트를 제거한다.

### 제외 (건드리지 않는다)
- 16-B 몫: `owner` 필드/`SetOwner`, `IgnoreOwnerCollisions`/`ignoredOwners`/`IsOwnerOrRelative`, `UnitChangeService.UpdateCollisionTriggerOwner`(→`ApplyCasterFaction`), `EventFlightTrackerComponent.ignorePlayerCollision`, 레이어/충돌 매트릭스/`FactionLayers`, `TagManager` 변경. **진영 기반 충돌 처리는 이번에 하지 않는다**(16-A 이후에도 아군 샷이 플레이어를 맞히는 현상은 그대로이며 16-B에서 해결).
- `CriticalStep`/`AttackStepFlags.Critical` 비트/순서 테이블 등록/`DamageContext`의 Crit 필드 삭제·수정 금지(어떤 엔티티도 `Critical`을 켜지 않는 것으로 충분). `SizeGate`/게이트별 결과 플래그(별도 기획서), 중립 NPC 적대화 트리거 규칙, 범위 마법 예외, 범용 예시 코드(`EvadeStep`/`BlockStep`/`BaseDamage*`) 정리, `PlayerStat`의 정적 구조 변경.

## 완료 기준 (기획서 §5 해당 항목)
- [ ] (5-1) 인스펙터에서 `PureStatData_Boss`의 `defaultHitFlags`를 바꾸면 코드 수정 없이 보스 피격 스텝 조합이 바뀐다(`CombatPipelineManager` 캐시 MISS 로그로 확인; 확인 후 원래 값으로 복원). `InteractionSystem`에 `DefaultAttackFlags`/`DefaultHitFlags`가 없다(grep).
- [ ] (5-2) 아군 투사체가 `attacker = 발사 NPC`, `faction = Ally`, `attackFlags = NPC 값`을 들고 있고, 마법(owner 강탈 포함)을 걸어도 `attacker`가 그대로이며 `DamageContext.Attacker`가 발사 NPC로 찍힌다(`[InteractionSystem.Damage]` 로그). 풀 재사용 후에는 이전 사이클의 진영/플래그가 초기화돼 있다.
- [ ] (5-5, 5-7 일부) 아군(Ally) 샷 → 돌문 1·2차 게이트 기존대로(얼음만 `cracked but survived` 20회 반복 파괴 없음, 얼음+크기 `DESTROYED`), 보스(Enemy) 샷 → 플레이어 HP 감소.
- [ ] (5-7) 회복(무적) 페이즈에서 보스 피격 플래그가 `AttributeGate` 단독으로 바뀌고 해제 시 원복된다. `BossEventHitFlagsComponent`가 `99.Legacy`로 이동했고 씬/프리팹 참조가 없다. 3단계 판정(얼음만/크기만/없음 실패, 얼음+크기 성공 10회 반복), 재도전, 13~15번 회귀(락온마다 팝업, 전환점 1회 발동, 이벤트 중 차단, 풀링 상한, 컨텍스트 스택 `Player` 복귀)에 변화가 없다.
- [ ] (5-8) 어떤 엔티티의 공격 플래그에도 `Critical`이 켜져 있지 않고 `[CriticalStep]` 로그가 나오지 않는다(피격 50회 이상에서 `Crit: False`, `RawDamage`가 `baseDamage` 그대로).
- [ ] (5-9-1) 아군 `NpcCombatActor_Dummy`에 스탯이 붙어도 `CharacterStatComponent.PlayerStat`이 플레이어를 가리킨다(Play Mode에서 진영 `Player` 확인, 씬 로드 순서와 무관). 아군이 보스 샷(`Enemy`)에 맞으면 HP가 감소한다. 검증용으로 NPC `CurrentFaction`을 `Neutral → Enemy`로 직접 바꿔도 provider가 바뀐 진영을 반환한다(검증 후 복원, 디스크에 남기지 않음).
- [ ] (5-9) `FactionRelation` 외에 같은 편/적대 판정 로직이 없다(`RuntimeStatData.IsHostile`은 위임만).
- [ ] (5-10) §4 파일 배치와 DLV/VContainer 규칙을 지킨다(`TryGetComponent` provider 조회만 사용, `GameObject.Find*`/구체 클래스 주입 금지). 콘솔 에러 0건, 디스크에 임시 코드/수치 잔존 없음.

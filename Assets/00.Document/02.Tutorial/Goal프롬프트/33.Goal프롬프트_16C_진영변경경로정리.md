## Goal
마법으로 투사체 진영이 바뀌는 경로를 한 곳으로 정리한다. (1) **시전이 성공한 경우에만** 진영을 바꾸고, (2) 범용 파이프라인 계층(`Assets/PipeLine`)이 `UnitSystem`의 로직 서비스 정적 메서드에 의존하는 순환을 인터페이스로 끊는다.

## 범위
### 포함
1. **조사 먼저**: `ApplyCasterFaction`/`SetFaction`/`FactionLayers` 사용처 전수(`UnitChangeService`, `ApplyUnitChangeStep`, `CollisionDamageTrigger`), `UnitChangeService.ChangeUnit`의 두 분기(파이프라인 분기 / 파이프라인 없는 폴백 분기)의 실행 순서와 마나 소모 시점, `ApplyUnitChangeStep.Execute`의 조기 반환 조건(`ManaCheckFailed`, `TargetInvalid`)과 적용 블록을 읽고 기획서 §6-1과 다른 점이 있으면 구현 전에 보고한다.
2. **인터페이스/헬퍼(§6-1)**: `Assets/PipeLine/Combat/IFactionSettable.cs`(신규)와 `FactionChange.cs`(신규, 정적 순수 C# 헬퍼 `ApplyCasterFaction(target, caster)` — 시전자 `IFactionProvider`를 읽어 대상 부모/자식의 모든 `IFactionSettable`에 설정, 구체 클래스 모름, `attacker` 불변). `CollisionDamageTrigger`가 `IFactionSettable`을 구현한다(기존 `SetFaction` 재사용).
3. **호출 정리**:
   - `ApplyUnitChangeStep`은 단위 변경이 **실제로 적용된 블록 안에서만** `FactionChange.ApplyCasterFaction`을 호출한다(조기 반환 경로에서는 호출되지 않음). `UnitSystem` 클래스 참조를 제거한다.
   - `UnitChangeService`의 파이프라인 분기에서 진영 변경 호출을 삭제한다. 폴백 분기는 마나 소모가 성공한 뒤 같은 헬퍼를 호출한다. `UnitChangeService.ApplyCasterFaction`(정적)은 삭제한다.
4. 결과적으로 진영 변경이 파이프라인 분기/폴백 분기 어느 쪽에서도 정확히 한 번만, 성공했을 때만 일어나게 한다.

### 제외 (건드리지 않는다)
- 중립 전용 투사체/몸체 레이어 추가(별도 확인 중), 레이어 매트릭스·`FactionLayers`의 규칙 변경, 마법 이름/설명 필드, 구르기·스태미나, `timeScale` 정리(별도 Goal), 3단계 판정 구조 변경, 지면 판정.
- 진영 변경 규칙 자체("단위를 바꾸는 모든 마법이 시전자 진영으로 바꾼다")는 바꾸지 않는다.

## 완료 기준 (기획서 §6-1 체크리스트)
- [ ] 마나 부족으로 시전이 실패하면(`ManaCheckFailed`) 대상 투사체의 진영과 레이어가 시전 전과 같다 — 보스 투사체에 마나 0으로 시전했을 때 `Enemy`/`AttackEnemy`를 유지하고 플레이어에게 명중해 HP가 감소한다.
- [ ] 시전이 성공하면(파이프라인 분기와 폴백 분기 각각 확인) 진영이 시전자 진영으로 바뀌고 레이어가 `AttackAlly`로 이동하며(루트+자식 모두) `attacker`는 그대로다. 적 투사체를 빼앗아 플레이어를 통과하고 원래 발사자(적)를 맞힐 수 있다(16-B 5-6과 같은 결과).
- [ ] `ApplyUnitChangeStep.cs`에 `UnitChangeService`/`UnitSystem` 로직 클래스 참조가 없고, `UnitChangeService`에 진영 변경 정적 메서드·파이프라인 분기 호출이 없다(grep). 진영 변경이 한 번만 일어난다(로그 중복 없음).
- [ ] 13~16번 회귀: 3단계 판정(얼음만/크기만/없음 실패, 얼음+크기 성공 반복), 락온마다 팝업·큐 1회 발동, 풀 재사용 시 진영/레이어 초기화, 콘솔 에러 0건.
- [ ] DLV/VContainer 규칙 준수, 디스크에 임시 코드 잔존 없음.

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 DLL 주의). `clear_console` 후 `console --level error` 0건.
2. Play Mode 실측. MP를 0으로 만들어 실제 `ChangeUnit` 경로로 시전 실패를 재현한다(실패 시 진영 불변, 성공 시 변경). 입력 주입이 필요한 항목은 Game 뷰 포커스 후 `InputSystem.QueueStateEvent`, 안 되면 UNVERIFIED로 명시.
3. `git diff --stat`/`git status`로 범위를 확인한다(이전 세션 미커밋분과 구분).

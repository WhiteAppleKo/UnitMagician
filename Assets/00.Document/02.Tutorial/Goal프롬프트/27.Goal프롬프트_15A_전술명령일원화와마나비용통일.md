## Goal
같은 기능(시간정지 중 마법 예약·발동)을 하는 두 시스템이 동시에 살아 있어 실제 입력에서 이중 처리될 수 있는 문제를 없앤다. 13번의 새 시스템(`RuntimeDataMultiLockOn` 큐 + 락온별 팝업 + 해제 시 일괄 발동)으로 일원화하고, 마나 비용 계산을 한 곳으로 통일하고, 락온 대상이 소실될 때 팝업/큐/미리보기/마나 UI가 정리되게 한다.

## 범위
### 포함
1. **조사 먼저(§3-A)**: `06.TacticalCommand` 타입(`TacticalCommandLogicSystem`, `RuntimeDataTacticalQueue`, `PureDataTacticalCommand`, `ITacticalCommandVisualizer`, `TacticalCommandVisualizer`, `TacticalCommandUIView`, `TacticalCommandLifetimeScope`)을 바깥에서 참조하는 곳을 전체 grep으로 조사하고(`CharacterHUDUIView`, `CharacterLifetimeScope`, `UnitMagicSlotSystem`/`IUnitMagicSlotService`, `PlayerStateVisualizer`/`PlayerStateLogicSystem`, `RuntimeDataUnitGroup`, `05.TimeSlowFilter`의 `ITargetStencilService` 계열 등) 의존의 성격을 구분해 보고한다. `05.TimeSlowFilter`는 이 작업에서 변경하지 않는다.
2. **일원화(§3-A)**: `TacticalCommandLogicSystem`의 입력 처리/큐/시전/`UseMP`를 제거하고, 옛 패널(`TacticalHUDContainer`)을 제거한다. 새 시스템과 중복인 시간정지 시 `TacticalContext` Push/Pop·`SetRequireRightClickToRotate`는 제거하되(`PlayerLockOnController.SetSlowMode`가 수행), 제거 후 컨텍스트가 정확히 한 번 Push/Pop되는지 확인한다. 새 시스템에 없는 시각 요소(호버 표시, 스텐실 컬러 보존, 궤적선 등)는 삭제하지 말고 `06.TacticalCommand/99.Legacy/`로 격리하거나, 새 시스템이 이미 같은 역할을 한다면 중복으로 제거한다(무엇을 어떻게 판단했는지 보고). 코드는 삭제 대신 `99.Legacy`로 이동하고 `TacticalCommandLifetimeScope`/씬의 `TacticalCommand` 관련 오브젝트는 비활성/제거한다. 바깥 의존이 있는 타입은 의존이 사라질 때까지 옮기지 않는다.
3. **마나 비용 통일(§3-B)**: 비용 규칙("장착된 마법의 쌍만, 대상이 해당 유형 유닛을 가진 쌍만, `BaseCost` 합")을 한 곳에 두고 `UnitCasterSystem.ExecuteBatchCast()`(실제 차감)와 `LockOnManaPreviewLogicSystem`(HUD 예상 비용)이 모두 그 한 규칙을 호출하게 한다. `RuntimeDataMultiLockOn`의 `PreviewTotalCost`/`RecalculatePreviewCost`/`OnPreviewCostChanged`와 그 호출부는 제거한다. 같은 로직을 두 번 쓰지 않는다(grep으로 `BaseCost` 합산 중복이 없음을 확인).
4. **락온 대상 소실 정리(§3-C)**: pending 대상이 파괴되거나 비활성(`activeInHierarchy == false`)이 되면 `CancelPending`이 정상 동작해 `OnPendingChanged`가 발행되고 팝업이 닫히게(현재 `PendingTarget == null` 비교로 일찍 반환하는 버그), 큐에 쌓인 대상이 파괴/비활성되면 엔트리를 제거하고 `OnEntryRemoved`를 발행해 미리보기와 마나 UI가 갱신되게 한다. 소실 감지 위치(주기 점검 vs 통지)는 가장 단순한 쪽으로 정하되 근거를 보고한다. "유효한 대상" 판정은 한 곳(예: `RuntimeDataUnitGroup`에 유효성 확인 또는 큐 쪽 헬퍼)으로 모은다.

### 제외
- 투사체 풀링(15-B). 필수 에셋 누락 등 설정 실수 방어. 13-A/13-D/13-B/13-C의 동작 변경(회귀만 확인). `05.TimeSlowFilter` 변경.

## 완료 기준 (기획서 §5의 3-A/3-B/3-C 항목)
- [ ] 시간정지 중 좌클릭 락온 → 팝업 지정 → 해제 시 마법이 정확히 한 번 적용되고 마나가 한 번만 차감된다. `[TacticalCommand]` 시전/예약 로그가 나오지 않는다. 실제 마우스 클릭 경로로 확인을 시도하고, 불가하면 입력을 코드로 주입해 옛 시스템이 반응하지 않음을 확인한 뒤 한계를 명시한다.
- [ ] 시간정지 진입/해제 시 `TacticalContext` 스택이 정확히 한 번 Push/Pop되고 카메라 우클릭 회전 설정이 정상 복원된다. 시간정지 필터(흑백, 스텐실 컬러 보존)는 회귀 없다.
- [ ] 옛 `TACTICAL TIME STOP MODE` 패널이 나타나지 않는다. 바깥 의존(`CharacterHUDUIView`, `UnitMagicSlotSystem`, `PlayerState*`, `RuntimeDataUnitGroup`)은 컴파일/동작 회귀 없다.
- [ ] 비용 규칙이 한 곳뿐이고 `RuntimeDataMultiLockOn`에 비용 멤버가 없다. HUD 표시 비용 == 실제 차감량이 일반 시간정지/3단계(마나 무제한)/미장착 마법 제외에서 모두 일치한다.
- [ ] pending 대상 파괴·비활성 시 팝업이 닫히고, 큐 대상 파괴·비활성 시 엔트리 제거와 미리보기·마나 UI 갱신이 된다.
- [ ] 13번 회귀: 락온마다 팝업/큐/마나, 전환점 1회 발동, 이벤트 중 `T`/인벤토리 차단, 판정(얼음+크기 성공/얼음만·크기만·없음 실패), 재도전, 12번 즐겨찾기/Q 목록, 휠 퀵슬롯, 1단계 돌문 퍼즐.
- [ ] DLV/VContainer 규칙 준수.

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인. `clear_console` 후 `console --level error` 0건.
2. Play Mode(`Time.frameCount` 정지 시 `editor_focus`, 안 되면 리플렉션 직접 호출): 옛 시스템이 반응하지 않음(콘솔 로그, `RuntimeDataTacticalQueue`가 없거나 비어 있음), 컨텍스트 스택, 마나 전후 비교, 대상 파괴/비활성 시나리오, 3단계 실제 경로 회귀를 실측한다.
3. `git diff --stat`/`git status`로 범위 확인(이전 세션 미커밋분은 구분).

## Goal
시간정지 중 락온할 때마다 팝업이 열려 그 락온에 쓸 마법을 **지정**하게 하고(시간정지 해제 안 함), 시전 파이프라인이 (대상, 마법) 쌍의 큐를 쌍마다 자기 마법으로 처리하도록 바꾼다. 한 대상에 여러 마법, 대상별 다른 마법이 가능해야 한다.

## 범위
### 포함
1. `LockOnCastEntry`(신규, `00.Data/`) + `RuntimeDataMultiLockOn` 재구성: `Entries`, `PendingTarget`, `BeginPending`/`CommitPending`/`CancelPending`/`RemoveLastEntry`/`ClearEntries`, 이벤트(`OnPendingChanged`/`OnEntryAdded`/`OnEntryRemoved`/`OnEntriesCleared`), `PreviewTotalCost` + `OnPreviewCostChanged`(값 계산·이벤트까지, HUD 표시는 13-C).
2. `UnitBatchCastingService`/`IUnitBatchCastingService`: 큐 기반 `ExecuteBatchCast`(총비용 = Σ 쌍의 BaseCost, 대상이 해당 유형 유닛을 가진 쌍만, `UseMP` 한 번, 부족 시 전부 실패 + 하이라이트 해제 + 큐 비움, 쌍 순서대로 `ChangeUnit`). `UnitCasterSystem.ExecuteBatchCast()`가 `Entries`를 사용하도록 수정(`quickSlotUI.CurrentSelectedUnit` 의존 제거).
3. `MagicLockOnComponent`: 좌클릭 락온 → `BeginPending`(이미 큐에 있는 대상도 허용), 우클릭 규칙(팝업 열림 중이면 `CancelPending`, 아니면 `RemoveLastEntry`), 휠클릭 `ToggleLockOn` 동작 정리.
4. `MagicSelectionPopupLogicSystem`/`IMagicSelectionPopupLogic`: `OnPendingChanged`로 **락온마다** 팝업 오픈, `ConfirmFavoriteSlot`/`ConfirmUnit`은 `CommitPending(spell)`만 하고 **`SetSlowActive(false)`를 호출하지 않음**. Q 전체 목록·즐겨찾기·`MagicSelectionPopupUIComponent`는 12번 UX 유지.
5. `RuntimeDataMultiLockOn`의 기존 멤버(`TargetCount`/`LockedTargets`/`OnTargetAdded` 등)를 쓰는 모든 호출부(`MultiLockOnVisualizer`, 하이라이트 로직, `99.Legacy`/죽은 전략 포함)를 grep으로 찾아 전부 갱신. 죽은 코드는 컴파일만 유지.

### 제외
- 이벤트 중 `T`/인벤토리 차단, `SetSlowActive(false)` 거부, 06 타임아웃 제거(13-B).
- 적용 전 미리보기 비주얼, 마나 UI 표시(13-C).
- 12번의 즐겨찾기 등록/스왑, 마우스 휠 퀵슬롯 로직 변경.

## 완료 기준 (기획서 §5 해당 항목)
- [ ] 락온할 때마다 팝업이 열리고 지정하면 쌍이 큐에 추가되며 시간정지는 유지된다. 같은 대상 재락온 시 쌍이 추가된다.
- [ ] A에 마법1, B에 마법2, C에 마법1+2를 지정 후 `T` 해제 시 4건이 모두 적용된다(서로 다른 유닛 종류 마법 기준).
- [ ] 마나는 지정 중 불변, 발동 시 Σ BaseCost 한 번 차감. 마나 부족 시 아무것도 적용되지 않고 하이라이트가 전부 해제되며 큐가 비워진다.
- [ ] 큐가 비어 있는 채 해제하면 아무 일도 일어나지 않는다.
- [ ] 12번의 Q 전체 목록, W/E/F 확정, 즐겨찾기 등록/스왑, 휠 퀵슬롯, Option/Inventory 메뉴, `T` 시간정지에 회귀가 없다.
- [ ] DLV/VContainer 규칙 준수(인터페이스 주입, `GameObject.Find`/`FindObjectOfType` 금지).

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 DLL 함정). `clear_console` 후 `console --level error` 0건.
2. Play Mode(`Time.frameCount`가 멈추면 `editor_focus`, 안 되면 리플렉션 직접 호출): 위 완료 기준을 A/B/C 시나리오(마법 종류가 다른 두 유닛으로)와 마나 부족 시나리오 포함해 실측. 마나 차감량은 `RuntimeStatData.MP` 전후 비교로 확인.
3. `git diff --stat`로 범위 확인(이전 세션 미커밋분은 구분).

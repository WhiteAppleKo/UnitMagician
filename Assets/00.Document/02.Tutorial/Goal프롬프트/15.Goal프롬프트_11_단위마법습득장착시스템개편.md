## Goal

`UnitCatalogService`의 단일 "해금(Unlock)" 상태를 **"소유(Possessed)"/"장착(Equipped)"** 두 단계로 분리하고, 장착 시 조건 판정(현재는 항상 통과하는 스텁)을 거치도록 한다. 장착 슬롯 개수 제한은 없다. 고장난 테스트 전용 `UnitUnlockTestUIComponent`는 삭제하고, 기존 `UnitInventoryUIComponent`(현재 읽기 전용 그리드)에 클릭 장착/해제 기능을 추가해 실제 인벤토리로 만든다.

## 배경 (조사로 확인된 현재 상태)

- `Assets/02.System/01.UnitSystem/01.Logic/UnitCatalogService.cs`/`IUnitCatalogService.cs` — 현재 `unlockedUnits(HashSet)` 단일 상태, `IsUnlocked`/`UnlockUnit`/`GetUnlockedUnits`/`OnUnitUnlocked`. 생성자가 `initialUnits[0]`을 자동 해금.
- **`IsUnlocked`/`GetUnlockedUnits`/`OnUnitUnlocked`를 참조하는 파일 9개**(grep으로 확인, 전부 갱신 필요): `UnitCasterSystem.cs`, `UnitQuickSlotLogicSystem.cs`, `UnitUnlockTestUIComponent.cs`(삭제 대상), `UnitUnlockPopupUIComponent.cs`, `UnitInventoryUIComponent.cs`, `UnitQuickSlotUIComponent.cs`, `UnitChangeService.cs`, `UnitCatalogService.cs`, `IUnitCatalogService.cs`.
- `UnitUnlockTestUIComponent.cs`(`03.UI/`) — 테스트 전용, `uiDocument.rootVisualElement`가 null이라 버튼이 생성된 적이 없는 고장난 코드. 삭제 대상.
- `UnitInventoryUIComponent.cs`(`03.UI/`) — 현재 `GetUnlockedUnits()`로 아이콘 그리드만 그리는 읽기 전용 컴포넌트, 클릭 핸들러 없음. 이번에 실제 장착/해제 인터랙션 추가.
- `UnitQuickSlotLogicSystem.cs`(`01.Logic/`) — 마우스 휠(Tactical 컨텍스트 한정)/숫자키로 `GetUnlockedUnits()` 목록을 순환·선택. 이 목록이 `GetEquippedUnits()`로 바뀌어야 한다.
- 09-11번 등 이미 QA 통과한 다른 시스템들이 이 파일들을 직접 참조하지 않으므로(01.UnitSystem은 다른 시스템들과 인터페이스로만 연결됨) 이번 개편이 다른 시스템에 영향을 줄 가능성은 낮지만, 혹시 모르니 최종 grep으로 재확인할 것.

## 범위

### 포함
1. **`IUnitCatalogService.cs`/`UnitCatalogService.cs` 전면 수정** (기획서 §3 그대로):
   - 내부 상태: `possessedUnits(HashSet<PureDataUnit>)`, `equippedUnits(HashSet<PureDataUnit>)`(슬롯 제한 없음).
   - 신규 메서드: `AcquireUnit(PureDataUnit)`, `bool TryEquipUnit(PureDataUnit, out string failReason)`, `UnequipUnit(PureDataUnit)`, `bool IsPossessed(PureDataUnit)`, `bool IsEquipped(PureDataUnit)`(기존 `IsUnlocked` 대체), `GetPossessedUnits()`, `GetEquippedUnits()`(기존 `GetUnlockedUnits()` 대체).
   - 이벤트: `OnUnitAcquired`, `OnUnitEquipped`, `OnUnitUnequipped`(기존 `OnUnitUnlocked` 대체).
   - 생성자: `initialUnits[0]`을 자동 습득 **+** 자동 장착(조건 검사는 스텁이라 항상 통과) — 씬 시작 시 즉시 사용 가능한 유닛 1개 보장(회귀 방지).
2. **`IUnitEquipRequirementChecker.cs`(신규 인터페이스) + `DefaultUnitEquipRequirementChecker.cs`(신규 스텁 구현체)** — `bool CanEquip(PureDataUnit unit, out string failReason)`, 스텁은 항상 `true`+빈 사유 반환. `UnitCatalogService.TryEquipUnit`이 이 인터페이스를 생성자 주입받아 사용.
3. **호출부 9개 파일 전부 갱신** — `IsUnlocked`→`IsEquipped`, `GetUnlockedUnits()`→`GetEquippedUnits()`, `OnUnitUnlocked`→`OnUnitEquipped`(의미상 맞는 이벤트로, 예를 들어 `UnitUnlockPopupUIComponent`가 "습득 팝업"이면 `OnUnitAcquired`가 더 맞을 수 있음 — 실제 팝업 문구/의도를 코드 주석·기존 이름으로 판단해서 결정, 애매하면 보고).
4. **`UnitUnlockTestUIComponent.cs` 삭제**(+ `.meta`).
5. **`UnitInventoryUIComponent.cs` 수정** — 그리드의 각 유닛 아이콘에 클릭 핸들러 추가: 미장착+소유 중이면 클릭 시 `TryEquipUnit` 호출, 이미 장착 중이면 클릭 시 `UnequipUnit` 호출. 장착 상태를 시각적으로 구분(예: 테두리 강조). 조건 미달(현재는 발생 안 함)은 회색 처리 로직만 넣어두고 실제 데이터는 스텁이라 항상 통과.
6. **`VContainer_가이드라인_v1.0.md` 준수** — `IUnitEquipRequirementChecker`는 인터페이스로 등록(`As<IUnitEquipRequirementChecker>()`), 구체 클래스 직접 주입 금지.

### 제외 (이번 작업 범위 아님)
- 실제 게이팅 스탯 구현 — `DefaultUnitEquipRequirementChecker`는 스텁으로만 남긴다.
- 필드 아이템 습득 트리거(월드 오브젝트 픽업 등) — `AcquireUnit()` API까지만, 실제 호출부는 초기 유닛 자동 습득 외에 없어도 됨.
- 인벤토리 메뉴를 여는 정확한 입력 바인딩 — 기존 씬에 이미 배치된 `UnitInventoryUIComponent`의 활성화 방식(있다면)을 그대로 쓰거나, 없다면 테스트 편의상 간단한 임시 키 바인딩으로 충분(정식 UX는 범위 밖).

## 완료 기준 (Definition of Done)

- [ ] `possessedUnits`/`equippedUnits` 분리, `AcquireUnit`/`TryEquipUnit`/`UnequipUnit`/`IsPossessed`/`IsEquipped`/`GetPossessedUnits`/`GetEquippedUnits` 전부 구현되고 컴파일 에러 없음
- [ ] `AcquireUnit(unit)` 호출 후 `IsPossessed(unit)==true`이지만 `IsEquipped(unit)==false`(습득≠장착)
- [ ] `TryEquipUnit(unit, out reason)` 호출 시 스텁 체커가 항상 통과해 `IsEquipped(unit)==true`가 되고 `GetEquippedUnits()`에 포함됨
- [ ] `UnequipUnit(unit)` 호출 후 `GetEquippedUnits()`에서 제외되고, `UnitQuickSlotLogicSystem`의 휠 순환 대상에서도 빠짐
- [ ] `UnitQuickSlotLogicSystem`이 `GetEquippedUnits()` 기준으로 순환·선택함(기존 `GetUnlockedUnits()` 완전 대체)
- [ ] `UnitInventoryUIComponent`에서 소유 중인 유닛 클릭 시 장착/해제가 토글되고 시각적으로 구분됨
- [ ] `UnitUnlockTestUIComponent.cs`가 삭제되고, 관련 `UIDocument or rootVisualElement is null` 경고가 더 이상 콘솔에 나타나지 않음
- [ ] 씬 시작 시 초기 유닛 1개가 자동 습득+자동 장착되어 즉시 퀵슬롯 순환 가능(회귀 없음)
- [ ] `IsUnlocked`/`GetUnlockedUnits`/`OnUnitUnlocked`를 참조하던 9개 파일 전부 새 API로 갱신, 프로젝트 전체 grep으로 옛 이름 잔존 없음 확인
- [ ] `UnitCatalogService`/`DefaultUnitEquipRequirementChecker`가 `MonoBehaviour`/`Transform` 등 구체 타입을 직접 참조하지 않음(DLV 준수)

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건, `UnitUnlockTestUIComponent` 관련 경고 소멸 확인.
3. **기능 검증(`unity eval`/Play Mode)** — 이전 세션에서 실제로 검증에 성공했던 방식(컨테이너에서 서비스 직접 Resolve) 그대로 재사용:
   - 시나리오 A(습득≠장착): 새 유닛에 `AcquireUnit()` 호출 → `IsPossessed==true`, `IsEquipped==false`, `GetEquippedUnits()`에 없음 확인.
   - 시나리오 B(장착): 그 유닛에 `TryEquipUnit()` 호출 → `true` 반환, `IsEquipped==true`, `GetEquippedUnits()`에 포함 확인.
   - 시나리오 C(휠 순환 반영): 09번 세션에서 썼던 방식대로 Tactical 컨텍스트 Push 후 `UnitQuickSlotLogicSystem.CycleSlot(1)` 호출 → 방금 장착한 유닛이 순환 대상에 포함되는지 확인.
   - 시나리오 D(해제): `UnequipUnit()` 호출 → `GetEquippedUnits()`에서 빠지고, 이후 `CycleSlot`으로 순환해도 나오지 않음 확인.
   - 시나리오 E(초기 유닛 회귀 없음): 씬 시작 직후 `GetEquippedUnits().Count >= 1`이고 그 유닛으로 즉시 캐스팅(이전 세션에서 검증했던 실제 캐스팅 체인 — `PlayerLockOnController.SetSlowMode`+락온+해제)이 정상 동작하는지 확인.
   - 시나리오 F(인벤토리 UI 클릭): `UnitInventoryUIComponent`가 실제로 씬에 배치돼 있다면, 생성된 버튼/아이콘 클릭 시 `TryEquipUnit`/`UnequipUnit`이 호출되는지 확인(UI 이벤트 시뮬레이션 또는 코드상 클릭 핸들러 등록 여부 직접 확인).
4. **DLV/VContainer 준수 자체 점검**: 신규 파일 grep으로 구체 타입 직접 참조 없음, 인터페이스 등록 확인.
5. **범위 확인**: `git status`/`git diff --stat`로 이번 작업이 `01.UnitSystem/` 내부(9개 갱신 파일 + 2개 신규 파일 + 1개 삭제)에 국한되고 다른 시스템(02~12) 폴더는 무변경인지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

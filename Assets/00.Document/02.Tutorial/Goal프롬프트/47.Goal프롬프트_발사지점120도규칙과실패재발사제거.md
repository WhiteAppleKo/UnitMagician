# Goal 47: 이벤트 발사 지점 "플레이어 우측 120°" 규칙 + 실패 시 즉시 재발사 제거

## Goal
1. 이벤트 발사 지점 `L`을 **`P→B`(수평) 직선을 기준으로 플레이어 우측 약 120° 방향**(플레이어 시야각 밖)에 `EventLaunchDistance`만큼 떨어진 지점으로 정한다. 각도는 SO 조정값.
2. 이벤트 실패(`OnCoreHitFail`) 시 아군이 **즉시 재발사하지 않게** 한다. 실패하면 보스 HP 회복(기존) 후, HP가 다시 50%에 도달할 때만 이벤트가 재시작된다.

## 사용자 확정 (대화 기록 근거는 22번 §11)
- 발사 지점: 보스–플레이어 직선 기준 플레이어 우측 약 120°(시야각 밖). 이벤트 시퀀서의 시간 개입은 투사체 발사와 함께 시작되고 카메라는 천천히 돈다.
- 실패 시 "보스 체력이 회복되므로 즉시 재발사가 아니다" — 50%에 다시 도달해야 이벤트가 재시작된다(사용자가 여러 번 말함).

## 범위
### 포함
1. **조사 먼저**: `EventFlightLogicSystem`의 `L` 결정(`ResolveLaunchPosition`, `MaxClearanceRatio`, `EventLaunchSideClearance`), 접근/전환점/이탈 판정(`d = normalize(B−L)`), `AllySupportTriggerLogicSystem.HandleCoreHitFail`과 그 구독, `TutorialSequencerLogicSystem`의 실패 후 단계 복귀, 06·02·03번 문서의 "재발사/즉각 재도전" 서술을 확인해 보고한다. 문서와 사용자 명세가 어긋나는 곳은 임의 판단하지 말고 보고한다.
2. **발사 지점**: `L = P + R(+120° 우측) × normalize(수평(B−P)) × EventLaunchDistance` (회전 방향·기준은 22번 §11 해석). 각도는 `PureDataTutorialSequence`에 조정값으로 추가하고 코드 하드코딩 금지. 이 규칙은 기존 `EventLaunchSideClearance` 방식을 대체하며(기존 값·`MaxClearanceRatio` 정리 여부는 개발이 판단해 보고) 판정 정합(전환점 = 투사체-플레이어 최근접 순간 = timeScale 최저, 접근 구간 단조 하강, 이탈 구간 1.0까지 상승, 마법 발동 정확히 1회)은 유지한다. 보스가 플레이어에 매우 가까운 경우의 투사체-플레이어 최소 거리 변화와 `L`이 벽 밖으로 나가는지(알려진 문제, 이번에는 해결 범위 밖이므로 수치만 보고)를 측정해 보고한다.
3. **즉시 재발사 제거**: `AllySupportTriggerLogicSystem`의 `HandleCoreHitFail`의 `ally.Attack(bossTarget)`과 불필요해진 구독을 제거한다. 실패 시 보스 HP 60% 회복·오버라이드 Off·카메라 복귀는 그대로. 50% 재도달 시 `OnBoss50Percent`가 다시 방송되는 기존 동작(시퀀서가 실패 후 2단계로 복귀)을 건드리지 않는다.
4. **문서 정정**: 06번(약 L24·L35·L41), 02번, 03번의 "아군 재발사 신호/즉각 재도전" 서술과 13번의 발사 지점 정의(축 위 + 옆 이격)를 사용자 명세에 맞게 고치고, 남은 작업 목록에서 "재도전 밸런스(재발사 샷 데미지)" 항목을 삭제한다.

5. **이벤트 값은 전부 이벤트 SO에서 조정(사용자 확정)**: "모든 값은 이벤트 SO를 통해 값을 조정할 수 있어야 한다." 이벤트 SO는 `PureDataTutorialSequence`(이벤트 시퀀서 SO)로 해석한다(틀리면 사용자가 정정). 이벤트 연출에 쓰이는 조정 수치를 전부 이 SO 한 곳에서 인스펙터로 조정할 수 있게 한다 — 보스 HP 임계값, 발사 지점 각도(120)·거리, 감속 최저 timeScale 및 접근/이탈 곡선 값(현재 `PureDataTimeSlow` 쪽에 있는 이벤트 전용 값 포함), 이벤트 카메라 블렌드 시간·FOV·눈 높이(현재 `PureDataCameraSetting`), 그 밖에 이벤트 연출에만 쓰는 수치. 현재 흩어진 위치(`PureDataTutorialSequence` / `PureDataTimeSlow` / `PureDataCameraSetting`)를 먼저 조사해 목록으로 보고하고, 기존 에셋에 저장된 값은 유실 없이 옮긴다(`FormerlySerializedAs` 등, 이전 값 그대로 유지 확인). 카메라(Movement)·감속(TimeSlow)이 이벤트 SO 값을 읽는 방식은 시스템 간 DIP를 지키는 인터페이스로 하고(스코프 트리가 달라 생성자 주입이 안 되면 `BindEventSequencer`와 같은 사후 배선 패턴), 선택한 방식과 이유를 보고한다. 평상시(이벤트가 아닌) 값은 옮기지 않는다.

### 제외
- 사운드(시스템 없음), 카메라 블렌드 시간의 의미 변경("천천히"의 구체 값은 사용자 확인 후 `PureDataCameraSetting.eventCameraBlendTime`으로 조정 — 이 Goal에서는 현재 값 유지), NPC를 `L`로 옮기는 부분(미구현·별도 결정), `L`이 벽 밖으로 나가는 문제의 해결, 감속 곡선 형태·마법 발동 로직, 평상시 숄더 구도, `ProjectSettings/DynamicsManager.asset`(md5 `803bedbcc15227e788d4fcc3332d80b4` 불변), 새 `*LifetimeScope.cs` 파일.
- 기획서에 없는 판단은 임의로 정하지 말고 "결정 필요"로 보고한다. 방어 로직 과다 금지. 커밋/`git add` 금지.

## 완료 기준 (22번 §11)
- [ ] 이벤트 시작 시 `L`이 `P→B` 수평 방향에서 우측 120°(조정값) 방향, `P`에서 `EventLaunchDistance` 거리에 놓인다(수치 로그로 각도·거리 확인). 플레이어가 보스를 보고 있을 때 `L`이 시야각 밖(좌우 약 90° 이상)임을 확인한다.
- [ ] 투사체가 `L`→`B`로 날아가며 플레이어에게 맞지 않고 이격해 스친다(최소 거리 수치), 전환점=최근접 순간=timeScale 최저, 마법 발동 1회.
- [ ] 실패(마법 미지정 → 속성 게이트 실패) 시 보스 HP가 60%로 회복되고 **아군 추가 발사가 0건**이며(이벤트 투사체 스폰 카운터), 이후 일정 시간(예: 10초) 동안 `OnBoss50Percent`가 재방송되지 않는다. 그 뒤 HP를 다시 50% 아래로 내리면 `OnBoss50Percent`가 정확히 1회 재방송되어 이벤트가 1회 진행된다.
- [ ] 성공 경로 정상(`OnCoreHitSuccess` 1회, 이벤트 투사체 총 1발), 이벤트 카메라(1인칭 vcam) 추적 오차 <0.1°, 이벤트 종료 후 숄더 복귀, 시선 한 프레임 큰 스냅 없음(°/프레임).
- [ ] 이벤트 연출 수치(발사 각도·거리, 감속 최저 timeScale·곡선, 카메라 블렌드·FOV·눈 높이, HP 임계값 등)가 이벤트 SO 하나의 인스펙터에서 조정되고, 값을 바꾸면 실제 동작이 바뀌며(최소 각도·블렌드 시간·최저 timeScale 3개를 값 변경 후 실측), 기존 값이 유실되지 않았다. 코드에 이벤트 수치 하드코딩이 없다.
- [ ] 컴파일 에러 0(DLL mtime 교차), 콘솔 에러 0(Animator `Hash 468800000` 기존 경고 제외), 씬 Missing Script 0 · Missing Reference 기존 1건 불증가, md5 불변.

## 검증 절차 (테스트 이벤트는 케이스당 1회)
1. 수정 전 상태 기록 → 구현 → recompile + recompile_status + 어셈블리 mtime 교차 → 콘솔 에러 0.
2. 케이스: ① 성공(마법 지정, 실제 입력 주입) ② 실패(마법 미지정) → 회복·추가 발사 0·재방송 없음 확인 ③ 실패 후 HP를 다시 50% 아래로 내려 재시작 1회 ④ 플레이어 시작 시선 3가지(보스 방향/반대/옆)에서 이벤트 1회씩(L 각도, 카메라 회전량, 스냅). 1단계 타이머 샷은 돌문 파괴/정지로 통제해 이벤트 투사체 카운트에 섞이지 않게 하고, 보스 일반 공격 투사체는 `IsEventProjectile`로 구분한다. 시퀀서 이벤트 억지 발화 금지(보스 HP를 API로 내려 `OnBoss50Percent`를 실제 경로로 발생). 스크린샷은 scratchpad 절대경로.
3. QA 에이전트는 개발 에이전트와 분리하고 위 수치를 독립 재측정. 실제 하드웨어 마우스/Locked 커서 락온과 플레이어의 실제 공격으로 HP를 내리는 흐름은 검증하지 못함을 한계로 명시.

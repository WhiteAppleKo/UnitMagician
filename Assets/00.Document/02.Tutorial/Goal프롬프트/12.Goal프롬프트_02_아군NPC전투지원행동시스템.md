## Goal

01번 프레임워크(`INpcCombatActor`)로 씬에 배치된 아군 NPC에게 "언제 무엇을 공격할지"만 지시하는 얇은 배선 로직을 구현한다. 1단계는 로컬 반복 타이머로 돌문을 공격, 3단계/재도전은 06(이벤트 시퀀서)의 신호로 보스를 공격.

## 배경 (조사로 확인된 현재 상태)

- `Assets/02.System/07.NpcSystem/00.Data/INpcCombatActor.cs` — `void Attack(GameObject target, PureDataUnit magic = null)`, `event Action OnAttackExecuted`, `event Action OnMoveCompleted`. 이미 구현 완료.
- **[선행 작업, 이번 Goal의 0번 항목] `Assets/02.System/08.DestructibleSystem/`에 파괴 여부 조회 프로퍼티가 없음** — `DestructibleDoorComponent.cs`(`02.Visualizer/`)/`DestructibleDoorLogicSystem.cs`(`01.Logic/`) 확인 결과 `IsDestroyed` 같은 공개 프로퍼티가 없다(02번 기획서 2.8절에서 이미 확인·사용자 승인됨). `PlayDestroy()`는 콜라이더만 비활성화할 뿐 GameObject를 파괴하지 않으므로 `target == null` 체크로는 감지 불가하다. **이번 작업에서 `DestructibleDoorComponent`에 `bool IsDestroyed { get; }` 프로퍼티를 추가하는 최소 확장을 먼저 수행한다**(이미 QA 통과한 04번 시스템의 기존 로직은 변경하지 않고, 프로퍼티 하나만 추가 — `DestructibleDoorLogicSystem`이 이미 파괴 여부를 내부적으로 판단하고 있을 가능성이 높으니 그 내부 상태를 그대로 읽어서 노출하면 됨. 내부에 그런 상태가 없다면 `PlayDestroy()` 호출 여부를 별도 bool로 기록해서 노출).
- 09/10번 작업에서 반복 확인된 함정: **06(이벤트 시퀀서)의 신호를 구독하려면 VContainer 스코프 트리 연결을 먼저 확인**하고, 부모-자식으로 안 이어져 있으면 09/10번과 동일한 해법(인스펙터 직접 참조 + 사후 바인딩, `GameObject.Find`/`FindObjectOfType` 금지)을 적용할 것.

## 범위

### 포함
0. **`DestructibleDoorComponent.cs`(기존 파일, 04번 시스템) 최소 확장** — `public bool IsDestroyed { get; }` 프로퍼티 추가. 기존 `PlayDestroy()`/`ApplyDamage()` 로직은 변경하지 않음(회귀 없이 상태 노출만 추가).
1. **`Assets/02.System/10.AllySupportSystem/`(신규 폴더) 생성** — 착수 직전 `Assets/02.System/` 디스크 상태를 재확인해서 여전히 10이 다음 번호인지 한 번 더 확인할 것(3-2절 규칙).
2. **`01.Logic/AllySupportTriggerLogicSystem.cs`(신규, 순수 C#, `ITickable`+`IDisposable`)**:
   - 생성자(또는 사후 바인딩 방식, 스코프 연결 상황에 따라 결정): `INpcCombatActor ally`, `GameObject stoneDoorTarget`, `GameObject bossTarget`, `IDestructibleDoorVisualizer`/`DestructibleDoorComponent`(`IsDestroyed` 조회용 — 인터페이스로 노출할지 구체 참조로 받을지는 DIP 원칙에 맞게 판단), 06의 이벤트(`OnBoss50Percent`/`OnCoreHitFail`).
   - 내부 상태: `elapsedSinceLastFire(float)`.
   - `Tick()`: 3~4초 간격으로 `stoneDoorTarget`의 `IsDestroyed` 확인 → false면 `ally.Attack(stoneDoorTarget)` 호출+타이머 리셋, true면 `ally.PlayMotion("Idle")`(있다면) 호출하고 타이머 정지(재개하지 않음).
   - `OnBoss50Percent` 구독 핸들러: `ally.Attack(bossTarget)` 1회.
   - `OnCoreHitFail` 구독 핸들러: `ally.Attack(bossTarget)` 즉시 재호출.
3. **`AllySupportSystemLifetimeScope.cs`(신규, 폴더 루트)** — `ally`/`stoneDoorTarget`/`bossTarget`/`destructibleDoorComponent` 인스펙터 참조 필드. 06과의 연결은 위 "배경"에서 언급한 사후 바인딩 패턴 적용.
4. 테스트: `00.TestScene`에 이미 배치된 아군 NPC 액터, 돌문(04번), 보스 대체 참조(`EnemyTest`)를 연결해 배선 검증.

### 제외 (이번 작업 범위 아님)
- 03(보스AI)/05(광역빙결) 시스템 자체 구현.
- `FlagRefCounter`/`CombatFlagState` 등 버프 시스템 연동 — `Attack` 호출 자체는 고정 방식으로 충분(02번 기획서 2.9절 참고 없음, 원 기획서에 언급 없어 범위 아님).
- 04번 시스템의 `IsDestroyed` 외 다른 확장(예: 파괴 애니메이션 개선 등) — 딱 프로퍼티 하나만 추가.

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(`unity eval`/Play Mode)**:
   - 시나리오 A(1단계 반복 발사): 시간 경과에 따라 `ally.Attack(stoneDoorTarget)` 호출 횟수가 3~4초 간격으로 누적되는지 확인(호출 카운트 계측).
   - 시나리오 B(파괴 후 정지): 돌문에 충분한 데미지를 줘서 파괴(`IsDestroyed=true`) → 이후 `Attack` 호출이 더 이상 발생하지 않는지 확인.
   - 시나리오 C(3단계 지원 사격): 06의 `OnBoss50Percent`를 실제로 트리거 → `ally.Attack(bossTarget)` 호출 1회 확인.
   - 시나리오 D(재도전): 06의 `OnCoreHitFail`을 트리거 → `ally.Attack(bossTarget)` 즉시 재호출 확인.
4. **DLV 준수 자체 점검**: 신규 Logic 파일에 구체 타입 직접 참조가 없는지 grep.
5. **범위 확인**: `git status`/`git diff --stat`로 `08.DestructibleSystem/`은 `IsDestroyed` 추가 한 곳만, `07.NpcSystem/`/`09.EventSequencerSystem/`은 무변경, `10.AllySupportSystem/`만 신규 추가됐는지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

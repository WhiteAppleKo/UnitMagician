## Goal
조사표의 신규 Legacy 후보(묶음 A~E, 15개 파일)를 각 기능 폴더의 `99.Legacy/`로 에디터 에셋 이동(GUID 유지)으로 격리하여, 폴더만 봐도 현재 코드와 Legacy가 구분되게 한다. 삭제하지 않고, 코드·네임스페이스·씬 참조를 바꾸지 않는다.

## 범위
### 포함
1. **조사 먼저**: 조사표의 묶음 A~E 파일 각각에 대해 이동 직전에 다시 확인한다 — 활성 코드/씬/프리팹/에셋이 참조하지 않는지(GUID와 타입명 grep, 활성 파일 기준), `.meta` GUID, 현재 위치, 목적지 존재 여부. 조사표와 다른 점(새로 생긴 참조 등)이 있으면 **그 파일은 이동하지 않고 보고**한다(Goal 31~40에서 코드가 바뀌었으므로 재확인 필수).
2. **이동(기획서 §3 표)**: 에디터 API(`AssetDatabase.MoveAsset`, 폴더는 `CreateFolder`)로만 이동한다(파일 시스템 `mv`로 `.meta`를 따로 옮기지 않는다). 묶음 A(7개)는 반드시 함께, 목적지는 `00.Movement/99.Legacy/PlayerMove/`. 묶음 B는 `00.Movement/99.Legacy/`, 묶음 C는 `00.Movement/99.Legacy/CameraModeUI/`, 묶음 D는 `01.UnitSystem/99.Legacy/`, 묶음 E는 신규 `99.Common/99.Legacy/SampleVContainer/`.
3. **정리**: 이동으로 비는 폴더(`00.PlayerMove` 3곳과 `Interface/`, `Strategy`, `UI/Legacy`, `99.Common/SampleVContainer`)를 폴더와 `.meta`째 제거한다(비어 있음을 확인한 뒤). 폴더 안에 다른 파일이 남아 있으면 지우지 말고 보고한다.
4. **문서**: 이동 후 상태에 맞게 조사표(`리팩토링/19.02System_Legacy_구분_조사표.md`)의 신규 후보 15개를 "격리 완료"로 갱신한다(요약 표 수치 포함).

### 제외 (건드리지 않는다)
- 코드 내용·네임스페이스·using 변경, 혼합 파일 4개(`CameraSettingSO.cs`, `ThirdPersonShoulderCameraStrategy.cs`, `TopViewMouseFocusStrategy.cs`, `CameraOptionUIController.cs`) 이동/분리, `02.CharacterSystem/00.Data/PureStatData_.asset`(보류), 이미 `99.Legacy`에 있는 12개, 폴더 규칙 위반 정리(명칭 변경 등), 서드파티 의존 정리, Legacy 삭제, `Assets/PipeLine`.
- 씬/프리팹 저장 금지(이동만으로 참조가 유지되므로 수정 불필요). 씬이 dirty해지면 저장하지 말고 보고.

## 완료 기준 (기획서 §5)
- [ ] 묶음 A~E 파일(.cs, .asset, .uxml 포함)이 목적지에 있고 원래 위치에는 없으며 `.meta` GUID가 이동 전과 같다(이동 전 GUID 목록을 기록해 대조). 비는 폴더가 남아 있지 않다. git에서 이동이 rename으로 보인다.
- [ ] 컴파일 에러 0건(`recompile` + DLL mtime 교차). 이동 외 코드 diff가 없다.
- [ ] `00.TestScene`에서 Missing Script/Missing Reference가 새로 생기지 않는다(씬 로드 후 MonoBehaviour 전수 검사). `Demo_01_Polygon`도 이동 전과 같은 상태로 열린다(확인 후 `00.TestScene`으로 되돌리기, 저장 금지).
- [ ] 이동하지 않기로 한 파일과 이미 격리된 12개는 변경되지 않았다.
- [ ] Play Mode 스모크: 이동/점프/구르기/달리기, 시간정지·락온·마법 시전, 1단계 돌문, 3단계 이벤트 판정 1회, 인벤토리 열기/닫기, LifetimeScope 12개 정상 빌드, 콘솔 에러 0건.
- [ ] 조사표가 이동 후 상태와 일치한다.

## 검증 절차
1. 이동 전 GUID·위치 목록 기록 → 이동 → `unity command recompile` + `recompile_status` + 어셈블리 mtime 교차 확인(스테일 DLL 주의) → `clear_console` 후 `console --level error` 0건.
2. 씬 로드 후 `eval`로 전체 GameObject의 MonoBehaviour null 스크립트 검사.
3. `git status`로 rename·범위 확인(이전 세션 미커밋분과 구분), `ProjectSettings/DynamicsManager.asset` md5 `803bedbcc15227e788d4fcc3332d80b4` 불변.

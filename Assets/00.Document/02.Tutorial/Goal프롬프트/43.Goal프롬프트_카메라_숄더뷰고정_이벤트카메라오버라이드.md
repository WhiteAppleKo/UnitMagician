## Goal
카메라 가상 카메라를 숄더 vcam 하나로 단일화하고, 3단계 이벤트 카메라를 별도 `CameraMode`가 아니라 `ICameraFollowService`의 이벤트 대상 오버라이드(피벗·시선각 덮어쓰기)로 구현하며, 비숄더 시점 코드를 `99.Legacy`로 격리한다.

## 범위
### 포함 (기획서 §3-1, §3-2)
1. **조사 먼저**: 조사표(23번)의 의존 지점이 현재 코드와 일치하는지 재확인한다(Goal 31~41에서 코드가 바뀌었음). 다른 점이 있으면 임의 판단하지 말고 보고한다.
2. **구현 순서(중요)**: ① `ICameraFollowService`에 오버라이드 멤버 추가 + `CameraFollowService`에 이벤트 피벗/시선각 계산 이식(`IEventCameraTargetProvider` 주입, `EventTargetTrackingCameraStrategy`의 계산 참조) + `PureDataCameraSetting`에 보간 시간 값 추가 → ② `EventCameraTriggerLogicSystem`을 오버라이드 호출로 교체 → ③ `CameraFollowVisualizer`를 숄더 vcam 단일 구조로 변경 → ④ 그 다음에야 `allowedModes`를 `[4]`로 정리 → ⑤ `UnitCasterSystem`의 모드 분기 제거 → ⑥ `OptionUIComponent`/`OptionUI.uxml` 모드 버튼 제거 → ⑦ 비숄더 전략·`MouseWorldPositionProvider`·`TopViewMouseCastingStrategy`/`IUnitCastingStrategy`를 `AssetDatabase.MoveAsset`으로 `99.Legacy`에 이동, `LocomotionLifetimeScope` 등록 정리 → ⑧ `CameraMode` 비숄더 멤버 `[Obsolete]` → ⑨ 씬 `Topview`/`FirstPerson` GO 삭제 및 visualizer 필드 정리(씬 저장).
3. **수치는 PureData(SO)로**: 보간 시간 등 조정 가능한 값은 `PureDataCameraSetting`에 두고 코드에 숫자를 하드코딩하지 않는다. DI는 인터페이스 주입, `Find*` 금지, 새 `*LifetimeScope.cs` 파일 금지.
4. **문서**: 10번 기획서, `98.System/02.Locomotion_CameraSystem.md`, `02.예상플레이흐름.md`의 시점·이벤트 카메라 서술만 이번 결정에 맞게 갱신한다.

### 제외 (건드리지 않는다)
- 숄더 오프셋/FOV 수치, `ThirdPersonShoulderCameraStrategy.cs`, `CameraSettingSO.cs` 분리·이동, `CameraOptionUIController.cs`, `SetRequireRightClickToRotate`, 서비스의 UI/Event 입력 게이트, `IEventCameraTargetProvider`/`EventCameraTargetProvider`, 레거시 파일 4종 삭제, `Demo_01_Polygon.unity`, 이력 문서, `ProjectSettings/DynamicsManager.asset`.
- 가정(기획서 §6)과 다르게 보이는 결정(예: 이벤트 종료 후 복귀 시선, 락온/이벤트 충돌, Camera 탭 유지)이 필요하면 임의 판단하지 말고 보고한다.

## 완료 기준 (기획서 §5)
- [ ] 이벤트 진입 시 활성 vcam이 숄더 vcam이고 거리·FOV·오프셋이 평상시와 같다(수치 비교). 이벤트 중 마우스 회전·줌 차단, 종료 후 표시 시선이 (이벤트 중 불변인) 플레이어 시선각으로 보간 복귀(진입 시점 스냅샷 저장 없음), `IsEventTargetOverrideActive` false 복귀.
- [ ] ~~이벤트 중 피벗 = 아군 발사 지점~보스 중점~~ → **정정(22번 §8): 피벗은 플레이어 위치 그대로, 시선만 이벤트 투사체 추적(후속 Goal 44에서 수정)**. 종료 후 피벗 = `player+1.4`. 이벤트 3회 반복해도 누적 오차 없음.
- [ ] 옵션 메뉴에 카메라 모드 버튼 5개 없음, Camera 탭 나머지 옵션 동작, `OptionUI`·`UIDocument (1)` 두 컴포넌트 에러 없음.
- [ ] `UnitCasterSystem`이 모드와 무관하게 락온 경로로만 동작하고, 시간정지→락온→팝업→지정→큐 1회 시전·3단계 판정 회귀 없음.
- [ ] 비숄더 전략·`MouseWorldPositionProvider`·`TopViewMouseCastingStrategy`/`IUnitCastingStrategy`가 `99.Legacy`에 있고 GUID 유지. 컴파일 에러 0건(`recompile` + DLL mtime 교차). `00.TestScene` Missing Script 0, Missing Reference는 기존 1건에서 늘지 않음.
- [ ] `CameraSettingSO.asset`이 `defaultMode: 4`, `allowedModes: [4]`, 혼합 파일 3개 이동·분리 없음.
- [ ] 일반 플레이(이동/점프/구르기/달리기/락온) 회귀 없음, 콘솔 에러 0건, `DynamicsManager.asset` md5 `803bedbcc15227e788d4fcc3332d80b4` 불변.

## 검증 절차
1. 수정 전 씬의 vcam 상태·카메라 수치(거리/FOV/오프셋)를 기록 → 구현 → `unity command recompile` + `recompile_status` + 어셈블리 mtime 교차(스테일 DLL 주의) → `clear_console` 후 `console --level error` 0건.
2. Play Mode에서 3단계 이벤트를 `eval`/로그로 진입·진행·종료까지 수치 확인(활성 vcam, 피벗, 시선각, 오버라이드 플래그), 실패 재도전 3회 반복.
3. 씬 로드 후 전체 MonoBehaviour 널 스크립트 검사, `git status`로 범위 확인(이전 세션 미커밋분과 구분).
4. 입력 주입이 필요하면 Game 뷰 포커스 복구 절차(실제 마우스 클릭 + `OnGameViewFocus(true)`)를 사용하고, 스크린샷은 scratchpad 절대경로에 저장한다.

# Goal 60: 캐릭터 인벤토리 + 마법 목록 탭

> 작성일: 2026-10-23

> 코드 작성은 `코드_가이드라인_v1.0.md`, `VContainer_가이드라인_v1.0.md`, `UI Toolkit 작업 가이드_v1.0.md`, `코드_작업_기획서_가이드라인_v1.0.md` §3-2를 따른다. **개발·QA는 33번 기획서를 기준으로 작업·검증한다.** 개발 에이전트와 QA 에이전트는 분리한다. Unity 라이브 연결은 Bash의 `unity` CLI.

## Goal
33번 기획서대로 다음을 구현한다.
- 플레이어 캐릭터 소유의 인벤토리(`RuntimeDataInventory`, PureData 보관, ItemType별)와 로직(`InventoryLogicSystem`)을 만든다.
- 보유 마법의 소유권을 `UnitCatalogService`에서 인벤토리로 옮긴다.
- 시작 마법의 원천을 플레이어 `PureStatData.defaultUnitMagics`로 옮긴다.
- 필드 습득과 디버그 습득이 인벤토리로 들어가게 한다.
- 인벤토리 창을 ItemType 탭 레지스트리 구조로 다시 만든다. 첫 탭은 마법 탭이고, 창은 드래그 이동 가변형 UI다.

## 사용자 확정 (33번 머리말)
- 인벤토리는 캐릭터가 소유한다. 보관 기준은 PureData이고, `RuntimeDataUnit`은 장착할 때 생긴다(③, 이번 범위 밖).
- 탭은 ItemType에 따라 분류한다(하드코딩 금지). 지금은 마법 탭만 만든다.
- 아이템 정의는 아직 만들지 않는다.
- 필드 아이템은 인벤토리로 들어간다.
- 같은 PureData 에셋은 중복 보유할 수 없다.

## 범위
### 포함
1. **조사 먼저**: 다음을 scratchpad에 기록한다. 기획서와 다른 점이 있으면 기획서 의도를 지키는 범위에서 처리하고 보고에 남긴다.
   - §4 파일과 현재 코드가 맞는지
   - 플레이어가 실제로 쓰는 `PureStatData` 에셋
   - 카탈로그 보유 API 사용처
   - `UnitInventoryUIComponent`의 입력·시간정지·입력 컨텍스트 처리
   - 작업 전 `git status`
2. 순서: Data(ItemType, IInventoryItem, RuntimeDataInventory, PureDataUnit 구현) → Logic(InventoryLogicSystem, 카탈로그 보유 제거) → 습득 경로(Pickup, 디버그, 습득 팝업) → UI(창 틀·탭 레지스트리·마법 탭·드래그) → 등록 → 에셋·씬.
3. 씬·에셋 작업은 코드가 컴파일된 뒤 에디터 API로 한다.
   - 저장 전에 eval로 참조 해석과 Missing Script 0을 확인한다.
   - 저장 후 `git diff`로 의도한 변경뿐인지 확인한다.
   - MainCamera는 CinemachineBrain이 에디터에서 덮어쓰므로, 저장 전에 카메라 값이 디스크와 같은지 확인한다. 다르면 Play를 껐다 켜는 등 원래 값인 상태에서 저장한다. 카메라 diff가 섞이면 멈추고 보고한다.

## 검증 절차
1. 단계별 recompile + `recompile_status` + DLL mtime 교차 → `clear_console` 후 에러 0.
2. Play에서 측정한다.
   - 인벤토리 내용
   - `I`로 창 열기·닫기, 탭 표시, 드래그(실제 입력 주입 우선)
   - 필드 습득
   - 중복 습득
   - 장착·즐겨찾기 회귀
   - 시험용 탭 런타임 등록
   
   키 입력 주입이 안 되면 한계를 명시한다.
3. QA는 개발과 분리해 독립적으로 재측정하고, `git status`로 범위를 확인하며, 검증 한계를 명시한다.

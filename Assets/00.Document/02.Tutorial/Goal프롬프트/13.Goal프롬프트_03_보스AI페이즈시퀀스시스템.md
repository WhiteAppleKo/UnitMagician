## Goal

보스의 페이즈 FSM("두뇌")을 구현한다 — `Idle → BasicAttack(순환) → HP 50% 도달 시 InvulnerableHealing 진입` 후, 06(이벤트 시퀀서)의 `OnCoreHitSuccess`/`OnCoreHitFail` 신호를 기다려 `Dead` 또는 `HP 60% 재설정+BasicAttack 재개`로 전환한다. 보스 액터(`INpcCombatActor`, 01번)는 몸통이고 이 FSM은 상속 없이 참조(주입)만 한다.

## 배경 (조사로 확인된 현재 상태 + 이번 작업의 전제)

- `Assets/02.System/07.NpcSystem/00.Data/INpcCombatActor.cs` — `Attack(GameObject, PureDataUnit)`, `PlayMotion(string)`. 이미 구현 완료.
- `Assets/02.System/02.CharacterSystem/01.Logic/ICharacterStatService.cs` — `RuntimeData.HP`(`OnValueChanged`), `SetInvincible(bool)`, `Heal(int)`. 08번 작업에서 이미 구현 완료.
- `Assets/02.System/09.EventSequencerSystem/01.Logic/IEventSequencer.cs` — `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail`. 09번 작업에서 이미 구현 완료.
- **09/10/02번 작업에서 3번 반복된 VContainer 스코프 연결 문제**: `IEventSequencer`(`EventSequencerSystemLifetimeScope` 소속)를 구독하려는 모든 신규 시스템이 서로 다른 스코프 트리 문제를 겪었다. **이번에도 같은 패턴을 그대로 적용한다** — 신규 `BossPhaseSystemLifetimeScope`에 `[SerializeField] private EventSequencerSystemLifetimeScope eventSequencerScope;` 필드를 두고, `Start()`에서 `eventSequencerScope.Container.Resolve<IEventSequencer>()`를 사후 바인딩(`BossPhaseLogicSystem.BindEventSequencer(...)` 같은 메서드로 노출). `GameObject.Find`/`FindObjectOfType` 금지.
- **06번 작업 이후 확인된 함정(중요)**: VContainer 패키지 자체의 에디터 훅(`ScriptTemplateModifier.cs`)이 새로 생성된 `*LifetimeScope.cs` 파일의 `.meta` 생성 시점에 내용을 빈 스텁으로 덮어쓴다 — `BossPhaseSystemLifetimeScope.cs`를 만든 직후 반드시 파일을 다시 읽어서 의도한 내용이 맞는지 확인할 것.
- 착수 직전 `Assets/02.System/` 디스크 상태를 재확인해서 폴더 번호가 여전히 11인지 확인할 것(3-2절 규칙, 최근 작업들로 09/10이 이미 소비됨).

## 범위

### 포함
1. **`Assets/02.System/11.BossPhaseSystem/`(신규 폴더, 번호 재확인)**:
   - `00.Data/BossPhaseType.cs`(enum) — `Idle/BasicAttack/InvulnerableHealing/Dead`.
   - `00.Data/PureDataBossPattern.cs`(SO) — `attackInterval(float)`, `healPerSecond(float)`, `invulnerablePhaseTimeoutSeconds(float)`, `reviveHpRatioOnFail(float, 기본 0.6f)`.
   - `00.Data/RuntimeDataBossPhase.cs`(RuntimeData) — private set `currentPhase`/`previousPhase`, 메서드 `ChangePhase(BossPhaseType)`, 이벤트 `OnPhaseChanged(BossPhaseType, BossPhaseType)`.
   - `01.Logic/BossPhaseLogicSystem.cs`(순수 C#, `ITickable`+`IDisposable`) — 생성자(또는 사후 바인딩): `INpcCombatActor bossActor`, `ICharacterStatService bossStatService`, `RuntimeDataBossPhase runtimeData`, `PureDataBossPattern pureData`, `GameObject playerTarget`. `BindEventSequencer(IEventSequencer)` 사후 바인딩 메서드로 06 연결.
     - `Tick()`: `currentPhase==BasicAttack`이면 `attackInterval` 주기로 `bossActor.Attack(playerTarget)`. `currentPhase==InvulnerableHealing`이면 매 프레임 `bossStatService.Heal(healPerSecond*deltaTime)`.
     - `bossStatService.RuntimeData.HP.OnValueChanged` 구독 — `current/max<=0.5f` 최초 도달 시 `SetInvincible(true)`+`ChangePhase(InvulnerableHealing)`(이미 이 상태 이상이면 재판정 안 함 — 09번의 `HandleBossHpChanged` 가드 패턴 재사용).
     - `OnCoreHitSuccess` 핸들러: `ChangePhase(Dead)` + `bossActor.PlayMotion("Death")`.
     - `OnCoreHitFail` 핸들러: 목표 HP(`reviveHpRatioOnFail*maxHp`)와 현재 HP 차이만큼 `Heal(diff)` + `SetInvincible(false)` + `ChangePhase(BasicAttack)`.
   - `02.Visualizer/IBossPhaseVisualizer.cs`(인터페이스) — `PlayPhaseTransitionEffect(BossPhaseType)` 등.
   - `02.Visualizer/BossPhaseVisualizer.cs`(구현체) — `RuntimeDataBossPhase.OnPhaseChanged` 구독, 페이즈별 플레이스홀더 이펙트(파티클/사운드는 실제 아트 없이 로그/임시 이펙트로 대체 가능, 10.4절과 동일한 수준의 플레이스홀더 허용).
   - `BossPhaseSystemLifetimeScope.cs`(폴더 루트) — `bossStatComponent`/`bossActor`/`playerTarget`/`eventSequencerScope` 인스펙터 참조, VContainer 등록.
2. 테스트: `00.TestScene`에 이미 배치된 보스 대체 참조(`EnemyTest`, 09/10/02번이 이미 이렇게 써온 관례)를 `INpcCombatActor` 구현체와 연결해 배선 검증(01번 프레임워크로 배치된 실제 NPC 액터가 씬에 있다면 그걸 사용).

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(`unity eval`/Play Mode)**:
   - 시나리오 A(BasicAttack 순환): 초기 상태에서 `attackInterval` 주기로 `Attack(playerTarget)` 호출 반복 확인.
   - 시나리오 B(50% 감지+무적): HP를 50% 이하로 낮춤 → `IsInvincible=true`, `CurrentPhase=InvulnerableHealing`, 이후 추가 HP 변화에도 재판정 없음 확인.
   - 시나리오 C(회복 진행): `InvulnerableHealing` 상태에서 시간 경과에 따라 HP가 실제로 증가하는지 확인.
   - 시나리오 D(성공): 06의 `OnCoreHitSuccess` 트리거(실제 얼음 속성 피격 재현 또는 직접 invoke) → `CurrentPhase=Dead`, `PlayMotion("Death")` 호출 확인.
   - 시나리오 E(실패): 06의 `OnCoreHitFail` 트리거 → HP가 목표 비율로 재설정, `IsInvincible=false`, `CurrentPhase=BasicAttack` 복귀 확인.
   - 시나리오 F(재도전): E 이후 다시 HP를 50% 이하로 낮춰서 B가 재현되는지 확인(전체 루프 재확인).
4. **DLV 준수 자체 점검**: `BossPhaseLogicSystem.cs` grep으로 구체 타입 직접 참조 없음 확인.
5. **범위 확인**: `git status`/`git diff --stat`로 `02.CharacterSystem/`, `07.NpcSystem/`, `09.EventSequencerSystem/`은 무변경(이전 세션 미커밋 잔여물 제외), `11.BossPhaseSystem/`만 신규인지 확인.

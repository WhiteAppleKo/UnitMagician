## Goal
3단계 감속을 "`EventSlowTimeScale`에서 1.0까지 시간 기반 선형 램프"에서 **아군 투사체의 위치(플레이어를 기준으로 한 접근/이탈)로 구동되는 곡선**으로 바꾼다. 접근 구간에서 `timeScale`이 점점 강해져 전환점 직전에 거의 정지(0보다 큰 최저값)가 되고, **전환점에서 쌓인 마법을 한 번 발동**한 뒤 이탈 구간에서 1.0까지 올라간다.

## 배경 (확인된 현재 상태)
- `TimeSlowLogicSystem.ProcessTimeSlow()`가 `RuntimeDataTimeSlow.TickEventRamp(unscaledDelta)`로 `t`를 얻어 `Mathf.Lerp(EventSlowTimeScale, 1.0f, t)`를 `visualizer.SetTimeSlowEffect(true, scale)`에 매 프레임 넘기고, `t >= 1`이면 `DeactivateEventSlow()`를 호출한다. 시작은 `HandleBoss50Percent()` → `ActivateEventSlow(CoreHitTimeoutSeconds)`.
- `RuntimeDataTimeSlow`에 `isEventTriggered`, `eventRampElapsedSeconds`/`eventRampDurationSeconds`, `BeginEventRamp`/`TickEventRamp`/`EndEventRamp`가 있다.
- `IEventSequencer`에는 `OnBoss50Percent`/`OnCoreHitSuccess`/`OnCoreHitFail` 세 이벤트만 있고, 구독자는 `TimeSlowLogicSystem`, `AllySupportTriggerLogicSystem`, `EventCameraTriggerLogicSystem`이다(UnitSystem/CharacterSystem과 EventSequencerSystem은 서로 다른 스코프라 `BindEventSequencer` 사후 배선 패턴 사용).
- 일괄 시전 실행은 `RuntimeDataMultiLockOn.RequestBatchCast()` → `OnBatchCastRequested` → `UnitCasterSystem.ExecuteBatchCast()` 경로가 이미 있다.
- **아군 NPC가 쏜 투사체의 참조/발사 지점을 이벤트 시퀀서가 받는 경로는 없다(사용자 확정).** 이벤트 시퀀서(`09.EventSequencerSystem`)에 이 기능을 새로 추가해야 한다.
- `TimeSlowVisualizer`가 전역 `Time.timeScale`을 직접 설정한다(`TimeSlowVisualizer.cs` 31/40행). 1단계 완전정지에서 같은 아군 투사체가 멈추는 것이 이미 검증돼 있어 투사체는 `timeScale`의 영향을 받을 가능성이 높다.

## 범위
### 포함
1. **발사 지점 지정 + 투사체 참조 수신(이벤트 시퀀서)**: `OnBoss50Percent` 시점에 시퀀서가 **플레이어 `P`와 보스 `B` 위치를 스냅샷(이벤트 진입 시점에 고정)**하고 **발사 지점 `L`을 그 축 위에 직접 정한다**(`d = normalize(B − P)`, `L = P − d × EventLaunchDistance`, `PureDataTutorialSequence.EventLaunchDistance` 신규 필드). 아군 NPC가 투사체를 쏘는 코드(`AllySupportTriggerLogicSystem`/`07.NpcSystem`/아군 발사 코드를 읽고 발사 방식을 확인)가 그 `L`에서 발사하도록 연결하고, **투사체 참조를 시퀀서가 받는 경로**를 `09.EventSequencerSystem`에 새로 만든다(예: 시퀀서가 구독하는 발사 신호 인터페이스 + 비행 추적기 구현체가 투사체 `Transform`을 보관). 구조상 `L`, `P`, `B`가 한 직선 위에 있으므로 축 배치 전제 검증/폴백은 필요 없다. 기존 아군 지원 로직의 변경은 최소로 하고, 크로스 스코프는 기존 `BindEventSequencer` 사후 배선 패턴을 재사용한다. 구현 중 투사체가 감속 중 실제로 느려지는지(`timeScale` 영향)를 라이브로 한 번 확인한다 — 영향을 받지 않으면 보고한다(기대: 받음).
2. **데이터**: `PureDataTimeSlow`에 `EventSlowMinTimeScale`(float, 0보다 큰 "거의 정지" 값, 인스펙터로 조정 가능, 기본 0.03 안팎) 추가(필요하면 접근/이탈 `AnimationCurve`). `RuntimeDataTimeSlow`의 시간 기반 램프(`BeginEventRamp`/`TickEventRamp`/`EndEventRamp`, `eventRamp*` 필드)를 `EventFlightPhase`(`None`/`Approach`/`Exit`)와 `EventFlightProgress`(0~1) 모델로 대체한다. `IsEventTriggered`는 "접근 시작부터 이벤트 종료까지 true"로 유지한다. 구간/진행도 변경 이벤트를 발행한다.
3. **비행 구간 계산 로직(순수 C#, `09.EventSequencerSystem/01.Logic/`)**: 인터페이스 `IEventFlightTracker`(`HasProjectile`, `LaunchPosition`, `PlayerPosition`, `BossPosition`, `ProjectilePosition` — 모두 `Vector3`/`bool`)로 위치를 받아 매 프레임(unscaled) `d = normalize(B − L)`, `s = dot(X − P, d)`, 접근 진행도 `t = dot(X − L, d) / dot(P − L, d)`, 이탈 진행도 `u = dot(X − P, d) / dot(B − P, d)`를 계산하고 구간(`s < 0` 접근, `s > 0` 이탈)과 **전환점(음→양, 래치로 한 번만)**을 판정한다. 진행도는 0~1로 클램프한다. `P`와 `B`는 이벤트 진입 시점의 스냅샷이고 `L`은 시퀀서가 축 위에 정하므로 축 전제는 구조상 성립한다(`EventLaunchDistance <= 0` 또는 `P == B`로 0으로 나누는 경우만 방어). 결과는 `IEventSequencer`에 신호(구간/진행도 변경, 전환점)로 추가해 노출한다.
4. **`IEventFlightTracker` 구현체(비주얼)**: 투사체 위치(매 프레임)와 이벤트 진입 시 고정된 `LaunchPosition`/`PlayerPosition`/`BossPosition`을 제공한다. Transform 접근은 이 구현체 안에서만 하고 Logic은 `Vector3` 값만 받는다. `GameObject.Find`/`FindObjectOfType` 금지, 기존 스코프/배선 패턴 재사용.
5. **`TimeSlowLogicSystem`**: `ActivateEventSlow()`는 접근 시작으로(게이지 오버라이드 + 이벤트 감속 + 마나 무제한 On 유지), `ProcessTimeSlow()`는 구간/진행도로 `timeScale`을 구동한다 — 접근: `lerp(1.0, EventSlowMinTimeScale, curve(t))`, 이탈: `lerp(EventSlowMinTimeScale, 1.0, curve(u))`. 시간 기반 `t >= 1`로 `DeactivateEventSlow()`를 호출하던 분기는 제거한다(이벤트 종료는 명중 판정 `OnCoreHitSuccess`/`OnCoreHitFail`이 기존대로 수행).
6. **전환점 발동**: 전환점 신호를 받은 UnitSystem 쪽 로직이 (a) 팝업/`PendingTarget` 취소 + 이후 락온 입력 무시(지정 창 닫기), (b) `RuntimeDataMultiLockOn.RequestBatchCast()` 호출, (c) 위상을 `Exit`로 전환한다. 큐가 비어 있으면 아무것도 적용하지 않는다. 이벤트 종료 시 `DeactivateEventSlow()` → `SetSlowActive(false)` 훅이 `ExecuteBatchCast()`를 다시 호출해도 큐가 이미 비어 있어 이중 발동이 없어야 한다.
7. 3단계 시청각(`ITimeSlowVisualizer.SetTimeSlowEffect(true, scale)`가 매 프레임 서로 다른 `scale`을 받는 구조)이 새 곡선에서도 그대로 동작하는지 확인한다.

### 제외
- 이벤트 중 `T`/인벤토리 차단, `SetSlowActive(false)` 거부, 06 타임아웃 분기 제거, 3단계 성공 조건 확장(13-B).
- 미리보기/마나 UI(13-C), 큐/락온별 팝업(13-A).
- 곡선의 정확한 모양/최저값 튜닝은 연출 값이므로 기본값으로 동작하게만 하고 세부는 나중에 조정 가능.

## 완료 기준 (기획서 §5 해당 항목)
- [ ] 접근 구간에서 투사체가 플레이어에 가까워질수록 `timeScale`이 단조롭게 내려가 전환점 직전에는 `EventSlowMinTimeScale`(0보다 큼)에 가깝고, 정상 속도로 비행하다 감속 중 정지하지 않고 전환점에 도달한다(투사체가 영영 닿지 못하는 상태 없음).
- [ ] 전환점(`dot(X − P, d)` 음→양)에서 **정확히 한 번** 큐가 발동한다. 이중 발동이 없고, 그 순간 팝업/`PendingTarget`이 닫히고 이후 락온 입력이 무시된다. 큐가 비어 있으면 아무것도 적용되지 않는다. 마나 소모는 0(마나 무제한 상태).
- [ ] 이탈 구간에서 `timeScale`이 최저값에서 1.0까지 올라간다. 명중은 항상 전환점 이후에만 일어난다. 발사 지점은 시퀀서가 플레이어 뒤쪽 축 위에 두며, 실제 아군 발사 경로로 투사체가 그 지점에서 나와 축을 따라 날아오는지 확인한다.
- [ ] 이벤트 종료는 명중 판정 신호로만 일어나고(타임아웃/`timeScale` 1.0 도달 자체가 종료 조건이 아님), 종료 후 `IsEventTriggered`/구간/게이지 오버라이드/마나 무제한이 모두 해제된다.
- [ ] 재도전(`OnCoreHitFail` 후 `OnBoss50Percent` 재방송) 시 접근→전환점→이탈 사이클이 처음과 똑같이 반복된다(래치/상태 초기화 포함).
- [ ] 일반 시간정지(1단계 스타일 완전정지), 게이지 오버라이드, HUD, 카메라 이벤트 트래킹(10번)에 회귀가 없다.
- [ ] DLV/VContainer 규칙 준수(Logic은 `Vector3` 값만, Transform은 비주얼 구현체에서만).

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인. `clear_console` 후 `console --level error` 0건.
2. Play Mode(`Time.frameCount`가 멈추면 `editor_focus`, 안 되면 리플렉션 직접 호출로 `IEventFlightTracker` 위치를 시뮬레이션): 투사체 위치 `X`를 `L`에서 `P`를 지나 `B`까지 단계적으로 이동시키며 각 단계의 구간/진행도/`timeScale`을 기록해 단조 하강 → 전환점 1회 발동 → 단조 상승을 확인한다. 큐가 비어 있는 경우, 마법 2개를 쌓은 경우(발동 시 마나/변환 결과)도 확인한다. 이벤트 진행 중 플레이어가 이동한 경우 판정이 `P` 스냅샷 기준으로 일관되게 동작하는지(시각적 어긋남 여부 포함)를 확인하고 결과를 보고한다. 실제 아군 발사 경로로도 한 번 이상 라이브 재현해 투사체 참조 경로가 동작하는지 확인한다.
3. `git diff --stat`로 범위 확인(이전 세션 미커밋분은 구분).

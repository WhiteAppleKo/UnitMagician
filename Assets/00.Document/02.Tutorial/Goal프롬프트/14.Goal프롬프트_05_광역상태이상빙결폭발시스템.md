## Goal

06(이벤트 시퀀서)의 `OnCoreHitSuccess`(이미 03/06이 판정 완료한 신호)를 받아, 보스 위치 중심 반경 내 `IFreezable` 대상(보스+지형)을 수집해 순차적으로 빙결 이펙트를 재생하는 4단계 피니시 연출 시스템을 구현한다.

## 배경 (조사로 확인된 현재 상태 + 반복 확인된 함정)

- `Assets/02.System/09.EventSequencerSystem/01.Logic/IEventSequencer.cs` — `OnCoreHitSuccess` 등. 09번 완료.
- `Assets/02.System/11.BossPhaseSystem/` — 03번 완료. `BossPhaseLogicSystem`이 이미 `OnCoreHitSuccess`를 독립 구독해 스스로 `Dead` 전환 + HP 0 처리(무적 게이트 우회) + `PlayMotion("Death")`을 수행한다. **05번은 03번에 신호를 중계하지 않는다 — 06의 같은 신호를 각자 독립적으로 구독하는 형제 관계다(05번 기획서 5.8절에 이미 명시).** 즉 결정타 성공 시 보스에게는 "사망 모션 재생"(03)과 "빙결 이펙트 재생"(05)이 동시에 독립적으로 일어나는 것이 의도된 설계다(둘 다 자연스럽게 겹쳐 보이는 연출 — 이 자체는 문제가 아니다).
- `Assets/PipeLine/Contexts/DamageContext.cs` — 명중 좌표 필드 없음(확인 완료). 폭발 중심은 `context.Victim.transform.position`(보스 위치)으로 대체(5.8절에서 이미 확정, 재확인 불필요).
- **보스에 `IFreezable`을 구현시켜야 하는데, 이미 QA 통과한 03번의 `BossPhaseVisualizer`를 수정하지 말 것.** 대신 같은 보스 GameObject에 신규 컴포넌트(예: `BossFreezableComponent : MonoBehaviour, IFreezable`)를 별도로 추가해 `IFreezable.Freeze()`를 구현하는 방식으로 03번 파일을 건드리지 않고 해결한다.
- **09/10/02/03번에서 4번 연속 반복된 VContainer 스코프 연결 문제**: `IEventSequencer` 구독은 이번에도 확립된 패턴(인스펙터 직접 참조 + `Start()` 사후 바인딩, `GameObject.Find`/`FindObjectOfType` 금지) 그대로 적용.
- **VContainer 에디터 훅 함정**: `*LifetimeScope.cs` 신규 파일은 `.meta` 생성 시점에 빈 스텁으로 자동 리셋될 수 있다(확정된 사실, 프로젝트 메모리 기록됨) — 생성 직후 반드시 재확인.
- 착수 직전 `Assets/02.System/` 디스크 상태를 재확인해서 폴더 번호가 여전히 12인지 확인할 것.

## 범위

### 포함
1. **`Assets/02.System/12.AreaFreezeSystem/`(신규 폴더, 번호 재확인)**:
   - `00.Data/PureDataAreaFreeze.cs`(SO) — `freezeRadius(float)`, `freezeSequenceDelay(float)`.
   - `01.Logic/AreaFreezeTriggerLogicSystem.cs`(순수 C#) — 06의 `OnCoreHitSuccess` 구독(사후 바인딩) → `IAreaFreezeVisualizer.TriggerAreaFreeze(bossGameObject)` 호출. `Physics`/`Transform` 직접 접근 금지(아래 Visualizer가 담당).
   - `02.Visualizer/IFreezable.cs`(인터페이스, `void Freeze()`), `IAreaFreezeVisualizer.cs`(인터페이스), `AreaFreezeVisualizer.cs`(구현체 — `Physics.OverlapSphere(bossGameObject.transform.position, pureData.FreezeRadius)`로 `IFreezable` 컴포넌트 수집 → `freezeSequenceDelay` 간격 순차 `Freeze()` 호출, 명중 순간 화이트아웃/파티클/폭발음 플레이스홀더 재생), `FreezableTerrainComponent.cs`(지형용 `IFreezable` 구현체, 플레이스홀더 이펙트로 충분).

2. **`BossFreezableComponent.cs`(신규, 위 "배경" 참고)** — 보스 GameObject에 추가로 부착할 `IFreezable` 구현체. `Freeze()` 호출 시 플레이스홀더 이펙트 재생(사망 모션은 03번이 이미 담당하므로 이 컴포넌트는 시각 효과만 책임).
3. 테스트: `00.TestScene`의 보스 대체 참조(`EnemyTest`)와 씬 내 임의 지형 오브젝트 1~2개에 `FreezableTerrainComponent`를 부착해 배선 검증.

### 제외 (이번 작업 범위 아님)
- 피격 파이프라인을 1:N 브로드캐스트로 확장하는 리팩토링(5.2/5.9절 기존 미해결 항목) — 이번엔 `Physics.OverlapSphere` 기반 별도 시각 계층으로 구현하는 것으로 확정, 파이프라인 자체 확장은 하지 않음.
- 실제 얼음 텍스처/셰이더 아트 리소스 — 플레이스홀더로 충분.
- 03번(`BossPhaseVisualizer`/`BossPhaseLogicSystem`) 수정 — 절대 건드리지 않음.

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정, 필요시 `write_text_file`).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(`unity eval`/Play Mode)**:
   - 시나리오 A(반경 내 수집): 보스 주변에 `FreezableTerrainComponent`가 붙은 오브젝트를 반경 안/밖에 각각 배치 → 06의 `OnCoreHitSuccess` 트리거 → 반경 안 대상만 `Freeze()` 호출됨을 확인(호출 카운트/로그로 계측).
   - 시나리오 B(순차 지연): 여러 대상이 있을 때 `Freeze()` 호출 시각이 `freezeSequenceDelay` 간격으로 벌어지는지 확인.
   - 시나리오 C(보스 포함): 보스 자신의 `BossFreezableComponent.Freeze()`도 호출되는지 확인, 이때 03번의 `Dead`/`PlayMotion("Death")` 처리와 충돌(예외 발생 등) 없이 공존하는지 확인.
   - 시나리오 D(무관 신호 무시): `OnCoreHitFail`이나 다른 신호에는 반응하지 않는지 확인.
4. **DLV 준수 자체 점검**: `AreaFreezeTriggerLogicSystem.cs` grep으로 구체 타입 직접 참조 없음 확인.
5. **범위 확인**: `git status`/`git diff --stat`로 `09.EventSequencerSystem/`, `11.BossPhaseSystem/`은 무변경(이전 세션 미커밋 잔여물 제외), `12.AreaFreezeSystem/`만 신규 + 보스 GameObject에 컴포넌트 추가만 있는지 확인.

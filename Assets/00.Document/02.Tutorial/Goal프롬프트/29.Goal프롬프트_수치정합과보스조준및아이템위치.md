## Goal

### A. 아군 투사체 기본 데미지를 04번 설계에 맞게 정합
현재 아군 투사체의 기본 데미지(`CollisionDamageTrigger.baseDamage`, 값의 출처는 `PureDataNpcActor_Dummy`/`ProjectileAttackBehaviorSO` 계열 에셋 — 코드를 읽고 정확한 출처를 찾을 것)가 **10**이라 돌문 HP 100에 대해 질량 ×2(`kg`)를 써도 `FinalDamage 20`에 그쳐 1단계 돌문을 못 부순다. 04번 설계(얼음만 → 실패, 얼음+크기 확대 → 파괴)가 성립하도록 기본 데미지를 올린다.
- **크리티컬 고려(중요)**: 아군 샷은 크리티컬(`critMultiplier` 1.5 추정 — 실제 값은 코드/에셋에서 확인)이 터질 수 있고 돌문 파이프라인에도 크리티컬이 적용된다(이전 검증에서 `raw 15 → final 30` 관찰). 설계 예시의 70을 그대로 쓰면 얼음만 + 크리티컬 = 105 ≥ 100으로 돌문이 부서진다. 따라서 **얼음만(크리티컬 포함) 최대값 < 돌문 HP(100) ≤ 얼음+크기 확대(×2, 크리티컬 미발동) 최소값**이 되도록 기본 데미지를 정한다(예: 기본 60 → 얼음만 60/크리티컬 90 < 100, 얼음+크기 120/180 ≥ 100). 크리티컬 배율과 질량 ×2를 실제 값으로 확인해 숫자를 확정하고 근거를 보고한다.
- **3단계 성공 기준 재조정**: `PureDataTutorialSequence_.asset`의 `CoreHitRequiredDamage`(현재 20)를 새 기본 데미지에 맞게 조정한다 — 얼음만(크리티컬 포함 최대) < 기준치 ≤ 얼음+크기 확대(크리티컬 미발동) 최소값(돌문 HP와 같은 값이 자연스럽다). 값을 바꾼 근거를 보고한다.
- **보스 HP 정합**: 같은 아군 투사체 데이터를 보스 쪽 일반 샷도 쓰므로(보스와 아군이 같은 `PureDataNpcActor_Dummy`/공격 SO를 공유) 데미지 상향이 보스에게도 영향을 준다. 테스트 씬 보스 최대 HP가 50이라 일반 피격 한 번에 죽는 문제가 생기지 않도록 보스 HP/아군·보스 샷 데미지 분리 등으로 13~15번 흐름(보스 HP 50% → 이벤트 → 실패 후 60% 회복 → 재도전)이 테스트 씬에서 계속 성립하게 한다. 가장 단순한 방법을 고르고(예: 보스 최대 HP 상향, 또는 보스 샷 데미지를 별도 값으로) 선택과 근거를 보고한다. 질량 배율/돌문 HP는 바꾸지 마라.
- 검증: 1단계에서 얼음만 → 돌문 `cracked but survived`(크리티컬 포함 여러 번 반복해도 파괴 안 됨), 얼음+크기(kg ×2, 마법 두 개를 한 투사체에 지정) → `DESTROYED`. 3단계에서 얼음만/크기만/없음 → `OnCoreHitFail`, 얼음+크기 → `OnCoreHitSuccess`(크리티컬 변동에도 일관되게 구분, 반복 10회 이상).

### B. 보스 투사체 스킬이 플레이어 가슴 높이를 조준
보스가 쏘는 투사체(보스 공격 스킬)가 플레이어를 맞히지 못한다(수십 발 동안 플레이어 HP 100 유지). 원인: `ProjectileAttackBehaviorSO`가 `target.transform.position`(플레이어 피벗 = 발 위치)을 겨냥하고, 12 m/s Discrete 충돌로 얇은 캡슐 바닥을 통과(추정).
- 조준점을 대상의 **가슴 높이**로 바꾼다. 하드코딩 오프셋 대신 대상의 콜라이더 중심(`Collider.bounds.center`/`CharacterController` 중심 등)을 우선 사용하고, 없으면 `transform.position + up × 조정 가능한 오프셋`을 쓰는 식으로 가장 단순하고 일관된 규칙을 택한다(규칙과 근거 보고).
- 이 규칙은 **모든 투사체 공격**에 적용되므로 아군→돌문, 아군→보스(이벤트 투사체 포함), 보스→플레이어 모두에 영향이 없는지 확인한다(돌문/보스에 대한 조준점 변화로 명중/판정이 깨지지 않아야 함). 필요하면 충돌 감지 설정(Collision Detection Mode 등)도 점검한다.
- 검증: 보스 샷이 플레이어에게 실제로 명중해 HP가 감소하는지(여러 발), 플레이어가 맞은 직후 풀 반환/판정이 정상인지, 아군→돌문/아군→보스 흐름(13번 이벤트, 1단계 돌문)과 풀링 회귀 없음.

### C. 습득 아이템 위치 조정 (Frost 아이템이 화면 구석/HUD에 가려짐)
14번 QA: `PickupItem_Frost`(-1.4, 0.5, -0.4)가 시작 위치(0.1, 0.11, 0.66)에서 화면 좌하단 구석(HUD 퀵슬롯 영역)에 걸려 거의 안 보이고 두 아이템 모두 줍기 반경(1.5m) 밖이다. 두 아이템(`PickupItem_Frost`, `PickupItem_Mass`)을 **시작 시점에 화면 중앙 부근에서 둘 다 보이고** HUD에 가려지지 않으며 몇 걸음 안에 반경에 들어오는 위치로 옮긴다(아군→돌문 사선, 보스, 락온 대상 구체와 겹치지 않게). 씬 저장. 카메라 시점(3인칭 숄더뷰)에서의 실제 화면 위치를 확인한다(스크린샷 또는 `Camera.WorldToScreenPoint`로 화면 좌표/HUD 영역과의 겹침을 수치로 확인).

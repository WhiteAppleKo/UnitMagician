## Goal
30번 기획서대로 다음을 구현한다.
- `RuntimeDataUnit`을 "원본 PureData + 캐싱 수치"를 가진 시전 마법 인스턴스(타입별 서브클래스)로 바꾼다.
- 피격 대상에 속성 상태(`RuntimeDataUnitAttribute`)와 적용 마법 목록(`RuntimeDataUnitTarget`)을 둔다.
  - 추가는 목록 끝에 누적한다.
  - 조건 해제 후에는 남은 항목을 앞으로 당긴다.
  - 같은 속성의 곱 배율은 합산한 뒤 베이스에 곱한다.
- 속성 값 계산·시각·데미지는 타입별 Applicator가 목록을 입력받아 처리한다. 실제 적용과 미리보기는 같은 계산 함수를 쓴다.

## 사용자 확정 (30번 머리말)
- RuntimeDataUnit = PureData 기반, 시전자 스탯·장비 영향을 받아 캐싱한 마법 한 번의 런타임 인스턴스(영향 계산 자리는 비워 둠).
- 대상은 적용 마법을 순서대로 누적하고, 같은 속성이어도 교체하지 않는다.
- 해제는 조건으로 골라 내고, 남은 항목은 순서를 유지한 채 앞으로 당긴다.
- 같은 속성은 곱 배율을 합산한 뒤 베이스에 곱한다(Mass ×2 3회 = ×6).
- 그 밖의 결합 규칙은 미리 정하지 않는다.

## 범위
### 포함
1. **조사 먼저**: §4 파일 목록과 §3-1 표가 현재 코드와 맞는지 확인한다. `RuntimeDataUnit`·`GetMatchingUnitData`·`CalculateNewValue`·`ChangeUnit` 사용처 전체 목록과 작업 전 `git status`를 scratchpad에 기록한다. 표와 다른 점이 있으면 보고하고, 기획서 의도에 맞게 처리할 수 있는지 판단해서 처리 내용을 최종 보고에 남긴다.
2. Data(인스턴스 4개 클래스, 속성·대상 상태) → Logic(Applicator 확장, 레지스트리, 적용 시스템, 시전·미리보기·비용) → 파이프라인·게이트 → UI 컴파일 유지 순서로 진행한다. 단계마다 recompile을 확인한다. 중간 단계에서 컴파일이 깨지는 묶음은 함께 진행해도 되며, 그 묶음은 보고에 적는다.
3. 해제 API는 eval로 검증한다. 게임플레이 호출처는 만들지 않는다.

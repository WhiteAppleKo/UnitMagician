# Goal 53: `Assets/02.System` 전체 기능별 하위 폴더 분류 (Legacy 제외, 순수 이동)

## Goal
27번 기획서의 분류에 따라 `01.UnitSystem`(Data/Visualizer/UI), `02.CharacterSystem`(Data/Logic), `07.NpcSystem`(Data/Logic/Visualizer), `09.EventSystem`(Data 루트 파일·Logic)의 파일을 기능별 하위 폴더로 에디터 에셋 이동(GUID 유지)한다.

## 사용자 확정 (27번 §2·§6)
- 기능(사용 방식)별로 나누되 **세세하게 나누지 않는다**(레이어 폴더에 8개 이상 + 2기능 이상일 때만). 비슷한 이름의 폴더(`Casting`/`Caster` 등) 금지. 공용 기반은 `00.Common`. 같은 기능은 레이어가 달라도 같은 이름·번호.
- 평탄 유지 대상: `03.InteractionSystem`, `04.OptionSystem`, `05.TimeSlowFilter`, `08.DestructibleSystem`, `10.AllySupportSystem`, `11.BossPhaseSystem`, `12.AreaFreezeSystem`, `13.PickupSystem`, `00.Movement`, `99.Common`.

## 범위
### 포함
1. **조사 먼저**: 각 대상 시스템 폴더의 현재 파일 목록이 27번 §3 표와 일치하는지 확인하고, 이동 직전 파일별 GUID·경로를 scratchpad에 기록한다(시스템별로). 표와 다른 점(새 파일 등)은 임의로 분류하지 말고 보고하며, 표에 없는 파일은 이동하지 않는다. 한 파일이 둘 이상의 기능에 걸쳐 보여도 분리하지 말고 표대로 둔다.
2. **이동**: 에디터 API(`AssetDatabase.CreateFolder`, `AssetDatabase.MoveAsset`)로만 이동한다(파일시스템 `mv`로 `.meta`를 따로 옮기지 않는다). 분류(27번 §3-2~§3-5):
   - `01.UnitSystem`: `00.Data`, `02.Visualizer`, `03.UI`를 `00.Common`/`01.QuickSlot`/`02.TimeStop`으로(`00.Data/Editor/`는 그대로).
   - `02.CharacterSystem`: `00.Data`(11) → `00.Stat`/`01.PlayerState`/`02.TimeSlow`, `01.Logic`(14 + `State/`) → `00.Stat`/`01.PlayerState`(기존 `State/` 폴더는 이 안으로 합쳐 `State/` 폴더 제거)/`02.TimeSlow`/`03.MagicSlot`. `02.Visualizer`(4)·`03.UI`(1)는 평탄.
   - `07.NpcSystem`: `00.Data`/`01.Logic`/`02.Visualizer`를 `00.CombatActor`/`01.Projectile`/`02.Blocker`로.
   - `09.EventSystem`: `01.Logic`(19) → `00.Core`/`01.Triggers`/`02.Completions`/`03.Actions`/`04.Flight`, `00.Data` 루트의 `RuntimeDataEvent` → `00.Definition`, `EventFlightPhase` → `04.Flight`(신설). `02.Visualizer`(5)는 평탄.
3. **문서**: 시스템 설명 문서(`Assets/00.Document/98.System/*.md`)가 폴더 구조를 서술하는 경우 해당 서술만 갱신(없으면 생략하고 보고). 옛 평탄 경로를 가리키는 과거 이력 문서는 수정하지 않는다(목록만 보고).

### 제외 (건드리지 않는다)
- 코드 내용·클래스명·네임스페이스·using·파일 이름 변경, 혼합 파일 분리, `99.Legacy`, `Editor/`, `*LifetimeScope.cs`, 이미 분류된 폴더(`00.Movement`, `99.Common/Input|Pooling`, `09.EventSystem/00.Data`의 기존 4개 하위 폴더, `01.UnitSystem/01.Logic`), `03.UI`·`02.Visual`(`05.TimeSlowFilter`) 등 기존 폴더 규칙 위반 정리, 기능 로직 변경, 씬/프리팹 저장(이동만으로 참조는 유지됨 — 씬이 dirty해지면 저장하지 말고 보고), `ProjectSettings/DynamicsManager.asset`(md5 `803bedbcc15227e788d4fcc3332d80b4` 불변). 새 `*LifetimeScope.cs` 파일 금지. 커밋·`git add` 금지.

## 완료 기준 (27번 §5)
- [ ] §3 표의 파일이 모두 새 위치에 있고 해당 레이어 폴더 루트에 분류 대상 .cs가 남지 않는다. 이동한 `.meta` GUID가 이동 전과 같다(씬/프리팹/에셋이 참조하는 컴포넌트·ScriptableObject 포함, 특히 `CharacterStatComponent`, `NpcCombatActorVisualizer`, `BlockerNPC`, `NpcProjectile`, `NpcProjectilePool`, `UnitInventoryUIComponent` 등 씬 컴포넌트). 빈 폴더/고아 `.meta`/`State/` 폴더 잔존 없음.
- [ ] 코드 내용·네임스페이스 변경 없음(이동 전후 내용 해시 동일), 컴파일 에러 0(`recompile` + DLL mtime 교차), 콘솔 에러 0, `00.TestScene`에서 Missing Script 0 · Missing Reference 기존 1건 불증가.
- [ ] 모든 LifetimeScope 컨테이너가 정상 빌드(Play 중 VContainer 에러 없음). Play 스모크(시스템별 1회, 실제 입력 주입 우선): 이동·점프·구르기, 퀵슬롯 선택, 시간 정지 → 락온 → 팝업 → 지정 → 해제 시전(MP 변화 이전과 동일), 돌문 이벤트(NPC 사격 → 파괴 → 비켜서기), 보스 50% 이벤트 1회, 옵션 메뉴, 인벤토리 장착/해제, 필드 아이템 습득, 광역 빙결.
- [ ] 범위 밖 폴더 무변경, `DynamicsManager.asset` md5 불변, staged 파일 0개.

## 검증 절차
1. 시스템별: 이동 전 GUID·경로 목록 기록 → 이동 → `unity command recompile` + `recompile_status` + 어셈블리 mtime 교차(스테일 DLL 주의) → `clear_console` 후 콘솔 에러 0 → 다음 시스템.
2. 전체 이동 후 씬 로드 `eval`로 MonoBehaviour null 스크립트 검사, Play 스모크.
3. QA는 개발과 분리해 독립 재측정한다(GUID 18+개 전수 대조 포함). `git status`로 범위 확인(이전 미커밋분과 구분), 한계(하드웨어 마우스 입력 등)를 명시한다.

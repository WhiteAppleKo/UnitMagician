## Goal
아군 투사체(`NpcProjectile_Dummy`)를 매 발사마다 생성하고 소멸하지 않게, 공용 풀링(`Assets/02.System/99.Common/Pooling`)으로 재사용한다. 반환은 두 경우다: (1) 충돌 판정을 마친 뒤, (2) 빗나가 최대 거리/수명을 넘은 경우.

## 범위
### 포함
1. **조사 먼저**: `99.Common/Pooling`(`IPoolService<T,TData>`, `IPoolable<TData>`(`Setting`/`SetActive`/`ReturnToPool`), `PoolingManager`, `PoolSettingStruct`/`PoolSettingData`)의 실제 구현을 읽고 현재 아무 데서도 쓰이지 않는 이 코드가 투사체에 바로 쓸 수 있는지, 필요한 최소 확장이 무엇인지 파악한다. 투사체 생성 경로(`ProjectileAttackBehaviorSO`, `NpcCombatActorVisualizer.SpawnAndInject`, `INpcProjectileLaunchHook`/발사 지점 예약, `CollisionDamageTrigger`, 13-D의 `EventFlightTrackerComponent.HandleProjectileSpawned`)를 읽는다.
2. **풀링 적용**: 투사체가 `IPoolable<TData>`를 구현하고(`TData` = 발사 설정: 소유자, 목표, 속도, 데미지, 발사 지점 등 현재 주입되는 값), 생성은 `IPoolService.Get`, 반환은 `Release`로 한다. `PoolingManager`는 기존 VContainer 패턴으로 인터페이스 등록한다(구체 클래스 주입 금지, `Find*` 금지).
3. **반환 경로 두 가지**: (a) `CollisionDamageTrigger`가 `ProcessDamageAsync`를 **마친 뒤에** `Release`(현재 `destroyOnImpact` 대신/연동 — 판정이 먼저 처리되는 순서를 반드시 유지), (b) 충돌하지 못하고 플레이어 또는 발사 지점으로부터 최대 거리/최대 수명을 넘기면 `Release`(수치는 조정 가능한 PureData 기본값).
4. **재사용 시 상태 초기화(`Setting`/`SetActive`에서 완전하게)**: `RuntimeDataUnitGroup`의 온도/질량/부피/방향 값과 스케일, `CollisionDamageTrigger`의 owner(`UpdateCollisionTriggerOwner`가 플레이어로 바꿈)와 `hitHistory`, 하이라이트/락온 마커, 13-C 미리보기 고스트, Rigidbody 속도/각속도, 13-D 이벤트 투사체 추적기 참조/`Source` 식별이 전부 초기값으로 돌아가게 한다.
5. **13번 시스템 정합 + 소실 통지 연동**: 풀 반환(비활성화)이 `RuntimeDataMultiLockOn`의 pending/큐 정리(15-A의 소실 정리)에 즉시 반영되게 한다(풀 반환 시점에 통지하는 쪽을 우선 검토). 이벤트 투사체 식별(`IsEventTriggered` 연계 `IsEventProjectile`)과 소실 감지(`HasProjectile`)가 풀 반환과 올바르게 동작하고, 판정 후 풀 반환이 "소실 → 실패"를 이중 발행하지 않아야 한다.

### 제외
- 아군 외 다른 투사체/오브젝트 풀링, 풀 크기/거리/수명의 최종 수치, 밸런스, 설정 실수 방어.

## 완료 기준 (기획서 §5의 투사체 풀링 항목)
- [ ] 투사체가 명중 후 풀로 반환되고 같은 개체가 다음 발사에서 재사용된다(발사 횟수에 비례해 씬의 활성 투사체/총 생성 수가 늘지 않는다). 빗나가 최대 거리/수명을 넘으면 풀로 반환된다. 수십 회 반복에도 총 생성 수가 상한 안에서 유지된다.
- [ ] 재사용된 투사체 상태가 초기값이다: 이전에 얼음+크기 확대를 걸었던 투사체가 다시 나올 때 온도/질량/스케일/owner/피격 이력/하이라이트/고스트가 모두 초기화돼 있다. 3단계에서 이전 사이클의 마법이 다음 사이클 투사체에 남지 않는다.
- [ ] 풀로 반환된 투사체를 가리키던 pending/큐 엔트리가 정리되고, 재사용된 투사체에 이전 큐 엔트리가 적용되지 않는다.
- [ ] 13번 회귀: 이벤트 투사체 식별·소실 감지·판정(얼음+크기 성공/얼음만·크기만·없음 실패), 전환점 1회 발동, 재도전이 동일하게 동작하고 풀 반환으로 `OnCoreHit*`가 이중 발행되지 않는다. 1단계 돌문 퍼즐(타이머 샷 → 락온 → 인챈트 → 크기 확대 → 파괴)이 동작하고 돌문 파괴 후 타이머 정지가 유지된다.
- [ ] DLV/VContainer 규칙 준수.

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인. `clear_console` 후 `console --level error` 0건.
2. Play Mode(`Time.frameCount` 정지 시 리플렉션 직접 호출): 반복 발사(수십 회)로 활성/총 생성 수 추적, 명중 반환과 범위 이탈 반환 각각, 얼음+크기를 건 투사체를 반환시킨 뒤 재사용 시 상태가 초기화됐는지(`RuntimeDataUnitGroup` 값/스케일/owner/hitHistory), 풀 반환 시 pending/큐/팝업/미리보기/마나 UI 정리, 3단계 실제 경로(발사 → 접근/전환점/이탈 → 명중 판정 → 재도전)를 풀링 후에도 여러 사이클 확인한다.
3. `git diff --stat`/`git status`로 범위 확인(이전 세션 미커밋분은 구분).

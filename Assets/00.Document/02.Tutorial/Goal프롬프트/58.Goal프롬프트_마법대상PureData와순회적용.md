# Goal 58: 마법 대상 PureData 신설 + 적용 마법 목록 순회 적용

## Goal
31번 기획서대로 다음을 구현한다.
- 마법 대상 PureData(`PureDataUnitTarget`)를 신설하고, 지원 속성과 원본 값을 컴포넌트 필드·코드 상수에서 PureData로 옮긴다.
- 대상 RuntimeData(`RuntimeDataUnitTarget`)는 PureData를 참조하고 실제 상태 필드를 갖는다. 목록이 바뀔 때마다 "PureData로 리셋 → 적용 목록 순회 적용 → 확정"으로 상태를 다시 만든다.
- `RuntimeDataUnitAttribute`는 삭제한다.
- 유저가 보는 결과는 30번 구현과 같아야 한다.

## 사용자 확정 (31번 머리말)
- 런타임 상호작용이 필요한 모든 항목은 PureData를 갖고, RuntimeData는 그 PureData 기반 캐시다. 마법 대상도 마찬가지다.
- `bakedMassValue`는 테스트용 임시 필드였다.
- 대상 RuntimeData는 PureData 값으로 초기화하고, 목록이 바뀔 때마다 PureData로 되돌린 뒤 목록을 순서대로 순회 적용한다.
- 누적, 조건 해제 후 당김, 같은 속성 곱 배율 합산 후 베이스에 곱하는 규칙은 30번 그대로 유지한다.

## 범위
### 포함
1. **조사 먼저**: §3-1 "지금 위치" 열과 §4 파일 목록이 현재 코드와 맞는지 확인한다. 기록할 것은 다음과 같다.
   - `bakedMassValue`·`supportedUnits`의 직렬화 값: 씬, 프리팹 2개(`Assets/_Recovery` 제외)
   - `RuntimeDataUnitAttribute`·`GetAttribute` 사용처
   - 작업 전 `git status`
   
   모두 scratchpad에 기록한다. 기획서와 다른 점이 있으면, 기획서 의도를 지키는 범위에서 처리하고 보고에 남긴다.
2. 순서: Data(PureData 클래스 → 에셋 3개) → RuntimeData 개편 → Logic(누적기, 계산기, Applicator, 적용 시스템, 시전, 미리보기, 비용) → 게이트 → UI 컴파일 유지 → 에디터 툴 → 씬·프리팹 연결.
3. **씬·프리팹 연결은 컴파일이 완전히 끝나고 새 필드가 직렬화된 뒤에만 한다.** 에디터 API로 `targetData`를 연결한다. 저장하기 전에 eval로 다음을 확인한다.
   - 각 대상의 `targetData`
   - `initialUnits`/`testUnits`/`grantedUnit` 참조 해석
   - Missing Script 0
   
   저장한 뒤에는 `git diff`로 의도한 변경(`targetData` 연결, 옛 필드 제거)뿐인지 확인한다. 카메라 등 의도하지 않은 변경이 섞였으면 원래 값으로 되돌린다.

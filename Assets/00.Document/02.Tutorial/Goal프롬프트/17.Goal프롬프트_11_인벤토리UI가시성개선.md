## Goal

사용자 피드백: "인벤토리 UI 가시성, 상단의 바 형태로 가시성이 안좋음, 장착해제 요소가 없음."

1. `UnitUI.uxml`의 `InventoryContainer`를 화면 상단 얇은 바 형태에서 **화면 중앙 모달 패널** 형태로 바꾼다.
2. `UnitInventoryUIComponent.cs`가 그리드로 그리는 각 유닛 아이콘 **하단에 유닛 이름 + 장착 상태("장착됨"/"미장착") 텍스트**를 추가한다.

## 배경 (조사로 확인된 현재 상태)

- `Assets/02.System/01.UnitSystem/03.UI/UnitUI.uxml`: `Root`는 `flex-direction: column; justify-content: space-between;`. `QuickSlotContainer`/`UnlockButtonContainer`/`TargetInfoContainer`/`PopupPanel`은 전부 `position: absolute`라 플로우에서 빠져 있는데, `InventoryContainer`(16행)만 `position` 지정이 없어 플로우에 남아 있고, 그 결과 `Root` 패딩(20px) 바로 아래 화면 최상단에 걸쳐진 얇은 가로 바로 렌더링된다(`flex-direction: row; flex-wrap: wrap; background-color: rgba(0,0,0,0.4);`).
- `Assets/02.System/01.UnitSystem/03.UI/UnitInventoryUIComponent.cs`의 `BuildUnitElement(PureDataUnit)`(166~204행)는 48×48 `VisualElement`에 배경 아이콘 이미지 + 테두리 색(장착 시 노랑 3px, 미장착 시 회색 1px)만 설정한다. 텍스트 요소(`Label` 등)는 전혀 추가하지 않는다.
- `PopupPanel`(25~28행)이 이미 이 UXML에서 화면 중앙 부근에 절대 위치로 배치된 모달형 패널의 참고 예시(`top: 30%; left: 35%; background-color: rgba(20,20,20,0.9); border-color: rgb(255,215,0); border-width: 2px; border-radius: 12px;`) — 인벤토리 패널의 톤도 이와 맞출 것.

## 범위

### 포함
1. **`UnitUI.uxml`(기존 파일) 수정** — `InventoryContainer`를 `position: absolute`로 바꾸고 화면 중앙에 위치시킨다(예: `top`/`left`/`translate` 또는 고정 `width`+`left: 50%`+마진 방식 등 UI Toolkit에서 통용되는 중앙 정렬 방법 중 적절한 것 선택). 배경을 더 불투명하게, 테두리를 추가해 "메뉴 창"임이 명확히 드러나게 한다. 내부 아이콘 그리드가 여러 줄로 wrap될 수 있도록 고정 폭을 준다.
2. **`UnitInventoryUIComponent.cs`(기존 파일) 수정** — `BuildUnitElement(...)`에서 아이콘 `VisualElement` 하단에 `Label` 2개(또는 줄바꿈 포함 1개) 추가:
   - 유닛 이름(`unitData.UnitName` 등 기존 코드에서 쓰던 필드 — `UnitUnlockPopupUIComponent.cs`가 참고한 필드명 확인해서 동일하게 사용).
   - 장착 상태 텍스트: `catalogService.IsEquipped(unitData)`가 `true`면 "장착됨", 아니면 "미장착"(조건 미달로 `canEquip==false`인 경우는 기존 회색+비활성 처리에 맞춰 "장착 불가" 등 구현 시 적절히 결정).
   - 아이콘 전체를 감싸는 부모 컨테이너를 만들어(현재 `unitElement` 자체가 아이콘이므로) 아이콘+라벨을 세로로 쌓는 구조로 바꾸되, 기존 `RegisterCallback<ClickEvent>` 클릭 대상(아이콘 전체)과 테두리/배경 스타일은 그대로 유지한다.
3. 씬에 배치된 `UI Test`(또는 해당 UIDocument) GameObject가 새 레이아웃으로도 정상 동작하는지 Play Mode에서 라이브 확인.

### 제외 (이번 작업 범위 아님)
- 인벤토리 열기/닫기 로직(`ToggleInventory`/`OpenInventory`/`CloseInventory`, `I` 키, `Time.timeScale`, `UIContext` Push/Pop) — 변경 없음.
- 장착/해제 자체 로직(`TryEquipUnit`/`UnequipUnit`, 클릭 핸들러) — 변경 없음, 그대로 재사용.
- 게이팅 스탯 실제 구현, 인벤토리 여는 키 확정, Option/Inventory 동시 오픈 문제 — 기존과 동일하게 범위 밖.

## 완료 기준 (Definition of Done)

- [ ] 인벤토리를 열면(`I` 키) 패널이 화면 상단의 얇은 바가 아니라 화면 중앙 부근의 눈에 띄는 모달 패널로 나타난다.
- [ ] 각 유닛 아이콘 하단에 유닛 이름과 장착 상태("장착됨"/"미장착") 텍스트가 표시된다.
- [ ] 장착 상태를 클릭으로 토글하면(기존 기능) 라벨 텍스트도 즉시 "장착됨"↔"미장착"으로 갱신된다(`RefreshInventory()`가 전체 재빌드하므로 자동으로 반영되어야 함).
- [ ] 기존 장착 시 테두리 강조(노랑) 표시는 유지된다.
- [ ] 인벤토리 열기/닫기, `Time.timeScale` 정지/복원, `UIContext` Push/Pop, Option 메뉴(Escape)/시간정지(T) 동작에 회귀가 없다.
- [ ] 숫자키 1~4 테스트 습득 키(`UnitDebugAcquireTestComponent`) 동작에 회귀가 없다.
- [ ] 신규/수정 코드가 DLV/VContainer 규칙을 위반하지 않는다(UI 컴포넌트 자체는 MonoBehaviour이므로 해당 없음, 서비스는 인터페이스로만 주입).

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `console --level error` 0건.
3. **기능 검증(Play Mode)**:
   - 시나리오 A(레이아웃): `I` 키로 인벤토리를 열고 패널이 화면 중앙에 눈에 띄게 나타나는지 스크린샷/직접 확인.
   - 시나리오 B(라벨): 숫자키로 유닛을 1~2개 습득한 뒤 인벤토리를 열어 각 아이콘 아래 이름+장착상태 텍스트가 정확히 보이는지 확인.
   - 시나리오 C(토글 반영): 미장착 유닛 클릭 → 라벨이 "장착됨"으로 바뀌고 테두리도 강조되는지 확인 → 다시 클릭 → "미장착"으로 복귀 확인.
   - 시나리오 D(회귀): Option 메뉴(Escape), 시간정지(T), 테스트 습득 키(1~4)가 여전히 정상 동작하는지 확인.
4. **범위 확인**: `git diff --stat`로 `UnitUI.uxml`, `UnitInventoryUIComponent.cs`에 한정되고 다른 시스템은 무변경인지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

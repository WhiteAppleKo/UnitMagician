## Goal
Goal 47 QA가 찾은 "이벤트 SO 밖에 남은 이벤트 값"을 전부 `PureDataTutorialSequence` 한 곳에서 조정되게 한다. 특히 (1) 보스 페이즈 임계값 상수가 이벤트 SO의 `bossHpThresholdRatio`와 따로 놀아 SO 값을 바꾸면 이벤트만 시작되고 보스가 무적·회복 상태로 들어가지 않는 결함을 없애고, (2) 실패 시 보스 회복 비율을 이벤트 SO에서 조정하게 한다.

## 사용자 확정 대상 (QA47 보고 §4-③ / 사용자에게 보고한 목록)
1. `BossPhaseLogicSystem.InvulnerableHealingHpThresholdRatio = 0.5` 상수 → 이벤트 SO의 `bossHpThresholdRatio`를 읽도록(단일 원천). **SO를 0.7로 바꿨을 때 이벤트 시작과 보스의 무적·회복 페이즈 진입이 같은 임계값에서 일어나야 한다.**
2. 실패 시 보스 회복 비율 `PureDataBossPattern.reviveHpRatioOnFail`(0.6) → 이벤트 SO.
3. 회복(무적) 페이즈 관련 `healPerSecond`, `invulnerablePhaseTimeoutSeconds` (`PureDataBossPattern`) → 이벤트 SO.
4. 아군 **이벤트 투사체(보스 50% 지원 사격)의 속도·데미지** → 이벤트 SO. **조사 결과(2026-10-14, 읽기 전용 확인)**: 현재 아군은 돌문을 부수는 1단계 타이머 샷(`Tick()`의 `ally.Attack(stoneDoorTarget)`)과 이벤트 샷(`HandleBoss50Percent`의 `ally.Attack(bossTarget)`)을 **같은 NPC·같은 공격 방식으로 쏜다** — 속도는 `ProjectileAttackBehavior_Dummy.asset`의 `projectileSpeed`(12)이고 **같은 에셋을 보스 NPC(`PureDataNpcActor_Boss`)도 쓰며**, 데미지는 NPC 데이터의 `baseDamage`(아군 `PureDataNpcActor_Dummy` 60, 보스 10)이다. 즉 현재는 돌문 샷과 이벤트 샷이 구분되지 않는다. **사용자 확정 설명(2026-10-14)**: 돌문 샷은 아군이 그냥 반복할 뿐이고 거기에 플레이어가 시간 정지 + 마법을 쓰는 퍼즐이므로 투사체 속도·데미지·부여된 마법이 유효한 값이다(아군/NPC 데이터의 값 그대로 유지). 반면 **보스 체력 50%에서 시작하는 연출은 이벤트 시퀀서가 직접 개입해 모든 것을 세팅**하므로 아군 NPC 자체의 투사체 속도·데미지는 의미가 없고, **이벤트 투사체의 속도는 곧 이벤트 진행 시간(= 플레이어가 판단할 수 있는 시간)** 이다 — 느리게 날수록 판단 시간이 길어진다. 따라서 이벤트 SO에는 "이벤트 투사체 속도(판단 시간을 결정하는 값, 툴팁에 이 의미를 적는다)"와 이벤트 투사체 데미지를 이벤트 샷 전용으로 두고, **이벤트 샷만** 이 값을 쓴다. 돌문 샷·보스 샷(공유 에셋)은 값이 바뀌지 않아야 한다. 구현 방식은 개발이 정하되(예: 이벤트 샷 호출 시 속도·데미지를 넘기는 경로) 공유 에셋 값(12 / 60 / 10)을 이벤트 SO로 단순 이동하지 않는다. 이벤트 SO 초기값은 현재 값(속도 12, 데미지 60)으로 시작해 이전 동작과 동일하게 한다.
5. 카메라 블렌드 곡선(`CameraFollowVisualizer`의 EaseInOut 하드코딩) → 이벤트 SO.
6. 투사체 추적 높이 오프셋 `EventFlightTrackerComponent.playerAnchorOffset`(0,1,0, 씬 직렬화) → 이벤트 SO.
- 위 6개 외에 조사 중 발견되는 "이벤트 연출에만 쓰는 하드코딩/분산 수치"도 목록으로 보고하고 같은 방식으로 옮긴다. **이벤트가 아닌 평상시 값(보스 일반 공격 주기, 1단계 아군 타이머 간격 등)은 옮기지 않는다** — 경계가 모호하면 임의 판단하지 말고 최종 보고에 "결정 필요"로 적는다.

## 범위
### 포함
1. **조사 먼저**: 위 6개 값의 현재 위치·사용처·현재 값(에셋 직렬화 포함)을 전수 확인하고 목록으로 보고한다. 특히 4번(아군 투사체 속도·데미지)은 1단계 타이머 샷과 이벤트 샷이 같은 값을 공유하는지 확인한다. **공유한다면 평상시 동작이 바뀌지 않도록, 이벤트 투사체에만 적용되는 값을 이벤트 SO에 두고 평상시 값은 그대로 두는 방식을 기본으로 하되, 구현 방식은 개발이 정해 보고한다(사용자 확인 대상).**
2. **옮기기**: 값은 이벤트 SO 한 곳의 인스펙터에서 조정. 읽는 쪽은 인터페이스(DIP)로(47번의 `IEventTimeSlowSettings`/`IEventCameraSettings` 패턴 확장 또는 새 읽기 전용 인터페이스). 스코프 트리가 달라 생성자 주입이 안 되면 기존 `BindEventSequencer`류 사후 배선 패턴, 선택한 방식과 이유 보고. 새 `*LifetimeScope.cs` 파일 금지(VContainer 훅이 빈 스텁으로 리셋함). Find* 금지.
3. **값 보존**: 기존 에셋에 저장된 값(0.6, 5, 10, 투사체 값, 곡선, (0,1,0) 등)은 유실 없이 이벤트 SO로 옮기고 이전/이후 값을 비교해 보고(`FormerlySerializedAs` 등). 옮긴 뒤 원래 위치의 중복 필드는 정리하되, 평상시에도 쓰는 필드는 지우지 않는다.
4. **임계값 단일 원천**: 이벤트 시퀀서의 50% 판정과 보스 페이즈(무적·회복) 진입이 같은 이벤트 SO 값을 읽는다. 보스 페이즈 쪽이 시퀀서와 다른 스코프 트리라면 그 연결 방식을 보고한다.
5. **문서**: 06·03·09·13번 및 22번 §12(구현 결과)에서 이 값들의 위치·설명을 새 구조에 맞게 정정한다.

### 제외
- 사운드(시스템 없음), 카메라 블렌드 시간의 값 자체("천천히"의 값은 사용자가 정할 때까지 현재 0.5초 유지), NPC를 `L`로 옮기는 부분(미구현·별도 결정), `L`이 벽 밖으로 나가는 문제의 해결, 각도·거리 안전 범위 제한, 감속 곡선 형태·마법 발동·판정 로직, 평상시 숄더 구도, 평상시(비이벤트) 값 이동, `ProjectSettings/DynamicsManager.asset`(md5 `803bedbcc15227e788d4fcc3332d80b4` 불변).
- 기획서에 없는 판단은 임의로 정하지 말고 "결정 필요"로 보고. 방어 로직 과다 금지. 커밋/`git add` 금지.

## 완료 기준
- [ ] 위 6개 값이 이벤트 SO(`PureDataTutorialSequence`) 한 곳에서 조정되고, 코드에 해당 수치 하드코딩이 없다(`InvulnerableHealingHpThresholdRatio` 상수 제거 확인). 기존 값 유실 없음(이전/이후 비교표).
- [ ] **임계값 단일 원천 실측**: 이벤트 SO `bossHpThresholdRatio`를 0.7로 바꿔 이벤트를 1회 발생시키면 이벤트 시작과 보스의 무적·회복 페이즈 진입이 모두 70% 근처에서 일어난다(`bossPhase`와 `IsInvincible`로 확인). 원복 후 0.5에서도 정상.
- [ ] **실패 시 회복 비율 실측**: 이벤트 SO의 회복 비율을 0.6에서 다른 값(예: 0.8)으로 바꾸면 실패 시 보스 HP가 그 비율로 회복된다(원복 후 0.6 정상). 회복 속도·무적 페이즈 타임아웃, 이벤트 투사체 속도/데미지, 카메라 블렌드 곡선, 추적 높이 오프셋도 값을 바꾸면 실제 동작이 바뀐다(각각 1회 실측 후 원복, 디스크 에셋 값 불변 확인).
- [ ] 평상시 동작 회귀 없음: 1단계 타이머 샷의 속도·데미지·주기, 보스 일반 공격이 변하지 않는다.
- [ ] 성공/실패 이벤트 흐름 회귀 없음(성공 1회, 실패 → HP 회복 → 아군 추가 발사 0건 → 50% 재도달 시 재시작 1회). 카메라 추적 오차 <0.1°, 시선 스냅 없음.
- [ ] 컴파일 에러 0(DLL mtime 교차), 콘솔 에러 0(Animator `Hash 468800000` 기존 경고 제외), 씬 Missing Script 0 · Missing Reference 기존 1건 불증가, md5 불변.

## 검증 절차 (테스트 이벤트는 케이스당 1회)
1. 수정 전 상태와 값 목록 기록 → 구현 → recompile + recompile_status + 어셈블리 mtime 교차 → 콘솔 에러 0.
2. 이벤트는 보스 HP를 API로 내려 `OnBoss50Percent`를 실제 경로로 발생(시퀀서 이벤트 억지 발화 금지). 1단계 타이머 샷은 돌문 파괴/정지로 통제. 값 변경은 런타임 인메모리로 하고 반드시 원복(디스크 에셋 md5 불변 확인). 스크린샷은 scratchpad 절대경로.
3. QA 에이전트는 개발 에이전트와 분리하고 위 수치를 독립 재측정. 한계(하드웨어 마우스/Locked 커서 락온, 실제 공격으로 HP를 내리는 흐름 미검증)를 명시.

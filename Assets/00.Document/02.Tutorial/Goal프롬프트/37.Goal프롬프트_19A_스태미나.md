## Goal
HP/MP처럼 `RuntimeStatData`에 스태미나 값을 추가하고, 소모(`TryUseStamina`/`DrainStamina`)·지연 회복·달리기 연속 소모와 고갈 시 달리기 차단(최대치의 30% 회복 전 재시작 불가)·HUD 바를 구현한다. 구르기는 이 Goal에 없다(19-B). 공격 소모는 **소모 경로만** 열어 둔다(플레이어 공격이 구현돼 있지 않음).

## 범위
### 포함
1. **조사 먼저**: `PureStatData`, `RuntimeStatData`(HP/MP 클램프 값, 이벤트 패턴), `ICharacterStatService`/`CharacterStatSystem`(MP 소모·회복 API 패턴, 무적/마나 무제한 오버라이드), `CharacterHUDUIView`(HP/MP 바 구성, UXML), `LocomotionLogicSystem`의 달리기(스프린트) 처리와 `InputReader.onSprintActivated/Deactivated`, 틱 구동 방식(`ITickable`/`Tick`)을 읽고 기획서와 다른 점이 있으면 구현 전에 보고한다.
2. **데이터(§3-1)**: `PureStatData`에 `maxStamina`/`staminaRegenPerSecond`/`staminaRegenDelaySeconds`, `RuntimeStatData`에 `Stamina`(HP/MP와 같은 클램프 값; 연속 소모에 소수 누적이 필요하면 보고하고 가장 단순한 방식 선택)·`TimeSinceLastStaminaUse`·`OnStaminaChanged`. `PureDataLocomotion`에 `sprintStaminaCostPerSecond`, `sprintRestartThresholdRatio`(기본 0.3), `RuntimeDataLocomotion`/적절한 데이터에 `IsSprintLocked`. 기존 `PureStatData_*.asset`(플레이어/보스/아군 등)에는 새 필드가 기본값 또는 명시값으로 들어가야 한다.
3. **서비스/로직**: `ICharacterStatService`에 `bool TryUseStamina(float)`(부족하면 소모 없이 false), `void DrainStamina(float)`, 조회·이벤트를 추가하고 `CharacterStatSystem`이 구현한다. 회복 틱: 마지막 소모 뒤 지연이 지나면 초당 회복(게임 시간 `Time.deltaTime` — 시간정지/일시정지 중 정지).
4. **달리기(§3-2)**: 달리는 동안(이동 중 스프린트) 매 프레임 `DrainStamina(sprintStaminaCostPerSecond × dt)`. 0이 되면 달리기 해제 + `IsSprintLocked = true`, 스태미나가 `maxStamina × sprintRestartThresholdRatio` 이상으로 회복되면 잠금 해제. **0.3 같은 임계값을 코드에 박지 않는다.**
5. **공격 소모 경로**: 공격 데이터에서 `TryUseStamina(attackStaminaCost)`를 호출할 수 있는 형태(메서드/필드 자리)만 열어 둔다. 실제 연결은 플레이어 공격 구현 시(범위 밖).
6. **HUD**: `CharacterHUDUIView`에 스태미나 바를 HP/MP 옆에 추가(UXML 요소 + 바인딩, `OnStaminaChanged` 구독). 소모 즉시 줄고 회복 시 찬다.

### 제외 (건드리지 않는다)
- 구르기·입력 재배치·`IgnoreAttack` 레이어(Goal 38), 플레이어 공격 구현, 스태미나 UI 연출(깜빡임 등), 보스/NPC의 스태미나 사용, 수치 밸런스 최종화.

## 완료 기준 (기획서 §5)
- [ ] `TryUseStamina`: 충분하면 정확히 소모되고 true, 부족하면 소모 없이 false. `DrainStamina`는 0 미만으로 내려가지 않는다. `OnStaminaChanged`가 값이 바뀔 때만 발행된다.
- [ ] 마지막 소모 뒤 `staminaRegenDelaySeconds`가 지나야 `staminaRegenPerSecond`로 회복이 시작된다. 시간정지(`timeScale 0`)/일시정지 중에는 회복·소모가 멈춘다.
- [ ] 달리는 동안 스태미나가 `sprintStaminaCostPerSecond`로 줄고 0이 되면 달리기가 멈춘다. 최대치의 `sprintRestartThresholdRatio`(기본 30%) 이상 회복되기 전에는 달리기를 시작하지 못하고, 이상이 되면 다시 달릴 수 있다. 인스펙터에서 이 비율 값을 바꾸면 코드 수정 없이 반영된다(코드에 임계값 숫자 없음 — grep).
- [ ] HUD 스태미나 바가 소모/회복에 맞게 갱신된다(스크린샷 또는 `eval`로 바 값 확인).
- [ ] 13~18 회귀(락온 팝업, 큐 1회 발동, 3단계 판정), 이동/점프/낙하/지면 판정 회귀 없음, 콘솔 에러 0건, 디스크에 임시 코드/값 잔존 없음.

## 검증 절차
1. `unity command recompile` → `recompile_status` + 어셈블리 mtime 교차 확인(스테일 DLL 주의). `clear_console` 후 `console --level error` 0건.
2. Play Mode 실측. 달리기는 Game 뷰 포커스 후 `InputSystem.QueueStateEvent`로 Shift+이동 입력을 주입해 확인하고, 안 되면 `eval`로 서비스를 직접 호출해 확인한 뒤 UNVERIFIED로 명시한다.
3. `git diff --stat`/`git status`로 범위 확인(이전 세션 미커밋분과 구분).

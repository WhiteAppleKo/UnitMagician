## Goal

기존 시간 정지 시스템(`Assets/02.System/02.CharacterSystem/`)에 **두 가지 서로 다른 시간 정지 모드**를 구현한다:
1. **완전 정지**(기존, 유저 수동 발동) — 변경 없음.
2. **감속 모드**(신규, 06번 이벤트 시퀀서 전용) — 부분 감속 배율로 시작해 06의 회복 페이즈 지속시간에 걸쳐 자동으로 원래 속도(1.0배)로 되돌아오며, 06의 성공/실패 판정을 받으면 즉시 정상 속도로 복귀.

더불어 게이지 오버라이드(시간 정지 유지 중 포커스 게이지 소모 억제)와, 이를 위해 필요한 06번 시스템의 소규모 인터페이스 추가(`IEventSequencer`)도 이번 작업 범위다.

## 배경 (조사로 확인된 현재 상태 + 이번 작업의 전제)

- `Assets/02.System/02.CharacterSystem/00.Data/RuntimeDataTimeSlow.cs`/`PureDataTimeSlow.cs`, `01.Logic/TimeSlowLogicSystem.cs` — 기존 완전 정지 로직(`ActivateSlow`/`DeactivateSlow`/`ToggleSlow`, `ProcessTimeSlow()`의 `DrainFocus`/`RecoverFocus`). 이번 작업은 이 파일들을 확장하되 기존 완전 정지 동작에 회귀가 없어야 한다.
- `Assets/02.System/09.EventSequencerSystem/01.Logic/TutorialSequencerLogicSystem.cs` — 06번 시스템(이미 구현·QA 완료). `event Action OnBoss50Percent/OnCoreHitSuccess/OnCoreHitFail`을 갖고 있지만 현재 **구체 클래스에만** 있고 인터페이스가 없다. `PureDataTutorialSequence`(SO, `CoreHitTimeoutSeconds` 필드 보유)도 같은 폴더 `00.Data/`에 존재.
- **8번 작업에서 이미 겪은 함정과 동일한 함정을 여기서도 미리 피할 것**: "오버라이드가 켜지는 시점에 게이지가 항상 가득 차 있다"고 가정하지 말 것. 실제로는 2단계 전투 중 게이지를 이미 소모했을 수 있으므로, HUD는 실제 값과 무관하게 게이지를 강제로 100%로 표시하는 코드가 반드시 필요하다(8번의 `CharacterHUDUIView` 수정과 동일한 패턴).
- **감속 램프 지속시간은 06의 `CoreHitTimeoutSeconds`와 반드시 일치해야 한다** — 별도로 하드코딩하거나 09 자체 값을 새로 정의하지 말 것(시간이 완전히 정상 속도로 돌아오는 시각적 순간이 06의 타임아웃 실패 판정 시점과 어긋나면 안 됨).

## 범위

### 포함

**A. 06번 시스템에 소규모 인터페이스 추가** (기존 로직 변경 없음, 최소 침습)
1. `Assets/02.System/09.EventSequencerSystem/01.Logic/IEventSequencer.cs`(신규) — `event Action OnBoss50Percent; event Action OnCoreHitSuccess; event Action OnCoreHitFail;` 세 개만 선언.
2. `TutorialSequencerLogicSystem`이 `IEventSequencer`를 구현하도록 클래스 선언에 인터페이스 추가(이벤트는 이미 이 시그니처로 존재하므로 별도 구현 코드 불필요).
3. `EventSequencerSystemLifetimeScope.cs`의 등록 코드에 `.As<IEventSequencer>()` 한 줄 추가(기존 `.As<ITickable>().As<System.IDisposable>()` 체이닝에 이어붙임).

**B. 02.CharacterSystem 확장**
4. `PureDataTimeSlow.cs`(기존 파일) — `[SerializeField] private float eventSlowTimeScale = 0.25f;` + `public float EventSlowTimeScale => eventSlowTimeScale;` 추가.
5. `RuntimeDataTimeSlow.cs`(기존 파일) — 신규 필드: `isGaugeOverride`(bool, private set), `isEventTriggered`(bool, private set), `eventRampElapsedSeconds`/`eventRampDurationSeconds`(float, private set). 신규 메서드: `SetGaugeOverride(bool value)`(변경 시에만 `OnGaugeOverrideChanged` 발행, 기존 `SetSlowActive` 패턴 재사용), `BeginEventRamp(float durationSeconds)`(`isEventTriggered=true`, `eventRampElapsedSeconds=0`, `eventRampDurationSeconds=durationSeconds`), `EndEventRamp()`(`isEventTriggered=false`), `TickEventRamp(float deltaTime)`(`eventRampElapsedSeconds += deltaTime`, 반환값 또는 프로퍼티로 진행률 노출). 신규 이벤트: `OnGaugeOverrideChanged(bool)`.
6. `TimeSlowLogicSystem.cs`(기존 파일) — 생성자에 `PureDataTutorialSequence pureDataTutorialSequence`(06의 SO, `CoreHitTimeoutSeconds` 읽기용), `IEventSequencer eventSequencer`(06 구독용) 인자 추가. 신규 메서드: `ActivateEventSlow(float rampDurationSeconds)`(`runtimeData.SetGaugeOverride(true)` + `runtimeData.BeginEventRamp(rampDurationSeconds)` + `isSlowActive`를 게이지 체크 없이 강제 true 전환 — 기존 `ActivateSlow()`의 `CanActivateSlow()` 게이트를 우회하는 별도 경로로 구현), `DeactivateEventSlow()`(`SetGaugeOverride(false)` + `EndEventRamp()` + `DeactivateSlow()`). 생성자에서 `eventSequencer.OnBoss50Percent += () => ActivateEventSlow(pureDataTutorialSequence.CoreHitTimeoutSeconds);`, `eventSequencer.OnCoreHitSuccess += DeactivateEventSlow`, `eventSequencer.OnCoreHitFail += DeactivateEventSlow` 구독(및 `Dispose()`에서 해제). `Tick()`/`ProcessTimeSlow()` 확장: `runtimeData.IsGaugeOverride`면 `DrainFocus` 스킵(기존 게이지 로직), `runtimeData.IsEventTriggered`면 매 프레임 `TickEventRamp(unscaledDelta)` 호출 후 진행률로 `Mathf.Lerp(pureData.EventSlowTimeScale, 1.0f, t)`를 계산해 `visualizer.SetTimeSlowEffect(true, currentTimeScale)`로 전달, `t>=1`이면 `DeactivateEventSlow()` 자동 호출.
7. `CharacterHUDUIView.cs`(기존 파일) — `OnGaugeOverrideChanged` 구독 추가. `true` 수신 시 `focusBar.style.width = Length.Percent(100f)` 강제 표시(실값 미변경), `false` 수신 시 즉시 `UpdateFocusUI(timeSlowData.FocusGauge.CurrentValue, timeSlowData.FocusGauge.MaxValue)` 호출해 실값 기준 복귀.

### 제외 (이번 작업 범위 아님)
- 시간 정지 시스템을 플레이어 종속 구조에서 독립 시스템으로 분리하는 리팩토링(9.9절 기존 미해결 항목) — 이번 작업 범위 아님, 현재 구조 그대로 확장.
- 3단계 자동 발동 구간에서 유저의 수동 시간정지 입력을 정확히 차단하는 로직(9.5절 "확인 필요" 항목) — 이번 작업 범위 아님. 단, `ActivateEventSlow`가 이미 `isSlowActive`를 강제 전환하므로, 유저가 그 상태에서 `ToggleSlow()`를 눌러 `DeactivateSlow()`를 직접 호출해버리는 회귀는 없는지 검증 절차에서 확인은 하되, 입력 차단 자체를 설계/구현하지는 않는다(발견되면 보고만 하고 별도 Goal로 분리).
- 감속 중 필터 강도를 시간 배율에 비례해 변화시키는 세부 연출(9.4절 "세부 연출은 미정") — 이번 작업 범위 아님, `timeScale` 값 전달까지만.

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` 폴링 + `Assembly.GetAssembly(type).Location` mtime과 소스 mtime 교차 확인(스테일 함정 주의). 개발 도중 직접 파일 쓰기로 AssetDatabase가 갱신을 못 잡는 문제가 06번 작업 때 있었으니, 필요하면 `unity command write_text_file`로 다시 쓰는 것을 고려할 것.
2. **콘솔 에러 확인**: `unity command clear_console` 후 `unity command console --level error`로 에러 0건.
3. **기능 검증 (`unity eval`/Play Mode)** — 씬의 `EventSequencerScope`(06번 작업 때 이미 배선됨, `EnemyTest`가 보스 대체 참조)를 그대로 활용:
   - 시나리오 A(완전 정지 회귀 없음): 기존처럼 `ActivateSlow()` → `IsSlowActive=true`, 게이지가 정상 소모됨(오버라이드 미적용 상태) → `DeactivateSlow()` → 정상 해제. 기존 동작과 동일한지 확인.
   - 시나리오 B(감속 시작): 06의 `OnBoss50Percent`를 직접 invoke(또는 `EventSequencerScope`를 통해 실제로 HP를 50% 이하로 낮춰서 트리거) → `TimeSlowLogicSystem`이 `ActivateEventSlow`를 호출했는지, `IsEventTriggered=true`, 초기 `currentTimeScale ≈ EventSlowTimeScale`인지 확인.
   - 시나리오 C(자동 램프 복귀): 테스트 편의상 `CoreHitTimeoutSeconds`를 짧은 값(예: 2초)으로 임시 조정 → 시간 경과에 따라 `currentTimeScale`이 점점 1.0에 가까워지다가, duration 도달 시 `IsEventTriggered=false`로 자동 전환되고 게이지 오버라이드도 꺼지는지 확인.
   - 시나리오 D(조기 종료): 감속 진행 중(램프 완료 전) 06의 `OnCoreHitSuccess`를 invoke → 즉시 `IsEventTriggered=false`, `currentTimeScale=1.0f`로 복귀하는지 확인. `OnCoreHitFail`에 대해서도 동일하게 확인.
   - 시나리오 E(게이지 부분값 HUD 강제): `FocusGauge`를 부분값(예: 40%)으로 소모시킨 뒤 `ActivateEventSlow` 호출 → `CharacterHUDUIView`의 `focusBar.style.width`가 즉시 100%로 강제 표시되는지 확인 → `DeactivateEventSlow` 호출 → 실제 부분값 기준으로 즉시 복귀하는지 확인.
   - 시나리오 F(재도전 재트리거, 9.3절 4번): `OnCoreHitFail` 이후 06이 재도전을 위해 `OnBoss50Percent`를 다시 방송한다고 가정하고(또는 06 자체 로직상 실제로 그런지 함께 확인), 다시 `ActivateEventSlow`가 호출되어 감속이 재시작되는지 확인.

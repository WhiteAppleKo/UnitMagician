## Goal

1단계의 "돌문"처럼 HP를 가진 캐릭터가 아니라 **비-캐릭터 오브젝트**가 투사체 충돌로 파괴되는 판정/연출을 구현한다. `IDamageable` + `AttackStepFlags`/`HitStepFlags` + `CombatPipelineManager`는 이미 존재하므로(리팩토링 완료), 이번 작업은 그 위에 **① 속성(온도) 게이트를 파이프라인 스텝으로 추가**하고 **② 돌문 전용 DLV 구조 컴포넌트**를 만드는 것이다.

## 배경 (조사로 확인된 현재 상태)

이미 완료된 두 작업(공격/피격 파이프라인 분리, 온도 단위 확장) 덕분에 아래는 **이미 존재하며 재사용만 하면 된다**:
- `Assets/PipeLine/Combat/IDamageable.cs` — `void ApplyDamage(int amount)` 하나뿐인 얇은 인터페이스
- `Assets/PipeLine/Contexts/DamageContext.cs` — `HitRegistered`(피격판정), `Aborted`(범용 중단 신호, 주석에 "향후 다른 게이트 스텝(예: 속성 게이트)도 재사용 가능"이라고 이미 명시돼 있음)
- `Assets/PipeLine/Combat/HitStepFlags.cs` — 이미 `// StatusResist = 1 << 2, // SizeGate = 1 << 3` 확장 예약 주석이 있음(이번에 실제로 채울 자리)
- `Assets/PipeLine/Combat/CombatPipelineManager.cs`의 `HitStepOrder` 정준 순서 테이블 — 새 스텝은 여기 등록해야 실제로 반영됨
- `Assets/02.System/01.UnitSystem/00.Data/UnitType.cs`의 `Temperature` 단위, `Assets/02.System/01.UnitSystem/02.Visualizer/MassUnitApplicatorSO.CalculateMassRatio(RuntimeDataUnit)` 공개 정적 헬퍼(질량 비율 재사용용)

**중요 — 반드시 고쳐야 할 기존 코드(빠뜨리면 조용히 무동작함)**:
- `Assets/PipeLine/CharacterDamage/Steps/ApplyDamageStep.cs`의 `Execute`는 지금 `context.IsEvaded`만 확인하고 `context.Aborted`는 확인하지 않는다. 즉 새 게이트 스텝이 `Aborted = true`를 설정해도 `ApplyDamageStep`은 그걸 무시하고 그대로 `IDamageable.ApplyDamage(...)`를 호출해버린다 — **`Aborted`도 함께 체크하도록 이 스텝을 반드시 수정해야** 게이트가 실제로 의미가 있다.
- `Assets/02.System/03.InteractionSystem/01.Logic/InteractionSystem.cs`의 `ProcessDamageAsync`는 현재 `HitStepFlags.Evasion | HitStepFlags.Defense`를 **모든 대상에게 하드코딩**해서 넘긴다. 돌문은 회피/방어 판정이 필요 없고 속성 게이트만 필요하므로, **피격 대상(victim)이 자신에게 맞는 `HitStepFlags`를 알려줄 수 있는 경로**가 있어야 한다(아래 설계 스펙 참고). 이게 없으면 돌문도 캐릭터와 똑같은 플래그로 처리돼서 이번 작업이 무의미해진다.

## 범위

### 포함
1. **`HitStepFlags.AttributeGate = 1 << 2`** 추가(주석의 예약 자리 실제로 채움)
2. **`AttributeGateStep`**(신규, `Assets/PipeLine/CharacterDamage/Steps/` 또는 새 폴더) — `context.Attacker`에서 `UnitSystem.RuntimeDataUnitGroup`을 가져와 `Temperature` 단위의 `RuntimeDataUnit.CurrentValue`를 확인, 음수(얼음)가 아니면 `context.Aborted = true`로 설정. `CombatPipelineManager.HitStepOrder`에 등록.
3. **`ApplyDamageStep` 수정** — `if (context.IsEvaded || context.Aborted)`처럼 `Aborted`도 함께 체크하도록 변경(회피와는 다른 무반응 처리 분기로 만들어도 됨 — 회피는 "회피 텍스트" 연출이 있지만, 속성 게이트 실패는 그냥 아무 연출 없이 조용히 끝나야 함, 투사체 자체의 물리 튕김은 파이프라인과 무관하게 이미 일어남).
4. **`IDamageable` 확장 또는 보조 인터페이스** — 피격 대상이 자신에게 필요한 `HitStepFlags`를 노출하도록(예: `HitStepFlags CurrentHitFlags { get; }`). `InteractionSystem.ProcessDamageAsync`가 하드코딩된 `Evasion|Defense` 대신, victim이 이 인터페이스를 구현하면 그 값을 쓰고, 안 하면 기존처럼 캐릭터 기본값(`Evasion|Defense`)을 쓰도록 수정.
5. **`PureDataDestructibleDoor`**(SO, [D]) — `int hp`(기본 100), `int baseDamage` 관련 값은 공격자 쪽에 있으므로 여기는 파괴 임계값만.
6. **돌문 컴포넌트 — DLV 3계층으로 분리** (직전 NPC 프레임워크 재작업에서 확립한 패턴, `Assets/02.System/07.NpcSystem/`의 `RuntimeDataNpcActor`/`NpcCombatActorLogicSystem`/`INpcCombatActorVisualizer`+`NpcCombatActorVisualizer` 구조를 그대로 참고할 것):
   - **[L] `DestructibleDoorLogicSystem`**(순수 C#, `IDamageable` 구현체 또는 `IDamageable`을 구현하는 얇은 wrapper가 이걸 들고 있는 형태) — `ApplyDamage(int amount)`를 받아서 `amount >= pureData.Hp`인지 판단(2차 게이트, 매 호출 독립 판정 — 절대 누적하지 않음). 판단 결과에 따라 `IDestructibleDoorVisualizer.PlayDestroy()` 또는 `.PlayCrackAndRepair()` 호출.
   - **[V] `IDestructibleDoorVisualizer`** — `PlayDestroy()`(분열 애니메이션+파편 파티클+파괴음+콜라이더 비활성화/통로 개방), `PlayCrackAndRepair()`(금 가는 이펙트+복구 파티클/사운드).
   - **[V] `DestructibleDoorComponent`**(MonoBehaviour) — `IDamageable`(및 위 4번의 `CurrentHitFlags => HitStepFlags.AttributeGate`) 구현, `Awake()`에서 자기 `DestructibleDoorLogicSystem`을 직접 `new`로 생성(NPC 프레임워크의 `Awake()` 패턴과 동일), `IDestructibleDoorVisualizer`도 구현해서 실제 콜라이더 비활성화/파티클 스폰을 수행.
7. 테스트: `00.TestScene`에 돌문 더미 오브젝트(HP=100) 배치, 투사체(Mass+Temperature 지원)로 충돌 테스트

### 제외 (이번 작업 범위 아님)
- 실제 아트 리소스(진짜 돌문 분열 애니메이션, 파편 메시) — 플레이스홀더로 충분
- 06번(이벤트 시퀀서), 08번(무적 플래그), 05번(광역 상태이상) — 이번 작업은 단일 타겟 파괴 판정까지만
- `FlagRefCounter`/`CombatFlagState`(참조 카운트 버프 시스템) 실제 배선 — `CurrentHitFlags`는 지금은 고정값 반환으로 충분(버프에 따라 동적으로 바뀔 필요 없음, 돌문은 항상 같은 게이트만 씀)

## 완료 기준 (Definition of Done)

- [ ] `HitStepFlags.AttributeGate` 추가 + `AttributeGateStep` 구현 + `CombatPipelineManager` 등록 + 컴파일 에러 없음
- [ ] `ApplyDamageStep`이 `Aborted`도 체크하도록 수정되어, 속성 게이트 실패 시 `IDamageable.ApplyDamage`가 호출되지 않음
- [ ] `InteractionSystem`이 victim별 `CurrentHitFlags`를 반영해서, 돌문에는 `AttributeGate`만, 캐릭터에는 기존처럼 `Evasion|Defense`가 적용됨(회귀 없음)
- [ ] 무속성 투사체 충돌 시 돌문에 완전히 무반응(데미지 0, 파괴 안 됨)
- [ ] 얼음 속성 + 데미지 부족 시 파손→복구 연출만 재생되고 파괴 안 됨, 그리고 **다음 시도 때 이전 실패가 누적되지 않고 항상 HP 100 기준으로 재판정**됨
- [ ] 얼음 속성 + 데미지 충분 시 파괴되고 콜라이더 비활성화(통로 개방)
- [ ] `DestructibleDoorLogicSystem`이 `MonoBehaviour`를 상속하지 않고, `Transform`/콜라이더/파티클을 직접 만지지 않음(전부 `IDestructibleDoorVisualizer` 경유) — DLV 준수
- [ ] 기존 캐릭터 대상 데미지 흐름(회피/방어/치명타)에 회귀 없음

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `recompile_status` "completed, no errors"까지 폴링, `Assembly.GetAssembly(type).Location` mtime과 소스 mtime 비교로 재확인(단정 금지 — 기록된 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `unity command console --level error`로 에러 0건.
3. **기능 검증 (`unity eval`/Play Mode)**:
   - 시나리오 A(무속성 → 무반응): 온도 단위가 중립(0)인 투사체로 돌문에 데미지 파이프라인 실행 → `ApplyDamage` 호출 안 됨(호출 카운트로 확인), HP/파괴 상태 불변.
   - 시나리오 B(얼음 + 데미지 부족 → 파손·복구): 온도 음수, `RawDamage × 질량비율 < 100`이 되도록 설정 → `PlayCrackAndRepair()` 호출 확인, 파괴 안 됨.
   - 시나리오 C(얼음 + 데미지 충분 → 파괴): `RawDamage × 질량비율 >= 100` → `PlayDestroy()` 호출 확인, 콜라이더 비활성화 확인.
   - 시나리오 D(누적 없음): B 실패 이후 같은 돌문에 다시 무속성 공격 → 여전히 무반응(이전 실패 데미지가 하나도 안 남아있음을 확인 — 예를 들어 B에서 90데미지를 맞았어도 다음 판정은 90에서 이어지는 게 아니라 매번 0부터 재계산).
   - 시나리오 E(캐릭터 회귀): 기존 캐릭터 타겟(`EnemyTest` 등)에 대한 회피/방어/치명타 파이프라인이 여전히 정상 동작(HP 정상 감소, `CurrentHitFlags`가 없는 대상은 기본값 `Evasion|Defense` 적용).
4. **DLV 준수 자체 점검**: `DestructibleDoorLogicSystem` 소스에 `UnityEngine.Transform`/`Collider`/`ParticleSystem` 등 구체 타입 참조가 없는지 직접 확인.
5. **범위 확인**: `git status`/`git diff --stat`로 이번 작업이 `07.NpcSystem`, `01.UnitSystem`(07번 작업분) 등 범위 밖 파일을 추가로 건드리지 않았는지 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

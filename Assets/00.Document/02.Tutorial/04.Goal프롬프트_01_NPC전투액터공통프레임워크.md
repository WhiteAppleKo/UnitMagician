## Goal

아군 NPC([02.아군NPC전투지원행동시스템.md])와 보스([03.보스AI페이즈시퀀스시스템.md])가 공유할 **범용 NPC 전투 액터(몸통/액추에이터)** 프레임워크를 구현한다. "이동하고 공격을 실행하는" 실행 규약(`INpcCombatActor`)과 그 기본 구현체(`NpcCombatActorComponent`)를 만들어, 이후 아군/보스 전용 "두뇌"(FSM, 이벤트 시퀀서)가 이 프레임워크를 참조·호출만 하면 되도록 한다. 실제 게임플레이 로직(언제 누구를 공격할지)은 이번 작업 범위가 아니다 — 순수하게 "명령을 받으면 실행하는 실행 계층"만 만든다.

## 배경

- 현재 프로젝트에는 AI/이벤트가 구동하는 NPC 이동·공격 실행 로직이 전혀 없다. 이동/전투 로직(`LocomotionLogicSystem`, `UnitCasterSystem`)은 전부 플레이어 입력(`InputReader`)에 묶여 있다.
- 최근(`18.공격피격파이프라인_분리_리팩토링_Goal프롬프트.md`) 작업으로 `Assets/PipeLine/`에 `IDamageable`, `CombatPipelineManager`, 재작성된 `CollisionDamageTrigger`가 이미 존재한다 — NPC의 공격은 **이 기존 데미지 처리 경로를 재사용**해야 하며 새로 만들지 않는다.
- 같은 작업에서 실제로 확인된 함정: `InteractionSystemLifetimeScope.autoInjectGameObjects`는 **씬에 미리 배치된 오브젝트에만** 적용되고, **런타임에 `Instantiate`한 오브젝트는 자동 주입되지 않는다.** NPC가 스폰하는 투사체가 `CollisionDamageTrigger`를 갖고 있다면, 스폰 직후 `IObjectResolver.InjectGameObject(instance)`를 명시적으로 호출해야 `interactionService`가 주입된다. 이걸 빠뜨리면 투사체가 조용히 아무 데미지도 못 입히는(에러 없이 무동작하는) 버그가 난다 — 이번 작업에서 반드시 처리할 것.
- 상속이 아니라 컴포지션 원칙을 지킬 것 — 이 프로젝트는 `OptionUIComponent`/`CameraOptionUIController` 상속 구조에서 중복 인스턴스 등록 버그를 겪은 이력이 있다. 보스/아군 전용 "두뇌"는 이 액터를 **참조(주입)해서 지시**할 뿐, 액터 클래스를 상속하지 않는다(이 원칙은 이번 작업이 아니라 02/03번 작업에서 지켜야 할 것이지만, 그러려면 이번 작업에서 `INpcCombatActor`를 인터페이스로 명확히 분리해둬야 한다).

## 범위

### 포함
- `INpcCombatActor` 인터페이스: `MoveTo(Vector3 destination)`, `Attack(GameObject target, PureDataUnit magic = null)`, `PlayMotion(string motionKey)`, `event Action OnAttackExecuted`, `event Action OnMoveCompleted`
- `PureDataNpcActor` ScriptableObject: 투사체 프리팹 참조, 발사 속도, 공격 쿨타임 필드 (기존 `PureDataUnit` 등과 동일한 컨벤션으로 인스펙터에서 설정 가능하게)
- `NpcCombatActorComponent` MonoBehaviour: `INpcCombatActor` 구현체
  - `MoveTo`: 간단한 Transform 기반 이동(속도값 사용, 도착 판정 포함) — NavMesh/NavMeshAgent 같은 고급 내비게이션 도입 금지(이번 튜토리얼 스테이지엔 불필요, 과설계)
  - `Attack`: 투사체 프리팹을 `Instantiate` → 스폰된 투사체의 `CollisionDamageTrigger`(기존 컴포넌트, 새로 만들지 않음)에 `SetOwner`/`SetBaseDamage` 호출 → **`IObjectResolver.InjectGameObject`로 명시적 DI 주입** → 목표 방향으로 발사(물리 힘 또는 속도 부여)
  - `PlayMotion`: `Animator` 컴포넌트가 있으면 `SetTrigger(motionKey)`, 없으면 조용히 무시(방어적 — 아직 실제 애니메이션 리소스가 없을 수 있음)
  - 타겟이 `null`이거나 이미 파괴된 상태에서 `Attack` 호출 시 아무 것도 안 하고 무시
  - 이동 중 새 `Attack` 명령이 들어오면 **공격이 이동을 즉시 중단시키고 우선 실행**하는 정책 채택(공격은 시간에 민감한 이벤트, 이동은 배경 행동이라는 근거) — 이 정책을 별도 private 메서드/필드로 분리해서 나중에 정책을 바꾸기 쉽게 할 것
  - `OnAttackExecuted`/`OnMoveCompleted`를 실제 실행 완료 시점에 정확히 발행
- 테스트 확인용: 씬에 더미 NPC(플레이스홀더 큐브/캡슐 + `NpcCombatActorComponent`)와 플레이스홀더 투사체 프리팹(구체 + 기존 `CollisionDamageTrigger`)을 배치/생성해서 검증에 사용

### 제외 (이번 작업 범위 아님)
- 아군 NPC 전투 지원 행동 시스템(02번), 보스 AI 페이즈 시퀀스 시스템(03번)의 실제 게임플레이 로직 — "언제 누구를 공격할지"는 이 작업이 관여하지 않는다
- 이벤트 시퀀서(06번)와의 실제 신호 연동
- NavMesh/네비게이션 시스템 도입
- 실제 아트 애니메이션 클립/이펙트/사운드 리소스 제작 — 전부 플레이스홀더로 충분
- 온도 단위(07번), 무적 플래그(08번) 등 다른 확장 시스템

## 완료 기준 (Definition of Done)

- [ ] 위 산출물이 모두 작성되고 컴파일 에러가 없다
- [ ] `MoveTo(destination)` 호출 시 NPC가 목적지까지 실제로 이동하고, 도착 시 `OnMoveCompleted`가 발행된다
- [ ] `Attack(target)` 호출 시 투사체가 스폰되어 목표 방향으로 날아가고, 목표와 충돌 시 기존 `CombatPipelineManager` 경로를 통해 실제로 데미지가 적용된다(런타임 스폰 오브젝트의 DI 누락 없음)
- [ ] 타겟이 없거나 파괴된 상태에서 `Attack` 호출 시 아무 예외 없이 조용히 무시된다
- [ ] 이동 중 `Attack`이 들어오면 이동이 중단되고 공격이 실행된다
- [ ] `PlayMotion`은 Animator가 없는 더미 오브젝트에서도 예외 없이 동작한다

## 검증 절차 (반드시 수행)

1. **컴파일 검증**: `unity command recompile` → `unity command recompile_status`가 "completed, no errors"일 때까지 폴링. 에러 없다고 성급히 단정하지 말고, `Assembly.GetAssembly(type).Location`의 mtime이 최신 소스 파일보다 새로운지 반드시 재확인(스테일 상태 재탕 방지 — 이 프로젝트에서 실제로 겪은 함정).
2. **콘솔 에러 확인**: `unity command clear_console` 후 `unity command console --level error`로 에러 0건 확인(과거 컴파일 실패 로그 잔재와 헷갈리지 않도록 먼저 clear).
3. **기능 검증 (`unity eval` 위주, 필요시 Play Mode)**:
   - 시나리오 A(이동): 더미 NPC에 `MoveTo(임의 좌표)` 호출 → 몇 프레임/몇 초 후 실제 `transform.position`이 목적지에 근접했는지, `OnMoveCompleted` 이벤트가 발행됐는지 확인.
   - 시나리오 B(공격→실제 데미지): 더미 NPC와 `IDamageable`을 가진 더미 타겟(예: `CharacterStatComponent` 부착 오브젝트)을 배치, `Attack(target)` 호출 → 투사체가 스폰되고, 충돌 후 타겟의 HP가 실제로 감소하는지 확인(런타임 스폰 오브젝트에 DI가 제대로 됐는지의 핵심 검증 — `interactionService`가 null이면 이 시나리오가 조용히 실패하니 반드시 HP 변화까지 확인할 것).
   - 시나리오 C(타겟 무효): `target = null` 또는 이미 파괴된 오브젝트로 `Attack` 호출 → 예외 없이 무시되는지 확인.
   - 시나리오 D(이동 중 공격 우선): `MoveTo`로 이동을 시작시킨 직후 `Attack`을 호출 → 이동이 중단되고 공격이 실행되는지(이동이 끝난 뒤에 공격이 실행되는 게 아니라 즉시 실행되는지) 확인.
   - 시나리오 E(PlayMotion 방어): Animator 컴포넌트가 없는 더미 오브젝트에서 `PlayMotion("Fire")` 호출 → 예외 없이 정상 반환되는지 확인.
4. **범위 확인**: 이번 작업이 `Assets/PipeLine/`(공격/피격 파이프라인), 02/03/06~10번 튜토리얼 시스템 관련 파일을 건드리지 않았는지 `git status`/`git diff --stat`로 확인.

모든 항목이 통과하면 이 작업은 완료된 것으로 간주한다.

# Shader Graph 물 효과(Water Shader) 제작 및 트러블슈팅 종합 가이드

## 개요
본 문서는 유니티 Universal Render Pipeline(URP) Shader Graph를 활용하여 물 구체(Water Sphere) 및 물 큐브/오브젝트 효과를 구현하는 과정에서 논의된 핵심 기술 연산 구조와 발생했던 8가지 주요 문제 상황(Troubleshooting)의 원인 및 해결책을 정리한 개발 가이드 문서입니다.

---

## 1. 큐브(Cube) 적용 관련 전용 트러블슈팅 (Cube Adaptation Issues)

### [문제 1] 큐브 메쉬에 셰이더 적용 시 표면 파도 출렁임 반응이 전혀 없음
- **원인**: 유니티 기본 Primitive Cube 메쉬는 전체 정점 수 24개(면 내부 분할 정점 0개)로 구부러질 내분 정점이 없어 파도 출렁임 연산이 불가능함.
- **해결책**: 면당 10x10 이상 내분 정점이 분할된 **Subdivided Cube** 메쉬(Blender Subdivide 또는 ProBuilder 생성)로 교체.

### [문제 2] 큐브 정점 변형 시 6개 면 모서리 경계선이 찢어지고 구멍이 뚫림
- **원인**: `Normal Vector` 노드 사용 시 상단면 노멀 `(0, 1, 0)`과 측면 노멀 `(1, 0, 0)`이 90도 직각 반대 방향으로 연산되어 모서리 정점들이 서로 찢어짐.
- **해결책**: 정점 이동 방향 연산을 `Normal Vector` 대신 **`Normalize(Position)`** 연산으로 교체. 구체 중심 `(0,0,0)` 기준 대각선 공통 방향 `(0.577, 0.577, 0.577)`으로 동시 팽창시켜 모서리 밀착 유지.

### [문제 3] 큐브 6개 면의 물 흐름 방향이 서로 다르게 꺾이고 다르게 보임
- **원인**: `Triplanar` 연산 특성상 3개 투영 축(XY, XZ, YZ) 매핑 시 상단/하단면과 측면 4개 면 간에 90도 회전 차이 발생.
- **해결책**: Position 3D 좌표 합산 시 시간 오프셋 수치를 Y축(세로) 전용 `Vector3(0, -Time, 0)`으로 지정하여 측면 4개 면의 수직 직하강 흐름 통일.

## 2. 구체(Sphere) 및 공통 구현 트러블슈팅 (Sphere & General Issues)

### [문제 4] 정점 변형 적용 시 구형 형태가 깨지고 결정체 모양으로 찌그러짐
- **원인**: `Position` 노드 데이터에 노이즈 연산 결과값을 `Multiply(곱셈)` 노드로 직접 곱함 -> 좌표축 비율이 왜곡됨.
- **해결책**: `Position` 대상 곱셈 연산을 금지하고, `Position + (Normal * Noise * Displacement)` 형태의 **`Add(덧셈)`** 연산으로 수정. `Displacement` 강도 수치를 `0.02` 이하로 축소.

### [문제 5] 구체 상단 정수리가 뾰족한 뿔 모양으로 솟아오르고 찢어짐
- **원인**: 유니티 기본 Primitive Sphere 메쉬 특성상, 정수리 상단 극점에 24개 삼각형이 1개 정점으로 모이는 구조적 결함(Polar Singularity) 존재.
- **해결책**: 정수리 쏠림 정점이 없는 **Icosphere** 메쉬로 교체하여 해결.

### [문제 6] 구체 표면에 수직 경계선/이음새(Seam Line)가 눈에 보임
- **원인**: 2D UV 좌표 맵의 `0 -> 1` 경계선 특성 및 `Polar Coordinates` 노드의 360도 각도 점프(`0 -> 1`) 발생.
- **해결책**: `Polar Coordinates` 노드를 제거하고, 2D `Sample Texture 2D` 대신 3D 공간 투영인 **`Triplanar`** 노드로 교체 적용. `Blend` 수치를 `4.0 ~ 8.0`으로 설정.

### [문제 7] Scene Color 배경 굴절 연출 시 배경이 왜곡되지 않고 평평하게 비침
- **원인**: `Screen Position` 노드가 `Scene Color` 노드의 UV 슬롯으로 오프셋(왜곡) 노이즈 연산 없이 직접 직결되어 굴절 변형 수치가 0으로 연산됨.
- **해결책**: `Screen Position + (Normal/Noise * 0.03)` -> **`Add`** -> `Scene Color (UV)` 구조로 굴절 오프셋 연산 추가.

### [문제 8] Add 노드로 텍스처/굴절 합성 시 수직 이음새 꺾임 선 재발생
- **원인**: `Add` 노드 합산 연산 시 UV 좌표 또는 색상 수치가 1.0을 초과(오버플로우)하여 좌표가 0.0으로 래핑(Wrap)되거나 하얗게 잘림(Clipping) 발생.
- **해결책**: `Add` 노드 대신 **`Lerp`** 노드를 사용하여 0~1 범위 내에서 부드러운 비율 혼합 처리.

## 3. 핵심 노드 연산 매커니즘

### 변형 방향 벡터 선택 기준
- **Normal Vector**: 각 면의 직각 수직 방향. 구체(Sphere) 변형에 적합하나 큐브 모서리에서는 면 찢어짐 유발.
- **Normalize(Position)**: 물체 중심 `(0, 0, 0)` 기준 방사형 대각선 방향. 큐브 모서리 찢어짐을 100% 방지함.

### Triplanar Mapping 표준 노드 연산
2D UV 좌표를 사용하지 않고 3D 공간 좌표(X, Y, Z)를 기준으로 텍스처를 3방향에서 자동 투영.
- **Position 슬롯**: `Position (Object Space)` + `(Time * Speed Vector3)` -> `Add` 노드 연결.
- **Normal 슬롯**: `Normal Vector (Object Space)` 연결.
- **Tile 슬롯**: 타일링 수치 (Float).
- **Blend 슬롯**: `4.0 ~ 8.0` (경계선 부드럽게 뭉개짐).

### 유틸리티 노드 활용
- **One Minus**: `1 - Input` 값 반전.
- **Combine**: R, G, B, A 단일 채널을 Vector2/3/4 합성.
- **Normal Strength**: Normal Map 굴곡 강도 조절.
- **Saturation**: 채도 조절 (0 설정 시 완전 무채색 흑백 변환).
- **Lerp**: 가중치 T(0~1) 기준 두 입력값 부드러운 비율 혼합.

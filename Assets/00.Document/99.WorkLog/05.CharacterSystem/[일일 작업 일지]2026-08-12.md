## 2. 문제 · 변경 · 성과 (Before-After + Why)

### 2-1. 기획서 컨벤션 표준화 및 용어 통일
* **Before**: `PureStatDataSO`, `CharacterStatController`, `WeaponSlotController` 등 DLV 아키텍처 규칙 미준수 클래스명 명시 및 `Weapon` 용어 잔재
* **After**: DLV 표 준수 (`PureStatData`, `CharacterStatSystem`, `UnitMagicSlotSystem`) 및 프로젝트 컨셉에 맞춘 `UnitMagic` 명칭 전면 통일
* **Why**: `코드_가이드라인.md` 규칙 및 프로젝트 환경 표준에 맞춰 코드 유지보수성 및 직관성 향상

### 2-2. 중복 데이터 구조 삭제 및 기존 시스템 통합
* **Before**: 캐릭터 시스템 전용 `PureUnitMagicData.cs` 중복 생성
* **After**: `PureUnitMagicData.cs` 및 `.meta` 파일 전면 삭제 후 기존 `UnitSystem.PureDataUnit` 직접 참조 연동
* **Why**: 불필요한 데이터 클래스 파편화를 방지하고 기존 유닛 시스템과의 일관성 보장

### 2-3. UI Toolkit 생명주기 타이밍 미연동 예외 해결
* **Before**: VContainer `[Inject] Construct` (Awake 시점) 호출 시 Unity `UIDocument.rootVisualElement`가 `null` 상태여서 `BindElements()` 조기 종료(`return`), UI 참조 변수 `null` 영구 유지 (UI 깡통 현상 발생)
* **After**: `CharacterHUDUIView.cs` 내 `OnEnable()` 및 `Start()` 생명주기 재바인딩 로직 추가
* **Why**: Unity UI Toolkit UXML 로딩 시점과 VContainer 주입 타이밍 간 불일치 예외를 방지하여 실시간 수치 및 게이지 갱신 보장

## 4. 문제 재현 방법

1. `CharacterHUDUIView.cs`에서 `OnEnable()` 및 `Start()` 재바인딩 코드를 제거한다.
2. VContainer `Construct()` (Awake 시점)만 유지한 채 플레이(Play) 모드에 진입한다.
3. `Awake` 시점 `uiDocument.rootVisualElement`가 `null`로 평가되어 `BindElements()`가 조기 종료(`return`)된다.
4. UXML 렌더링이 완료된 후에도 `hpBar`, `hpLabel` 참조가 `null` 상태를 유지하여 UI 수치가 업데이트되지 않는 깡통 UI 현상을 재현할 수 있다.

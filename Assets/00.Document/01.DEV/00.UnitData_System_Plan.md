## 2. 유형별 맞춤 핵심 요구사항

### 2-1. 비시청각 영역 요구사항 (공식: [구현 수단 / 방법] + [최적화 / 기대 효과])

* **데이터 안정성 확보**: 읽기 전용 카탈로그 SO(`UnitDataSO`)와 런타임 수치 데이터 구조체(`UnitRuntimeData`)를 분리 구조로 구현하여 인게임 수치 변형에 의한 에디터 원본 파일 오염 방지 및 메모리 안정성 확보
* **검색 성능 최적화**: `Dictionary<UnitType, UnitDataSO>` 메모리 캐싱 구조로 구현하여 단위 데이터 반복 조회 시 GC 할당 최소화 및 검색 성능 최적화
* **결합도 최소화**: VContainer `IUnitCatalogService` 인터페이스 주입 아키텍처로 구현하여 단위 시스템과 UI 간 직접 참조를 배제하고 결합도 최소화 및 모듈성 향상
* **마나 소모 검증 연산**: $Cost = BaseCost \times |TargetValue - NewValue|$ 공식 수식 연산 구조로 구현하여 마나 잔여량 부족 시 단위 변환 차단 및 자원 연산 정확성 확보

### 2-2. 시청각 영역 요구사항 (사용자 행동 입력에 따른 실질적 동작 및 결과)

* **퀵슬롯 단축키 반응**: 사용자가 퀵슬롯 단축키(1, 2, 3, 4) 입력 조작 시 화면 하단 퀵슬롯 UI 슬롯에 현재 선택 단위 아이콘 및 필요 마나 수치가 즉시 강조 표출된다.
* **단위 해금 연출 반응**: 사용자가 스테이지 진행 연동 단위 해금 조작 시 획득 단위 팝업 UI가 표출되고 퀵슬롯 인벤토리 창에 해당 단위 아이콘이 실시간으로 활성화된다.
* **단위 선택 하이라이트**: 사용자가 마우스 커서를 단위 조작 타깃 위로 이동 조작 시 타깃 팝업 UI 및 선택 단위 아이콘이 노란색 아웃라인으로 즉시 표출된다.

## 3. 세부 DLV 아키텍처 설계 명세

```
[ Data Layer ]          ↔       [ Logic Layer ]          ↔       [ Visual Layer ]
- UnitType (Enum)                - IUnitCatalogService             - UnitQuickSlotUIComponent
- UnitDataSO (ReadOnly)          - UnitCatalogService             - UnitInventoryUIComponent
- UnitRuntimeData                - UnitChangeService               - UnitUnlockPopupUIComponent
```

### 3-1. Data Layer (데이터 레이어)
* **`UnitType` (Enum)**: `Mass_Kg`, `Mass_G`, `Volume_L`, `Volume_mL`, `Vector_Reverse`
* **`UnitDataSO` (ScriptableObject)**:
  * 읽기 전용 카탈로그 원본 데이터
  * `UnitType unitType` (단위 타입)
  * `string unitName` (표시 이름)
  * `int baseCost` (기본 마나 코스트 계수)
  * `float materialMultiplier` (재질별 광역 범위 확장 계수)
  * `Sprite icon` (UI 아이콘)
  * `Material overlayMaterial` (변환 시각 셰이더)
* **`UnitRuntimeData` (Class / Struct)**:
  * 런타임 개별 수치 데이터
  * `UnitType currentUnit`
  * `float currentValue`
  * `float originalValue`
  * `float effectRadius` (산출된 런타임 광역 영향 반지름)
  * `UnitDataSO currentUnitSO`

### 3-2. Logic Layer (로직 레이어)
* **`IUnitCatalogService` (Interface)**:
  * `UnitDataSO GetUnitData(UnitType type)` (단위 데이터 조회)
  * `IReadOnlyList<UnitDataSO> GetUnlockedUnits()` (해금 단위 목록 조회)
  * `bool IsUnlocked(UnitType type)` (해금 여부 검증)
  * `void UnlockUnit(UnitType type)` (단위 해금 처리)
* **`UnitCatalogService` (Implementation)**:
  * `Dictionary<UnitType, UnitDataSO>` 딕셔너리 메모리 캐싱 관리
  * `HashSet<UnitType>` 단위 해금 상태 관리 (VContainer `Lifetime.Singleton` 등록)
* **`UnitChangeService` (Implementation)**:
  * `IResourceService` 및 `IUnitCatalogService` 주입받아 수치 계산 및 마나 차감 수행
  * **광역 범위 연산 공식**: $EffectRadius = Mass.CurrentValue \times VolumeMaterialMultiplier$ 연산 수행
  * **`Cover` 태그 엄폐물 차단 연산**: 광역 범위 내 `Cover` 태그 오브젝트 감지 시 뒤쪽 영역 영향 차단 (안전 지대 형성)

### 3-3. Visual Layer (시청각 레이어)
* **`UnitVectorGizmoUIComponent`**: 마우스 3D 원형 회전 Dial UI + 우측 수직 속도 슬라이더 UI 표출
* **`UnitSurfaceDecalComponent`**: 3D 입체 표면 밀착 원형 마커 렌더링 (URP Decal Projector, 뒷면 Back-face Culling 적용)
* **`UnitQuickSlotUIComponent`**: 퀵슬롯 단축키(1, 2, 3, 4) 등록, 선택 아이콘 및 마나 코스트 실시간 표출
* **`UnitInventoryUIComponent`**: 해금 완료 단위 도감 렌더링
* **`UnitUnlockPopupUIComponent`**: 신규 단위 해금 시 획득 팝업 애니메이션 표출

## 4. 예상 검수 방법 및 테스트 가이드

### 4-1. SO 원본 오염 방지 검수
* **테스트 항목**: 인게임 런타임 수치 변경(`kg` → `g`, 수치 수정) 연속 실행 후 에디터 정지
* **검증 기준**: Unity Editor `UnitDataSO` Asset 파일 원본 수치가 오염되지 않고 유지되는지 확인

### 4-2. 카탈로그 캐싱 메모리 검수
* **테스트 항목**: `IUnitCatalogService.GetUnitData()` 1,000회 연속 조회 실행
* **검증 기준**: 딕셔너리 캐싱 통해 Garbage Collection(GC) 메모리 할당이 0 바이트로 유지되는지 확인

### 4-3. UI 단축키 및 해금 연동 검수
* **테스트 항목**: 숫자키 1~4 입력 및 신규 단위 해금 이벤트 발생
* **검증 기준**: 퀵슬롯 선택 포커스 실시간 이동 확인, 해금 팝업 표출 후 퀵슬롯 인벤토리 수치 아이콘 즉시 활성화 확인

## 5. 수정 요구 사항

### 5.1 26-08-12 단위 조작 마법 무기(UnitMagic) 시스템 개편 및 마나 연동

* **단위 조작 마법 무기화 (`UnitMagic` 상속)**: 
  * 기존 단위 조작 마법(kg, g, L, mL, 벡터 등)을 각각 독립 `UnitMagic` 상속 클래스로 개편 정의
  * `UnitMagicSlot` 무기 슬롯 내 보관 및 `UnitMagicSlot.Fire()` 호출 호환 구조 구현
* **Player RuntimeStatData MP 연동**:
  * `UnitChangeService` 단위 조작 마법 발동 시 플레이어 `RuntimeStatData.MP` 수치 검증 및 차감 연동
  * 마나 잔여량 부족 시 단위 변환 연산 차단 및 `OnInsufficientMana` 이벤트 발송 연계
* **UI Toolkit 현재 장착 마법 표출**:
  * 플레이어가 장착/선택한 현재 단위 조작 마법(`CurrentWeapon`) 정보를 UI Toolkit HUD Document 슬롯에 실시간 연동 표출

### 5.2 26-08-12 PipeLine 마법 동작 방식 도입
* **UnitMagicPipeLine 기반 마법 발동 개편**:
  * 기존 단위 마법 발동 방식 `UnitMagicPipeLine` 비동기 파이프라인 방식 전면 검증 및 전환
  * 단위 마법 실행 시 `UnitMagicPipeLine` (`ManaCheckStep` → `TargetValidStep` → `ApplyUnitChangeStep`) 순차 스텝 연산 통한 마나 검증, 타깃 검증, 수치 변환 적용

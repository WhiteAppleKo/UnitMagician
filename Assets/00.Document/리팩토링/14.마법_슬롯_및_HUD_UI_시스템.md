## 2. 문제점 분석 (Code Smells - 5대 기준 위배 상세)

### 2-1. 시스템 간 기능 중복 (파편화)
* **마법 슬롯 관리 이원화:** 마법 슬롯을 `UnitQuickSlotUIComponent`(UnitSystem)와 `UnitMagicSlotSystem`(CharacterSystem) 양쪽에서 각각 관리하여 현재 선택된 마법 상태가 불일치할 위험이 있음.

### 2-2. 설계 원칙 위배 (DIP)
* `UnitMagicSlotSystem`이 인터페이스(`IUnitMagicSlotService`) 없이 구체 클래스로 구현됨.

---

## 3. 리팩토링 설계 (To-Be Architecture)

```
[D: Data Layer]
RuntimeDataMagicSlot (Observable Selected Magic DTO)

[L: Logic Layer]
IUnitMagicSlotService (Interface)
└── UnitMagicSlotSystem (단일 진실 공급원 - 마법 목록 및 선택 슬롯 관리)

[V: UI View Layer]
CharacterHUDUIView (HP/MP/포커스/현재 마법 아이콘 표출 전담)
```

### 3-1. 마법 슬롯 시스템 단일화
* 마법 슬롯 선택 및 목록 관리를 `IUnitMagicSlotService`로 단일화하고 퀵슬롯 UI 및 캐릭터 HUD가 동일한 서비스를 구독하도록 리팩토링.

## 4. 단계별 변경 명세

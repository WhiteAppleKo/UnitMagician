> 선행(이 세션에서 완료, 미커밋): `PureDataUnitValidator.cs`·`PureDataUnitEditor.cs` 삭제, 프로젝트 전체 `99.Legacy` 삭제, `00.TestScene`의 `initialUnits`/`testUnits`에서 Volume·Torus 마법 제거, `Sphere.prefab` `supportedUnits` -1 → 9(Mass|Temperature).
> 사용자 확정:
> - 의도: **같은 타입의 마법은 하나의 Applicator로 적용하고, 마법마다 다른 값과 연출은 데이터(에셋)로만 구분한다.**
> - `PureDataUnit` = 공통 요소(이름·설명·Cost·아이콘). 타입별 특화 변수는 서브클래스에 둔다. 마법 하나는 서브클래스 에셋 하나다. 필드가 비어 있는 타입도 서브클래스를 만든다.
> - 연출 에셋은 **전부** PureData 서브클래스로 옮긴다(빈 슬롯은 나중에 사용자가 채운다).
> - `unitType` 직렬화 필드는 없애고 서브클래스가 고정값을 반환한다. `UnitType` enum은 대상 쪽 카테고리 식별자로 유지한다.
> - **Applicator는 Logic이다. ScriptableObject가 아닌 순수 C# 클래스로 교체한다.** (타입당 하나)
> - **마법을 적용할 때, BaseDamage를 바탕으로 연산된 CurrentDamage가 투사체의 RuntimeData에 저장된다.** 데미지 게이트는 Applicator가 아니라 투사체 RuntimeData를 읽는다(충돌 시점에 질량 비율을 곱하던 기존 구조 폐기).
> - 이번 범위는 튜토리얼에 쓰이는 **Mass·Temperature**다. Vector·Volume은 씬에서 접근만 막고 코드는 나중에 쓰기 위해 보존한다(컴파일 유지 수준으로만 따라 고친다).
>
> 경위(데미지): 튜토리얼 04·07번 기획서(세션 3)가 "질량 비율을 재사용한다"는 결정을 "충돌 시점에 `기본 데미지 × 질량 비율`을 계산한다"로 옮기면서, 데미지 게이트가 `MassUnitApplicatorSO.CalculateMassRatio`를 호출하는 구조가 됐다. 마법 적용 시 데미지를 저장하는 방식은 검토되지 않았고, 20번이 이를 그대로 이어받았다. 투사체의 기본 데미지는 RuntimeData가 아닌 `CollisionDamageTrigger`(MonoBehaviour)의 직렬화 필드 `baseDamage`에 있다.
>
> 경위(계층): Applicator는 `02.Visualizer`에 SO로 만들어졌고, 08번 리팩토링 기획서(2026-09-03)가 이를 "Visualizer Layer"로 분류했다. 27번(기능별 하위 폴더 분류)은 레이어를 바꾸지 않는 순수 이동이라 그대로 `02.Visualizer/00.Common`에 남았다. 실제 역할(RuntimeData를 읽어 연산·판단하고 Visual Interface에 지시)은 코드 가이드라인 1-2의 Logic이다.

## 1. 작업 개요 및 유형
**비시청각**(Pure Data / Logic 구조 개편). 유저가 보는 결과(스케일 변화, 얼음 머티리얼, 서리 파티클)는 바뀌지 않는다.

지금은 세 가지 문제가 있다.
- `PureDataUnit` 하나가 모든 타입의 필드를 합집합으로 갖는다.
- 연출 에셋이 타입당 하나뿐인 Applicator에 있어서, 같은 타입의 마법끼리 연출을 다르게 줄 수 없다.
- Logic 역할인 Applicator가 SO로 `02.Visualizer`에 있고, Visual 컴포넌트(`UnitTargetObjectVisualizer.ApplyVisuals`)가 Applicator를 호출하는 역방향 구조다.

이번 작업은 데이터를 타입별 서브클래스로 나누고, 연출 에셋을 마법 단위로 옮기고, Applicator를 순수 C# Logic으로 옮겨 **Logic → Visual Interface** 방향으로 호출하게 한다.

## 2. 핵심 요구사항
1. `PureDataUnit`을 공통 메타데이터만 가진 abstract ScriptableObject로 바꾸고 타입별 서브클래스로 특화 필드를 나눈다. 새 마법은 코드 수정 없이 에셋 생성만으로 추가되고, 타입과 무관한 필드는 인스펙터에 노출되지 않는다.
2. Applicator를 상태 없는 순수 C# 클래스(타입당 하나, 제네릭 기반 `UnitApplicator<TData>`)로 바꾸고 PureData의 Applicator 참조를 없앤다. 마법 타입이 곧 적용 로직을 결정하게 해서 에셋 연결 실수(예: Mass 마법에 Volume Applicator)를 원천적으로 없애고, PureData를 Logic-Free로 만든다.
3. 연출 에셋(스케일 VFX, 얼음 머티리얼, 서리 파티클)을 PureData 서브클래스로 옮겨, 같은 타입 안에서 마법마다 다른 연출을 데이터만으로 지정할 수 있게 한다.
4. `unitType` 직렬화 필드를 서브클래스의 고정 반환 프로퍼티로 대체해 클래스와 enum 값의 불일치를 막고, 기존 `spell.UnitType` 호출부는 수정 없이 유지한다.
5. 같은 단위 변경에 `Apply`가 두 번 호출되는 경로를 이벤트 경로 하나로 합쳐, 이펙트 이중 스폰과 불필요한 재적용을 없앤다(§6-1).
6. Applicator 안의 Rigidbody·MeshRenderer·Transform 직접 조작 폴백과 `Object.Instantiate`를 제거해, 대상 조작은 `IUnitTargetVisualizer`를 통해서만 하게 한다(가이드라인 1-2 "Rigidbody, transform 직접 참조 금지").
7. BaseDamage를 쓰는 모든 런타임 주체(충돌 데미지 오브젝트, NPC 전투 주체)의 데미지를 공용 RuntimeData(`RuntimeDataAttackDamage`: BaseDamage·CurrentDamage)로 옮기고, 모든 Applicator에 비어 있는 데미지 계산 자리를 두어 계산식을 넣은 마법이 적용될 때 CurrentDamage를 연산해 저장하게 한다(현재 계산식은 Mass = `BaseDamage × 질량 비율`). 데미지 게이트는 저장된 `CurrentDamage`만 읽게 해서, 전투 판정이 마법 적용 코드에 의존하지 않고 투사체 데이터만으로 이루어지게 한다.

## 3. 데이터 정의 및 흐름

### 3-1. 데이터

**`PureDataUnit`** (abstract SO, 기존 파일 수정 · 공통)
| 필드 | 타입 | 의미 |
|---|---|---|
| `unitName` | string | 마법 이름 |
| `description` | string | 인벤토리 목록/상세 설명(비면 설명 요소 미생성, 기존 규칙 유지) |
| `baseCost` | int | 마나 기본 비용 |
| `icon` | Sprite | 아이콘 |
| `UnitType` | UnitType (abstract get) | 서브클래스가 고정값 반환. 직렬화하지 않음 |

삭제 필드: `unitType`, `applicator`(Applicator 참조 자체를 없앰), `overlayMaterial`(Volume으로 이동), `massScaleMultiplier`(Mass로 이동), `temperatureTarget`(Temperature로 이동).

**`PureDataMassUnit`** (신규 · `UnitType => Mass`)
| 필드 | 타입 | 의미 |
|---|---|---|
| `massScaleMultiplier` | float (기본 1) | 새 질량 = 원래 질량 × 이 값 |
| `scaleChangeVfxPrefab` | GameObject | 스케일 변화 시 스폰할 VFX(비면 스폰 안 함) — Applicator에서 이동 |

**`PureDataTemperatureUnit`** (신규 · `UnitType => Temperature`)
| 필드 | 타입 | 의미 |
|---|---|---|
| `temperatureTarget` | float | 시전 후 온도. 음수 = 얼음 방향 |
| `iceMaterial` | Material | 얼음 방향일 때 교체할 머티리얼(비면 교체 안 함) — Applicator에서 이동 |
| `frostParticlePrefab` | GameObject | 얼음 방향일 때 스폰할 서리 파티클(비면 스폰 안 함) — Applicator에서 이동 |

**범위 밖 보존용 최소 서브클래스** (동작은 현재와 동일, 씬에서 접근 불가)
- `PureDataVolumeUnit` (`UnitType => Volume`): `overlayMaterial`(Material). `VolumeUnitApplicatorSO`에 있던 같은 필드는 여기로 합친다.
- `PureDataVectorUnit` (`UnitType => Vector`): 필드 없음.

**`RuntimeDataAttackDamage`** (신규 · 순수 C# · **BaseDamage를 쓰는 모든 런타임 주체의 공용 데미지 데이터**)
| 멤버 | 타입 | 의미 |
|---|---|---|
| `BaseDamage` | int (private set) | 기본 데미지(PureData나 발사 값에서 초기화) |
| `CurrentDamage` | int (private set) | 마법 등 런타임 변화가 반영된 현재 데미지. 이 주체가 데미지를 줄 때 쓰는 값 |
| `OnDamageChanged` | event Action\<RuntimeDataAttackDamage\> | 값이 바뀔 때 발행 |
| `Initialize(int baseDamage)` | 메서드 | `BaseDamage = CurrentDamage = baseDamage` (생성·발사·풀 재사용 시) |
| `SetCurrentDamage(int value)` | 메서드 | 런타임 변화 결과 저장 |

- 규칙(사용자 확정): **BaseDamage가 있는 모든 RuntimeData는 CurrentDamage를 가진다.** 각 주체가 BaseDamage를 별도 필드로 두지 않고 이 클래스 인스턴스를 보관해 같은 규칙을 공유한다.
- 적용 대상(현재 BaseDamage를 쓰는 런타임 주체 전부):

| 주체 | 지금 BaseDamage가 있는 곳 | 변경 |
|---|---|---|
| 충돌 데미지 오브젝트(`NpcProjectile_Dummy`, 씬의 `Sphere` 2개) | `CollisionDamageTrigger.baseDamage`(직렬화 필드, 발사 시 `SetBaseDamage`로 덮어씀) | `RuntimeDataAttackDamage` 보관, 충돌 시 `RawDamage = CurrentDamage`. `IAttackDamageProvider`로 노출 |
| NPC 전투 주체 | `PureDataNpcActor.BaseDamage`를 `ProjectileAttackBehaviorSO`가 발사 때마다 직접 읽음(런타임 값 없음) | `RuntimeDataNpcActor`가 `RuntimeDataAttackDamage`를 갖고 `PureDataNpcActor.BaseDamage`로 초기화. 투사체 발사 시 NPC의 `CurrentDamage`를 투사체 `BaseDamage`로 넘긴다(이벤트 투사체 전용 데미지 예약은 기존대로 우선) |

- 범위 밖: `NpcProjectileLaunchData.BaseDamage`(발사 값 전달용 readonly 구조체, RuntimeData 아님), `BaseDamageContext.BaseDamage`(파이프라인 Context. `BaseDamagePipeLineSO`·`BlockStep`·`EvadeStep` 외에 사용처 없음), `PureDataNpcActor.baseDamage`(PureData는 불변 원본 값으로 유지).
- 플레이어는 공격 데미지 데이터가 아직 없다(무기·공격 미구현). 생기면 같은 규칙을 따른다.

**`RuntimeDataUnit.ValueRatio`** (신규 get 프로퍼티): `CurrentValue / OriginalValue`(원래 값 0 이하면 1로 계산, 기존 `CalculateMassRatio`와 동일).

**적용 대상 묶음 `UnitApplyTarget`** (신규 · 순수 C# · Applicator 입력, 가이드라인 Rule 1 "인자 나열 전달 금지")
| 멤버 | 타입 | 의미 |
|---|---|---|
| `Visualizer` | IUnitTargetVisualizer | 스케일·머티리얼·이펙트 지시 대상 |
| `AttackDamage` | RuntimeDataAttackDamage (nullable) | 공격 데미지를 가진 대상(투사체)이면 값, 아니면 null |

**Applicator (Logic, 순수 C#, 상태 없음)**
- `IUnitApplicator`: `void Apply(UnitApplyTarget target, RuntimeDataUnit runtimeData, PureDataUnit unitData)`
- `UnitApplicator<TData> : IUnitApplicator where TData : PureDataUnit`: 위 메서드에서 `unitData`를 `TData`로 확인한 뒤 `protected abstract Apply(UnitApplyTarget, RuntimeDataUnit, TData)`를 호출한다. 타입이 맞지 않으면 경고 로그를 남기고 적용하지 않는다.
- `MassUnitApplicator`, `TemperatureUnitApplicator`(이번 범위), `VolumeUnitApplicator`, `VectorUnitApplicator`(보존, 기존 동작을 그대로 옮김).
- 타입 → Applicator 조회 방식은 §6-6.

### 3-2. 흐름 (값 계산 공식은 변경 없음)
1. **값 계산** — `UnitCastRuleService.CalculateNewValue`가 `switch (spellUnit.UnitType)`를 타입 패턴 매칭(`case PureDataMassUnit mass:`)으로 바꿔 서브클래스 필드를 직접 읽는다.
   - Mass: `원래값(0 이하면 1) × massScaleMultiplier`
   - Temperature: `temperatureTarget`
   - Volume·Vector: 기존 공식 그대로
2. **런타임 반영** — `RuntimeDataUnit.UpdateUnitData(type, newValue, unitData)`가 값을 저장하고 `OnUnitChanged`를 발행한다(변경 없음).
3. **적용(단일 경로, Logic → Visual)** — `OnUnitChanged` → `RuntimeDataUnitGroup.OnUnitGroupChanged` → (§6-6의 Logic 호출 주체)가 대상의 `UnitApplyTarget`(Visualizer + 있으면 AttackDamage)을 만들고, `runtimeData.CurrentUnitData`의 타입으로 Applicator를 찾아 `Apply(target, runtimeData, unitData)`를 호출한다.
   - `ApplyUnitChangeStep`과 `UnitChangeService` 폴백에 있던 직접 `Apply` 호출은 제거한다(§6-1).
   - `IUnitTargetVisualizer.ApplyVisuals`와 `UnitTargetObjectVisualizer.ApplyVisuals`(Visual이 Applicator를 부르던 역방향 호출)는 제거한다.
4. **Applicator 적용**
   - `MassUnitApplicator`: 비율 = `runtimeData.ValueRatio`, 스케일 비율 = 세제곱근(§6-2). `visualizer.ApplyMassScale(currentMass, scaleRatio)`를 호출하고, `data.scaleChangeVfxPrefab`이 있으면 `visualizer.SpawnEffect`로 스폰한다. 데미지 계산 자리(`ApplyDamage`)에 `CurrentDamage = RoundToInt(BaseDamage × ValueRatio)`를 넣어 **투사체 데이터에 데미지를 저장**한다(항상 BaseDamage 기준이라 중첩 곱셈이 생기지 않는다).
   - **데미지 계산 자리(공통)**: 모든 Applicator는 `target.AttackDamage`가 있으면 `ApplyDamage`를 호출한다. 기본 구현은 비어 있고, 계산식을 넣은 Applicator만 CurrentDamage를 바꾼다(§6-9).
   - `TemperatureUnitApplicator`: `CurrentValue < 0`이면 `data.iceMaterial`로 `visualizer.ApplyMaterial`을 호출하고, `data.frostParticlePrefab`을 `SpawnEffect`로 스폰한다. 스케일은 `clamp(|온도|/10, 0.5, 3)`.
   - 이펙트 스폰 위치는 §6-7.
5. **발사·재사용** — `NpcProjectile.SetActive`가 `SetBaseDamage(launchData.BaseDamage)` 대신 `AttackDamage.Initialize(launchData.BaseDamage)`를 호출한다. 풀 재사용 시(`CollisionDamageTrigger.ResetForReuse`) 기본값으로 `Initialize`한다.
6. **충돌 판정** — `CollisionDamageTrigger`가 `DamageContext.RawDamage = AttackDamage.CurrentDamage`로 채운다.
   - `AttributeGateStep`: 온도 조건만 판정하고, 통과 시 `FinalDamage = RawDamage`(질량 비율 곱셈 제거 — 이미 CurrentDamage에 반영됨). Applicator 참조 제거.
   - `SizeGateStep`: 크기 조건은 데미지와 별개(20번 확정)이므로 `massUnit.ValueRatio ≥ RequiredMassRatio`로 판정한다. Applicator 참조 제거.
   - 돌문·보스 코어의 `FinalDamage ≥ 기준` 판정 결과는 변경 전과 같은 값이 나온다(`기본 데미지 × 질량 비율` 값이 그대로 `FinalDamage`가 된다).
7. **미리보기** — `LockOnPreviewCalculator`의 `spell.UnitType == Mass && spell.Applicator is MassUnitApplicatorSO` 조건을 `spell is PureDataMassUnit`으로 바꾼다.

### 3-3. 시청각
결과는 변경 전과 **동일해야 한다**(구조 개편 작업이므로 새 연출은 없다).
- Mass(kg): 시전하면 대상 스케일이 질량 비율의 세제곱근만큼 바뀌고, 질량 변화 VFX가 **1회** 스폰된다(이전에는 2회였을 수 있음, §6-1).
- Temperature(Frost): 시전하면 대상 머티리얼이 얼음 머티리얼로 바뀌고, 서리 파티클이 **1회** 스폰된다.
- 연출 슬롯을 비운 마법은 해당 연출 없이 수치(스케일/머티리얼 미교체)만 적용되고 에러는 나지 않는다.
- 같은 타입의 마법 에셋을 하나 더 만들어 다른 VFX를 넣으면, 그 마법만 다른 VFX가 나온다.
- 질량을 키운 투사체로 돌문·보스 코어를 맞히면 파괴/성공·금 갔다 복구 같은 기존 피드백이 같은 조건에서 그대로 나온다(데미지 값이 저장 시점만 바뀌고 수치는 같다).

## 6. 결정 사항 (전 항목 확정)
1. **[확정] Apply 이중 호출 정리**: 지금은 `UpdateUnitData`가 발행하는 이벤트 경로와 `ApplyUnitChangeStep`의 직접 `Apply` 호출이 겹쳐서, 한 번 시전할 때 `Apply`가 2번 실행된다(VFX·파티클 2회 스폰). **이벤트 경로만 남기고 직접 호출 2곳(`ApplyUnitChangeStep`, `UnitChangeService` 폴백)을 제거**한다. 씬과 프리팹의 모든 대상(`RuntimeDataUnitGroup` 보유 3곳)에 `UnitTargetLogicSystem`과 `UnitTargetObjectVisualizer`가 함께 붙어 있어 안전하다.
   - 사용자 원칙: 마법 적용은 **적용 담당 시스템을 통해서만 파이프라인에 들어가 발동**되어야 한다. 현재 실제 경로(`UnitBatchCastingService` → `ChangeUnit(pipeLine: null)`)가 파이프라인을 우회하는 문제는 29번 기획서에서 다룬다(§7).
2. **[확정] 질량 비율 계산 위치**: 별도 Rule 클래스는 만들지 않는다.
   - `RuntimeDataUnit.ValueRatio`(신규 get 프로퍼티) = `CurrentValue / OriginalValue`(원래 값 0 이하면 1로 계산, 기존 `CalculateMassRatio`와 동일).
   - 데미지 게이트는 Applicator를 참조하지 않는다. 데미지는 투사체의 `CurrentDamage`(§3-2-6)를, 크기 게이트는 `massUnit.ValueRatio`를 읽는다(전투 판정은 데이터만 본다).
   - 스케일 변환(세제곱근)은 `MassUnitApplicator`(Logic)의 정적 함수로 두고, Applicator와 미리보기(`LockOnPreviewCalculator`)가 쓴다.
3. **[확정] Torus Mass(`PureDataUnit_ 2.asset`)**: 씬에서 이미 뺐다. `PureDataMassUnit`으로 옮겨 보존한다. (Applicator 참조가 없어지므로 잘못 연결된 Volume Applicator 문제는 자연히 사라진다.)
4. **[확정] 에셋 마이그레이션 방식**: 개발 에이전트가 PureData `.asset`의 `m_Script` GUID를 새 클래스 GUID로 교체하고, 이동하는 연출 값은 에디터 API(`SerializedObject`)로 넣은 뒤 저장한다. 1회성 마이그레이션 코드는 디스크에 남기지 않는다.
5. **[확정] 클래스 이름**: PureData는 가이드라인 `[PureData]명` 규칙에 따라 `PureDataMassUnit`, `PureDataTemperatureUnit`, `PureDataVolumeUnit`, `PureDataVectorUnit`. `CreateAssetMenu`는 `UnitSystem/PureData/Mass` 등 타입별. Applicator는 `MassUnitApplicator`, `TemperatureUnitApplicator`, `VolumeUnitApplicator`, `VectorUnitApplicator`. 호출 주체는 `UnitApplyLogicSystem`.
6. **[확정 — (b)] Applicator 조회·호출 주체**: Logic이 "이 PureData 타입 → 이 Applicator"를 어떻게 찾고, 누가 호출하는가. 대상 오브젝트는 풀링되는 프리팹이라 개별 MonoBehaviour에 DI 주입하기 어렵다(`NpcSystemLifetimeScope` 주석의 `InjectGameObject` 문제).
   - (a) [기각] 정적 레지스트리(`UnitApplicatorRegistry`)에 타입별 인스턴스를 등록하고, 기존 `UnitTargetLogicSystem`이 조회해서 호출. 수정이 적지만 정적 구체 클래스 참조가 생긴다.
   - (b) **[채택]** VContainer에 등록한 중앙 순수 C# 시스템(`UnitApplyLogicSystem`)이 `RuntimeDataUnitGroup`의 정적 이벤트(기존 `OnAnyTargetRetired`와 같은 방식)를 구독해서 Applicator를 주입받아 호출. 가이드라인(순수 C#·DI·인터페이스)에 맞고 풀링 주입 문제가 없다. `UnitTargetLogicSystem`(01.Logic에 있는 MonoBehaviour)은 역할이 없어져 제거 대상이 된다(씬·프리팹 3곳의 컴포넌트도 제거). `UnitApplyTarget`은 `RuntimeDataUnitGroup`이 같은 오브젝트의 `IUnitTargetVisualizer`/`IAttackDamageProvider`로 만들어 정적 이벤트에 실어 보낸다(Logic이 `GetComponent`하지 않음).
7. **[확정] 이펙트 스폰 위치**: Applicator가 `target.transform.position`을 읽던 부분을 Logic에서 할 수 없다. `IUnitTargetVisualizer.SpawnEffect(GameObject prefab)`로 바꿔 Visualizer가 자기 위치·회전에 스폰한다.
8. **[확정] 기즈모 UI의 Applicator 검사**: `UnitVectorGizmoUIComponent`가 `CurrentUnitData.Applicator == null`이면 적용을 막는다. `CurrentUnitData is PureDataVectorUnit` 검사로 바꾼다(동작 동일, 컴파일 유지).
9. **[확정] CurrentDamage 저장**: 마법 적용 시 CurrentDamage를 투사체 RuntimeData에 저장한다. **BaseDamage가 있는 모든 RuntimeData는 CurrentDamage를 가진다**(사용자 확정, §3-1 표의 충돌 데미지 오브젝트·NPC 전투 주체 전부).
   - **[확정]** 공용 클래스 위치: `Assets/PipeLine/Combat/`(InteractionSystem·NpcSystem 공용 전투 타입이 이미 있는 곳).
   - **[확정] 데미지를 바꾸도록 설계된 마법은 전부 CurrentDamage에 반영한다**(특정 타입으로 고정하지 않는다). 구조:
     - `UnitApplicator<TData>`에 **비어 있는 데미지 계산 자리** `protected virtual void ApplyDamage(RuntimeDataAttackDamage damage, RuntimeDataUnit runtimeData, TData data) { }`를 둔다. `Apply`는 대상에 `AttackDamage`가 있으면 항상 이 자리를 호출한다.
     - 지금 계산식이 들어가는 것은 `MassUnitApplicator`뿐이다: `damage.SetCurrentDamage(RoundToInt(damage.BaseDamage × runtimeData.ValueRatio))`(기존 공식과 동일, 항상 BaseDamage 기준이라 중첩되지 않음).
     - Temperature·Volume·Vector는 자리만 있고 비어 있어 데미지가 바뀌지 않는다. 나중에 어떤 마법이든 이 자리에 계산식을 넣으면 그대로 CurrentDamage에 반영되고, 데미지 게이트나 호출 흐름은 수정하지 않는다.
     - 여러 마법의 계산식을 어떻게 합칠지는 두 번째 계산식이 생길 때 정한다(지금은 정하지 않음).
   - NPC의 `CurrentDamage`를 바꾸는 런타임 요소는 현재 없다(값은 BaseDamage와 같게 유지되고, 발사 값의 원천만 RuntimeData로 바뀐다).
   - `CollisionDamageTrigger`가 `01.Logic`에 있는 MonoBehaviour인 DLV 위반은 이번 범위에서 정리하지 않는다(데이터 보관 위치만 RuntimeData로 옮김).

  - 마나: 일괄 시전은 `UnitBatchCastingService`의 **큐 전체 일괄 차감을 유지**하고, 일괄 시전용 파이프라인은 `ManaCheckStep` 없이 조립한다.

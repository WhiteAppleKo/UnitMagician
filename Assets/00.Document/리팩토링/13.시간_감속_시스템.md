## 2. 문제점 분석 (Code Smells - 5대 기준 위배 상세)

### 2-1. DLV 아키텍처 위배 (전역 엔진 환경 직접 제어)
* **Logic 계층의 Time.timeScale 직접 조작:** `TimeSlowLogicSystem.cs`의 `HandleSlowStateChanged()`, `ProcessTimeSlow()`, `RestoreTimeScale()`에서 `Time.timeScale`과 `Time.fixedDeltaTime`을 직접 덮어씀.
* **가이드라인 위배:** 순수 로직 클래스는 판단 및 게이지 연산만 수행해야 하며, 전역 엔진 API 수정은 Time Service 또는 Visualizer를 통해 실행되어야 함.

### 2-2. 디자인 패턴 적용 위배 (입력 폴링)
* **Update 폴링:** `HandleInput()`에서 `Keyboard.current.tKey.wasPressedThisFrame`을 매 프레임 폴링함 -> Input System 이벤트 푸시 방식으로 전환 필요.

## 3. 리팩토링 설계 (To-Be Architecture)

```
[D: Data Layer]
PureDataTimeSlow (SO - MaxFocus, DrainRate, RecoveryRate)
RuntimeDataTimeSlow (Observable FocusGauge Model)

[L: Logic Layer]
TimeSlowLogicSystem (ITickable, IDisposable)
└── 포커스 게이지 소모/회복 순수 연산 및 상태 전이 판정

[V: Visualizer Layer]
ITimeSlowVisualizer
└── TimeSlowVisualizer (포스트 프로세싱 볼륨 블러/채도 조절 + Time.timeScale 조정 전담)
```

### 3-1. TimeScale 제어 Visualizer/TimeService 이관
* `ITimeSlowVisualizer.SetTimeSlowEffect(bool isActive, float targetScale)`에서 `Time.timeScale` 및 `Time.fixedDeltaTime` 변경을 전담하도록 역할 재배치.

### 3-2. InputReader 이벤트 연동
* `InputReader.onTimeSlowToggled` 이벤트를 구독하여 폴링 제거.

## 4. 단계별 변경 명세

### Step 1: ITimeSlowVisualizer 역할 확장
* `TimeSlowVisualizer.cs`의 `SetTimeSlowEffect()` 내부에서 `Time.timeScale = targetScale` 및 `Time.fixedDeltaTime` 설정 수행.

### Step 2: TimeSlowLogicSystem 리팩토링
* `Time.timeScale` 및 `Keyboard.current` 직접 참조 완전 제거.
* 게이지 계산 순수 로직만 유지.

## 5. 기능 무결성 검증 기준 및 테스트 케이스

### 검증 체크리스트
1. **시간 정지 발동:** T키 입력 시 Time.timeScale이 지정된 배율(0.0)로 즉시 변경되고 화면 포스트 프로세싱 이펙트가 활성화되는가?
2. **포커스 게이지 소모 및 강제 해제:** 시간 정지 유지 중 게이지가 초당 소모량에 따라 정상 차감되며, 게이지 소진 시 즉시 정지가 자동 해제되는가?
3. **지연 회복:** 정지 해제 후 RecoverDelaySeconds 동안 대기 후 초당 회복량에 따라 게이지가 정상 충전되는가?

## 2. 문제점 분석 (Code Smells - 5대 기준 위배 상세)

### 2-1. DLV 아키텍처 위배
* **Logic 폴더의 MonoBehaviour 및 Visual 컴포넌트 상속:** `CharacterStatComponent.cs`가 `01.Logic`에 위치하면서 `SampleObjectLockOn`을 상속받아 마커 렌더링 및 하이라이트(`Highlight()`)를 직접 처리함.
* **계층 혼용:** 스탯 데이터 홀딩과 시각적 락온 마커가 단일 컴포넌트에 결합되어 있음.

### 2-2. VContainer DI 전환 위배
* **수동 new 생성 Fallback:** `CharacterStatComponent.cs`의 `EnsureInitialized()`에서 DI 주입 실패 시 `new CharacterStatSystem(pureStatData)`를 수동 호출하여 런타임 인스턴스 관리가 컨테이너 밖에서 이루어짐.
* **팩토리 부재:** 런타임에 동적으로 스폰되는 적(Enemy) 캐릭터의 스탯 인스턴스를 생성하고 주입할 팩토리가 없음.

### 2-3. 설계 원칙 위배 (DIP)
* `CharacterStatSystem`이 인터페이스 없이 구체 클래스로만 전달되어 모의 객체(Mock) 테스트 및 다형적 확장이 제한됨.

## 3. 리팩토링 설계 (To-Be Architecture)

```
[D: Data Layer]
PureStatData (SO)
RuntimeStatData (HP, MP ClampValueInt Observable Model)

[L: Logic Layer]
ICharacterStatService (Interface)
└── CharacterStatSystem (TakeDamage, Heal, UseMP, RecoverMP 순수 연산)
ICharacterStatFactory (다중 엔티티 스탯 인스턴스 생성 팩토리)

[V: Visualizer Layer]
CharacterStatVisualizer / CharacterStatHolder (MonoBehaviour)
├── ICharacterStatService 보유
└── 적대 진영 판별 및 락온 마커(ILockOnTarget) 표출 전담
```

### 3-1. ICharacterStatService 인터페이스 추출
* 스탯 조작 메서드(`TakeDamage`, `Heal`, `UseMP`)를 추상화하여 DIP 준수.

### 3-2. DLV 계층 재배치
* `CharacterStatComponent`를 `02.Visualizer`로 이동하고 순수 비주얼/마커 책임을 담당하도록 리팩토링.

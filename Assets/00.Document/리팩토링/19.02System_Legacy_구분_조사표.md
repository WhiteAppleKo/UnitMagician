작성 기준: 2026-10-12(조사 시점은 프로젝트 파일 수정 없음). **2026-10-12 Goal 41로 신규 Legacy 후보 15개를 각 기능 폴더의 `99.Legacy/`로 격리(에디터 에셋 이동, GUID 유지) 완료 — 아래 요약 표·상세 표는 이동 후 상태 기준이며, 상세 표의 근거/영향 열은 이동 전 조사 내용 그대로다.** 분석 파일 수: 02.System 아래 261개(.meta 제외, .gitkeep 2개 제외; .gitkeep 포함 263개).

## 0. 판정 방법과 한계

- 빌드 씬: `ProjectSettings/EditorBuildSettings.asset`에 `Assets/01.Scenes/00.TestScene.unity` 1개만 등록(확인됨). `Demo_01_Polygon.unity`는 빌드 비대상.
- Assets 전체(.meta 855개의 GUID)를 대상으로 씬/프리팹/.asset/.mat/.uxml 등의 `guid:` 참조 그래프를 만들고, 여기에 C# 코드의 타입명(class/struct/interface/enum) 식별자 참조(주석 제거 후)와 YAML의 `type: {class: X}`(SerializeReference) 참조를 합쳐 TestScene에서 BFS 도달성을 계산함. Editor 폴더/Tests 폴더 소스는 "활성 참조원"에서 제외.
- asmdef/asmref 0개(Assets 전체) -> 모두 Assembly-CSharp 단일 어셈블리. 따라서 폴더 이동은 어셈블리 경계 문제를 만들지 않음.
- 씬에 부착된 LifetimeScope(전부 활성 GameObject, enabled=1): Locomotion, Unit, Character, Interaction, Option, TimeSlowFilter, Npc, EventSequencer, AllySupport, BossPhase, AreaFreeze, Pickup. `MovementLifetimeScope`, `TacticalCommandLifetimeScope`, `GameLifetimeScope_KWT`는 TestScene/Demo 어디에도 없음. 08.DestructibleSystem은 LifetimeScope 자체가 없음(DestructibleDoorComponent가 씬에 직접 부착).
- `Resources.Load`, `Type.GetType`, `Activator.CreateInstance`(런타임) 사용은 02.System/PipeLine에 없음(Editor 코드의 AssetDatabase.FindAssets("t:PureDataUnit") 등만 존재). 따라서 문자열 기반 숨은 참조는 확인되지 않음.
- 한계: "클래스명이 활성 파일에 등장함"을 "사용됨"으로 간주(과대 추정 방향). 활성 파일 내부의 도달 불가능한 분기에서만 쓰이는 타입은 걸러내지 못함. 반대로 Legacy 후보는 "참조 0건" 또는 "Legacy 묶음 내부 참조뿐"이라 확정도가 높음.
- 문서(.md)는 참조원으로 보지 않음(클래스명이 문서에 등장하는 것은 무관).

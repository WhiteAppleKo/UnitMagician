> 형식: `코드_작업_기획서_가이드라인_v1.0.md`
> 선행: 28번(PureData 타입별 서브클래스, Applicator 순수 C#, CurrentDamage 데이터화, §8 Volume 삭제·`03.Magic` 분리) — 구현·QA 합격, 미커밋.
> 사용자 확정(2026-10-19 대화):
> - **`RuntimeDataUnit`은 PureData를 바탕으로, 시전자의 스탯·장착 아이템 등의 영향을 받아 최종 수치를 캐싱해 둔 마법 한 번의 런타임 인스턴스다.**
> - **피격 대상은 적용된 마법 목록을 가진다.** 적용될 때마다 **뒤에 하나씩 추가(누적)**하고, 같은 속성이어도 교체하지 않는다(Mass 3번 → Mass 항목 3개).
> - **해제는 조건으로 골라 낸다.** "Mass 전부 해제" → Mass 항목만 빠지고, 남은 항목은 상대 순서를 유지한 채 **앞으로 당겨진다**(빈칸 없음).
> - **같은 속성 누적 계산**: 곱 배율끼리 먼저 **합산**한 뒤 베이스(프리팹 원본 값)에 곱한다. Mass ×2가 3번 → 베이스 × (2+2+2) = ×6(×8 아님).
> - 다른 결합 규칙은 미리 정하지 않고 계산식 자리만 둔다(28번 §6-9와 같은 원칙).
>
> 경위: 28번까지 `RuntimeDataUnit`은 대상이 `supportedUnits` 비트마다 미리 만드는 **속성 칸**(대상 질량·온도 값 + 마지막 마법 참조 `CurrentUnitData` + Vector 전용 필드)이었다. 같은 속성 마법은 원래 값 기준으로 덮어써서 누적되지 않았고, 시전자 영향과 해제가 없었다.

---

## 1. 작업 개요 및 유형
**비시청각**(Pure Data / Logic 구조 개편). 마법을 한 번씩 거는 현재 튜토리얼 흐름의 결과(스케일, 얼음, 데미지, 게이트 판정)는 변경 전과 같아야 한다. 새로 생기는 결과는 두 가지다.
- 같은 속성 마법을 여러 번 걸면 누적된다.
- 조건별로 해제할 수 있다.

## 2. 핵심 요구사항
1. `RuntimeDataUnit`을 대상 속성 칸에서 **시전 마법 인스턴스**(원본 PureData + 캐싱된 최종 수치)로 바꾼다. 마법 타입별 서브클래스로 나눠 Vector 같은 타입 전용 값이 공용 클래스에 섞이지 않게 하고, 시전자 영향은 계산 자리로 열어 둔다.
2. 대상 쪽에 속성 상태(베이스 값·현재 값)와 **적용 마법 목록**을 가진 RuntimeData를 새로 둔다. 목록에 추가하거나 해제할 때마다 해당 속성을 목록 전체로 다시 계산하게 해서, 누적과 해제가 같은 규칙으로 처리되게 한다.
3. 속성 값 계산·시각 적용·데미지 계산은 타입별 Applicator가 맡는다. Applicator는 "그 속성의 목록 항목들"을 입력으로 받아 계산하고, 계산 공식을 Applicator 한 곳에서만 갖게 해 실제 적용과 미리보기가 같은 결과를 내게 한다.
4. 데미지 게이트·미리보기·비용 계산은 RuntimeDataUnit이 아니라 대상 속성 상태를 읽게 한다.

## 3. 데이터 정의 및 흐름

### 3-1. 데이터

**`RuntimeDataUnit`** (abstract, 순수 C# · 마법 한 번의 런타임 인스턴스 · 기존 파일을 교체)
| 멤버 | 타입 | 의미 |
|---|---|---|
| `Source` | PureDataUnit (get) | 원본 마법(kg, Frost …). 연출 에셋도 여기서 읽는다 |
| `UnitType` | UnitType (get) | `Source.UnitType` |

삭제: `CurrentUnit`, `CurrentValue`, `OriginalValue`, `CurrentUnitData`, `ValueRatio`, `CalculateValueRatio`, `VectorDirection`, `VectorSpeed`, `UpdateUnitData`, `SetPureDataUnit`, `SetVectorData`, `OnUnitChanged`. 인스턴스는 생성 후 값이 바뀌지 않는다(불변 캐시).

**타입별 인스턴스** (`00.Data/03.Magic/`, 신규)
| 클래스 | 캐싱 필드 | 원천 |
|---|---|---|
| `RuntimeDataMassUnit` | `ScaleMultiplier`(float) | `PureDataMassUnit.massScaleMultiplier` + 시전자 영향(계산 자리) |
| `RuntimeDataTemperatureUnit` | `TargetTemperature`(float) | `PureDataTemperatureUnit.temperatureTarget` + 시전자 영향(계산 자리) |
| `RuntimeDataVectorUnit` | `Direction`(Vector3), `Speed`(float) | 시전 시 입력(기즈모 UI 등) |

**`RuntimeDataUnitAttribute`** (신규, 순수 C# · 대상의 속성 하나의 상태)
| 멤버 | 타입 | 의미 |
|---|---|---|
| `UnitType` | UnitType | 속성 종류 |
| `BaseValue` | float (private set) | 프리팹 원본 값(Mass = `bakedMassValue`, Temperature = 0, Vector = 1) |
| `CurrentValue` | float (private set) | 적용 목록에서 계산된 현재 값 |
| `ValueRatio` | float (get) | `CurrentValue / BaseValue`(베이스 0 이하면 1로 계산 — 기존 공식과 동일) |
| `SetCurrentValue(float)` | 메서드 | Logic이 계산한 값을 저장 |

**`RuntimeDataUnitTarget`** (신규, 순수 C# · 피격 대상의 마법 상태)
| 멤버 | 타입 | 의미 |
|---|---|---|
| `Attributes` | IReadOnlyList\<RuntimeDataUnitAttribute\> | `supportedUnits` 비트마다 1개 |
| `AppliedUnits` | IReadOnlyList\<RuntimeDataUnit\> | **적용 마법 목록**(적용 순서대로) |
| `GetAttribute(UnitType)` | 메서드 | 없으면 null |
| `GetApplied(UnitType)` | 메서드 | 그 속성 항목만 순서대로 |
| `AddApplied(RuntimeDataUnit)` | 메서드 | 목록 끝에 추가 → `OnAppliedUnitsChanged(type, added: instance)` 발행 |
| `RemoveApplied(Predicate<RuntimeDataUnit>)` | 메서드 | 조건에 맞는 항목 전부 제거, 남은 항목은 순서 유지·앞으로 당김. 바뀐 속성마다 `OnAppliedUnitsChanged(type, added: null)` 발행. 제거 개수 반환 |
| `RemoveAllOfType(UnitType)` | 메서드 | `RemoveApplied(u => u.UnitType == type)` |
| `Reset()` | 메서드 | 목록 비움, 속성 현재 값 = 베이스(풀 재사용 시) |
| `OnAppliedUnitsChanged` | event Action\<UnitType, RuntimeDataUnit\> | 목록이 바뀐 속성과(추가면) 추가된 인스턴스 |

- 보유자: `RuntimeDataUnitGroup`(기존 MonoBehaviour)이 `RuntimeDataUnitTarget` 하나를 갖는다. `InitUnits`/`ResetForReuse`는 이것을 만들거나 `Reset`한다. 기존 `UnitRuntimeDataList`, `Units`, `GetMatchingUnitData`, `OnUnitGroupChanged`(구독자 0)는 제거하고 `UnitTarget` 프로퍼티와 `GetAttribute(UnitType)` 위임으로 대체한다. `HasUnit`, `supportedUnits`, `bakedMassValue`는 유지한다.

**시전자 정보 `UnitCastSource`** (신규, 순수 C# · 인스턴스 생성 입력)
| 멤버 | 타입 | 의미 |
|---|---|---|
| `Caster` | GameObject | 시전자(없을 수 있음) |
| `CasterStat` | RuntimeStatData | 시전자 스탯(없을 수 있음) |

**Applicator (`IUnitApplicator`, 기존 확장)**
| 멤버 | 역할 |
|---|---|
| `Type DataType` | 담당 PureData 타입(기존) |
| `UnitType UnitType` | 담당 속성(신규 — 목록 재계산 조회 키) |
| `RuntimeDataUnit CreateInstance(PureDataUnit data, UnitCastSource source)` | 인스턴스 생성. `UnitApplicator<TData>`의 `protected virtual` **시전자 영향 계산 자리**(기본: PureData 값 그대로)를 거친다 |
| `float CalculateValue(RuntimeDataUnitAttribute attribute, IReadOnlyList<RuntimeDataUnit> applied)` | 속성 현재 값 계산(§3-2 공식). 미리보기도 이 함수를 쓴다 |
| `void Apply(UnitApplyTarget target, RuntimeDataUnitAttribute attribute, IReadOnlyList<RuntimeDataUnit> applied, RuntimeDataUnit added)` | 시각 적용 + 데미지 계산 자리(기존 `ApplyDamage`) |

- 조회: `UnitApplyLogicSystem`이 `DataType`(인스턴스 생성)과 `UnitType`(재계산) 두 가지 키로 찾는다. 같은 조회를 미리보기·시전에서도 쓰도록 `IUnitApplicatorRegistry`(신규 인터페이스, `UnitApplyLogicSystem`이 아닌 별도 순수 C# 구현 `UnitApplicatorRegistry`)로 분리해 VContainer에 등록한다.

### 3-2. 흐름

1. **시전(인스턴스 생성)** — `UnitChangeService.ChangeUnit(target RuntimeDataUnitGroup, PureDataUnit spell, UnitCastSource source, …)`가 `IUnitApplicatorRegistry`에서 `spell`의 Applicator를 찾아 `CreateInstance`로 인스턴스를 만든다. 기존 `newValue` 매개변수는 없앤다(값은 목록에서 계산됨). 파이프라인 경로는 `UnitMagicContext`에 `TargetUnitGroup`·`UnitInstance`를 담고, `ApplyUnitChangeStep`이 `AddApplied`를 호출한다. 폴백 경로는 `UnitChangeService`가 직접 `AddApplied`를 호출한다(진입점 단일화는 29번).
2. **목록 추가** — `RuntimeDataUnitTarget.AddApplied(instance)` → 목록 끝에 추가 → `OnAppliedUnitsChanged(type, instance)`.
3. **재계산·적용(단일 경로)** — `RuntimeDataUnitGroup`이 이벤트를 받아 정적 이벤트 `OnAnyUnitApplyRequested(UnitApplyTarget, RuntimeDataUnitAttribute, IReadOnlyList<RuntimeDataUnit> applied, RuntimeDataUnit added)`로 넘긴다. `UnitApplyLogicSystem`이 `type`의 Applicator로:
   1. `value = CalculateValue(attribute, applied)` → `attribute.SetCurrentValue(value)`
   2. `Apply(target, attribute, applied, added)` → 시각 적용 + 데미지 계산 자리
4. **속성 계산 공식(Applicator별 `CalculateValue`)**
   - **Mass**: 항목이 없으면 `BaseValue`. 있으면 `BaseValue × Σ(ScaleMultiplier)`. 예: ×2가 3개 → ×6, ×2 1개 → ×2(기존과 동일).
   - **Temperature**: 항목이 없으면 `BaseValue`(0). 있으면 **목록에서 가장 나중 항목의 `TargetTemperature`**(§6-2).
   - **Vector**: 가장 나중 항목의 `Speed`(보존용, §6-3).
5. **시각·데미지(Applicator별 `Apply`)**
   - **Mass**: 스케일 비율 = `cbrt(attribute.ValueRatio)`로 `ApplyMassScale`. `added`가 있을 때만(추가 시) `added.Source.scaleChangeVfxPrefab` 스폰. 데미지 계산 자리: `CurrentDamage = RoundToInt(BaseDamage × attribute.ValueRatio)`.
   - **Temperature**: `CurrentValue < 0`이면 얼음 머티리얼(가장 나중 항목의 `Source.iceMaterial`). `added`가 있을 때만 서리 파티클을 `clamp(|CurrentValue|/10, 0.5, 3)` 배율로 스폰.
   - **Vector**: 가장 나중 항목의 `Direction`·`Speed`로 `ApplyVelocity`(보존용).
   - 대상이 `IUnitTargetVisualizer`/`AttackDamage`를 갖지 않으면 해당 부분은 건너뛴다(기존과 동일).
6. **해제** — `RemoveApplied(조건)`/`RemoveAllOfType(type)` → 남은 항목 순서 유지·당김 → 바뀐 속성마다 3번 경로로 재계산·적용(`added = null`이므로 이펙트 스폰 없음). Mass를 전부 해제하면 질량 = 베이스, 스케일 ×1, CurrentDamage = BaseDamage.
7. **판정·미리보기·비용**
   - `AttributeGateStep`: `GetAttribute(Temperature).CurrentValue`로 온도 조건(속성이 없으면 기존처럼 실패).
   - `SizeGateStep`: `GetAttribute(Mass)?.ValueRatio ?? 1`.
   - `LockOnPreviewCalculator`: 대상 속성마다 "현재 적용 목록 + 큐에 있는 마법(`CreateInstance`로 만든 임시 인스턴스, 목록에는 추가하지 않음)"을 순서대로 이어 붙여 Applicator의 `CalculateValue`로 예상 값을 계산한다. 예상 스케일 = `cbrt(예상 값 / BaseValue)`.
   - `UnitCastRuleService`: `CalculateNewValue` 계열은 Applicator `CalculateValue`로 대체되므로 제거한다. `CostOfPair`는 `target.HasUnit(spell.UnitType)`이면 `BaseCost`, 아니면 0(동작 동일).
   - `UnitChangeService` 폴백의 마나 비용 공식(`BaseCost × |현재 − 새 값|`)은 "추가 후 예상 값"(현재 목록 + 새 인스턴스로 `CalculateValue`)과 현재 값의 차로 계산한다(기존과 같은 의미).
8. **풀 재사용** — `ResetForReuse` → `RuntimeDataUnitTarget.Reset()`(목록 비움, 현재 값 = 베이스). 이벤트는 발행하지 않는다(시각 복원은 기존대로 각 `IPoolReusable`).

### 3-3. 시청각
- **현재 튜토리얼 흐름은 변경 전과 같다**: kg 1회 → 스케일 ×2^(1/3), VFX 1회, CurrentDamage ×2 / Frost 1회 → 얼음 머티리얼, 파티클 1.5배 1회 / 얼음+확대 투사체로 돌문 파괴·보스 코어 성공.
- **새로 보이는 결과**: 같은 대상에 kg를 3번 걸면 질량 ×6, 스케일 ×6^(1/3) ≈ ×1.817, VFX는 걸 때마다 1회씩 총 3회, CurrentDamage ×6.
- **해제**: Mass를 전부 해제하면 스케일이 원래 크기로 돌아오고 CurrentDamage가 BaseDamage로 돌아온다(이펙트 없음). Temperature 해제 시 온도 값은 베이스(0)로 돌아오지만 얼음 머티리얼 원복 연출은 없다(28번 §7과 같은 범위 밖).

## 6. 설계 판단 (사용자 명세 밖 — 기존 동작 유지 기준으로 정함, 변경 가능)
1. **Mass 누적 결과의 적용 대상**: "Mass는 부피를 키우는 마법"이므로 합산 배율(×6)은 **부피(질량)**에 곱하고, 화면 스케일은 기존처럼 세제곱근(×6^(1/3))으로 한다. 크기(스케일) 자체를 ×6으로 하려면 `MassUnitApplicator`의 스케일 변환만 바꾸면 된다.
2. **Temperature 누적**: 사용자가 Mass 외 규칙은 정하지 않았으므로, 목록의 **가장 나중 항목의 목표 온도**를 쓴다(1회 적용 결과는 기존과 같다). `TemperatureUnitApplicator.CalculateValue` 한 곳만 바꾸면 규칙을 바꿀 수 있다.
3. **Vector**: 보존용이므로 가장 나중 항목의 방향·속도를 쓴다.
4. **해제 호출처**: 해제 API(`RemoveApplied`/`RemoveAllOfType`)만 만들고, 게임플레이에서 부르는 곳(해제 마법·지속 시간 등)은 이번 범위가 아니다. 검증은 eval로 한다.
5. **이펙트 스폰 시점**: 추가될 때만 스폰하고, 해제나 재계산만 할 때는 스폰하지 않는다.
6. **시전자 영향**: 현재 마법 수치에 영향을 주는 스탯·장비는 없으므로, 계산 자리만 두고 비워 둔다(28번 §6-9의 데미지 계산 자리와 같은 원칙).

### 6-A. 구현 중 정한 세부 (Goal 57 개발, QA 적합 판정)
- 인스턴스 서브클래스는 `Source` 외에 타입별 읽기 전용 `Data`(예: `PureDataMassUnit`)를 둔다. 같은 에셋을 가리키며, 연출 에셋을 캐스트 없이 읽기 위한 것이다.
- `UnitApplicator<TData>` 내부 구성: protected `CreateInstance`/`Calculate`/`ApplyVisual`, 시전자 영향 계산 자리 `ApplyCasterInfluence(TData, float pureValue, UnitCastSource)`(기본: 값 그대로), 헬퍼 `FindLatest<T>`.
- `ChangeUnit(RuntimeDataUnitGroup target, PureDataUnit spell, UnitCastSource source, RuntimeStatData manaPayer = null, UnitMagicPipeLine pipeLine = null)`: 시전자 영향 계산용 스탯(`source.CasterStat`)과 마나 차감 대상(`manaPayer`)을 분리한다. 일괄 시전은 마나를 미리 총비용으로 차감하므로 `manaPayer = null`. 폴백 로그는 실제로 차감했을 때만 "Mana Cost Consumed"를 찍는다.
- `RuntimeDataUnitTarget.AddApplied`는 bool을 반환한다(속성 없으면 false). `ApplyUnitChangeStep`은 성공 시에만 진영을 바꾼다. `RemoveApplied`는 조건을 항목마다 한 번만 평가하는 단일 순회이고, 바뀐 속성 이벤트는 처음 제거된 순서대로 발행한다.
- `UnitMagicContext`에서 `VectorDirection`·`VectorSpeed`도 삭제했다(Vector 인스턴스가 보유).
- Vector 입력 경로: `IVectorUnitInstanceFactory`(`01.Logic/03.Magic/`, `VectorUnitApplicator`가 구현, `.As<IUnitApplicator>().As<IVectorUnitInstanceFactory>()` 등록)를 기즈모 UI가 주입받아 방향·속도가 있는 인스턴스를 만든다(구체 클래스 참조 없음). `OpenVectorGizmo(RuntimeDataUnitGroup)`.
- `UnitCastRuleService`에는 `CostOfPair`만 남았다. `UnitCasterSystem`의 미사용 `IUnitCastRuleService` 주입은 삭제했다.
- `LockOnPreviewCalculator`는 `IUnitApplicatorRegistry`를 쓰고, 임시 인스턴스는 `UnitCastSource.None`으로 만든다. 시전자 영향을 구현할 때는 실제 시전자 정보를 넘겨야 한다.
- Temperature: 얼음 머티리얼은 온도 < 0이면 재계산 때마다 가장 나중 항목의 에셋으로 재적용하고, 서리 파티클은 추가된 인스턴스의 에셋으로만 스폰한다.
- `RuntimeDataUnitAttribute.ResetToBase()`와 static `CalculateValueRatio`(기존 `RuntimeDataUnit`에서 이동), `UnitCastSource.None`. `ResetForReuse`는 대상이 있으면 `Reset()`, 없으면 `InitUnits()`.

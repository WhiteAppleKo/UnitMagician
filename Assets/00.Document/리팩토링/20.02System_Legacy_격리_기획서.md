# [리팩토링 기획서] 20. `Assets/02.System` 현재 코드 / Legacy 코드 구분 (격리)

> 사용자 지시(세션 12, `/goal`): "`Assets/02.System` 경로에서 현재 쓰이는 코드와 Legacy 코드의 구분을 명확히 한다."

---

## 1. 작업 개요 및 유형
**비시청각**(구조 정리). 코드를 바꾸지 않고 **현재 쓰이지 않는 코드를 각 기능 폴더의 `99.Legacy/`로 격리(이동)** 하여 폴더만 봐도 활성/레거시가 구분되게 한다. **삭제하지 않는다**(재사용 가능성 보존, 프로젝트 관행 — `06.TacticalCommand/99.Legacy` 등).

판정 기준("현재 쓰이는"): 빌드 씬(`ProjectSettings/EditorBuildSettings.asset`의 `00.TestScene`)에서 씬/프리팹/에셋의 **GUID 참조**와 활성 코드의 **타입 참조**로 도달 가능한 것. 근거와 한계는 조사표 참조(Active 쪽은 과대 추정, Legacy 후보 쪽은 확정도 높음).

## 2. 핵심 요구사항
Unity 에디터의 에셋 이동(GUID 유지)으로 조사표의 신규 Legacy 후보를 각 기능 폴더의 `99.Legacy/`로 옮기고 코드·네임스페이스·씬 참조를 변경하지 않아, 컴파일과 씬 동작을 그대로 유지한 채 현재 코드와 Legacy를 폴더 단위로 구분한다.

## 3. 데이터 정의 및 흐름
**이동 대상(확정, 조사표 §2 근거: 활성 코드/씬 참조 0건, 묶음 내부 또는 이미 Legacy인 파일에서만 참조)**

| 묶음 | 파일 | 현재 위치 | 목적지 |
|---|---|---|---|
| A. 구형 플레이어 이동(7개, 반드시 함께) | `PureDataPlayerMovement.cs`·`.asset`, `RuntimeDataPlayerInput.cs`, `PlayerInputSystem.cs`, `PlayerMovementSystem.cs`, `IPlayerMovementVisualizer.cs`, `PlayerMovementVisualizer.cs` | `00.Movement/00.Data/00.PlayerMove/`, `01.Logic/00.PlayerMove/`, `02.Visualizer/00.PlayerMove/`(+`Interface/`) | `00.Movement/99.Legacy/PlayerMove/` |
| B. 구형 락온 전략 인터페이스 | `ILockOnStrategy.cs` | `00.Movement/01.Logic/00.Locomotion/Strategy/` | `00.Movement/99.Legacy/` (이미 있는 `NormalCombatLockOnStrategy.cs`와 함께) |
| C. 구형 카메라 모드 UI | `CameraModeUIComponent.cs`, `CameraModeUI.uxml` | `00.Movement/02.Visualizer/01.CameraMovement/UI/Legacy/` | `00.Movement/99.Legacy/CameraModeUI/` |
| D. 미채택 시전 전략 | `AimLockOnCastingStrategy.cs` | `01.UnitSystem/01.Logic/Strategy/` | `01.UnitSystem/99.Legacy/` |
| E. 샘플 VContainer | `GameController.cs`, `GameLifetimeScope_KWT.cs`, `GameManager.cs`, `Tester.cs` | `99.Common/SampleVContainer/` | `99.Common/99.Legacy/SampleVContainer/` (신규 생성; 99.Common은 기능 폴더가 아니라 표준 구조가 없어 같은 이름 규칙을 적용) |

**이동하지 않는 것(명시)**
- **한 파일에 활성 타입과 별칭이 섞인 파일**: `CameraSettingSO.cs`(활성 `PureDataCameraSetting` + 별칭, `CameraSettingSO.asset`이 GUID 사용), `ThirdPersonShoulderCameraStrategy.cs`, `TopViewMouseFocusStrategy.cs`, `CameraOptionUIController.cs`(`namespace CameraMovement.UI` 유일 정의) — 분리·이동하지 않는다.
- **판정 보류(Unclear)**: `02.CharacterSystem/00.Data/PureStatData_.asset`(참조 0건이나 기본 템플릿 여부 불명) — 이동하지 않고 사용자 확인 대상으로 남긴다.
- **폴더 규칙 위반 목록**(조사표 §4: `05.TimeSlowFilter/02.Visual` 명칭, 규칙에 없는 `03.UI` 폴더, 숫자 prefix 없는 하위 폴더, 루트에 흩어진 `*UnitApplicator_.asset`, Assets 루트의 `PureStatData_*.asset`, Logic 폴더의 MonoBehaviour 등) — 이번 범위가 아니다(목록만 유지).
- 이미 `99.Legacy`에 있는 12개(`MovementLifetimeScope`, `NormalCombatLockOnStrategy`, `MultiLockOnLogicSystem`, TacticalCommand 8개, `BossEventHitFlagsComponent`)는 활성 참조 0건으로 격리 상태가 정확하다 — 변경 없음.

**흐름**: ① 각 묶음을 에디터 에셋 이동(`AssetDatabase.MoveAsset`, `.meta` 동반 → GUID 유지)으로 목적지에 옮긴다 → ② 코드 내용·네임스페이스는 수정하지 않는다(어셈블리가 1개뿐이라 경계 문제 없음) → ③ 이동으로 비는 폴더(`00.PlayerMove` 3곳, `Strategy`, `UI/Legacy`, `99.Common/SampleVContainer`)는 폴더와 `.meta`를 함께 정리한다 → ④ 컴파일·씬 참조·플레이 스모크로 영향 없음을 확인한다.

**시청각(UX)**: 없음(플레이 동작 변화 없음).

## 4. 폴더 구조
기존 기능 폴더 안의 `99.Legacy/`를 사용한다(신규 기능 폴더/LifetimeScope 없음). 신규 생성: `00.Movement/99.Legacy/PlayerMove/`, `00.Movement/99.Legacy/CameraModeUI/`, `99.Common/99.Legacy/SampleVContainer/`. Legacy 내부 하위 폴더는 묶음 이름으로 구분하되 Data/Logic/Visualizer로 다시 나누지 않는다.

## 5. 체크리스트 (검수)
1. [ ] 묶음 A~E의 모든 파일이 목적지에 있고 원래 위치에는 없다. 이동한 `.meta`의 GUID가 이동 전과 같다(특히 `PureDataPlayerMovement.asset`, `CameraModeUI.uxml`, 각 `.cs`). 이동으로 비는 폴더와 `.meta`가 남아 있지 않다.
2. [ ] 컴파일 에러 0건(`recompile`, DLL mtime 교차). 코드 내용·네임스페이스가 변경되지 않았다(이동 외 diff 없음; git에서 rename으로 인식).
3. [ ] `00.TestScene`과 모든 프리팹/에셋에 Missing Script/Missing Reference가 새로 생기지 않는다(씬 로드 후 전체 MonoBehaviour 검사, 참조 GUID 유지 확인). `Demo_01_Polygon`도 이동 전과 같은 상태로 열린다(빌드 비대상이지만 확인).
4. [ ] 이동하지 않기로 한 파일(혼합 파일 4개, `PureStatData_.asset`)과 이미 격리된 12개는 변경되지 않았다. 활성 폴더에 남은 파일 중 조사표의 신규 Legacy 후보가 없다.
5. [ ] Play Mode 스모크: 플레이어 이동/점프/구르기/달리기, 시간정지·락온·마법 시전, 1단계 돌문, 3단계 이벤트 판정 1회, 인벤토리 열기/닫기, 콘솔 에러 0건. LifetimeScope 12개가 모두 정상 빌드된다.
6. [ ] 새로 생긴 구분이 문서에 반영된다: 조사표(19번)의 최종 상태가 이동 후 상태와 맞는다(Legacy 목록 갱신).

## 6. 확정/가정
- **확정(사용자 지시)**: 현재 코드와 Legacy를 폴더로 명확히 구분한다.
- **가정(추천안, 변경 가능)**: ① 삭제가 아니라 `99.Legacy` 이동. ② `AimLockOnCastingStrategy`도 이동(주석에 '재사용 가능성 때문에 삭제하지 않음'이라고 적혀 있어 삭제가 아니라 격리만). ③ `99.Common`에도 `99.Legacy/`를 같은 규칙으로 신설. ④ 폴더 규칙 위반 정리, `PureStatData_.asset` 처리, 서드파티(Synty Samples) 의존 정리는 범위 밖.

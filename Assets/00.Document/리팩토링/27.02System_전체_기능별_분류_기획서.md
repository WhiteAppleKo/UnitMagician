> 사용자 지시(2026-10-16): "`Assets/02.System` 경로의 Legacy를 제외한 모든 시스템 파일들에 대해 UnitSystem에서 진행한 분류를 진행해야 한다."
> 선행: 21번(UnitSystem Logic 분류, 완료·QA 통과). 사용자가 UnitSystem 분류에서 확정한 원칙: ① 기능(사용 방식)별로 나눈다 ② 너무 세세하게 나누지 않는다(`Casting`/`Caster` 같은 비슷한 이름의 폴더 금지, 한 카테고리 안에서 한 번 더 나뉘는 경우만 허용) ③ 두 방식이 같이 쓰는 기반은 `00.Common`.

---

## 1. 작업 개요 및 유형
**비시청각**(구조 정리, **순수 이동**). 각 시스템의 레이어 폴더(`00.Data`/`01.Logic`/`02.Visualizer`/`03.UI`) 안에 서로 다른 기능의 파일이 평탄하게 섞여 있는 곳을 기능별 하위 폴더로 나눈다. 코드 내용·클래스명·네임스페이스는 바꾸지 않고, 에디터 `AssetDatabase.MoveAsset`(GUID 유지)으로만 이동한다. `99.Legacy`는 대상이 아니다.

## 2. 분류 규칙 (제안)
1. **분류 대상**: 한 레이어 폴더에 파일이 **8개 이상**이고 **서로 다른 기능 묶음이 2개 이상** 섞여 있을 때만 하위 폴더로 나눈다. 7개 이하이거나 단일 기능이면 평탄 유지(세세하게 나누지 않기).
2. **이름**: `00.Movement`의 선례(`00.Locomotion`/`01.CameraMovement`)와 21번처럼 `숫자.영문기능명`. 공용 기반은 항상 `00.Common`.
3. **같은 기능은 레이어가 달라도 같은 이름·번호**를 쓴다(예: `UnitSystem`의 `02.TimeStop`은 Data/Logic/Visualizer/UI 모두 `02.TimeStop`).
4. 혼합 파일(한 파일에 둘 이상의 책임)은 분리하지 않고 파일 단위로만 분류한다. `Editor/` 폴더, `*LifetimeScope.cs`(기능 루트), `99.Legacy`, 이미 분류된 폴더(`00.Movement`, `99.Common/Input|Pooling`, `09.EventSystem/00.Data/*`)는 건드리지 않는다.
5. 이동만으로 씬/프리팹 참조가 유지되므로 씬 저장 금지.

## 6. 확정 사항 (사용자 승인 + 조사 결과)
- 분류 규칙(§2), `01.UnitSystem` Data/Visualizer/UI 분류, `02.CharacterSystem` 4분류, `07.NpcSystem` 3분류, `09.EventSystem` Logic 5분류는 사용자가 초안 그대로 승인했다.

  - `RuntimeDataMagicFavoriteSlots` → `02.TimeStop`: 인벤토리에서 편집하지만 소비처는 시간 정지 팝업(`MagicSelectionPopupLogicSystem`/`MagicSelectionPopupUIComponent`)의 즐겨찾기(W/E) 선택이다.

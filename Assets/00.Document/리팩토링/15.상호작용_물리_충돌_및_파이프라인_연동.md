## 2. 문제점 분석 (Code Smells - 5대 기준 위배 상세)

### 2-1. VContainer DI 전환 위배 (LifetimeScope 역조회)
* **LifetimeScope Find 탐색:** `CollisionDamageTrigger.cs`의 `EnsureInteractionService()`에서 `FindFirstObjectByType<InteractionSystemLifetimeScope>()`를 호출하고 `scope.Container.Resolve<IInteractionService>()`로 의존성을 수동 획득함. 이는 VContainer의 자동 주입 생명주기를 파괴하는 중대한 안티패턴임.

### 2-2. DLV 아키텍처 위배
* **Logic 폴더의 물리 컴포넌트:** `CollisionDamageTrigger.cs`가 `01.Logic`에 위치하여 `MonoBehaviour`, `OnTriggerEnter`, `OnCollisionEnter`, `Physics.IgnoreCollision`을 처리함. 물리 이벤트 수신기는 Visualizer 계층이어야 함.

### 2-3. 설계 원칙 위배 (디미터의 법칙 / 체이닝)
* `InteractionSystem.cs`에서 `context.Victim.TryGetComponent<CharacterStatComponent>(out var statComponent)` -> `statComponent.StatSystem.TakeDamage()`로 과도한 체이닝 발생.

## 3. 리팩토링 설계 (To-Be Architecture)

```
[L: Logic Layer]
IInteractionService (Interface)
└── InteractionSystem (Pure C# - 데미지/힐/단위마법 파이프라인 실행 및 결과 도출)

[V: Visualizer Layer]
CollisionDamageTriggerVisualizer (MonoBehaviour)
├── 충돌 감지(OnTriggerEnter, OnCollisionEnter)
├── 시전자 충돌 무시(Physics.IgnoreCollision)
└── [Inject] IInteractionService를 통한 비동기 요청 전송
```

### 3-1. LifetimeScope 역조회 제거 및 자동 주입화
* `CollisionDamageTrigger`의 수동 `FindFirstObjectByType` 제거.
* 프리팹 인스턴스화 시 `IObjectResolver.Instantiate`를 사용하거나 글로벌 서비스 주입 적용.

### 3-2. DLV 계층 재배치
* `CollisionDamageTrigger`를 `02.Visualizer` 계층으로 이동.

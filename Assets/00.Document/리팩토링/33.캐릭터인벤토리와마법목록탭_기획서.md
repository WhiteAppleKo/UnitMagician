# 33. 캐릭터 인벤토리 + 마법 목록 탭 (기획서)

> 작성일: 2026-10-23 · 상태: **구현 완료 · QA 합격**(2026-10-23, Goal 60) · 구현 세부 §6-A, QA 권고 §6-B · 실행 Goal: [60번](../02.Tutorial/Goal프롬프트/60.Goal프롬프트_캐릭터인벤토리와마법목록탭.md)
> 형식: `코드_작업_기획서_가이드라인_v1.0.md`
> 작업 순서(사용자 확정 2026-10-23): ① 캐릭터 인벤토리 → ② 마법 목록 탭 → ③ 마법 장착 → ④ RuntimeDataUnit 갱신 이벤트 → ⑤ 퀵슬롯 → ⑥ 기존 시스템 Runtime 캐싱 전환. **이 기획서는 ①과 ②를 다룬다.** ③ 이후는 별도 기획서.
> 사용자 확정(2026-10-23):
> - 인벤토리는 **캐릭터가 소유**한다(지금은 인벤토리 데이터가 없고, 씬 전역 `UnitCatalogService`가 보유 마법을 들고 있음).
> - 탭은 **ItemType에 따라 분류**한다. 탭을 하나하나 하드코딩하지 않는다. 지금은 마법 탭만 만들고, 다른 ItemType 탭은 언제든 추가할 수 있게 열어 둔다.
> - 아이템 정의(PureData/RuntimeData)는 아직 만들지 않는다.
> - 필드 아이템을 주우면 **인벤토리로 들어간다**.
> - 같은 PureData 에셋은 중복 보유할 수 없다. 같은 클래스라도 값·이름이 다른 별개 에셋이면 각각 보유할 수 있다.
> - **인벤토리의 아이템 보관 기준은 PureData다. `RuntimeDataUnit`은 장착할 때 생긴다**(사용자 확정 2026-10-23 — ③에서 다룸). 인벤토리는 PureData 에셋 참조만 들고 있는다.
> - 마법 장착·해제는 테스트 중에는 어디서든, 나중에는 안전지대에서만(③에서 다룸).

## 1. 작업 개요 및 유형
**시청각 + 비시청각.**
- 비시청각: 캐릭터 소유 인벤토리 데이터를 새로 만들고, 보유 마법의 소유권을 씬 전역 카탈로그에서 인벤토리로 옮긴다. 인벤토리는 PureData 에셋을 보관한다.
- 시청각: 인벤토리 창을 ItemType별 탭 구조로 다시 만들고, 첫 탭으로 마법 목록 탭을 둔다. 가이드라인의 가변형 UI 규칙(드래그 이동)을 적용한다.

## 2. 핵심 요구사항
1. **(비시청각)** 인벤토리 RuntimeData(`RuntimeDataInventory`)를 플레이어 캐릭터 스코프(`CharacterLifetimeScope`)에 두고, 항목을 ItemType별로 보관하게 한다. 보유 마법의 단일 원천을 씬 전역 서비스에서 캐릭터 데이터로 옮기고, 새 ItemType을 추가해도 인벤토리 코드를 고치지 않게 한다.
2. **(비시청각)** 마법을 습득하면 그 **PureData 에셋을 그대로** 인벤토리에 넣는다(RuntimeData는 만들지 않음 — 장착 시 생성, ③). 같은 PureData 에셋이 이미 있으면 넣지 않는다.
3. **(비시청각)** 시작 보유 마법의 원천을 씬 컴포넌트 필드(`UnitSystemLifetimeScope.initialUnits`)에서 **플레이어 PureData**(`PureStatData.defaultUnitMagics`)로 옮긴다(원본 값은 PureData에 둔다는 원칙).
4. **(시청각)** `I` 키(기존 `onInventoryToggled`)로 인벤토리 창을 열면, 위쪽에 **ItemType별 탭 버튼**이 보이고 지금은 "마법" 탭 하나만 있다. 마법 탭에는 보유 마법 목록(이름, 설명, 아이콘, 장착 표시, 즐겨찾기 배지)과 호버 상세 패널이 기존과 같이 보인다.
5. **(시청각)** 인벤토리 창은 제목 영역을 끌어 옮길 수 있고, 화면 밖으로 나가지 않는다(UI Toolkit 가이드 §3 가변형 UI).
6. **(시청각)** 필드 아이템(`PickupItem_Frost` 등)을 `E`로 주우면 인벤토리 마법 탭에 그 마법이 추가되고, 습득 팝업이 기존과 같이 뜬다.
7. **(유지)** 마법 탭의 클릭 장착·해제와 우클릭 즐겨찾기 등록은 기존과 같이 동작한다. 장착 목록의 소유 이전은 ③에서 다룬다.

## 3. 데이터 정의 및 흐름

### 3-1. 데이터

**`ItemType`** (신규 enum) — `Magic = 0`. 새 종류(장비, 소모품 등)는 값만 추가한다.

**`IInventoryItem`** (신규 인터페이스) — 인벤토리에 넣을 수 있는 **PureData**의 공통 계약.
| 멤버 | 타입 | 의미 |
|---|---|---|
| `ItemType` | ItemType | 탭 분류 키 |
- `PureDataUnit`이 이 인터페이스를 구현한다(`ItemType => Magic`, 읽기 전용 값이라 PureData의 Logic-Free 규칙에 어긋나지 않음). 나중에 장비 PureData 등도 같은 인터페이스를 구현하면 인벤토리에 들어간다.
- 항목 자체가 PureData 에셋이므로, 같은 에셋(참조 동일)이면 같은 항목이다.

**`RuntimeDataInventory`** (신규 · 순수 C# · 캐릭터 인벤토리 — PureData 참조 보관)
| 멤버 | 의미 |
|---|---|
| `GetItems(ItemType)` | 그 종류 항목(PureData)을 넣은 순서대로 |
| `Contains(IInventoryItem)` | 같은 PureData 에셋이 있는지 |
| `TryAdd(IInventoryItem)` | 같은 에셋이 없으면 끝에 추가하고 `OnItemAdded(item)` 발행. 있으면 false |
| `Remove(IInventoryItem)` | 제거하고 `OnItemRemoved(item)` 발행(지금 호출처는 없고, 확장용) |
| `ItemTypes` | 항목이 하나 이상 있는 종류 목록 |
- 등록: `CharacterLifetimeScope`에 Singleton으로 등록한다. 스코프 트리(`Character` → `Locomotion` → `UnitSystem` → `Pickup`)상 UnitSystem·Pickup에서 주입받을 수 있다.

**`IInventoryService` / `InventoryLogicSystem`** (신규 · 순수 C# Logic · Character 스코프)
| 멤버 | 의미 |
|---|---|
| `TryAcquire(IInventoryItem)` | `inventory.TryAdd`. 이미 있으면 false |
| `IsPossessed(IInventoryItem)` | `inventory.Contains` |
| `GetItems(ItemType)` | `inventory.GetItems` |
- 시작 시 플레이어 `PureStatData.defaultUnitMagics`를 순서대로 `TryAcquire`한다.
- RuntimeData를 만들지 않으므로 Applicator가 필요 없고, 데이터와 로직 모두 Character 스코프에 둔다.

**`UnitCatalogService`** (수정 — 보유 소유권 이전)
- `possessedUnits` 삭제. `IsPossessed`/`GetPossessedUnits`/`AcquireUnit`는 `IInventoryService`에 위임하거나 제거하고, 호출처를 인벤토리로 옮긴다(§3-2).
- 장착(`equippedUnits`, `TryEquipUnit`, `UnequipUnit`, `IsEquipped`, 이벤트)은 ③ 전까지 그대로 둔다. `TryEquipUnit`의 "보유 중" 검사는 인벤토리로 묻는다.
- 전체 마법 순서(`orderedUnits`)와 생성자의 `initialUnits` 입력은 삭제한다(시작 마법은 플레이어 PureData에서 옴). 장착 목록 순서는 인벤토리 마법 탭 순서를 따른다.

**`UnitSystemLifetimeScope`** — `initialUnits` 직렬화 필드와 `RegisterInstance<IReadOnlyList<PureDataUnit>>` 삭제. 씬의 kg·Frost 목록은 플레이어 `PureStatData` 에셋의 `defaultUnitMagics`로 옮긴다(§3-3 에셋).

### 3-2. 흐름
1. **시작**: 플레이어 `RuntimeDataInventory` 생성(빈 상태) → `InventoryLogicSystem` 초기화 시 `defaultUnitMagics`를 순서대로 `TryAcquire` → 지금 에셋 값(kg)이면 인벤토리 마법 항목 1개(`PureDataMassUnit_kg` 에셋). 장착은 기존처럼 첫 번째(kg)만 자동 장착(③ 전까지 카탈로그가 처리). Frost는 기존대로 필드에서 습득한다(§6-3).
2. **필드 습득**: `PickupLogicSystem.HandleInteractPressed` → `inventoryService.TryAcquire(target.GrantedUnit)` → 성공하면 `target.Consume()`. 이미 보유 중이면 줍지 않는다(기존 규칙). `PickupDetectorComponent`의 보유 확인도 인벤토리로 묻는다.
3. **디버그 습득**: `UnitDebugAcquireTestComponent` → `inventoryService.TryAcquire`.
4. **습득 팝업**: `UnitUnlockPopupUIComponent`는 카탈로그 `OnUnitAcquired` 대신 `RuntimeDataInventory.OnItemAdded`(ItemType Magic)를 구독한다.
5. **인벤토리 창**:
   - `InventoryUIComponent`(Character UI)가 창 틀(제목·드래그 영역·탭 바·내용 영역)을 그린다.
   - 탭은 `IInventoryTabRegistry`에 등록된 `IInventoryTabView`들로 만든다. 각 탭 뷰는 자기 `ItemType`, 탭 이름, 내용 그리기 함수를 가진다. 등록된 순서대로 탭 버튼이 생기고, 하드코딩된 탭은 없다.
   - `MagicInventoryTabView`(UnitSystem UI)가 `ItemType.Magic`으로 자신을 등록한다. 내용은 기존 `UnitInventoryUIComponent`의 목록·상세 패널·클릭 장착·우클릭 즐겨찾기를 옮긴 것이고, 목록은 `inventoryService.GetItems(ItemType.Magic)`(PureDataUnit의 이름·아이콘·설명)로 그린다.
   - 열기·닫기·시간정지 연동·입력 컨텍스트 전환은 기존 `UnitInventoryUIComponent`의 동작을 그대로 옮긴다.
6. **드래그**: 제목 영역 `PointerDownEvent`에서 포인터를 캡처하고 `BringToFront()` → `PointerMoveEvent`에서 `style.translate` 갱신(패널 경계 안으로 좌표 제한) → `PointerUpEvent`에서 해제.

### 3-3. 시청각
- `I`로 열면 창 위쪽에 "마법" 탭 버튼 하나가 선택된 상태로 보이고, 아래에 보유 마법 목록과 상세 패널이 기존과 같은 모양으로 보인다.
- 제목 영역을 끌면 창이 따라 움직이고, 화면 가장자리에서 멈춘다.
- 시작하면 마법 탭에 `defaultUnitMagics`의 마법이 보인다. 필드 아이템을 주우면 목록에 하나 더 생기고 습득 팝업이 뜬다.
- 클릭하면 장착·해제(테두리 색), 우클릭하면 즐겨찾기 배지(W/E/F)가 기존과 같이 바뀐다.

## 5. 예상 검수 방법 및 체크리스트
1. [ ] 플레이 시작 → 플레이어 `RuntimeDataInventory`에 `defaultUnitMagics`의 마법이 그 순서대로 **PureData 에셋 참조**로 들어 있고, 습득 시 `RuntimeDataUnit`이 생성되지 않는다(`CreateInstance` 호출 0). `UnitCatalogService`에 보유 목록 필드가 없다(grep `possessedUnits`).
2. [ ] `I`를 누르면 인벤토리 창이 열리고 탭 바에 "마법" 탭 하나가 선택된 상태다. 마법 목록·상세 패널·장착 테두리·즐겨찾기 배지가 기존과 같이 보인다. 다시 `I`를 누르면 닫히고 시간정지·입력 컨텍스트가 기존과 같이 복원된다.
3. [ ] 탭 코드에 ItemType 분기나 탭 이름 하드코딩이 없다. 시험용 `IInventoryTabView`(다른 ItemType)를 런타임에 등록하면 코드 수정 없이 탭 버튼이 하나 더 생긴다(eval 후 제거).
4. [ ] 제목 영역을 끌면 창이 이동하고, 화면 밖으로 끌어도 경계에서 멈춘다. 끌기 시작하면 창이 맨 앞으로 온다.
5. [ ] 필드 `PickupItem_Frost`를 `E`로 주우면(시작 보유 목록에 Frost가 없는 경우) 인벤토리 마법 탭에 Frost가 추가되고 습득 팝업이 뜨며, 픽업 오브젝트가 사라진다. 이미 보유한 마법의 픽업은 줍지 않는다.
6. [ ] 같은 PureData 에셋을 `TryAcquire`로 두 번 넣어도 항목은 1개다. 같은 클래스의 다른 에셋(예: `PureDataMassUnit_kg`과 `PureDataMassUnit_Torus`)은 각각 들어간다.
7. [ ] 마법 탭 클릭 장착·해제, 우클릭 즐겨찾기가 기존과 같이 동작하고, 퀵슬롯·시간정지 팝업·일괄 시전이 장착된 마법으로 기존과 같이 동작한다(회귀).
8. [ ] `UnitSystemLifetimeScope.initialUnits`가 없고, 시작 마법이 `PureStatData.defaultUnitMagics` 에셋 값에서만 온다(코드·씬에 시작 마법 목록 없음).
9. [ ] `UnitInventoryUIComponent`가 삭제됐고 참조 0건, 씬 Missing Script 0.
10. [ ] 컴파일 에러 0(recompile + DLL mtime 교차), 콘솔 에러 0, VContainer 정상, Missing Reference 기존 1건 불증가. 씬 diff는 이번 변경분뿐(카메라는 CinemachineBrain이 덮어쓰므로 저장 전 확인).

## 6. 설계 판단 (사용자 명세 밖 — 변경 가능)
1. **폴더와 스코프**: 인벤토리는 캐릭터 소유이므로 새 기능 폴더(`14.Inventory…`)를 만들지 않고 `02.CharacterSystem`의 하위 기능(`04.Inventory`)으로 둔다. 데이터(`RuntimeDataInventory`)와 로직(`InventoryLogicSystem`)을 모두 Character 스코프(루트)에 두어 UnitSystem·Pickup이 주입받게 한다.
2. **UI 구성**: 창 틀과 탭 구조는 캐릭터 UI(`02.CharacterSystem/03.UI`), 마법 탭 내용은 UnitSystem UI(`MagicInventoryTabView`)가 등록하는 방식으로 나눈다. 탭 뷰가 자신을 레지스트리에 등록하므로, 새 탭을 추가할 때 인벤토리 창 코드는 고치지 않는다.
3. **시작 보유 마법**: 플레이어 `PureStatData.defaultUnitMagics`에 **kg만** 넣는다. 기존 동작(kg만 보유, Frost는 필드에서 습득)과 같게 하기 위해서다.
4. **장착 목록**: ③ 전까지 `UnitCatalogService`에 남긴다. 장착 순서는 인벤토리 마법 탭 순서를 따른다(기존 `orderedUnits` 대체).
5. **시전 경로**: 시전 시 인스턴스를 새로 만드는 지금 경로(`UnitChangeService.CreateInstance`)는 이번에 바꾸지 않는다. ③에서 장착할 때 `RuntimeDataUnit`을 만들고, ⑥에서 시전이 그 장착 캐시를 복사해 대상에 넘기도록 바꾼다.

### 6-A. 구현 중 정한 세부 (Goal 60, QA 적합 판정)
- `MagicInventoryTabView`는 MonoBehaviour가 아니라 순수 C# 엔트리 포인트다(`IInitializable`에서 탭 레지스트리에 등록, `IDisposable`에서 해제). 씬에 컴포넌트를 붙이지 않는다.
- **우클릭 즐겨찾기 결함 수정(기획서 밖)**: 런타임 UI 패널은 `ContextClickEvent`를 발행하지 않아서, 기존 코드의 우클릭 즐겨찾기는 실제 입력으로는 동작하지 않았다(QA가 이벤트 관찰로 확인). `PointerDownEvent` 버튼 1로 처리하도록 바꿨다. 왼쪽 클릭 장착(`ClickEvent`, 버튼 0)과 충돌하지 않는다.
- UXML: `InventoryContainer`를 창 틀로 바꾸고 안에 `InventoryTitleBar`(제목 "인벤토리"), `InventoryTabBar`, `InventoryContent`를 두었다(기존 `UnitUI.uxml` 안). 가운데 정렬은 `left/top 50%` + 음수 margin(translate는 드래그 전용). 크기 640×480. 창은 picking Position, 탭바·내용·제목 텍스트는 Ignore.
- 탭 레지스트리: `Tabs` 공개, 같은 ItemType 중복 등록 거부, 첫 등록 탭이 기본 선택, 버튼 이름 `InventoryTab_{ItemType}`. 탭 이름 "마법"은 `MagicInventoryTabView` 안의 상수다.
- 창 위치는 닫았다 다시 열어도 유지하고, 열 때 화면 경계 안으로 다시 맞춘다.
- 시작 자동 장착: `UnitCatalogService` 생성자가 인벤토리 마법 탭의 첫 항목을 장착한다(Character 스코프 `InventoryLogicSystem.Initialize`가 먼저 실행되는 VContainer 빌드 순서에 의존).
- `RuntimeDataInventory`는 `ISaveableData`를 구현하지 않았다(저장·불러오기 범위 밖).
- 플레이어 PureData는 `Assets/PureStatData_.asset`(Y Bot 전용)이다. 재직렬화로 이미 코드에 있던 `hostileHitThreshold`·`hostileHitWindowSeconds` 기본값 줄이 함께 기록됐다(동작 변화 없음).

### 6-B. QA 권고 (필수 아님)
1. 시작 자동 장착이 스코프 빌드 순서라는 부작용에 의존한다. ③에서 장착 소유를 옮길 때 인벤토리 초기 지급 이후의 명시적 단계로 옮긴다.
2. 모든 UIDocument가 같은 PanelSettings·sortingOrder 0이라, 인벤토리 창을 왼쪽 위로 끌면 캐릭터 HUD가 창 위에 그려진다(클릭은 정상). 인벤토리 UIDocument의 sortingOrder를 HUD보다 높이면 해결된다.
3. UXML에 창 크기(640×480)와 가운데 정렬 margin(-320/-240)이 따로 적혀 있어, 크기만 바꾸면 중앙이 어긋난다.
4. 숫자키 1~4가 디버그 습득과 퀵슬롯 선택에 함께 묶여 있다(기존부터, 범위 밖).

## 2. 문제점 분석 (Code Smells - 5대 기준 위배 상세)

### 2-1. DLV 아키텍처 위배 (UI View의 입력 직접 폴링)
* **View 계층의 Hardware Input 직접 감지:** `UnitQuickSlotUIComponent.cs`의 `Update()`에서 `Keyboard.current[quickSlotKeys[i]].wasPressedThisFrame`을 직접 폴링함.
* **DLV 원칙 위배:** UI View는 Model 이벤트를 수신하여 렌더링만 갱신해야 하며, 하드웨어 입력을 직접 읽고 선택 상태를 능동적으로 결정하면 안 됨.

### 2-2. 디자인 패턴 적용 위배 (이벤트 푸시 부재)
* Update 폴링 방식의 입력 검사를 사용 중이므로 Input System의 이벤트 콜백 방식으로 전환 필요.

## 3. 리팩토링 설계 (To-Be Architecture)

```
[D: Data Layer]
RuntimeDataUnitQuickSlot (Observable Selected Slot Model)

[L: Logic Layer]
UnitQuickSlotLogicSystem (InputReader 이벤트 구독 -> RuntimeData 갱신)

[V: UI View Layer]
UnitQuickSlotUIView (Model 변경 이벤트 구독 -> VisualElement 스타일/아이콘 갱신만 수행)
UnitInventoryUIView (해금 이벤트 구독 -> 인벤토리 슬롯 동적 생성)
```

### 3-1. UI View의 순수 수동 렌더러 전환
* `UnitQuickSlotUIComponent`에서 `Update()` 및 `Keyboard` 입력 로직을 제거하고 `UnitQuickSlotUIView`로 개명.
* `RuntimeDataUnitQuickSlot`의 `OnSelectedUnitChanged` 이벤트만 수신하여 UI 요소를 갱신.

# [리팩토링 기획서] 21. `01.UnitSystem/01.Logic` 기능별 하위 폴더 분류

> 작성일: 2026-10-12 · 형식: `코드_작업_기획서_가이드라인_v1.0.md`
> 사용자 지시(세션 12): `01.UnitSystem/01.Logic`에 단위 관련 코드가 한 폴더에 섞여 있어 퀵슬롯과 시간정지 마법 사용이 구분되지 않으니 **기능별로 분류**한다. 범위는 이 폴더만이다.
> 선행: 20번 리팩토링 기획서(Legacy 격리, 완료·QA 통과).

---

## 1. 작업 개요 및 유형
**비시청각**(구조 정리). 파일 내용·네임스페이스를 바꾸지 않고 `01.Logic` 안에서 기능별 하위 폴더로 **이동만** 한다. 현재 20개 파일이 한 폴더에 평평하게 있다(`Strategy/` 2개만 하위 폴더).

## 2. 핵심 요구사항
Unity 에디터 에셋 이동(GUID 유지)으로 `01.Logic`의 파일을 기능별 하위 폴더 5개로 나눠, 폴더 이름만 보고 "마법 보유/장착", "퀵슬롯", "시간정지 마법 지정", "마법 시전·변환", "시점별 조작 전략"을 구분할 수 있게 하고 컴파일과 씬 참조를 그대로 유지한다.

## 3. 분류 (확정 안)
| 하위 폴더 | 파일 | 역할 |
|---|---|---|
| `00.Catalog/` | `IUnitCatalogService.cs`, `UnitCatalogService.cs`, `IUnitEquipRequirementChecker.cs`, `DefaultUnitEquipRequirementChecker.cs` | 마법 획득·소유·장착/해제, 장착 조건 판정 |
| `01.QuickSlot/` | `UnitQuickSlotLogicSystem.cs` | 평상시 숫자키/휠 퀵슬롯 선택·순환 |
| `02.TimeStopCasting/` | `MagicSelectionPopupLogicSystem.cs`, `IMagicSelectionPopupLogic.cs`, `MagicLockOnInputGate.cs`, `LockOnTargetLossLogicSystem.cs`, `LockOnPreviewCalculator.cs`, `LockOnPreviewLogicSystem.cs`, `LockOnManaPreviewLogicSystem.cs`, `EventCastTriggerLogicSystem.cs` | 시간정지 중 락온→팝업→지정 큐, 입력 허용 판정, 대상 소실 정리, 미리보기·마나 비용 표시, 3단계 전환점 발동 |
| `03.Casting/` | `UnitBatchCastingService.cs`, `IUnitChangeService.cs`, `UnitChangeService.cs` | 큐 일괄 시전·마나 계산/차감, 유닛 값 변환(공용 시전 계층) |
| `04.CasterStrategy/` | `UnitCasterSystem.cs`, `UnitTargetLogicSystem.cs`, `Strategy/IUnitCastingStrategy.cs`, `Strategy/TopViewMouseCastingStrategy.cs` | 카메라 시점별 시전 전략 Context, 대상 유닛 판정 (기존 `Strategy/` 하위 폴더는 `04.CasterStrategy` 안으로 합쳐 `Strategy` 폴더를 없앤다) |

- 합계 20개 파일(위 표의 파일 수: 4+1+8+3+4=20)이 모두 새 위치에 있어야 한다.
- 폴더 번호/이름은 `00.Movement/01.Logic/00.Locomotion`처럼 기존 프로젝트의 하위 폴더 명명 관행(숫자 prefix + 영문)을 따른다.

## 4. 데이터 정의 및 흐름
- 변경 대상은 파일 위치뿐이다(필드/메서드/네임스페이스/클래스명 무변경). 어셈블리가 1개(Assembly-CSharp)라 폴더 이동이 컴파일 경계에 영향을 주지 않는다.
- 흐름: ① 이동 전 파일별 GUID·경로 기록 → ② `AssetDatabase.CreateFolder`로 하위 폴더 생성 후 `AssetDatabase.MoveAsset`으로 이동 → ③ 비는 `Strategy/` 폴더 제거 → ④ 컴파일·씬 참조·플레이 스모크 확인.
- `UnitCasterSystem`, `UnitTargetLogicSystem`은 씬 컴포넌트(MonoBehaviour)이며 GUID로 참조되므로 반드시 에디터 이동(GUID 유지)으로 옮긴다.

## 5. 체크리스트
1. [ ] 20개 파일이 §3 표의 새 위치에 있고 `01.Logic` 루트에는 .cs 파일이 남아 있지 않다. 각 `.meta` GUID가 이동 전과 같다(`UnitCasterSystem`, `UnitTargetLogicSystem`은 씬 참조 GUID 유지 확인). `Strategy/` 폴더와 `.meta`가 제거됐다. 빈 폴더/고아 `.meta` 없음.
2. [ ] 코드 내용·네임스페이스 변경 없음(git에서 R100 rename). 컴파일 에러 0건(recompile, DLL mtime 교차).
3. [ ] `00.TestScene`에 Missing Script/Missing Reference가 새로 생기지 않는다(이동 전과 동일: Missing Script 0, Missing Reference 1건 `OptionUI/UIDocument.m_PanelSettings`는 기존). `UnitSystemLifetimeScope` 등록과 Container 빌드 정상.
4. [ ] Play Mode 스모크: 퀵슬롯 휠/숫자키 순환, 시간정지(T) → 락온 → 팝업 → 지정 → 해제 시 큐 1회 시전, 마나 예상 비용 표시, 인벤토리 장착/해제, 3단계 이벤트 1회, 콘솔 에러 0건.
5. [ ] 범위 밖 폴더(`00.Data`, `02.Visualizer`, `03.UI`, 다른 기능 폴더)는 변경되지 않았다.

## 6. 가정 (추천안, 변경 가능)
1. 하위 폴더 5개 구성과 이름은 위 표(안 1)로 한다. `EventCastTriggerLogicSystem`과 `LockOnTargetLossLogicSystem`은 시간정지 마법 지정 묶음(`02.TimeStopCasting`)에 넣는다(이벤트·시간정지 양쪽에서 쓰이는 경계 사례).
2. `00.Data`, `02.Visualizer`, `03.UI`의 같은 혼재 정리는 이번 범위가 아니다(요청 범위: 이 폴더만).
3. 파일 이름 접두사 변경은 하지 않는다(클래스명/참조 변경 위험).

## 7. 범위 밖
- 클래스명·네임스페이스 변경, `Data/Visualizer/UI` 폴더 분류, Logic 폴더 안의 MonoBehaviour(`UnitCasterSystem`, `UnitTargetLogicSystem`)를 Visualizer로 옮기는 구조 정리, 기능 로직 변경.

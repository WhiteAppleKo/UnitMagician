## 2. 문제점 분석 (Code Smells - 5대 기준 위배 상세)

### 2-1. DLV 아키텍처 위배
* **Blind Logic 원칙 위배:** `PlayerMovementSystem.cs`에서 `m_visualizer.Transform.Rotate(...)` 및 `Cursor.lockState`, `Cursor.visible`을 로직 계층에서 직접 변경함. 로직은 판단만 수행해야 하며 커서 및 트랜스폼 조작은 Visualizer 계층의 책임임.

### 2-2. 아키텍처 중복 (기능 중복성 레거시)
* **이동 시스템 이원화:** 신규 고기능 로코모션 시스템(`Movement.RefactoredLocomotion`)과 본 레거시 이동 시스템(`PlayerMovement`)이 동시에 존재하여 프로젝트 구조 복잡도 및 혼선을 유발함.

### 2-3. VContainer DI 전환
* **선택적 매개변수 남용:** 생성자에서 `ICameraFollowService cameraFollowService = null`과 같이 기본값을 사용하여 명시적인 의존성 그래프 구성을 방해함.

## 3. 리팩토링 설계 (To-Be Architecture)

```
[D: Data Layer]
PureDataPlayerMovement (SO)
RuntimeDataPlayerInput (Pure Input DTO)

[L: Logic Layer]
PlayerMovementSystem (IFixedTickable)
└── 판단 결과(목표 이동 벡터, 회전각)를 DTO/Interface로 Visualizer에 전달

[V: Visualizer Layer]
IPlayerMovementVisualizer
└── PlayerMovementVisualizer (Rigidbody / CharacterController 물리 적용 및 커서 제어 전담)
```

### 3-1. 로직-비주얼 완전 분리
* `PlayerMovementSystem`의 `Cursor.lockState` 및 `Transform.Rotate` 호출을 `IPlayerMovementVisualizer.SetCursorLockState(bool)` 및 `IPlayerMovementVisualizer.Rotate(Vector3)` 메서드로 이관.

### 3-2. 시스템 통합 및 점진적 Deprecation 로드맵 수립
* 신규 `LocomotionLogicSystem`으로 완전 전환 시 본 네임스페이스를 `[Obsolete]` 처리 후 안전하게 제거할 수 있도록 독립 모듈화.

## 4. 단계별 변경 명세

### Step 1: IPlayerMovementVisualizer 인터페이스 확장
* `Assets/02.System/00.Movement/02.Visualizer/00.PlayerMove/Interface/IPlayerMovementVisualizer.cs`:
  ```csharp
  public interface IPlayerMovementVisualizer
  {
      void Move(Vector3 direction, float speed);
      void Rotate(Vector3 direction, float rotateSpeed);
      void RotateYaw(float angle);
      void SetFirstPersonCameraPitch(float pitch);
      void SetCursorLocked(bool isLocked);
  }
  ```

### Step 2: PlayerMovementSystem 리팩토링
* `Cursor.lockState` 직접 호출 제거 -> `m_visualizer.SetCursorLocked(isFirstPerson)`으로 대체.
* `m_visualizer.Transform.Rotate` 제거 -> `m_visualizer.RotateYaw(yawRotation)`으로 대체.

### Step 3: MovementLifetimeScope 바인딩 명확화
* `MovementLifetimeScope.cs` 내 주입 인터페이스 명시적 등록.

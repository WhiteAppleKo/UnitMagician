## 2. 문제점 분석 (Code Smells - 5대 기준 위배 상세)

### 2-1. VContainer DI 전환 위배
* **컴포넌트 직접 검색:** `PlayerLockOnController.cs`에서 `FindFirstObjectByType<TimeSlowVisualizer>()`, `GetComponentInChildren<NormalCombatLockOnComponent>()`를 호출하여 종속성을 스스로 탐색함.
* **로직에서 비주얼 컴포넌트 쿼리:** `LocomotionLogicSystem.cs`의 `ToggleLockOn()`에서 `_visualizer.Transform.GetComponent<PlayerLockOnController>()`를 호출하여 VContainer 주입 컨테이너를 우회함.

### 2-2. 디자인 패턴 적용 위배 (상태 패턴 부재)
* **거대 Switch-Case 분기:** `LocomotionLogicSystem.cs` 내부에서 `LocomotionAnimationState` 열거형에 따른 `EnterState()`, `ExitCurrentState()`, `Tick()` 분기가 780줄에 걸쳐 단일 클래스에 집중됨.
* **확장성 부재:** 새로운 이동 상태(예: 슬라이딩, 벽 타기, 피격 경직) 추가 시 기존 클래스 전체를 수정해야 하므로 개방-폐쇄 원칙(OCP) 위배.

### 2-3. 중복 코드 및 불필요한 코드 잔재
* **빈 이벤트 핸들러 방치:** `LocomotionLogicSystem.cs`의 `AddTargetCandidate()`, `RemoveTarget()`이 빈 메서드로 남아있으며, Visualizer의 이벤트에 의미 없이 연결/해제됨.

### 2-4. 설계 원칙 위배 (SRP 및 Demeter 원칙)
* **God Class (SRP 위배):** `LocomotionLogicSystem`이 입력 해석, 이동 가속도, 회전 댐핑, 접지 판정, 천장 검사, 가산 회전값(Head/Body Turn, Lean) 연산, 락온 전환 등 과도한 책임을 동시에 보유함.
* **디미터의 법칙(LOD) 위배:** `_visualizer.Transform.GetComponent<...>()`와 같이 체이닝 호출 발생.

### 2-5. DLV 아키텍처 위배
* **Blind Logic 위배:** Logic 계층에서 Visualizer의 구체 컴포넌트 타입을 알고 `GetComponent`를 수행하여 Logic과 Visualizer 간의 계층 분리가 훼손됨.

## 3. 리팩토링 설계 (To-Be Architecture)

```
[D: Data Layer]
PureDataLocomotion (ScriptableObject)
RuntimeDataLocomotion (Observable State Data)

[L: Logic Layer]
LocomotionLogicSystem (Context / Dispatcher)
├── ILocomotionState (Interface)
│   ├── LocomotionGroundState (일반 보행/달리기/전력질주)
│   ├── LocomotionJumpState (도약)
│   ├── LocomotionFallState (낙하)
│   └── LocomotionCrouchState (앉기)
└── ILockOnController (추상화 인터페이스)

[V: Visualizer Layer]
ILocomotionVisualizer (Interface)
├── LocomotionVisualizer (CharacterController + Animator 구체 구현)
└── PlayerLockOnController (ILockOnController 구현, 무기/락온 컴포넌트 스위칭)
```

### 3-1. 상태 패턴(State Pattern) 도입
* `ILocomotionState` 인터페이스를 정의하고 각 상태별 `Enter()`, `Exit()`, `Tick()`을 독립 클래스로 분리.
* `LocomotionLogicSystem`은 현재 상태 객체로의 위임만 담당.

### 3-2. 락온 제어 인터페이스 추출 및 주입
* `ILockOnController` 인터페이스를 Visualizer 계층에 선언하고, `LocomotionLogicSystem`은 생성자 주입을 통해 `ILockOnController`를 직접 참조하여 컴포넌트 검색 제거.

### 3-3. VContainer 수명 주기 등록
* `LocomotionLogicSystem`: `builder.RegisterEntryPoint<LocomotionLogicSystem>(Lifetime.Scoped)`
* `ILocomotionVisualizer`, `ILockOnController`: `builder.RegisterComponentInHierarchy<...>()` 바인딩.

## 4. 단계별 변경 명세

### Step 1: 인터페이스 및 신규 상태 클래스 작성
* `Assets/02.System/00.Movement/01.Logic/00.Locomotion/State/ILocomotionState.cs`
  ```csharp
  namespace Movement.RefactoredLocomotion
  {
      public interface ILocomotionState
      {
          LocomotionAnimationState StateType { get; }
          void Enter();
          void Exit();
          void Tick();
      }
  }
  ```
* `LocomotionGroundState.cs`, `LocomotionJumpState.cs`, `LocomotionFallState.cs`, `LocomotionCrouchState.cs` 생성하여 기존 Switch 블록 로직 이관.
* `Assets/02.System/00.Movement/02.Visualizer/00.Locomotion/ILockOnController.cs` 인터페이스 추출.

### Step 2: 기존 클래스 수정
* `PlayerLockOnController.cs`: `ILockOnController` 상속, `[Inject]`를 통한 `TimeSlowVisualizer` 주입 방식으로 전환.
* `LocomotionLogicSystem.cs`:
  * `ILockOnController`를 생성자 주입 매개변수로 추가.
  * Switch-case 문을 `Dictionary<LocomotionAnimationState, ILocomotionState>` 또는 State 인스턴스 전환으로 교체.
  * `ToggleLockOn()` 내부의 `GetComponent` 제거 및 `_lockOnController.ToggleLockOn()` 호출로 단순화.
  * 미사용 `AddTargetCandidate`, `RemoveTarget` 잔재 코드 제거.

### Step 3: LifetimeScope 바인딩 갱신
* `LocomotionLifetimeScope.cs`:
  ```csharp
  builder.RegisterInstance(pureDataLocomotion);
  builder.Register<RuntimeDataLocomotion>(Lifetime.Scoped);
  builder.RegisterComponentInHierarchy<LocomotionVisualizer>().As<ILocomotionVisualizer>();
  builder.RegisterComponentInHierarchy<PlayerLockOnController>().As<ILockOnController>();
  builder.RegisterEntryPoint<LocomotionLogicSystem>(Lifetime.Scoped);
  ```

## 5. 기능 무결성 검증 기준 및 테스트 케이스

### 검증 체크리스트
1. **기본 이동 및 전이:** WASD 입력 시 Idle -> Walk -> Run -> Sprint 전이가 정상 동작하는가?
2. **점프 및 낙하:** Space 입력 시 점프 상태 진입 후 중력 적용 및 착지 판정(Fall -> Locomotion)이 끊김 없이 연결되는가?
3. **앉기 제어:** C키 입력 시 캡슐 콜라이더 축소/복구 및 천장 충돌 시 기립 불가 처리가 정상 유지되는가?
4. **락온 토글:** 마우스 휠 클릭 시 `PlayerLockOnController`를 통해 일반 락온/마법 락온이 정상 전환되는가?
5. **시간 정지 연동:** T키로 시간 정지 활성화 시 마법 락온 컴포넌트로 정상 스위칭되는가?

# 32. RuntimeDataUnitTarget 정리 — Mass = 기본 Scale × 배율, MassRatio 제거, Vector 즉시 마법화 (기획서)

> 작성일: 2026-10-20 · 상태: **구현 완료 · QA 합격**(2026-10-20, Goal 59 — 1차 조건부 합격 후 수정, 재검증 합격) · 구현 세부 §6-A · 실행 Goal: [59번](../02.Tutorial/Goal프롬프트/59.Goal프롬프트_RuntimeDataUnitTarget정리_질량배율과Vector즉시마법.md)
> 형식: `코드_작업_기획서_가이드라인_v1.0.md`
> 선행: 31번(마법 대상 PureData 신설 + 적용 목록 순회 적용, Goal 58 QA 합격, 미커밋).
> 사용자 확정(2026-10-20 대화):
> - **Mass 마법 = 프리팹의 기본 Scale × `CurrentMass`.** `CurrentMass`는 질량 절대값이 아니라 **스케일 배율**이다(초기 1, ×2를 3번 걸면 2+2+2 = 6). 베이스는 프리팹 원본 크기이며, 별도 `baseMass`·`UnitMassBaker`·세제곱근 변환은 필요 없다.
> - `RuntimeDataUnitTarget.MassRatio`는 필요 없다(계산기가 곱한 배율을 다시 나눠 되돌리는 값).
> - `RuntimeDataUnitTarget`의 전용 변경 메서드(`SetMass`, `SetTemperature` 등)는 유지한다(RuntimeData는 전용 메서드로만 변경).
> - **마법 전용 대상 데이터(`PureDataUnitTarget`/`RuntimeDataUnitTarget`)와 대상 자신의 데이터(예: `PureDataNpcProjectile`)는 분리(이중화)한다.**
> - `RuntimeDataUnitTarget`은 "대상 PureData + 적용 마법 전부"의 최종 결과다.
> - **Vector는 한 번 적용하면 되돌릴 필요가 없다.** 속도를 한 번 바꾸고 끝나는 즉시 적용 마법이므로 적용 목록에 남기지 않는다(해제·재계산 대상이 아님).
> - **기즈모 관련 내용은 일단 전부 지운다**(나중에 다시 추가하더라도). 이전의 "속도 슬라이더에 쓸 예정이라 보존"은 철회.

---

> 용어: 이 문서의 "Mass 마법(×2)"은 Mass 속성 마법 에셋 `PureDataMassUnit_kg`(배율 2), "Temperature 마법"은 `PureDataTemperatureUnit_Frost`(목표 온도 -15)를 말한다.

## 1. 작업 개요 및 유형
**시청각 + 비시청각.**
- 데이터 정리: `MassRatio`, Vector 상태, `baseMass`·`baseVectorSpeed`, `UnitMassBaker`, 세제곱근 변환을 제거한다.
- 계산 의미 변경: `CurrentMass`를 배율로 바꾼다.

이 변경으로 **유저가 보는 결과가 바뀐다**. 질량 마법의 크기 변화가 세제곱근이 아니라 배율 그대로 적용된다.
- Mass 마법(×2) 1회: ×1.26 → **×2**
- Mass 마법(×2) 3회: ×1.82 → **×6**

데미지와 게이트 판정 수치(배율 2 → 데미지 ×2, 크기 게이트 2.00 ≥ 1.50)는 그대로다.

## 2. 핵심 요구사항
1. **(시청각)** 대상에 Mass 마법(×2)을 시전하면 대상 크기가 프리팹 기본 크기의 2배가 되고, 3번 시전하면 6배가 된다. Mass를 전부 해제하면 기본 크기로 돌아온다.
2. **(시청각)** 같은 배율로 Rigidbody 질량도 대상 원래 질량 × 배율이 된다(§6-1).
3. **(비시청각)** `CurrentMass`를 "초기 1에서 Mass 항목 배율을 합산한 스케일 배율"로 바꾸고, 크기·데미지·크기 게이트·미리보기·비용이 이 배율 하나를 그대로 읽게 해서, 곱했다가 다시 나누는 계산과 세제곱근 변환을 없앤다.
4. **(비시청각)** 마법을 "지속 마법(적용 목록에 누적, 해제·재계산 대상: Mass·Temperature)"과 "즉시 마법(시전 시 한 번 적용하고 목록에 남기지 않음: Vector)"으로 나눈다. Vector는 시전할 때 인스턴스 값으로 속도를 한 번 바꾸게 하고, 대상 RuntimeData와 누적기에서 Vector 상태를 없애서, 되돌릴 필요가 없는 물리 변화를 대상 상태에 남기지 않는다.

### 3-2. 흐름
1. **재계산(`UnitTargetStateCalculator.Recalculate`)**: `ResetToData()` → 목록 순회 `Accumulate` → 확정.
   - 질량 배율 = `MassEntryCount > 0 ? MassMultiplierSum : 1` → `SetMass`
   - 온도 = `acc.Temperature ?? Data.BaseTemperature` → `SetTemperature`
   - Vector 확정 줄은 삭제한다.
2. **Mass 적용(`MassUnitApplicator`)**
   - 시각: `ApplyMassScale(state.CurrentMass)`. `CalculateScaleRatio`(세제곱근) 삭제. 추가된 인스턴스가 Mass면 VFX 스폰(기존과 같음).
   - 데미지: `RoundToInt(currentDamage × state.CurrentMass)`.
   - 값 읽기(`ReadValue`): `state.CurrentMass`.
3. **Vector 적용(즉시 마법, 보존용)**:
   - 시전(`UnitChangeService` / `ApplyUnitChangeStep`)에서 Applicator가 `IsInstant`이면 `AddApplied` 대신 `state.ApplyInstant(instance)`를 호출한다.
   - 이벤트 경로: `OnInstantUnitApplied` → `RuntimeDataUnitGroup` → 정적 이벤트 → `UnitApplyLogicSystem`. 재계산하지 않고 `ApplyVisual(target, state, instance)`만 실행한다.
   - `VectorUnitApplicator`가 그 인스턴스의 방향·속도로 `ApplyVelocity`를 한 번 호출하고 끝난다. 목록에 남지 않으므로 해제·재계산·풀 재사용 시 되돌리지 않는다.
   - 진영 변경(`ApplyCasterFaction`)은 적용에 성공했을 때만 일어난다(지속 마법과 같음).
4. **크기 게이트(`SizeGateStep`)**: `state.HasUnit(Mass) ? state.CurrentMass : 1` ≥ `RequiredMassRatio`.
5. **미리보기(`LockOnPreviewCalculator`)**: `PredictedMass` = 시뮬레이션의 `CurrentMass`(배율), `ScaleMultiplier` = 같은 값(세제곱근 없음). `LockOnPreviewVisualizer`의 고스트 크기 = `InitialScale × ScaleMultiplier`(기존 경로).
6. **폴백 비용(`UnitChangeService`)**: `ReadValue` 차이 공식은 그대로다. Mass 값이 배율이 되므로 Mass 마법(×2) 1회의 차이는 1(이전 0.97)이고, 최소 비용 `BaseCost`가 적용되는 결과는 같다.
7. **기즈모 UI 삭제**: 방향·속도를 정하는 입력 UI는 삭제한다(아래 3-4). Vector 인스턴스는 공용 경로로 만들고, 방향·속도 입력이 없으면 기존처럼 방향 forward·속도 0이다. 방향을 넣는 입력 경로는 나중에 다시 추가한다.

## 6. 설계 판단 (사용자 명세 밖 — 변경 가능)
1. **Rigidbody 질량**: 크기와 같은 배율을 적용한다(`rb.mass = 원래 질량 × CurrentMass`). 원래 질량은 Visualizer가 이미 캡처하는 Rigidbody 초기 질량이다. 크기만 바꾸고 질량은 그대로 둘 수도 있다.
2. **TestDummy 에셋**: `baseMass` 5가 사라져 나머지 대상과 값이 같아진다. 에셋을 합치지 않고 그대로 둔다(대상별 에셋 유지).
3. **누적기·계산기 구조**: 사용자 확정에 따라 setter를 유지하므로, 계산기가 누적기 결과를 setter로 기록하는 31번 구조는 그대로 두고, Vector와 질량 의미만 바꾼다.

### 6-A. 구현 중 정한 세부 (Goal 59, QA 적합 판정)
- `UnitMagicContext.IsInstantUnit` 신설: 파이프라인 스텝은 Applicator를 조회할 수 없으므로 `UnitChangeService`가 `applicator.IsInstant`로 값을 채운다. `ApplyUnitChangeStep`은 이 값으로 `AddApplied`와 `ApplyInstant` 중 하나를 고른다.
- 미리보기: 즉시 마법(Vector) 인스턴스는 시뮬레이션 목록에 넣지 않고 변화 표시("Vector (instant)")와 `EntryCount`에만 반영한다.
- 폴백 `ChangeUnit`은 `AddApplied`/`ApplyInstant`의 결과를 반환하고, 적용에 성공했을 때만 진영을 바꾼다.
- `rb.mass = initialMass × 배율`(예전 하한 `Max(0.1)` 제거). `RuntimeDataUnitTarget.DefaultMassMultiplier = 1`은 원본 값이 아니라 배율의 항등값이다.
- 빈 폴더가 된 `00.Data/Editor/`를 삭제했다.

## 1. 작업 개요 및 유형
**비시청각**(구조 재설계) + 결과적으로 시청각(돌문 NPC 연출, 보스 50% 연출)에 영향.

### 1-1. 사용자 원문 (확정)
- 2026-09-16: "범용적인 NPC(적 포함) 로직이 있을 거 아니야. 여기서 이벤트 전용 로직을 새롭게 만들지 말고 이벤트 시스템에서 **특정 조건(이벤트 조건)이 만족되면 저 로직에 접근해서** 이벤트를 구현하는 게 어떻냐는 거지."
- 2026-09-18: "튜토리얼 이벤트 시퀀서라는 이름으로 이벤트 시스템이 정의되어 있는데, **이벤트 시스템은 튜토리얼 이외에서도 사용되어야 함.** 네이밍이 좀 문제 있는 것 같음, 수정해야 함."
- 2026-10-14: "튜토리얼에서 이벤트(**로직에 따라 반복하는 게 아닌 반드시 일어나야 하는 행동**)가 뭐야. 첫 번째가 돌문 이벤트고 두 번째가 보스 체력 50% 이벤트잖아. 강약을 나누자면 **돌문 이벤트는 NPC만의 행동을 강제하는 약 이벤트**고 **보스 이벤트는 플레이어의 카메라 + 시간 정지까지 강제하는 강 이벤트**잖아."
- 2026-10-14: "돌문 이벤트는 돌문을 향해 **일반 NPC들이 길을 막고 투사체를 쏘아내고 있다 → 유저의 마법을 통해 문을 부순다 → 부숴지면 NPC들이 길을 비켜선다 → 비켜선 길로 따라가 문을 넘어가면 보스를 조우한다.**"
- 2026-10-14: "**이벤트 시퀀서는 하드코딩된 이벤트 SO를 반영하는 게 아니고, 확장성 좋게 어떤 이벤트 SO가 들어오냐에 따라 동적으로 작동하는 거고.**"
- 2026-10-13: "**모든 값은 이벤트 SO를 통해 값을 조정할 수 있어야 한다.**"
- 보스 50% 이벤트(22번 §11): 보스 50% → 발사 지점 설정(보스–플레이어 직선 기준 플레이어 우측 약 120°, 시야각 밖) → 투사체 발사 사운드와 함께 시퀀서의 시간 개입(감속) 시작, 카메라가 천천히 투사체를 따라 돈다(1인칭 이벤트 카메라, 시선=카메라→투사체) → 플레이어가 락온·마법 지정 → 스칠 때 timeScale 최저 → 성공/실패. 실패 시 보스 HP 회복, 아군 즉시 재발사 없음, 50% 재도달 시에만 재시작. 이벤트 투사체 속도는 곧 판단 시간.

### 1-2. 현재 상태 (코드 확인)
- `TutorialSequencerLogicSystem` 하나가 **보스 HP 50% 이벤트 한 개**를 직접 구현한다: 보스 HP 구독 → 임계값 이하면 Stage3 + `flightLogic.Begin()` + `OnBoss50Percent` 방송, 피격 구독 → 이벤트 투사체의 게이트·FinalDamage 판정 → `OnCoreHitSuccess/Fail` 방송, 실패 시 `Stage2`로 복귀. 단계는 `TutorialStage` 열거형, 상태는 `RuntimeDataTutorialSequence`.
- 방송 신호는 5개 고정(`OnBoss50Percent`, `OnCoreHitSuccess/Fail`, `OnEventFlightChanged`, `OnEventFlightTurnaround`). 연출은 각 시스템이 구독해 알아서 한다: `EventCameraTriggerLogicSystem`(카메라), `TimeSlowLogicSystem`(감속), `AllySupportTriggerLogicSystem`(아군 발사), `BossPhaseLogicSystem`(보스 무적·회복), `EventCastTriggerLogicSystem`(마법 지정·발동). 시퀀서가 지시하는 것이 아니다.
- `PureDataTutorialSequence`는 수치 모음일 뿐 이벤트 정의가 아니다(06번 6.9: 수치 하드코딩 금지 관례로 만든 SO).
- 돌문 사격은 시퀀서 밖의 `AllySupportTriggerLogicSystem.Tick()` 자체 타이머(+ 매 틱 `IsDestroyed` 폴링)가 돌린다. 시퀀서는 돌문을 모른다. NPC는 돌문 파괴 후 그 자리에서 `Idle`로 멈춘다.
- 시퀀서 이름·구조가 튜토리얼 전용(`Tutorial*`).

## 2. 핵심 요구사항
이벤트를 "시작 조건 + 강제할 동작 + 완료 조건 + 결과별 동작"을 담은 이벤트 SO로 정의하고, 어떤 이벤트 SO가 들어와도 같은 방식으로 실행하는 범용 시퀀서로 바꿔, 튜토리얼 밖에서도 이벤트를 에셋 추가만으로 만들 수 있게 하고 돌문(약)·보스 50%(강) 두 이벤트를 이 구조 위에서 동작시킨다.

## 3. 데이터 정의 및 흐름 (제안)

### 3-1. 데이터 구조 (PureData, 필드 단위)
**`EventDefinitionSO`** (이벤트 한 개의 정의)
- `eventId (string)`: 이벤트 식별자.
- `intensity (EventIntensity: Weak/Strong)`: **사용자 확정 — 약/강 구분은 플레이어에 영향을 주냐 안 주냐.** 약=플레이어에 영향 없음(NPC·월드 동작만, 예: 돌문 이벤트), 강=플레이어에게 영향(카메라·시간 정지·입력 락, 예: 보스 50% 이벤트).
- `trigger (EventTriggerSO)`: 시작 조건.
- `requiresCompleted (string[])`: 선행으로 완료돼야 하는 이벤트 id(예: 보스 이벤트는 돌문 이벤트 이후).
- `onStart (EventActionSO[])`: 시작 시 순서대로 실행할 동작.
- `completion (EventCompletionSO)`: 완료 판정 방식(성공/실패 결과를 낼 수 있음).
- `onSuccess / onFail (EventActionSO[])`: 결과별 동작.
- `rearmOnFail (bool)`: 실패 후 다시 시작 조건을 감시할지(보스 50%는 true: 실패 → 보스 HP 회복 → 50% 재도달 시 재시작).

**트리거 SO** (`EventTriggerSO` 파생)
- `SceneStartTrigger`: 씬 시작.
- `BossHpRatioTrigger`: `targetId`, `ratio (float, 이하일 때 발동)`.
- `EventCompletedTrigger`: `eventId`.

**완료 SO** (`EventCompletionSO` 파생)
- `TargetDestroyedCompletion`: `targetId`(예: 돌문) → 성공.
- `CoreHitCompletion`: `requiredDamage`, `requireAttributeGate`, `requireSizeGate` → 성공/실패(현재 `TutorialSequencerLogicSystem.HandleDamageProcessed` 판정과 소실 안전망을 일반화).

**동작 SO** (`EventActionSO` 파생, 각자 필드 소유)
- NPC 동작: `NpcMoveAction(npcIds, 목적지)`, `NpcTeleportAction(npcId, 위치)`, `NpcRepeatAttackAction(npcIds, targetId, interval, 투사체 속도/데미지)`, `NpcStopAttackAction`, `NpcStepAsideAction(npcIds, 비켜서는 위치/방향·거리)`.
- 강 이벤트 동작: `EventProjectileLaunchAction(발사 각도, 발사 거리, 투사체 속도(= 판단 시간), 투사체 데미지)`, `TimeSlowOverrideAction(최저 timeScale, 접근/이탈 곡선)`, `CameraOverrideAction(블렌드 시간, 블렌드 곡선, FOV, 눈 높이, 추적 높이 오프셋)`, `InputLockAction`, `BossRecoverAction(회복 비율, 회복 속도, 타임아웃)`, `BossInvulnerableAction`.
- 현재 `PureDataTutorialSequence`·`PureDataTimeSlow`·`PureDataCameraSetting`·`PureDataBossPattern`에 흩어진 이벤트 수치(Goal 47/48 목록)는 이 동작 SO의 필드로 옮긴다(모든 값은 이벤트 SO에서 조정, 값 유실 금지).

**RuntimeData**: `RuntimeDataEventSequencer` — 이벤트별 `state (Locked/Armed/Running/Completed)`, 마지막 `result (Success/Fail)`. 변경 시에만 이벤트 발행.

### 3-2. 가공/흐름
1. 씬에 이벤트 SO 목록이 등록된다(순서/선행 조건은 SO 안). 시퀀서는 `Locked/Armed` 이벤트의 트리거를 감시한다(트리거 종류별 평가기).
2. 트리거 충족 + 선행 완료 → 이벤트 `Running`, `onStart` 동작을 순서대로 실행하고 범용 신호 `OnEventStarted(eventId)`를 방송한다.
3. 동작은 **동작 SO를 처리하는 핸들러**가 실행한다. 핸들러는 각 소유 시스템에 있다(카메라 시스템이 `CameraOverrideAction`을, 감속 시스템이 `TimeSlowOverrideAction`을, NPC 시스템이 `Npc*Action`을, 보스 페이즈가 `BossRecoverAction`을 처리). 시퀀서는 동작 SO 타입으로 핸들러를 찾아 호출한다. 스코프 트리가 달라 생성자 주입이 안 되므로 기존 `BindEventSequencer`류 사후 배선 패턴으로 핸들러를 등록한다.
4. 완료 판정(`completion`)이 결과를 내면 `onSuccess` 또는 `onFail` 동작을 실행하고 `OnEventCompleted(eventId, result)`를 방송한다. `rearmOnFail`이면 `Armed`로 복귀.
5. 기존 5개 고정 신호는 이 범용 신호와 동작 핸들러로 대체된다(전환 중 호환 방법은 개발이 보고).

### 3-3. 두 이벤트의 정의 (에셋 2개)
- **돌문 이벤트 (약)**: trigger=`SceneStartTrigger` / `onStart`=`NpcMoveAction`(길을 막는 위치로), `NpcRepeatAttackAction`(돌문 대상, 주기) / completion=`TargetDestroyedCompletion(돌문)` / `onSuccess`=`NpcStopAttackAction`, `NpcStepAsideAction`(길 비켜서기) / `rearmOnFail`=false. 이후 보스 이벤트의 선행.
- **보스 50% 이벤트 (강)**: trigger=`BossHpRatioTrigger(0.5)`, requiresCompleted=[돌문 이벤트] / `onStart`=`InputLockAction`, `EventProjectileLaunchAction`(120°, 거리, 속도, 데미지), `TimeSlowOverrideAction`, `CameraOverrideAction`, (특수 NPC를 발사 지점 L로 순간이동: §7-3) / completion=`CoreHitCompletion` / `onSuccess`=감속·카메라·입력 락 해제 / `onFail`=해제 + `BossRecoverAction` / `rearmOnFail`=true.

### 3-4. 시청각(UX)
- 돌문: 일반 NPC들이 길을 막고 돌문을 향해 투사체를 쏜다 → 플레이어의 마법으로 문이 부서지면 NPC들이 길을 비켜서고 플레이어가 지나갈 수 있다.
- 보스 50%: 22번 §11 연출 그대로(시퀀서가 모든 것을 세팅).

## 5. 체크리스트 (데이터 흐름 근거)
1. [ ] 이벤트 SO 에셋만 추가/교체하면 시퀀서 코드 수정 없이 새 이벤트가 동작한다(예: 테스트용 약 이벤트 SO 1개 추가 → 조건 충족 시 `OnEventStarted/Completed`와 동작 실행).
2. [ ] 돌문 이벤트: 씬 시작 → NPC들이 길을 막고 돌문에 투사체를 쏜다 → 돌문 파괴(`TargetDestroyedCompletion`) → `onSuccess`로 사격 중단 + NPC들이 길을 비켜선다 → 플레이어가 통과해 보스 영역으로 이동 가능. 시퀀서 밖 자체 타이머/폴링이 없어진다.
3. [ ] 보스 50% 이벤트: 선행(돌문) 완료 후 보스 HP가 SO의 비율 이하가 되면 시작, 22번 §11 연출(120° 발사 지점, 감속·최저 timeScale, 1인칭 이벤트 카메라 추적, 락온·지정, 전환점 발동)이 이벤트 SO 값으로 동작한다. 성공/실패 두 경로가 `onSuccess/onFail`로 처리되고 실패 시 아군 즉시 재발사 없이 HP 회복 후 50% 재도달에만 재시작.
4. [ ] 모든 이벤트 수치(임계값, 각도, 거리, 투사체 속도·데미지, 최저 timeScale·곡선, 카메라 블렌드·곡선·FOV·눈 높이, 보스 회복 비율·속도·타임아웃, NPC 비켜서기 위치, 사격 주기)가 이벤트 SO에서만 조정되고, 값을 바꾸면 실제 동작이 바뀐다(원복). 코드에 이벤트 수치 하드코딩이 없다.
5. [ ] 기존 `Tutorial*` 시퀀서·고정 신호가 `99.Legacy`로 격리되거나 대체되고 컴파일 에러 0, 씬 Missing Script 0, 콘솔 에러 0. 평상시(이벤트 외) 동작 회귀 없음.

## 6. 이행 순서 (Goal 50 → Goal 51)
1. 범용 실행기 + 이벤트 정의 SO 골격 + 트리거/완료/동작 핸들러 등록 구조 (돌문 이벤트로 먼저 검증: 가장 단순한 약 이벤트). **[완료: Goal 50, §11]**
2. 보스 50% 이벤트를 이벤트 SO로 이전(기존 신호·구독자를 동작 핸들러로 전환, 수치 이전 — 47/48번 내용 흡수). **[완료: Goal 51, §12]**
3. 문서·Legacy 정리. **[완료: Goal 51, §12]**

## 7. 사용자 확정 (2026-10-14) 및 남은 결정

**확정**
1. **약/강**: 플레이어에 영향을 주냐 안 주냐(§3-1).
2. **돌문 이벤트 NPC = `BlockerNPC.cs`(신규 컴포넌트)**: 길을 막고 투사체를 쏘는 일반 NPC들에 붙인다. `BlockerNPC`가 **막고 있는 위치**와 **비켜설 위치**를 가지고, 이벤트 시스템의 명령에 따라 `MoveTo`로 비켜선다. (검토 의견은 §9)
3. **보스 이벤트의 발사 NPC**: **순간이동**으로 발사 지점 `L`에 옮긴다. 이 NPC는 돌문 이벤트의 일반 NPC(`BlockerNPC`)와 **다른 특수한 NPC**다.
4. **이벤트 SO 등록**: **씬 시작 시에 등록**하고, **조건 분기가 있는 이벤트 SO가 마무리되면 활성 이벤트 목록을 새로 갱신**한다(해석: 분기 이벤트의 성공/실패 결과에 따라 다음 이벤트를 열거나 실패한 이벤트를 다시 감시 상태로 되돌리는 갱신을 시퀀서가 완료 시점에 수행).

**남은 결정**
- (확정 2026-10-14) 이름: §10의 고정 이름과 네임스페이스 `GameEvent`.

## 9. BlockerNPC 검토 의견 (코드 확인, 2026-10-14)
**결론: 구조상 맞고 구현 가능하다.** 기존 NPC 시스템과 어긋나는 곳은 없다. 다만 아래 5가지는 설계에 반영해야 한다.
- **계층**: `BlockerNPC`는 씬에 놓이는 MonoBehaviour이므로 `07.NpcSystem/02.Visualizer/`의 [V] 컴포넌트로 두고, 막는 위치/비켜설 위치(씬 고정 좌표)와 `groupId`를 직렬화 필드로 가진다. 로직은 이 컴포넌트에 쓰지 않고, 같은 GameObject의 `NpcCombatActorVisualizer.CombatActor`(이미 노출된 `INpcCombatActor`)를 통해 `MoveTo`만 호출한다. 이벤트 시스템과의 접점은 인터페이스(예: `IBlockerNpc`: 위치 `Vector3` 읽기 + `groupId`)로 한다.
- **찾는 방법**: Find* 금지이므로 `NpcSystemLifetimeScope`가 `NpcCombatActorVisualizer` 목록을 인스펙터로 받는 기존 패턴과 같이 `BlockerNPC` 목록을 인스펙터로 등록하고, 비켜서기 동작 핸들러가 `groupId`로 조회한다.
- **명령 순서(중요)**: `NpcCombatActorLogicSystem.Attack`은 "이동 중 공격 명령이 오면 공격이 이동보다 우선"하도록 이동을 끊는다. 따라서 돌문 파괴 후 **사격 반복(`NpcRepeatAttackAction`)을 먼저 멈추고** 그다음 `MoveTo`(비켜서기)를 내려야 한다. `onSuccess` 동작 순서가 `NpcStopAttackAction` → `NpcStepAsideAction`인 이유.
- **이동 방식**: `MoveTo`는 NavMesh가 아니라 목적지로 직선 `MoveTowards`(속도=NPC 데이터 `moveSpeed`)라서 다른 콜라이더에 막히지 않는다. 비켜설 위치로 가는 직선 경로가 비어 있어야 하고, 이는 씬 배치(레벨) 책임이다. 비켜서는 속도·도착 임계값은 NPC 데이터의 `moveSpeed`/`arrivalThreshold`를 쓴다(이벤트 SO에서 덮어쓰려면 `NpcStepAsideAction`에 이동 속도 필드를 추가).
- **복수 NPC**: 일반 NPC들 각각이 `NpcCombatActorVisualizer`(+ `NpcSystemLifetimeScope` 목록 등록)와 `BlockerNPC`를 가진다. 완료 동기화(모두 비켜섰을 때 이벤트 후속 처리)가 필요하면 `OnMoveCompleted`를 모아 쓴다.
- **특수 NPC(보스 이벤트)**: 순간이동은 `INpcCombatActor`에 아직 없다(`MoveTo`만 있음). `NpcTeleportAction` 처리를 위해 `TeleportTo`(또는 동등 기능)를 NPC 로직/비주얼 인터페이스에 추가해야 한다. 현재 단일 아군 NPC(`NpcCombatActor_Dummy`)가 이 특수 NPC 역할로 남고, 돌문 사격은 `BlockerNPC`들이 맡으므로 `AllySupportTriggerLogicSystem`의 돌문 타이머 로직은 이벤트 시스템으로 대체된다.

**참고/주의**: (1) `BossHpRatioTriggerEvaluator`는 평가 시작 시점에 이미 비율 이하면 즉시 충족시키므로, 실패 회복 비율이 트리거 비율 이하로 설정되면(`recoverHpRatio <= ratio`) 실패 직후 이벤트가 바로 재시작된다(HP가 "다시 도달"하지 않아도). (2) 트리거 비율은 이벤트가 `Armed`가 되는 시점에 읽혀, 비율을 바꾸면 다음 `Armed`(실패 후 재무장 포함)부터 적용된다. (3) 선행 이벤트(`StoneDoor`)가 끝나기 전에는 보스 HP가 낮아져도 보스 이벤트·무적·회복 진입이 일어나지 않는다. (4) `requiresCompleted`는 결과(Success/Fail) 무관 `Completed`면 충족(Goal 50에서 정한 의미 그대로). (5) 무적 최대 지속시간 값은 이전부터 판정에 쓰이지 않아 값만 옮겼다.

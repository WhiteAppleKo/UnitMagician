# 08. 아키텍처 결함 및 리팩토링 점검

---

## 1. 의존성 주입 위반 및 안티패턴

1. **직접 씬 탐색 의존 (Service Locator 및 Find 계열 남발)**
   - `TacticalCommandLogicSystem.cs`:
     - `UnityEngine.Object.FindAnyObjectByType<CameraFollowVisualizer>()`
     - `UnityEngine.Object.FindAnyObjectByType<UnitQuickSlotUIComponent>()`
     - `UnityEngine.Object.FindAnyObjectByType<UnitCasterSystem>()`
     - 상위 스코프에 연결되지 않은 형제 스코프 컴포넌트를 주입받지 못하여 씬 전체를 탐색하는 안티패턴이 존재합니다.
   - `UnitCasterSystem.cs`:
     - 생성자에서 `IObjectResolver`를 직접 받아 `resolver.TryResolve<ICameraFollowService>()`와 `resolver.TryResolve<RuntimeDataTimeSlow>()`를 수동 호출하는 Service Locator 패턴이 혼재되어 있습니다.
   - `TimeSlowFilterLogicSystem.cs`:
     - 동일하게 `IObjectResolver`를 통해 `ITimeSlowVisualizer`와 `RuntimeDataTimeSlow`를 런타임에 동적으로 역조회하고 있습니다.

2. **강제 다운캐스팅 (인터페이스 추상화 파괴)**
   - `UnitCasterSystem.cs`:
     - `this.changeService = (UnitChangeService)changeService;`
     - 인터페이스 규격인 `IUnitChangeService`로 파라미터를 수신한 뒤, 내부에서 구체 클래스로 강제 변환하여 사용 중입니다. 이로 인해 모듈 간 결합도가 상승하고 인터페이스 분리 원칙이 훼손됩니다.

3. **정적 싱글톤 접근 의존**
   - `InputContextManager.cs`:
     - `InputContextManager.Instance` 정적 프로퍼티를 전역에서 참조하고 있습니다. 컨테이너를 통한 명시적 주입 흐름을 우회하고 있어 테스트 코드 작성 및 다중 씬 로드 시 추적이 어려워집니다.

---

## 2. Public API 노출도 및 캡슐화 평가

1. **내부 런타임 데이터의 무분별한 참조 노출**
   - `CharacterStatSystem.RuntimeData`:
     - `RuntimeStatData` 클래스의 내부 가변 프로퍼티(`HP.CurrentValue`, `MP.CurrentValue` 등)가 외부에 그대로 열려 있습니다.
     - 외부 객체(`InteractionSystem`, `UnitChangeService` 등)가 서비스의 보호 메서드(`TakeDamage`, `UseMP`)를 거치지 않고 직접 수치를 조작할 수 있는 결함 위험이 존재합니다.

2. **카메라 서비스 프로퍼티 중복 노출**
   - `CameraFollowService.cs`:
     - `CurrentTargetPosition`과 `TargetPosition`, `CurrentLookAngles`와 `LookAngles`처럼 동일한 역할을 하는 프로퍼티가 네이밍 호환성을 이유로 중복 노출되어 있어 호출자 측에 혼선을 초래합니다.

3. **지연 초기화 프로퍼티의 부수 효과**
   - `UnitCasterSystem.MultiLockOnData`:
     - getter 호출 시 내부 필드가 null이면 즉시 `new RuntimeDataMultiLockOn()`을 생성합니다. 단순 조회 연산이 내부 상태를 변경하는 부수 효과를 일으키고 있습니다.

## 3. 데이터 흐름 및 런타임 병목 지점

1. **상호 참조 및 순환 종속 위험**
   - `TacticalCommandLogicSystem`은 `UnitCasterSystem`과 `CameraFollowService`를 참조합니다.
   - 반대로 `UnitCasterSystem`은 전술 모드에서 공유되는 시간 정지 데이터(`RuntimeDataTimeSlow`)와 카메라 서비스(`CameraFollowService`)를 상호 참조합니다.
   - 세 시스템의 실행 순서가 명시적으로 통제되지 않으면 프레임 단위의 상태 불일치가 발생할 수 있습니다.

2. **비동기 파이프라인 프레임 지연 지점**
   - `InteractionSystem.ProcessDamageAsync(DamageContext context)`:
     - 메서드 진입부에 `await UniTask.Yield();`가 하드코딩되어 있습니다.
     - 피격 판정이 물리 충돌 프레임에서 즉시 처리되지 못하고 다음 프레임으로 지연되어, 빠른 연타 피격이나 정밀 물리 반응 시 시각적 싱크 어긋남이 발생할 수 있습니다.

3. **입력 이벤트 다중 분산 구독**
   - `InputReader`의 동일한 델타/스크롤 이벤트(`onMouseWheelScrolled`, `Look`)를 `CameraFollowService`, `UnitQuickSlotLogicSystem`, `UnitCasterSystem`이 각각 개별적으로 구독하고 있습니다.
   - 입력 컨텍스트 전환 시 이벤트 실행 순서가 보장되지 않아 마우스 휠 조작 시 카메라 줌과 퀵슬롯 변경이 동시에 반응하는 등의 입력 간섭 위험이 내포되어 있습니다.

## 4. 종합 리팩토링 실행 프롬프트 (/goal)

```text
/goal 프로젝트 전체 아키텍처 결함 및 DI 안티패턴 종합 리팩토링

당신은 유니티 아키텍처, VContainer 의존성 주입 및 성능 최적화 전문 시니어 수석 프로그래머입니다.
프로젝트 전반에 걸쳐 식별된 3대 아키텍처 결함(직접 씬 탐색, 캡슐화 누수, 비동기 파이프라인 프레임 지연)을 단계별로 완벽히 리팩토링해 주세요.

[목표]
1. FindAnyObjectByType 및 IObjectResolver 수동 조회를 전면 제거하고 명시적 생성자 주입 구조 확립.
2. RuntimeStatData 등 내부 가변 데이터의 캡슐화를 보호하고 중복 프로퍼티 정리.
3. 데미지 파이프라인의 불필요한 UniTask.Yield 1프레임 지연 제거 및 입력 이벤트 우선순위 단일화.

[작업 단계]
Phase 1: VContainer 스코프 및 의존성 주입 정규화
- TacticalCommandLogicSystem, UnitCasterSystem, TimeSlowFilterLogicSystem 내 직접 씬 탐색 코드 제거 및 생성자 주입 전환.
- UnitCasterSystem의 IUnitChangeService 강제 다운캐스팅 제거.

Phase 2: 도메인 데이터 캡슐화 강화
- CharacterStatSystem의 RuntimeData 노출 제한 및 외부 직접 수정 차단.
- CameraFollowService의 중복 프로퍼티 단일화.
- UnitCasterSystem.MultiLockOnData 지연 생성 부수 효과 제거.

Phase 3: 데이터 흐름 및 성능 최적화
- InteractionSystem의 ProcessDamageAsync 내 await UniTask.Yield() 제거 및 즉각 반응형 파이프라인 구성.
- InputReader 이벤트 다중 분산 구독을 InputContextManager 기반의 활성 컨텍스트 단일 중계 구조로 정돈.

[검증 기준]
- 씬 로드 및 플레이 시 VContainerException 또는 NullReferenceException 발생 제로.
- 시간 정지 전술 모드, 마법 시전, 피격 연산, 카메라 시점 전환이 부드럽고 오차 없이 실행될 것.
```
